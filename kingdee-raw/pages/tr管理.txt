======TR管理======
====== TR管理概述======
定义规范的立项评审流程，保证研发资源的有效利用；对关键里程碑和工作计划，组织联合评审，并记录在系统中。对项目阶段的关键节点进行技术评审，定义明确的checklist，实现早期错误预防，提高项目质量。\\
===== TR管理操作手册 =====

===== 1.TR流程维护 =====





=== 1.1.	TR流程发布 ===

进入【流程中心】→【工作流】→【流程设计中心】，找到预置的TR审批流程，勾选发布，发布时勾选生成流程模板。（因为每次打补丁都会把这个预置的TR流程覆盖，所以如果没有修改预置TR流程的可以直接发布这个流程，如果想要修改TR流程，就另外新建一个审批流，复制这个预置的TR流程再发布）\\
 {{:cloud:plm:tr01.jpg?400|}}\\

== 1.2.	TR流程节点配置 ==

进入【流程中心】→【工作流】→【流程配置中心】，可以看到TR流程发布生成的流程模板，双击进入详情页面，点击【流程节界面配置】\\
{{:cloud:plm:tr02.jpg?400|}}\\
 
在节点配置界面，给流程节点选择对应名称的视图，选择完视图后，在【菜单项】配置页面勾选对应节点的操作保存就可以了。各节点勾选操作如下：
【SE提供评审材料】：勾选【评审要素裁切】、【查看附属子项】
【TR自检】：勾选【填写TR自检表】、【查看TR自检表】
【SE完成TR报告】：勾选【填写TR报告】、【填写TR自检仲裁表】
【会签TR报告】：勾选【查看TR报告】
【签发TR报告】：勾选【查看TR报告】、【查看TR自检信息表】
其他节点不用勾选菜单项操作
== 2.	TR基础信息维护 ==

== 2.1.	后续活动 ==

每个TR点需要绑定后续活动，进入【PLM】→【TR管理】→【新增后续活动】新增，填写保存后点击提交、审核，只有审核状态的后续活动才能在TR点中选到\\

 {{:cloud:plm:tr03.jpg?400|}}\\
== 2.2.	质量目标 ==

每个TR点可以绑定质量目标，绑定后，在QA填写质量目标节点就会带出TR点绑定的质量目标，进入【PLM】→【TR管理】→【新增质量目标】新增，填写保存后点击提交、审核，只有审核状态的后续活动才能在TR点中选到。\\
 {{:cloud:plm:tr04.jpg?400|}}\\
== 2.3.	TR评审要素 ==

确定每个TR点的评审要素
== 2.3.1.	导入评审要素 ==

进入【PLM】→【TR管理】→【评审要素列表】，可以通过导入和新增两种方式来创建评审要素。点击【下载导入模板】\\
 {{:cloud:plm:tr05.jpg?400|}}\\
在下载的模板里按字段填写内容，预留行不可删除，角色列（比如验收角色等）需要填写角色的名称（需要提前在金蝶云系统里新建角色）。保存好Excel后点击【导入Excel生成数据】，在弹出的窗口中点击+图标，选择Excel，等待上传完成。\\
 {{:cloud:plm:tr06.jpg?400|}}


== 2.3.2.	新增TR点和评审要素 ==

== 1、新增TR点 ==

在【评审要素列表】左侧直接点击【新增】，进入新增TR点页面，在该页面可以同时绑定TR点的后续活动和质量目标。保存后点击提交、审核。也可以选择已建好的TR点点击【编辑】进入该页面。\\
 {{:cloud:plm:tr06-1.jpg?400|}}\\
 {{:cloud:plm:tr07.jpg?400|}}\\
== 2、新增要求大类和要求小类 ==

选择TR点，点击左侧的【新增】，进入要求大类新增页面，选择要素大类，点击左侧的【新增】，进入要求小类新增页面。保存后都点击一下提交和审核\\
 {{:cloud:plm:tr08.jpg?400|}}\\

== 3、新增评审要素 ==

选择左侧的要求大类或要求小类，点击右侧的【新增】，进入评审要素新增页面。
这里用户需要设置验收角色时，才能在节点中查看TR评审要素\\
 {{:cloud:plm:tr09.jpg?400|}}


== 2.4.	附属子项和产品状态转换配置 ==

可以配置过哪个TR点时，附属子项里选择的物料和TR单中的产品的生命周期阶段变化\\
== 2.4.1.	附属子项状态转换配置 ==

进入【PLM】→【系统建模】→【业务类型配置】，选择物料的业务类型，点击【阶段转换规则】，在【TR完成阶段转换规则
这里设置过哪个TR点时附属子项里的该业务类型的物料转换到哪个阶段。
说明：阶段转换规则不会继承。\\
 {{:cloud:plm:tr010.jpg?400|}}\\
== 2.4.2.	产品状态转换配置 ==

进入【PLM】→【系统建模】→【业务类型配置】，选择产品的业务类型，点击【阶段转换规则】，在【TR完成阶段转换规则】里设置过哪个TR点时附属子项里的该业务类型的产品转换到哪个阶段。
说明：阶段转换规则不会继承。\\
 {{:cloud:plm:tr011.jpg?400|}}


 == 3.TR评审 ==
 

== 3.1.	新增TR评审单 ==

点击【PLM】→【TR管理】→【新增评审单】或进入【PLM】→【TR管理】→【TR评审列表】中点击【新增】来创建TR评审单。
【附属子项】：选择不提取，则TR单提交后流程就进入了【SE提供评审材料】节点，选择提取，则TR单提交后流程进入【CME添加附属子项】节点。
【TR自检人】：选择完产品后再选择TR点，选择好TR点，会将该TR点的评审要素里的【验收角色】与【参与验收角色】带入到【TR自检人】中。
【评审要素裁切】：将TR点中不需要进行评审的要素裁切掉，保存关闭该页面后，【TR自检人】里也会相应地裁切掉带出来的对应的角色。
【TR会签人】里的角色来源于【TR自检人】和产品团队里的角色与人员。
【后续活动】：TR点上绑定的后续活动，没有绑定可以新增。\\
 {{:cloud:plm:tr015.jpg?400|}}\\
{{:cloud:plm:tr016.jpg?400|}}



 

== 3.2.	CME添加附属子项 ==

CME进入待办任务，选择附属子项物料，【转到的生命周期】为该物料业务类型设置的TR点阶段转换规则，配置见 2.4附属子项和产品状态转换配置\\
{{:cloud:plm:tr017.jpg?400|}}
 

== 3.3.	SE提供评审材料 ==

在【SE提供评审材料】节点，SE可以再次裁切评审要素。该节点主要是在【附件】处上传评审所需的文档材料。提交流程后进入【TR自检】与【QA填写质量目标】并行节点。\\
 {{:cloud:plm:tr018.jpg?400|}}
== 3.4.	TR自检 ==

【TR自检】与【QA填写质量目标】节点为并行节点，都提交后，才会进入【SE完成TR报告】节点。【TR自检】为会签节点，所有自检人自检完成后才算完成该节点。

在填写TR自检表中，自检人只能看到属于自己角色的评审要素。\\

 {{:cloud:plm:tr019.jpg?400|}}\\

自检人需要填写风险分析建议和对后续活动给出意见。\\
 {{:cloud:plm:tr20.jpg?400|}}

== 3.5.	QA填写质量目标 ==

QA为创建TR单的用户，【质量目标完成情况】里会带出TR点上绑定的质量目标，没有绑定可以自己新增。\\
 {{:cloud:plm:tr21.jpg?400|}}

== 3.6.	SE完成TR报告节点 ==

SE完成TR报告节点，可以看到在自检节点填写的后续活动的会签意见，SE可以修订意见。
【TR报告会签人】里角色【来自核心组】表示该角色是从产品团队里带过来的，【来自TR自检人】表示从【TR自检人】里带过来的，【其它会签人】表示是自己新增的会签人。\\
 {{:cloud:plm:tr22.jpg?400|}}


TR报告里点击【从评审要素中选择不符合项】会带出自检表里评审要素满足情况填写了除【完全满足】和【不涉及】外的其它情况的评审要素。\\
 {{:cloud:plm:tr23.jpg?400|}}

SE填写完TR报告和自检仲裁表，提交后，流程进入了【TR会签】节点\\
{{:cloud:plm:tr24.jpg?400|}}
== 3.7.	TR会签 ==

TR报告会签人在该节点会对后续活动再一次评审，会带出之前在自检节点填写或者SE完成TR报告节点修订的意见，所有会签人提交后，流程进入【签发TR报告】节点\\
 {{:cloud:plm:tr20.jpg?400|}}


== 3.8.	签发TR报告 ==

签发人填写签发意见，提交后就完成了TR单的评审。TR单状态就会变成已关闭。\\
 {{:cloud:plm:tr24.jpg?400|}}
