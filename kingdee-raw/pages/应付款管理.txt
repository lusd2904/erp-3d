====== 1 应付款管理概述  ======


===== 1.1 应付款管理概述  =====


系统将应付款管理分为四个基本业务环节，构成应付款管理完整的业务循环，包括应付款确认、到期付款、付款核销、期末处理。这四个业务环节，基本涵盖应付款管理日常业务处理流程。

应付款管理主要处理两方面的业务：采购应付和其他应付。

本手册将以应付款四个业务环节为主线，从采购业务应付和其他业务应付两方面，详细说明各个业务节点可以实现的功能和操作方法，为您能够更加高效、灵活的使用本系统提供帮助。

===== 1.3 系统特性 =====

应付款管理主要处理两方面的业务：采购应付和其他应付。主要功能包括：

  * 通过应付单管理采购业务应付。
  * 通过其他应付单管理其他业务应付。
  * 应付单与采购发票彻底分离，应付账款通过应付单确认，应付单是债务成立的标志。
  * 支持“暂估应付”和“业务应付”两种立账模式。
  * 应付单的快速新增功能。
  * 入库单审核时自动生成应付单功能。
  * 支持供应商的多方交易。
  * 按角色区分的应付单、其他应付单新增、付款功能。 
  * 支持一张应付单的多到期日管理。
  * 应付单支持按照含税单价或者不含税单价不同的录入方式。
  * 应付单支持价内税和价外税两种税额计算逻辑。
  * 应付单到付款单，支持按付款计划付款。
  * 费用应付单支持指定入库单或者出库单。 
  * 付款单支持现金折扣和手续费的应用场景。
  * 付款退款单支持手续费的应用场景。
  * 可以针对供应商、订单预付。
  * 有关联关系的应付单/其他应付单与付款单自动核销。
  * 有关联关系的应付单与发票自动核销。  
  * 支持无关联关系的应付单/其他应付单与付款单匹配条件核销。
  * 支持无关联关系的应付单与发票匹配条件核销。
  * 支持应收单/其他应收单与应付单/其他应付单核销。
  * 特殊业务核销支持任意单据的核销，包括：单据尾数的冲销、不同往来单位的应付单/其他应付单与付款单的冲销等。
  * 支持内部应付清理功能。
  * 所有业务单据都可以通过智能会计平台生成业务凭证、总账凭证。
  * 提供各种报表查询功能，具体包括：应付款汇总表、应付款明细表、账龄分析表、到期债务表、往来对账明细表、应付单跟踪表、应付未开票明细表、应付单开票核销明细表、供应商对账单。

====== 2 应付款管理业务专题 ======

应付款管理主要处理两方面的业务：采购应付和其他应付。这两项业务仅是在应付确认环节区别较大，确认后的付款、报表查询等等方面都是相同的。本部分主要包括如下内容：

===== 2.1 采购应付 =====

采购应付主要处理企业有关材料采购产生的应付款项。

**业务场景**

各个企业确定应付款项的环节不一样，有的企业入库后确认应付款项，有的企业发出订单就确认应付款项。为了满足不同企业的不同应用方式，系统通过应付单来确认应付款项。在系统中应付单是企业对采购应付进行管理的唯一单据，采购业务是否收到发票、是否付款以及账龄分析等都是以应付单为依据。

===== 2.2 其他应付 =====

其他应付主要处理的是企业除了材料采购外产生的应付款项。

**业务场景**

除了材料采购，企业还会有很多其他原因产生的应付款项，例如员工报销费用、要支付的一些行政费用等。本系统通过其他应付单来确认除采购业务外产生的应付款项。该部分应付款项确认是通过其他应付单来实现的。在系统中其他应付单是企业除采购业务外应付账款管理的依据。

===== 2.3 费用应付单 =====

企业材料采购过程中，除了购买价款外还会发生一些相关的税费、运输费、装卸费等等。故将应付单分为标准应付单和费用应付单。费用应付单主要来解决企业这部分应付的结算。

===== 2.4 预付款 =====

预付款是向供应商预先支付货款的业务行为，预付款主要有两种场景：
 
  * 针对供应商预付：与供应商商定先预付一定的款项给供应商，之后向供应商发出的订单不允许超过该预付金额的一定比例。
  * 针对订单预付：在与供应商签订订单的条件中规定必须先预付一定比例的款项供应商才会执行该订单。

===== 2.5 应付开票 =====

**业务场景**

企业可以根据自己的实际情况入库后、发出订单后等时点确认应付，确认应付后还会收到供应商开具的采购发票。 

由于企业确认应付的时点与收到发票的时点会有差异，所以应付单与发票的金额可能会存在差异，但是最后的应付款项应该以发票为准，所以还需要将应付单与发票进行核对，根据发票金额对应付金额进行调整，系统因此提供了应付开票核销功能，有关该功能的介绍请参见应付开票核销。

**特别说明：**应付开票业务仅用于采购应付业务，其他应付业务不需要开票。

===== 2.6 到期付款 =====

**业务场景**

及时付款是保证企业良好信用的关键因素，而应付款在确认时，就已经同时确定了付款计划，即明确的到期日，一般采购业务人员在款项快到期时，会向财务部提出付款申请，而具体的付款一般是由出纳负责的。在系统中付款是通过付款单实现的。

  * 应付付款核销
应付款的账龄分析是很重要的业务资料。为了提供准确的账龄分析表，需要准确的知道每一笔应付款项的付款情况，即将应付单与付款单相对应，因此需要进行应付付款核销，有关该功能的介绍请参见[[应付付款核销]]。

===== 2.7 组织间交易 =====

除了企业外部的交易业务，集团型企业内部不同法人之间、利润中心之间、甚至部门之间也经常会存在交易，这即是组织间交易。当组织间交易发生的两个组织是需要各自考核的情况下，就会涉及内部结算。如下图：

{{:cloud:fin:fin_组织间交易2.png?300|}}

如上图：蓝海公司下各车间存货的流转都属于组织间交易，铸造车间、组装车间属于同一核算组织，不需要单独的考核，所以一般不需内部结算；而铸造车间、组装车间与精密制造属于不同核算组织，那么铸造车间与精密制造之间的交易需要内部结算。

===== 2.8 内部往来清理 =====

对于组织间交易形成的内部往来，有时需要实际的现金收付或者开具发票，有时不需要实际的现金收付或者开具发票。针对不需要实际的现金收付或者开具发票的情况，很多企业都是在年末或者年中进行清理，即内部往来清理。在系统中分为内部应付清理和内部应收清理。



===== 2.9 立账模式 =====

支持“暂估应付”与“业务应付”两种不同的立账模式。“暂估应付”立账模式是根据发票确认应付账款的原则，如果没有到票，则确认为暂估应付，如果已到票了，则确认为财务应付，同时红冲暂估应付；“业务应付”立账模式是货物转移来确认应付账款的原则，如果货已入库，则确认应付账款，后续已到票，如果应付账款与发票存在差异，则进行调差处理生成差异应付单。

===== 3.3 业务初始化=====

为了保证应付款管理系统使用前后数据的衔接，本功能提供录入系统启用前已存在的各种单据的功能。

第一步：[[应付启用日期|启用日期设置]]

任何结算组织需要使用应付款管理模块前首先要设置启用日期。启用日期设置后如未有业务发生，则可以修改；否则不再允许修改。

第二步：录入期初单据

期初单据包括：期初应付单、期初其他应付单、期初付款单、期初付款退款单。各单据的录入功能与正常业务期间的单据相同，只是业务日期必须早于启用日期。

第三部：[[应付结束初始化|结束初始化]]

当期初单据全部录入完毕后，就可以结束初始化了。结束初始化后不可以再录入期初单据。

结束初始化后尚未结账前可以[[应付反初始化|反初始化]]。

===== 3.7 应付开票核销=====

应付开票核销包括关联关系核销、匹配条件核销和手工核销、定时核销。

一般情况下通过关联关系核销、匹配条件核销可以将用户多数的单据核销完毕。手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何的单据核销，但是建议用户仅在需要对单据尾数冲销或者不同往来单位的应付单与发票核销时才使用。

详细描述请见：[[应付开票核销]]
===== 3.8 应付付款核销=====

应付付款票核销包括关联关系核销、匹配条件核销和手工核销。

一般情况下通过关联关系核销、匹配条件核销可以将用户多数的单据核销完毕。手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何的单据核销，但是建议用户仅在需要对单据尾数冲销或者不同往来单位的应付单与付款单核销时才使用。

详细描述请见：[[应付付款核销]]
===== 3.9 应付转销=====

由于某种原因（例如公司更名），用户需要将A往来单位的应付转为B往来单位的应付，此时需要使用应付转销的功能。转销后付款、对账都需要与B往来单位进行。

转销支持应付单、预付单、其他应付单、费用应付单的转销。 

详细描述请见：[[应付转销]]
===== 3.10 内部应付清理=====

对于组织间交易产生的内部往来，有时候不需要实际的现金支付或者开具发票，年末或者年中统一清理掉。所以应付款管理模块提供了内部应付清理功能。

内部应付清理包括无需付款清理和无需开票清理。通过“内部应付清理”可以进入“无需付款清理”界面，在该界面上通过“无需开票清理”按钮进行切换。

详细描述请见：[[内部应付清理]]

===== 3.12 账务处理=====

账簿中可以设置是通过应付单、其他应付单。生成凭证时如果选择的单据与账簿的设置不相符，系统会提示用户，由用户决定是否继续。此外有以下两点需要注意：

  * 当立账模式为业务应付时，通过业务应付单生成“应付账款”的凭证。
  * 当立账模式为暂估应付时，通过财务应付单生成“应付账款”的凭证。

账务处理的其他功能都是由智能会计平台提供的。有关说明请参考智能会计平台用户手册。
===== 3.13 报表分析=====

==== 3.13.1 应付款汇总表 ====

应付款汇总表主要是用来反映某段时间内与往来单位的期初余额、本期应付数、本期实付数、期末余额等数据的汇总信息。在企业的实际应用中可能需要根据往来单位、采购部门、采购组等不同维度查询。

详细描述请见：[[应付款汇总表]] 

==== 3.13.2 应付款明细表 ====

应付款明细表主要是用来反映某段时间内与往来单位的期初余额、本期应付数、本期实付数、期末余额等数据的明细信息。

详细描述请见：[[应付款明细表]]

==== 3.13.3 应付款账龄分析表 ====

应付款账龄分析表反映的是截止到某一时间点，往来款项余额的时间分布。

此报表的数据来源于应付付款核销未完毕的应付单、付款单、付款退款单。

详细描述请见：[[应付款账龄分析表]]
 
==== 3.13.4 到期债务表 ====

到期债务列表反映截止到指定日期止，已经到期的未核销应付款及过期天数、未到期的应付款及未过期天数。

详细描述请见：[[到期债务表]] 

==== 3.13.5 往来对账明细表 ====

往来对账对账明细表所展示的数据与应付款明细表基本相同，只是当往来单位既是客户有是供应商时，往来对账对账明细表可以将与该往来单位的所有往来都列示出来。

详细描述请见：[[往来对账明细表|往来对账明细表]] 

==== 3.13.6 应付单跟踪表 ====

应付单跟踪表是用来查询与应付业务有关的各种信息的报表，例如应付单的订单情况、入库情况、开票情况、付款情况等等。

详细描述请见：[[应付单跟踪表]] 

==== 3.13.7 应付未开票明细表 ====

应付未开票明细表反映企业当期应付的开票情况，包括本期未开票情况，截止日期未开票情况，支持按物料明细显示。

详细描述请见：[[应付未开票明细表]] 



==== 3.13.8 应付单开票核销明细表 ====

应付单开票核销明细表反映企业当期应付单的开票核销明细情况，包括本期未开票核销情况，截止日期未开票核销情况，按应付单的明细分录显示。

详细描述请见：[[应付单开票核销明细表]] 

==== 3.13.9 供应商对账单 ====
供应商账单提供应付的原始金额、已付款金额、未付款金额和对应的账龄分析，主要用来传递给供应商进行对账。其与往来对账明细表的区别是往来对账明细表会单独列示付款单行数据，供应商对账单不会单独列示付款单单据数据，而是依据核销记录直接取该应付单已核销金额列示在与应付单数据行同一行中。

详细描述请见：[[供应商对账单]]
