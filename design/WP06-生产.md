## 2. 各单据要点

### D03 生产订单

1. **分录级业务状态**：计划 → 计划确认（审核自动）→ 下达（可参数自动）→ 开工（手工或领料自动）→ 完工（入库达下限自动或手工）→ 结案 → 结算（二期由成本模块置位）；下达/开工可挂起、可反向跳跃执行（SM-04）【来源:需求4.4】
2. **主产品状态同步联副产品**；联副产品 `product_type` 由 BOM 携带，`cost_weight` 从 BOM 取值（主产品100，副产品0）（G1a 3.6）
3. **计划开工时间** `plan_start` 默认系统当前日期，须≤计划完工且在车间日历可生产日内（G1a 3.6）
4. **BOM 版本** `bom_id` 下达前必录，默认"自制+通用"最新审核版本；**生产车间** `workshop_id` 下达前必录（G1a 3.6）
5. **领料状态** `pick_status`：未领料（套数=0且无领料单）/部分领料/全部领料/超额领料，按 `pick_sets` 领料套数计算（G1a 3.6）
6. **手工完工**：须无非作废/非审核入库单；勾"手工完工考虑入库下限"时，主产品及联副产品（入库−退库）≥ `in_lower` 入库下限（SM-04）【来源:需求4.4】【来源:生产单据类型参数】
7. **结案控制**（单据类型参数）：控制范围（所有物料/非倒冲/关键物料）+ 控制强度（在制材料=0/在损耗范围内/不控制），返还件单独一组参数；不能有未审核/未作废下游单据；**已结算不能反结案**（SM-04）（C-24）（N-02）【待确认 Q41：默认"所有物料+在损耗范围内"】
8. **反审核限制**：存在未审核的生产用料清单变更单时不能反审核（SM-04）（N-08）【来源:生产单据类型参数】
9. **"结算"状态**：一期保留状态值、不提供入口，二期由成本结算后置位（C-03）【待确认 Q22】
10. **扩展字段**：`reel_qty` 卷盘规格、`test_prog_ver` 测试程序版本、`cust_part_no` 客户料号（G1a 3.6）（技术方案 pp_mo_entry）

### D04 生产用料清单

1. **生成时机**：生产订单保存时按 BOM 版本自动生成，下达时可参数自动审核（R03）（G1a 3.7）
2. **需求数量** `need_qty` 公式：固定用量 = 使用比例 × 分子/分母 × (1+变动损耗率) + 固定损耗；变动/阶梯 = 订单数量 × 使用比例 × 分子/分母 × (1+变动损耗率) + 固定损耗；**向上取整**（G1a 3.7）（C-11：损耗率默认"方式一 × (1+r)"）【待确认 Q30：损耗率计算方式默认值】
3. **应发数量** `must_qty`：是否发损耗="是"时 = 需求数量，否则 = 标准用量 `std_qty`（G1a 3.7）
4. **在制材料数量** = 已领 `picked_qty` + 补领 `repick_qty` − 良品退 `good_ret_qty` − 来料不良退 `inc_bad_ret_qty` − 作业不良退 `op_bad_ret_qty` − 报废 `scrap_qty` − 已消耗 `consume_qty`（G1a 3.7）（技术方案 pp_ppbom_entry）
5. **子项类型** `child_type` 锁定规则：领料、补料、退料、调拨选单数量任一 > 0 时，子项类型和发料方式 `issue_type` 锁定（R20）（G1a 3.8）
6. **返还件强制不发料**（G1a 3.7）
7. **倒冲时机** `backflush_time`：发料方式为倒冲时必录，取值顺序 BOM → 物料 → 单据类型参数（G1a 3.7）
8. **需求日期** `need_date` 默认计划开工 + 偏置提前期，须≤计划完工且在车间日历内（G1a 3.7）
9. **审核后修改只能走变更单**（G1a 3.7）

### D05 生产订单变更单

1. **变更类型** `change_type`：新增/变更；为"变更"时物料、订单编号、单位、BOM版本、工艺路线锁定（G1a 3.8）
2. **可变更订单状态**：计划、计划确认、下达、开工；**完工后不能变更**（G1a 3.8）
3. **审核动作**：反写生产订单 `mo_id`，刷新用料清单；可自动生成暂存退料单（R19）（G1a 3.8）
4. **分录存储** `before_json` / `after_json` 变更前后快照（技术方案 pp_mo_change_entry）

### D06 生产用料清单变更单

1. **变更类型**：新增/变更前/变更后；审核即执行变更（R20）（G1a 3.8）
2. **变更后锁定**：原值为"阶梯"时用量类型不可编辑；**领料、补料、退料、调拨选单数量任一 > 0 时子项类型和发料方式锁定**（R20）（G1a 3.8）
3. **分录字段**：`ppbom_entry_id`、`change_type`、`material_id`、`numerator`、`denominator`、`fixed_scrap`、`scrap_rate`、`must_qty`、`issue_type`（技术方案 pp_ppbom_change_entry）

### D07 生产齐套分析单

1. **方案字段** `scheme_json`：优先顺序（优先级+计划开工/计划开工+优先级/计划完工+优先级）、考虑预留、物料替代、物料范围、提前天数（G1a 3.9）【来源:生管平台】
2. **分析算法**：按优先顺序排序订单，取方案仓库范围内现有库存和预计入（扣除已预留部分）逐行分配；子项发料仓不在方案范围内时也计入（SM-05）【来源:生产备料单】
3. **缺料公式**：缺料 = 应发 − 已领 − 预留_库存 − 预留_预计入 − 分配库存 − 分配预计入（SM-05）（C-17）（N-04）【来源:生管平台】
4. **齐套判定**：有缺料="不齐套"；预计齐套数 = 库存齐套数="库存齐套"；预计齐套数 > 库存齐套数="预计齐套"（SM-05）（C-17）【来源:生管平台】
5. **审核动作**：反写用料清单 `prepare_qty` 备料数量（R05）；可生成领料单或直接调拨单（G1a 3.9）
6. **参与订单状态**：下达、开工或完工且未挂起（SM-05）
7. **未分析或改过订单页签不能提交**（SM-05）

### D14 生产日排产

1. **状态**：未确认 `confirm_status` → 已确认；可锁定 `locked` / 解锁（SM-06）（G1a 3.13）
2. **删除限制**：不允许删除当前日期之前、或已有 `online_qty` 上线/齐套/发料数量的排产明细（SM-06）【来源:日排产参数】
3. **反写**：入库单/汇报单审核反写 `online_qty` 上线数量（R22）【来源:生产订单排产明细】
4. **关键字段**：`mo_entry_id`、`line_id` 产线、`sched_date` 排产日期、`sched_qty` 排产数量（技术方案 pp_day_schedule）

## 2. 各单据要点

### D08 生产领料单

1. **物料编码 item_id**：从上游生产用料清单分录携带，不可修改（G1a 3.10）
2. **申请数量 apply_qty / 实发数量 actual_qty**：系统自动计算，可修改；申请数量不能大于下推数量（G1a 3.10）
3. **可选数量**：应发数量 − 领料选单数量 + 良品退料数量 + 来料不良退料数量 > 0（R06）
4. **前置条件**：生产订单分录处于下达、开工或完工状态且未挂起；生产用料清单已审核（R06, C-23, N-06）
5. **自动开工**：首次领料时如生产订单为下达状态，可配置自动置为开工（R06, Q23）
6. **反写上游**：审核时回写生产用料清单的已领数量 `issued_qty`，同时更新生产订单的领料状态（未领料/部分领料/全部领料/超额领料，按领料套数计算）（R06, SM-04）
7. **倒冲标识 is_backflush**：技术方案 pp_pick_entry 列清单中存在，用于入库倒冲场景（技术方案 103）
8. **仓库 wh_id / 仓位 loc_id**：仓库启用仓位管理时仓位必填，否则为空（G1a 3.10）
9. **批号 lot_no / 生产日期 prod_date / 失效日期 exp_date**：启用批次管理或保质期管理时必录（G1a 3.10）
10. **【扩展】卷盘号 reel_id**：子分录表 pp_pick_reel，每盘一码（Q05）；记录领料明细，用于 SMT 上料追溯（R43, 技术方案 104）
11. **已退料选单数量 ret_sel_qty**：生成退料单时累计，用于可退数量计算（R07, 技术方案 103）
12. **核算维度 acct_dims**：技术方案 pp_pick_entry 预留，二期成本结算用（技术方案 103）

### D09 生产退料单

1. **退料类型 ret_type**：良品退料、来料不良退料、作业不良退料（技术方案 106, G1a 3.10）
2. **可选数量**：来源领料单或补料单的实发数量 − 已退料选单数量 > 0（R07）
3. **前置条件**：生产订单分录处于下达、开工或完工状态且未挂起（C-23, N-06）
4. **申请数量 apply_qty / 实收数量 actual_qty**：不能大于下推数量；实收数量不能超出用料清单的数量控制（G1a 3.10）
5. **反写上游**：审核时回写源领料单或补料单的良品退料数量、来料不良退料数量、作业不良退料数量（R07）
6. **生成下游**：作业不良退料单可下推生成补料单（R08）
7. **【扩展】卷盘号 reel_id / 剩余数量 remain_qty**：退料时记录卷盘剩余数量，用于车间库存管理（技术方案 106, Q05）
8. **收料组织 issue_org_id**：必须具有库存职能（G1a 3.10）
9. **生产车间 workshop_id**：表头字段仅用于过滤，不保存（G1a 3.10）
10. **补料选单数量 feed_sel_qty**：生成补料单时累计，用于可补数量计算（R08, 技术方案 106）

### D10 生产补料单

1. **来源**：从生产订单（取用料清单）或作业不良退料单生成（R08）
2. **可选数量（从退料单生成）**：实退数量 − 补料选单数量 > 0（R08）

## 4. 材料之间的冲突、缺口与待确认

### 冲突
1. **让步接收定义不一致**（C-04）：`检验单.txt` 第 71 行写让步接收为不合格，`自制工序检验.txt` 第 24 行写合格数 = 接收 + 让步接收。**裁决**：按检验单主页面，合格数只算"接收"，让步接收单独统计。
2. **首检状态取值不一致**（C-08）：`首检_柔性单件.txt` 有四个值（空/待首检/首检中/首检完成），`产品检验.txt` 只写三个值。**裁决**：一期取并集四个值，结果映射按产品检验页。

### 缺口
1. **技术方案表 pp_pick_entry 缺损耗控制字段**：材料中提到领料需满足超发控制（G1a 3.10），但 103 表清单未列损耗率、超发上限等字段。**设计**：沿用生产用料清单 `pp_bom_entry` 的损耗率和超发控制参数，不在领料单行存储，校验时关联查询。
2. **合单分组规则在技术方案表清单未体现**：补料单、入库单需按组织 + 货主合单（C-25, N-03），但头表未预留 `合单分组键` 字段。**设计**：由单据引擎 convert_rule 配置的 `merge_key` JSON 字段实现分组逻辑，业务表不额外存储。
3. **卷盘主档表名未在技术方案 3.2.4 基础资料清单中出现**：领料、退料、入库子分录需关联 reel_id（Q05），但基础资料章节缺 `bas_reel` 表定义。**待确认**：卷盘主档表名、核心字段（卷盘号、MSD 等级、开封时间、剩余数量）由 WP04 基础资料包定义后同步。
4. **生产订单的入库下限字段名**：材料中多次提及"入库下限"（R17, SM-04），技术方案 3.2.5 第 101 表 `pp_mo_entry` 列清单未列此字段。**设计**：增加列 `in_lower_limit DECIMAL(18,6) COMMENT '入库下限'`，用于自动完工判断。
5. **领料申请单（二期）表名未出现**：G1a 3.10 详细描述了领料申请单字段和流程，但技术方案 3.2.5 未预留表。**设计**：二期新增 `pp_pick_apply` / `pp_pick_apply_entry`，一期不涉及。
6. **补料原因枚举值未定义**：技术方案 107 表有 `feed_reason` 字段，G1a 3.10 未给出枚举值。**待确认**：由业务方提供补料原因字典（工艺变更/报废补料/损耗补料/其他）。
7. **损耗数量入库规则版本差异**（C-12）：`工序汇报.txt` 写 7.5.1 版默认不入库、7.7.0 补丁改为默认入库。**裁决**：按较新版本，损耗按废品逻辑默认生成报废品入库，可在单据类型参数关闭。
8. **超损耗补料的审批规则未详述**：D10 单据清单写"超损耗补料走审批"，但未给出损耗率阈值和审批流配置。**设计**：在补料单单据类型参数增加 `over_loss_rate_threshold DECIMAL(5,2)`，超过时自动触发 SM-01 的"审核中"状态，需审批后才能到"已审核"。
9. **执行机器人触发入库自动完工的数量判断字段**：SM-04 材料写"入库数量等于订单数量/入库上限/入库下限"，但技术方案 101 表未列入库上限字段。**设计**：增加列 `in_upper_limit DECIMAL(18,6) COMMENT '入库上限'`，与入库下限配合使用。

### 待确认
1. **Q05 已确认**：卷盘每盘一码，需条码主档。

### 0.x 与《平台开发约定》V0.1 的对齐说明（人工核对）

约定文件：`/workspace/erp-3d/fullsys/code/docs/平台开发约定.md`（V0.1）。Claude 半成品（WP05 第1、4节；WP06/WP07 依据提炼）写于约定发布之前；续写章节已尽量按约定起草，但仍有与约定不一致处。编码时以约定为准，已完成正文不据此改写，只在下面和【核对】中标注。

1. **建表方式（约定 3.2、3.5、10.3）**：单据表不能手写 `CREATE TABLE`，要用 `@erp3d/shared` 的 BillMeta（字段 snake_case）配合 `ensureBillTables` 在 `apps/api/src/db/migrations` 的幂等迁移里建表；表头 25 个公共列、分录 18 个公共列由框架自动加，元数据里不能再声明。第 1 节 DDL 只作为字段清单参考。非单据表用 `ensureTable` / `addColumnIfMissing` / `addIndexIfMissing`；禁止 DROP，也禁止改已有列类型。主键为 53 位雪花 BIGINT，不是 AUTO_INCREMENT。
2. **字段类型（约定 3.1）**：数量、金额用 DECIMAL(23,10)（JSON 里用字符串），datetime 用 DATETIME(3)，bool 用 TINYINT(1)，enum 用 VARCHAR(20)。正文里状态列宽度有 VARCHAR(16/32) 等写法，实现时按 FieldType 映射统一。
3. **状态维度取值（约定 5.1）**：`close_status`、`cancel_status`、`forbid_status` 一律用 `A` 正常、`B` 关闭/作废/禁用。正文 DDL 里出现的 OPEN/CLOSED、NORMAL/CANCELLED、缺 `forbid_status` / `closer_id` / `closed_at` / `canceller_id` / `cancelled_at` / `cancel_prev_status`，实现时按约定补齐。已审核须先反审核才能作废；有下游有效单据禁止反审核（`BIZ_HAS_DOWNSTREAM`）。
4. **模块注册与接口（约定 4.1–4.4）**：模块用 `BillEngineRegistry.registerBill()` 注册；接口前缀 `/api/v1`；响应 `{code,msg,data,traceId,errors?}`，成功 `code` 为字符串 `'OK'`（不是数字 0）。标准单据走 `/api/v1/bills/{form}…`。
5. **反写（约定 6.2、6.5）**：两段反写——保存写关联数量，审核写执行数量；`WritebackRuleConfig.onEvent` 为 `save|audit`，`mode` 为 `add|sub|overwrite`。`srcForm` 是被反写的上游，`tgtForm` 是触发反写的下游。超发用 `issueLimit()`。

7. **钩子（约定 2.2）**：beforeSave / afterSave / beforeAudit / afterAudit / beforeUnaudit / afterUnaudit / beforeCancel / afterCancel / beforeDelete / rowGuards。生产模块代码目录约定为 `apps/api/src/prd/`。

#### 2) 分析算法伪代码

```pseudo
// 入口：pp_kitting 分析动作（业务 op，走 /ops/{op}，引擎事务内执行）
function analyseKitting(kittingId, db) {
  scheme = loadSchemeJson(kittingId)            // 优先顺序/预留/替代/物料范围/提前天数/截止日期/仓库范围/供应开关
  orders = loadKittingOrders(kittingId)         // pp_kitting_order join pp_mo_entry
    .filter(biz_status in [CONFIRMED, RELEASED, STARTED, FINISHED] && !hung)   // SM-05
    .sortBy(scheme.priorityOrder)               // 优先级+计划开工 / 计划开工+优先级 / 计划完工+优先级

  // ① 汇总供给池（SM-05 步骤②，先扣预留）
  stockPool = {}   // key: material_id+aux_prop+warehouse+owner..., value: qty
  for wh in scheme.warehouses:
    for inv in InventoryService.getAvailable(org, wh, scheme.dataStatus=AUDITED):
      stockPool[key(inv)] = inv.qty - (scheme.considerReserve ? inv.lock_qty : 0)   // 【核对：只读预留量；建议经 WP10 InventoryService.getAvailable 取，冻结走 D46 状态转换，不直接写 lock_qty】   // 预留_库存

  inPool = {}      // 预计入池，按供应来源开关过滤，截止日期 & 提前天数过滤
  for src in scheme.supplySources:              // scm_receive/scm_pur_order/pp_mo/sub_order/...
    for line in queryAuditedSupply(src, scheme.cutOffDate):
      if (line.supply_date <= demand_date + scheme.leadDays)   // 供应允许提前天数
        inPool[key(line)] += line.qty - (scheme.considerReserve ? line.reserved_qty : 0)  // 预留_预计入

  // ② 逐订单分配（SM-05 步骤③，先库存后预计入，扣已分配）
  for order in orders:
    entries = loadPpbomEntries(order.mo_entry_id)  // pp_ppbom_entry，按物料范围过滤
    for e in entries:
      must = e.std_qty * order.analyse_qty         // 应发
      picked = sumAuditedPick(e)                   // 已领（pp_pick/pp_return/pp_feed 冲减）
      wh = e.issue_warehouse
      stockAvail = stockPool[key(e.material, wh)] ?? 0
      if wh not in scheme.warehouses:              // 发料仓外也计入（SM-05 步骤④）
        stockAvail += rawStock(e.material, wh) - reserveOf(wh)
      inAvail = inPool[key(e.material)] ?? 0
      // 替代料（G1a 考虑替代）
      if scheme.considerSubstitute:
        for sub in md_substitute(e.material): stockAvail += stockPool[key(sub)]; inAvail += inPool[key(sub)]

      allocStock = min(stockAvail, max(0, must - picked))     // 先配库存
      allocIn    = min(inAvail,    max(0, must - picked - allocStock))  // 再配预计入
      stockPool[key] -= allocStock; inPool[key] -= allocIn    // 扣已分配，供下一订单

      short = must - picked - reserveStock - reserveIn - allocStock - allocIn   // N-04 缺料公式
      saveEntry(order, e, { must_qty: must, picked_qty: picked,
        avail_qty: allocStock + allocIn, short_qty: short,
        prepare_qty: allocStock + allocIn, this_pick_qty: 0 })  // pp_kitting_entry
    // ③ 订单级齐套数（C-17）
    stockKit = min over entries of floor((picked + allocStockOnly) / unit_qty)
    expectKit = min over entries of floor((picked + allocStock + allocIn) / unit_qty)
    saveOrder(order, { stock_kit_qty: stockKit, kit_qty: expectKit })  // pp_kitting_order
    // 判定：任一 short>0 → 不齐套；expectKit==stockKit → 库存齐套；expectKit>stockKit → 预计齐套
}

// 审核钩子 afterAudit：反写备料数量 R05（走 sys_writeback_rule，不直接写 pp_ppbom）

    linkBy: 'pp_kitting_order.mo_entry_id -> pp_ppbom.mo_entry_id + ppbom_entry_id' })  // R05
  // 可选生成领料单 pp_pick 或直接调拨单 scm_transfer（G1a 3.9），走 ConvertRule
}
```

### 4) 一期简化点

- 供应范围一期只开：即时库存 + 采购订单 + 生产订单 + 委外订单预计入；收料通知单、委外采购订单、组织间需求单、受托加工收料、采购申请单 暂不纳入池【建议】。
- 预留一期只处理「弱预留」，强预留不参与齐套分析【建议】。
- 替代料一期支持 `md_substitute` 主替代链一层，不做多级替代与替代比例（`md_substitute_entry` 比例字段二期）【建议】。
- 提前天数仅作用于预计入分配：供应日期 ≤ 需求日期 + 提前天数 才可分配（算例中 M3 在产 2026-12-08 超 3 天窗口被剔除）。
- 发料仓外库存计入（SM-05 步骤④）一期实现为：按子项发料仓聚合追加可用量，不做跨仓调拨计算【建议】。
- 调拨策略（补足车间库存/补齐调拨数量/按齐套数调拨）一期不实现，审核后只反写 `prepare_qty`，领料/调拨由后续单据处理（G1a 3.9）。
