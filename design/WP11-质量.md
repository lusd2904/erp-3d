### 0.3 与《平台开发约定》V0.1 的对齐说明（人工核对）

约定文件：/workspace/erp-3d/fullsys/code/docs/平台开发约定.md（V0.1）。它是在本设计正文生成之后才发布的，所以正文没有参照它。下面是人工逐条比对后的结论；编码时以约定为准，正文没有据此改写。

1. **建表方式（约定 3.2、3.5、10.3）**：单据表不能手写 `CREATE TABLE`，要用 BillMeta 元数据（字段 snake_case）配合 `ensureBillTables` 在幂等迁移里建表；表头 25 个公共列、分录 18 个公共列（如 id、org_id、bill_no、status、close_status、src_form、src_entry_id、lot_no、qty、base_qty、biz_close 等）由框架自动加，元数据里不能再声明。所以第 1 节单据表的 DDL 只作为字段清单参考，实现时要改写成 BillMeta，并去掉公共列。非单据表（即时库存、流水、条码主档、国标抽样表等）在迁移里用 `ensureTable`、`addColumnIfMissing`、`addIndexIfMissing` 幂等建表；约定禁止 DROP，也禁止改已有列的类型。
2. **字段类型（约定 3.1）**：数量、金额统一用 DECIMAL(23,10)，datetime 用 DATETIME(3)，bool 用 TINYINT(1)，enum 用 VARCHAR(20)。正文里状态、枚举列宽度有 VARCHAR(16/32) 等写法，实现时按 FieldType 映射统一。
3. **状态维度取值（约定 5.1）**：close_status、cancel_status、forbid_status 一律用 `A` 正常、`B` 关闭/作废/禁用。正文 DDL 里出现的 OPEN/NORMAL/NO、0/1 都要改。作废不是主状态，是维度：正文状态机表中“to=作废”“已关闭”应理解为 cancel_status=B、close_status=B，主状态 status 不变。
4. **操作规则（约定 5.2）**：已审核单据必须先反审核才能作废；cancel 只允许从 CREATED、REAUDIT 发起；下游有有效单据时禁止反审核，错误码为 `BIZ_HAS_DOWNSTREAM`。正文与此冲突的地方以约定为准。
5. **钩子名（约定 2.2 BillHooks）**：已确认的钩子有 beforeSave、afterSave、beforeAudit、afterAudit、beforeUnaudit、afterUnaudit、beforeCancel、afterCancel、beforeDelete，以及行级 rowGuards。正文里标的“钩子名【待确认】”这些可以销项。正文用到的 `beforeSubmit` 不在约定列表里，要么并入 beforeSave、beforeAudit，要么请 WP02 增加。
6. **反写规则字段（约定 6.2 WritebackRuleConfig）**：约定中 `srcForm` 是**被反写的上游**单据，`tgtForm` 是**触发反写的下游**单据。正文反写表大多写成“下游→上游 = src_form→tgt_form”，方向正好相反，实现时要对调。`onEvent` 只有 `save` 和 `audit` 两个值，反审核、删除、作废的回滚由引擎按两段规则自动完成，不用单独配。正文里的 `unaudit`、`delete`、“质检完成”等事件不能直接配置：“质检完成”属于行级状态，需要用 RowStatusConfig 加 rowGuards，或者请 WP02 支持行状态事件触发反写，已列入待确认。`mode` 取值为 add、sub、overwrite（正文写的是累加、扣减、覆盖）；`overCtrl` 取值为 FORBID、ONCE、ALLOW（正文写的是禁止、允许一次、允许）；`closeScope` 取值为 ALL、ANY、NONE。
7. **转换规则字段（约定 6.1 ConvertRuleConfig）**：字段为 srcForm、tgtForm、srcStatus、srcQtyField、srcLinkField、header/entry 映射、groupBy、filterExpr、autoPushOnAudit。正文的 bill_type_map_json、field_map_json、group_json、auto_push 分别对应 header/entry、groupBy、autoPushOnAudit；自动下推统一用 `autoPushOnAudit`。
8. **两段反写（约定 6.5 第 3 条）**：保存时累加上游关联数量（释放发生在删除或作废时），审核时累加上游执行数量（反审核时冲减）。正文总体一致，个别段落用同一个字段先累加再扣减，见段内批注。
9. **事务与并发（约定 6.5）**：上游行按 id 升序 `SELECT … FOR UPDATE`；累加一律用增量 UPDATE；状态变更、反写、库存（scm_inventory、scm_inv_txn）、sys_bill_link 放在同一个 `DbService.tx` 事务里；outbox、WebSocket 用 `DbService.afterCommit` 在提交后发出。正文写的是“outbox 行在事务内写入、由 worker 发送”。约定 6.5 第 5 条的原话是“sys_event_outbox 触发事件必须通过 afterCommit 调度”，没说清 outbox 行能不能在事务内 INSERT，需要 WP02 确认，已列入待确认。
10. **接口（约定 4.1–4.4）**：标准单据的增删改查和操作统一走引擎的 `/api/v1/bills/{form}…`，正文第 4 节一致。列表参数是 page、size（默认 50，最大 500）、sort、filter（JSON）。响应统一为 `{code,msg,data,traceId,errors?}`，成功时 code='OK'，逐行错误放在 RowError（entity、row、field、msg）。正文的专用接口（扫码、AQL 计算、查询报表等）也要套这个响应外壳。
11. **sys_bill_link 列（约定 6.3）**：列为 src_form、src_bill_id、src_entry_id、tgt_form、tgt_bill_id、tgt_entry_id、base_qty、rule_id、flow_instance_no、created_at。

### 0.4 本轮实现裁决（2026-11-18）

以下裁决覆盖正文及测试用例中相冲突的旧描述：

1. 所有库存冻结、解冻和质量判定库存状态变化都必须生成并审核 D46 `scm_status_convert`；WP11 不直接更新库存表，也不以 `lock_qty` 冻结库存。
2. GB/T 2828.1 抽样表不预置任何行。取得正式国标正文后，通过版本化导入接口导入字码表和抽样表；导入版本校验完成后再切换为当前版本。本文附录中的参考数值不得用于生产计算。
3. 让步接收不计入 `ok_qty`，但允许 R29 将 `concession_qty` 下推为 `scm_pur_instock_entry.in_type='让步接收'` 的入库数量；库存状态按普通可用状态处理，统计只按实际审核入库数量计算。
4. 让步接收统计视图只统计已审核采购入库行，以采购入库为唯一事实来源；检验决策仍保留在检验明细，不与实际入库量 `UNION ALL` 汇总。
5. R 编号按需求说明书 R01–R45 使用。R29 是“收料通知单 → 采购入库单”，不是检验单审核反写事件；R30 是检验退货下推，R31 是库存退货。R29/R30/R31 在质量规则中仅作为可下推数量约束，不得误列为检验单审核规则。
6. YYWW 使用 ISO 8601 周年和周序；单据公共列、状态 A/B、元数据与幂等迁移遵循平台开发约定。

#### 2.1 设计范围与依据

### 3. 来料检验的转换与反写规则（上）

#### 3.1 适用范围与单据链路

本节覆盖来料检验（IQC）一期链路：收料通知单 `scm_receive` → 检验单 `qm_inspect`（biz_type=来料）→ 采购入库单 `scm_pur_instock` / 采购退料单 `scm_pur_return`；以及委外来料检验：采购入库单（委外）`scm_pur_instock` → 检验单（biz_type=委外来料）→ 委外订单。涉及反写规则 R28、R25、R29、R30、R38（不良品处理回写收料通知单部分）。

硬约束（F 节）：WP11 不直接 UPDATE/INSERT 任何上游表（`scm_receive_entry`、`scm_pur_instock_entry`、`scm_pur_return_entry` 等），全部由单据引擎在事务内按 `sys_writeback_rule` 执行；回滚依据 `sys_writeback_log`；库存冻结/转换由 WP10 库存服务承接，WP11 只通过引擎下推/自动生成 `scm_status_convert`（R39、R40 场景）。

|---|---|---|---|---|

### 5. AQL 抽样表算法（GB/T 2828.1-2012，一次抽样）

#### 5.1 算法步骤与伪代码

```typescript
// 输入：批量 N、检验水平 level（S-1|S-2|S-3|S-4|I|II|III）、严格度 strictness（正常|加严|放宽）、AQL
// 输出：{ code, n, ac, re, fullInspection: boolean }

interface SamplingResult {
  code: string;            // 样本量字码
  n: number;               // 样本量
  ac: number;              // 允收数
  re: number;              // 拒收数
  fullInspection: boolean; // n >= N 时改为全检
}

async function getSamplingPlan(N: number, level: string, strictness: string, aql: number): Promise<SamplingResult> {
  // 1) 批量 N + 检验水平 → 样本量字码（GB/T 2828.1 表 1，对应 qm_gb2828_code）
  let code = await qmGb2828Code.lookup(N, level);          // SELECT code FROM qm_gb2828_code WHERE batch range covers N AND level = ?

  // 2) 字码 + 严格度 + AQL → 主表（正常 2-A / 加严 2-B / 放宽 2-C，对应 qm_gb2828_table）
  const table = { '正常': '2-A', '加严': '2-B', '放宽': '2-C' }[strictness];
  let row = await qmGb2828Table.lookup(code, aql, table);   // SELECT n, ac, re, arrow FROM qm_gb2828_table WHERE code=? AND aql=? AND table_name=?

  // 3) 遇到箭头：沿箭头方向取第一个抽样方案，字码随之改变
  while (row.arrow) {
    code = await qmGb2828Code.nextCode(code, row.arrow);     // ↓ 取下一字码 / ↑ 取上一字码
    row = await qmGb2828Table.lookup(code, aql, table);
  }

  // 4) n ≥ N 时改为全检（样本量 = N）
  const fullInspection = row.n >= N;
  return { code, n: fullInspection ? N : row.n, ac: row.ac, re: row.re, fullInspection };
}

// 判定：样本不合格数 d
function judge(d: number, ac: number, re: number): '接收' | '拒收' | '继续' {
  if (d <= ac) return '接收';
  if (d >= re) return '拒收';
  return '继续'; // 一次抽样正常不会出现，防御性返回
}
```

#### 5.2 查询 SQL（对应 qm_gb2828_code / qm_gb2828_table）

```sql
-- Step 1：批量 + 检验水平 → 字码（表 1）
SELECT CASE #{level}
         WHEN 'I' THEN level_i WHEN 'II' THEN level_ii WHEN 'III' THEN level_iii
         WHEN 'S-1' THEN level_s1 WHEN 'S-2' THEN level_s2 WHEN 'S-3' THEN level_s3 WHEN 'S-4' THEN level_s4
       END AS code
FROM qm_gb2828_code
WHERE version = #{activeVersion}
  AND #{N} BETWEEN batch_from AND batch_to;

-- Step 2：字码 + AQL + 主表 → n / Ac / Re / 箭头方向
SELECT sample_qty, ac, re, arrow  -- arrow: NONE 无箭头 | DOWN ↓ | UP ↑
FROM qm_gb2828_table
WHERE version = #{activeVersion}
  AND code = #{code}
  AND aql = #{aql}
  AND table_type = #{tableType};  -- NORMAL / TIGHTENED / REDUCED

-- Step 3（箭头循环）：按箭头取相邻字码，再回到 Step 2
--   ↓：取字码表中下一行字码；↑：取上一行字码（字码顺序 A,B,C,...,R）
```

> 【本轮修正：查询列与 DDL 对齐，并且固定读取已激活的数据集版本。】
