## 2. 各单据要点

### D01 计划订单（pl_plan_order / pl_plan_order_bom）

1. **单据类型 bill_type**：MPS 计划订单 / MRP 计划订单，跟随物料的计划策略（`md_material.plan_strategy`），一期只实现 MRP 计划订单（G1a 3.5）。
2. **投放类型 release_type**：生产订单类、采购申请类、委外订单类、组织间受托类、生产线类（不可投放）；一期只做前三类；必须匹配物料的 allow_produce / allow_purchase / allow_subcontract（G1a 3.5）。
3. **BOM编号 bom_id**：投放类型为生产或委外时**必录**；BOM 用途（`md_bom.usage`）要匹配：生产用自制或通用，委外用委外或通用（G1a 3.5）。
4. **建议日期/建议订单量 sugg_start / sugg_finish / sugg_qty**：运算生成或手工录入；必须落在供应组织日历内；建议完工 = 建议开工 + 固定提前期 + 建议订单量 ÷ 变动提前期批量 × 变动提前期；**需求确认后锁定**（G1a 3.5）。
5. **确认日期/确认订单量 firm_start / firm_finish / firm_qty**：订单量 > 0；日期在日历内；**供应确认后锁定**（G1a 3.5）。
6. **业务状态 biz_status**：计划 → 需求确认（锁建议字段）→ 供应确认（锁确认字段）→ 关闭；反确认操作回到上一状态；计划 / 需求确认 / 供应确认三个状态都能直接手工关闭（SM-02）。
7. **关闭类型 close_type**：手工关闭、投放关闭、拆分关闭、合并关闭；反关闭回到关闭前的状态；拆分、合并生成新计划订单，原单置对应关闭类型（SM-02、N-01）。
8. **计划BOM pl_plan_order_bom.need_qty / need_date**：标准用量 std_qty = 固定用量或数量 × 变动用量 × 使用比例 × 分子 ÷ 分母；应发数量 need_qty = 是否发损耗为"是"时取计划投料数量（损耗公式见 Q30、C-11），否则取标准用量；需求日期 need_date = 确认开工 + 偏置提前期，超过确认完工日期时取确认完工（G1a 3.5）。
9. **供应商 supplier_id**：采购类只能选供应类别不是委外的，委外类只能选供应类别为委外的（G1a 3.5）。
10. **数据来源 data_source / 运算编号 run_id**：运算生成 / 合并生成 / 拆分生成 / 手工录入；运算编号记 MRP 运算的 run_id，每次运算重新赋值（G1a 3.5）。
11. **投放反写 R02**：业务状态为供应确认（或参数允许直接投放）；生产/委外类 BOM 必录；投放后计划订单置"投放关闭"（R02）。
12. **MRP 供需明细 pl_mrp_detail**：销售订单、安全库存 → MRP → 计划订单，生成时记 run_id 和供需明细（src_form / src_entry_id）（R01）。

### D02 工程变更单 ECN（ecn_order / ecn_order_entry）

1. **变更类型 change_type**：立即生效、按日期变更、用完旧料（G1a 3.3）。
2. **生效日期 eff_date**：变更类型为按日期变更时使用，由定时任务生效（G1a 3.3、SM-03）。
3. **版本升级 upgrade_version**：勾选时生成新的 BOM 版本，与"现场更新"不能同时勾选；默认都不勾选（G1a 3.3）。
4. **更新用料清单 update_ppbom**：勾选时同步更新生产和委外用料清单（G1a 3.3、R21）。
5. **子项更换 sub_keep**：保留替代料 / 删除替代料；用完旧料时，在 BOM 里把旧料设为替代件（优先级 0）、新料设为主料（优先级 1），只限修改子项（G1a 3.3、SM-03）。
6. **BOM 版本**：使用组织必须等于变更组织；**BOM 父项必须勾选"启用ECN"**（`md_bom.enable_ecn`）（G1a 3.3、R21）。
7. **行标示 ecn_order_entry.row_flag**：新增 / 修改前 / 修改后 / 失效 / 删除；决定子项字段的选择范围和是否可编辑（G1a 3.3）。
8. **业务状态 status / 生效状态 effect_status**：创建 → 审核中 → 已审核 → 生效；生效方式三种（立即、按日期、用完旧料）（SM-03）。
9. **旧料清理触发生效**：查询本组织和其他组织的库存与预计入；单据类别包括生产订单、采购申请、采购订单、采购入库、盘盈、其他入库（G1a 3.3）。
10. **生效反写 R21**：审核并生效；BOM 父项勾选"启用ECN"；生成或修改 BOM 版本（`md_bom.version`）；勾"更新用料清单"时同步在制生产/委外用料清单（R21）。
11. **一期范围裁决 C-09**：一期只做 ERP 内 ECN，审批时提供"在制、在途、库存"影响查询（复用 ECN 旧料清理的取数口径）；ECR 申请单随 PLM 放二期（C-09）。
12. **联副产品行**：行类型为新增 / 修改 / 失效 / 删除；物料必须勾选"可为联副产品"（G1a 3.3）。

## 3. 与其他任务包的边界

### 本包负责
- **MRP 运算引擎**：pl_mrp_scheme / pl_mrp_run / pl_mrp_run_log / pl_mrp_detail / pl_mrp_selected 的读写。
- **计划订单**：pl_plan_order / pl_plan_order_bom 的 CRUD、状态机 SM-02、需求确认/供应确认锁定、关闭类型判断、拆分/合并生成新单。
- **ECN**：ecn_order / ecn_order_entry 的 CRUD、状态机 SM-03、生效触发（立即、按日期、用完旧料）、BOM 版本生成逻辑。

### WP02 单据引擎（依赖）
- **状态机配置**：sys_state_machine 中 SM-02（计划订单）和 SM-03（ECN）。
- **转换规则 sys_convert_rule**：计划订单 → 生产订单 / 采购申请 / 委外订单的投放规则（R02）。
- **反写规则 sys_writeback_rule**：ECN 生效后反写 BOM 版本、用料清单的规则（R21）；投放后反写计划订单"投放关闭"的规则（R02）。

### WP04 基础资料（依赖）
- **物料主档 md_material**：plan_strategy / allow_produce / allow_purchase / allow_subcontract / safety_stock / mpq。
- **BOM md_bom / md_bom_entry**：usage / enable_ecn / bom_type / yield_rate；子项的 numerator / denominator / scrap_rate / fixed_scrap / offset_lead / backflush_time。
- **替代料 md_substitute / md_substitute_entry**：组合替代、非组合替代的优先级和使用比例计算。
- **工艺路线 md_route**：提前期计算（固定提前期 + 变动提前期 × 订单量）。

### WP08 采购（下游）
- **采购申请单**：计划订单投放时创建采购申请单，状态可配置为"创建"或"审核"（G1a 3.4）。

### WP09 生产、WP07 委外（下游）
- **生产订单 / 委外订单**：计划订单投放时创建；携带 BOM 生成用料清单。
- **用料清单反写**：ECN 勾选"更新用料清单"时，由 WP09/WP07 提供用料清单的更新接口，本包调用（R21）。

### WP10 库存（依赖）
- **库存可用量查询**：MRP 运算取"期初库存 − 已分配"（N-10），仓库状态为"MRP可用"的才参与（G1a 3.4）。
- **ECN 旧料清理**：查询本组织和其他组织的库存（库存表、采购入库、盘盈、其他入库等单据）（G1a 3.3）。

### WP11 质量（依赖）
- **IQC / OQC 标志**：物料主档 iqc_required / oqc_required，影响预计入库的 MRP 可用时机（设计：入库前扣减安全提前期或质检提前期）。

### WP12 车间（依赖）
- **车间日历**：计划订单建议日期/确认日期必须落在供应组织的日历内（G1a 3.5）。
- **车间产能**：二期能力中心、优先级计算、净需求拆分（N-12），一期不做。

9. **MPS 计划订单与 MRP 计划订单的区别**：G1a 3.5 写 MPS 物料默认 MPS 计划订单，但一期只做 MRP 计划订单；**设计**：一期 bill_type 统一为"MRP 计划订单"，MPS 放二期；表字段 bill_type 预留枚举值。
10. **生产线类计划订单"不可投放"的强控还是软控**：G1a 3.5 写"只作生产线需求来源，不可投放"，**设计**：投放按钮隐藏或置灰；若手工调 API 则返回错误"生产线类计划订单不允许投放"。
11. **批量增量的取整逻辑**：G1a 3.4 写"批量增量"但未说明向上取整还是四舍五入；**设计**：按金蝶标准实现向上取整（Ceiling）。

### 0.x 与《平台开发约定》V0.1 的对齐说明（人工核对）

约定文件：`/workspace/erp-3d/fullsys/code/docs/平台开发约定.md`（V0.1）。Claude 半成品（WP05 第1、4节；WP06/WP07 依据提炼）写于约定发布之前；续写章节已尽量按约定起草，但仍有与约定不一致处。编码时以约定为准，已完成正文不据此改写，只在下面和【核对】中标注。

1. **建表方式（约定 3.2、3.5、10.3）**：单据表不能手写 `CREATE TABLE`，要用 `@erp3d/shared` 的 BillMeta（字段 snake_case）配合 `ensureBillTables` 在 `apps/api/src/db/migrations` 的幂等迁移里建表；表头 25 个公共列、分录 18 个公共列由框架自动加，元数据里不能再声明。第 1 节 DDL 只作为字段清单参考。非单据表用 `ensureTable` / `addColumnIfMissing` / `addIndexIfMissing`；禁止 DROP，也禁止改已有列类型。主键为 53 位雪花 BIGINT，不是 AUTO_INCREMENT。
2. **字段类型（约定 3.1）**：数量、金额用 DECIMAL(23,10)（JSON 里用字符串），datetime 用 DATETIME(3)，bool 用 TINYINT(1)，enum 用 VARCHAR(20)。正文里状态列宽度有 VARCHAR(16/32) 等写法，实现时按 FieldType 映射统一。
3. **状态维度取值（约定 5.1）**：`close_status`、`cancel_status`、`forbid_status` 一律用 `A` 正常、`B` 关闭/作废/禁用。正文 DDL 里出现的 OPEN/CLOSED、NORMAL/CANCELLED、缺 `forbid_status` / `closer_id` / `closed_at` / `canceller_id` / `cancelled_at` / `cancel_prev_status`，实现时按约定补齐。已审核须先反审核才能作废；有下游有效单据禁止反审核（`BIZ_HAS_DOWNSTREAM`）。
4. **模块注册与接口（约定 4.1–4.4）**：模块用 `BillEngineRegistry.registerBill()` 注册；接口前缀 `/api/v1`；响应 `{code,msg,data,traceId,errors?}`，成功 `code` 为字符串 `'OK'`（不是数字 0）。标准单据走 `/api/v1/bills/{form}…`。
5. **反写（约定 6.2、6.5）**：两段反写——保存写关联数量，审核写执行数量；`WritebackRuleConfig.onEvent` 为 `save|audit`，`mode` 为 `add|sub|overwrite`。`srcForm` 是被反写的上游，`tgtForm` 是触发反写的下游。超发用 `issueLimit()`。
6. **字段锁定（约定 FieldLockRule）**：可编辑白名单，不是锁定列黑名单。正文若按黑名单列举，实现时要改写成白名单。
7. **钩子（约定 2.2）**：beforeSave / afterSave / beforeAudit / afterAudit / beforeUnaudit / afterUnaudit / beforeCancel / afterCancel / beforeDelete / rowGuards。生产模块代码目录约定为 `apps/api/src/prd/`。
8. **库存入口（与 WP10 对齐）**：库存更新只走 WP10 `InventoryService.applyTxn` / `rollbackTxn` 等进程内服务，即时库存表为 `scm_inventory`，流水为 `scm_inv_txn`；卷盘主档为 `bc_barcode_master`（Q05 每盘一码），不使用 `bas_` / `bd_` 前缀。
9. **WP02 自定义业务事件（反重力 2026-11-13 确认）**：WP02 将提供自定义业务事件（如 `inspect_complete`），反写规则可挂在事件上，与事件同事务执行，撤销时反冲；分录级钩子尽量提供。正文中“质检完成触发反写”“入库达下限自动完工”“首次领料自动开工”“ECN 生效同步在制用料清单”等非 save/audit 触发的动作，统一按 **依赖 WP02 扩展，接口待定** 处理，正文里出现 `onEvent` 取 save/audit 以外的值、或行级事件触发处，以本条为准。
10. **与 WP10/WP11 定稿方向对齐**：① 库存冻结/解冻一律走 WP10 的 D46 库存状态转换单，不直接写 `scm_inventory.lock_qty`；② 库存流水 `scm_inv_txn` 只增不删，反审核写反向流水（唯一键：单据类型+单据ID+分录ID+方向+审核批次），正文中“删除流水”“回滚删除”的说法按此改为写反向流水；③ 日期码 D/C（YYWW）按 ISO 周；④ 让步接收按 R29 入库，单独统计。WP05–07 中生产/委外入库、领退料、MSL 超时、检验不合格等涉及处按以上执行。

## 第3节 ③ 转换与反写规则

> 【核对】本节合并时删除了模型复述任务的构思草稿和续写接缝处被截断后重写的重复段落，正文未改写。

### R01 MRP→计划订单（R01-01）

MRP 系统记录（pl_mrp_run / pl_mrp_detail）非单据，不配置 `sys_convert_rule`，由 MRP 运算服务在 `pl_mrp_run` 事务内直接生成 `pl_plan_order` 头与 `pl_plan_order_bom` 行，并写 `pl_mrp_detail`（run_id, src_form, src_entry_id）供追溯。生成的计划订单 `data_source` 置"运算生成"、`run_id` 记当次运算编号。

| 项目 | 内容 |
|---|---|
| 转换规则 | 无 sys_convert_rule（源非单据）【建议】 |
| 来源 | pl_mrp_detail（run_id, material_id, date, net_req, src_form, src_entry_id） |
| 目标字段映射 | pl_mrp_detail.run_id → pl_plan_order.run_id；pl_mrp_detail.material_id → pl_plan_order.material_id；pl_mrp_detail.date → pl_plan_order.sugg_finish；pl_mrp_detail.net_req → pl_plan_order.sugg_qty；pl_mrp_detail.src_form/src_entry_id → pl_mrp_detail 保留（供需明细） |
| 反写规则 | 无（上游非单据）；pl_mrp_selected 记录选单需求范围（run_id, src_form, src_entry_id） |
| 钩子 | pl_plan_order afterSave（mode: save）：若 data_source=运算生成，校验 run_id 已写入且 pl_mrp_detail 已存在对应行；禁止手工修改 run_id |

### R02 计划订单投放→生产订单 / 采购申请单 / 委外订单

选单条件：pl_plan_order.biz_status = '供应确认'（或参数允许直接投放【待确认：参数名与取值，是否允许"需求确认"态投放】）；生产/委外类 release_type 必录 bom_id 且 BOM 用途匹配（生产用自制/通用，委外用委外/通用）。投放后计划订单置"投放关闭"（close_type='投放关闭'）。

### R21 ECN→BOM / 在制用料清单

触发条件：ecn_order 审核并生效（立即生效直接生效；按日期由 sys_job 定时任务生效；用完旧料由旧料清理触发）。BOM 父项须 `md_bom.enable_ecn=true`，使用组织等于变更组织。

#### R21-01 ECN生效→BOM版本（md_bom）

md_bom 属 WP04 基础资料，非单据，**不配置 sys_convert_rule / sys_writeback_rule**，由 ecn_order 的 afterAudit（及生效触发）钩子调用基础资料服务生成/修改 BOM 版本。

| 项目 | 内容 |
|---|---|
| 转换规则 | 无（目标非单据） |
| 反写规则 | 无 sys_writeback_rule；效果由钩子完成，写 sys_event_outbox 记录事件【建议】 |
| 钩子 | ecn_order afterAudit：若 change_type='立即生效' 或生效任务触发，按 ecn_order_entry.row_flag（新增/修改前/修改后/失效/删除）生成新 md_bom 版本（upgrade_version 勾选时）或修改现版本；用完旧料时按 sub_keep 把旧料设为替代件（优先级 0）、新料设为主料（优先级 1）；版本号写 md_bom.version |
| 回滚 | 反审核 ecn_order：已生效的 BOM 版本不回滚，置失效并生成还原版本【建议】【待确认：BOM 版本是否允许回滚】；禁止直接 UPDATE md_bom，走基础资料服务 |

#### R21-02 ECN生效→在制生产/委外用料清单（pp_ppbom / sub_ppbom）

勾选 `update_ppbom` 时，同步更新在制 pp_ppbom（D04）与 sub_ppbom（D16）。目标为单据，配置反写规则；禁止直接写 pp_ppbom 表，由引擎 writeback + 钩子完成。

| 项目 | 内容 |
|---|---|
| sys_writeback_rule.code | `R21-02`（pp_ppbom）；`R21-03`（sub_ppbom，建议对称命名【待确认：code 命名是否纳入 sys_convert_rule 同一规则】） |
| src_form → tgt_form | ecn_order → pp_ppbom（R21-02）；ecn_order → sub_ppbom（R21-03） |
| on_event | audit（ECN 审核生效时） |
| src_field → tgt_field | ecn_order_entry 变更内容 → pp_ppbom_entry 对应字段：child_material_id, numerator, denominator, scrap_rate, fixed_scrap, use_ratio, std_qty, need_qty, must_qty（按新 BOM 版本重算）；pp_ppbom_entry.src_rule 置 'R21-02' |
| mode | overwrite（整行按新版本覆盖）；over_ctrl=ONCE（同一 ECN 对同一用料清单行只生效一次） |
| close_expr / close_scope | 不关闭用料清单行；close_scope=NONE |
| filter | 仅更新在制单据：pp_ppbom 对应 pp_mo_entry.biz_status ∈ (CONFIRMED, RELEASED, STARTED)（在制，未 FINISHED/CLOSED）【建议，待确认在制状态集合】；sub_ppbom 对应 sub_order_entry 未关闭 |
| 钩子 | ecn_order afterAudit：若 update_ppbom=true，枚举受影响在制用料清单行，经 writeback 规则重算；pp_ppbom beforeSave rowGuards：禁止手工改由 ECN 标记（src_rule='R21-02'）的行关键字段 |
| 回滚 / 保护 | 反审核 ecn_order：已生效用料清单不自动回滚，需再下新 ECN 还原【建议】【待确认】；有下游领退补/汇报有效单据的用料清单行禁止被 ECN 覆盖（BIZ_HAS_DOWNSTREAM） |

#### 2) 主流程伪代码

```pseudo
FUNCTION mrpRun(schemeId, mode, selected?: pl_mrp_selected[], runId):
  scheme ← load pl_mrp_scheme where id=schemeId          // horizon_days, demand_fence, plan_fence, params_json
  run ← insert pl_mrp_run(run_no, scheme_id, mode, start_at=now, status='RUNNING')
  try:
    // 1. 范围与时界
    horizonEnd ← today + scheme.horizon_days               // G1a 3.4 计划展望期：超出不参与
    fenceD ← today + scheme.demand_fence                    // 需求时界
    fenceP ← today + scheme.plan_fence                      // 计划时界
    warehouses ← scheme.params_json.availableWarehouses      // 仅 mrp_available 状态参与

    // 2. 低位码（运算前更新）
    IF params.batchGuide.lowLevelCode THEN recalcLowLevelCode()   // Nemotron 低位码运算

    // 3. 收集独立需求（销售订单；选单时以 pl_mrp_selected 为范围）
    demandSources ← []
    IF mode = 选单:
        selected ← pl_mrp_selected where run_id=runId        // R01 记运算编号
        demandSources ← salesOrders.filter(src in selected, 非暂存, 未关闭, date ≤ horizonEnd)
    ELSE:
        demandSources ← salesOrders.filter(非暂存, 未关闭, date ≤ horizonEnd)
    // 需求时界规则：≤fenceD 取销售订单；fenceD~fenceP 取销售与预测较大者；>fenceP 取预测
    // 一期无预测单【见4)】，故 fenceD 之后仅销售订单参与【待确认】

    // 4. BOM 展开（按低位码升序），得毛需求 grossReq[material][date]
    grossReq ← {}
    FOR d IN demandSources ORDER BY date:
        explodeBOM(d.material, d.qty, d.date, grossReq)      // 见公式表 BOM 展开与损耗

    // 5. 收集供给 scheduledReceipt[material][date]（G1a 3.4 取数口径表）
    supply ← collectSupply(scheme, warehouses)               // 计划订单/生产订单/委外订单/采购申请/采购订单
    // 现有库存 onhand[material] ← InventoryService.getAvailable(warehouse in warehouses, status.mrp_available)
    // 已分配 allocated[material] ← 生产/委外用料清单已分配量（G1a: 生产用料清单作为已分配的预计量参与运算）

    // 6. 按低位码升序逐物料分日净需求计算
    FOR m IN materials ORDER BY low_level_code ASC:
        safety ← md_material.safety_stock (IF 考虑安全库存)
        FOR date IN [today .. horizonEnd] ORDER BY date ASC:
            gross ← grossReq[m][date] or 0
            sched ← supply[m][date] or 0
            alloc ← allocated[m][date] or 0
            onhand ← (date=today ? initialOnhand[m] : prevEnding[m])
            // 净需求 N-10 / G1a 制造策略分项
            net ← gross + alloc - onhand - sched + safety      // 见公式表 F2（开关组合）
            IF net > 0:
                qty ← applyLottery(m, net, scheme.params_json)  // LFL/POQ/FOQ + 最大/最小/增量；成品率见 F4
                planOrder ← createPlanOrder(m, qty, date, runId) // 写 pl_plan_order(DRAFT) + pl_plan_order_bom
                write pl_mrp_detail(run_id, m, date, gross, onhand, sched, alloc, safety, net, src_form, src_entry_id)
                supply[m][finishDate] += qty                    // 计划订单回补供给（供给优先顺序内）
                logExceptionIfAny(m, date, qty)                 // 例外码见公式表
            prevEnding[m] ← onhand + sched - gross + (net>0 ? qty : 0) - safety  // 期末可用量 G1a
    // 7. 全重排：释放既有计划订单预留（手工预留除外）；选单：不释放【G1a 3.4 预留释放方式】
    IF mode = 全重排: releaseExistingPlanOrderReservations(except manual)
    update pl_mrp_run set status='DONE', end_at=now
  CATCH e:
    insert pl_mrp_run_log(run_id, null, 'SYS', e.message)
    update pl_mrp_run set status='FAIL', end_at=now
    ROLLBACK
```
