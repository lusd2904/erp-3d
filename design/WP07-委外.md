## 2. 各单据要点

### D15 委外订单（sub_order / sub_order_entry）

1. **委外组织**（sub_org_id）：必须具有委外职能；默认当前组织（G1a 3.14）
2. **物料**（material_id）：只能选 `bd_material.allow_outsource = true` 的物料（G1a 3.14）
3. **供应商**（supplier_id）：初始选择规则为采购组织下、供应类别为委外或综合、已审核未禁用；**下推采购订单后由 R23 反写更新**（G1a 3.14）
4. **BOM 版本**（bom_id）：默认用途为"委外+通用"的最新版本（G1a 3.14）
5. **计划完工日期**（plan_finish）：由计划开工日期（plan_start）和委外数量自动计算，必须在委外车间日历的可委外日（G1a 3.14）
6. **领料状态**（pick_status）：未领料 / 部分领料 / 全部领料 / 超额领料，由 R24 反写（G1a 3.14，R06）
7. **审核自动计划确认**：审核时自动置 `biz_status = '计划确认'`，不是"计划确认 → 审核 → 下达"（C-16）
8. **首次领料自动开工**：状态枚举含"开工"，但操作说明无开工按钮；建议首次领料时自动置 `biz_status = '开工'`（C-02、Q23，Q23 已确认"可以"）
9. **结案前置条件**：用料清单已审核、采购订单已关闭、无未审核领退补单；**未入库的委外订单只能强制结案**（SM-07、G1a 3.14）
10. **采购选单数量**（po_sel_qty）、**采购执行数量**（po_exec_qty）、**入库数量**（in_qty）：系统累计，由 R23、R25 反写（G1a 3.14）
11. **核算组织**（acct_org_id）：预留字段，二期成本核算用；原文"委外申请单"即本单（C-20）
12. **拆分规则**：可拆分数量 = 数量 − po_sel_qty；参数可设置保留原单号+001（G1a 3.14）

### D16 委外用料清单（sub_ppbom / sub_ppbom_entry）

1. **头表关联**（sub_entry_id）：指向 sub_order_entry，一对一（技术方案 122）
2. **子项规则同生产用料清单**：child_material_id, child_type, qty_type, use_ratio, fixed_scrap, scrap_rate 等（技术方案 123，G1a 3.14）
3. **需求日期**（need_date）：计划开工 + 偏置提前期（G1a 3.14）
4. **需求数量**（need_qty）：向上取整（G1a 3.14）；计算公式采用 Q30 确认的"方式一：× (1 + 损耗率)"（Q30）
5. **返还件强制不发料**：返还件行的 issue_type 强制为"不发料"（G1a 3.14）
6. **货主默认值**：货主类型（owner_type）默认业务组织，货主（owner_id）默认委外组织（G1a 3.14）
7. **变更单锁定规则**：picked_qty, repick_qty, ret_sel_qty, feed_sel_qty **任一 > 0 时**，child_type 和 issue_type 锁定（G1a 3.14）
8. **已领数量**（picked_qty）、**补领数量**（repick_qty）、**退料选单数量**（ret_sel_qty）、**补料选单数量**（feed_sel_qty）：由 R24 反写（技术方案 123，R24）

### D17 委外领料单（sub_pick / sub_pick_entry）

1. **前置订单状态**：委外订单分录 biz_status 为下达 / 开工 / 完工**且未挂起**；用料清单已审核（R24、C-23）
2. **可领数量校验**：应发（need_qty）− 领料选单（pick_sel_qty）+ 良品退（good_ret_qty）+ 来料不良退（inc_bad_ret_qty）> 0（R24）
3. **反写目标**：审核时反写 sub_ppbom_entry.picked_qty、sub_order_entry.pick_status（R24）
4. **自动开工触发**：首次领料审核后自动置委外订单分录为"开工"（R24、Q23）
5. **卷盘扩展**：需关联 reel_id，记录实际发出的卷盘（Q05）
6. **申请数量**（apply_qty）不能大于下推数量（G1a 3.14）

### D18 委外退料单（sub_return / sub_return_entry）

1. **前置状态同领料**：委外订单分录下达 / 开工 / 完工且未挂起（C-23）
2. **可退数量校验**：实发（actual_qty）− 退料选单（ret_sel_qty）> 0（R24）
3. **退料类型**（ret_type）：良品 / 来料不良 / 作业不良（技术方案 127，R24）
4. **反写目标**：审核时反写 sub_ppbom_entry.good_ret_qty / inc_bad_ret_qty / op_bad_ret_qty（R24）
5. **卷盘退料**：需记录 reel_id 和 remain_qty（技术方案 127，Q05）
6. **补料来源**（feed_sel_qty）：退料后可再补料，记录已被补料单选单的数量（技术方案 127）

### D19 委外补料单（sub_feed / sub_feed_entry）

1. **前置状态同领料**：委外订单分录下达 / 开工 / 完工且未挂起（C-23）
2. **生成来源**：从委外用料清单下推（损耗补料），或从委外退料单生成（退料再补）（R24）
3. **从退料单生成校验**：实退（actual_qty）− 补料选单（feed_sel_qty）> 0（R24）
4. **超损耗审批**：补料数量超损耗率时走审批流（R24）
5. **合单分组**：发料组织 + 生产组织（即委外组织）+ 货主 + 货主类型相同的分录合成一张（C-25）
6. **反写目标**：审核时反写 sub_ppbom_entry.repick_qty（补领数量）和 scrap_qty（报废数量）（R24）
7. **委外组织职能**：委外组织必须具有工厂职能（G1a 3.14）

### 0.x 与《平台开发约定》V0.1 的对齐说明（人工核对）

约定文件：`/workspace/erp-3d/fullsys/code/docs/平台开发约定.md`（V0.1）。Claude 半成品（WP05 第1、4节；WP06/WP07 依据提炼）写于约定发布之前；续写章节已尽量按约定起草，但仍有与约定不一致处。编码时以约定为准，已完成正文不据此改写，只在下面和【核对】中标注。

1. **建表方式（约定 3.2、3.5、10.3）**：单据表不能手写 `CREATE TABLE`，要用 `@erp3d/shared` 的 BillMeta（字段 snake_case）配合 `ensureBillTables` 在 `apps/api/src/db/migrations` 的幂等迁移里建表；表头 25 个公共列、分录 18 个公共列由框架自动加，元数据里不能再声明。第 1 节 DDL 只作为字段清单参考。非单据表用 `ensureTable` / `addColumnIfMissing` / `addIndexIfMissing`；禁止 DROP，也禁止改已有列类型。主键为 53 位雪花 BIGINT，不是 AUTO_INCREMENT。
2. **字段类型（约定 3.1）**：数量、金额用 DECIMAL(23,10)（JSON 里用字符串），datetime 用 DATETIME(3)，bool 用 TINYINT(1)，enum 用 VARCHAR(20)。正文里状态列宽度有 VARCHAR(16/32) 等写法，实现时按 FieldType 映射统一。
3. **状态维度取值（约定 5.1）**：`close_status`、`cancel_status`、`forbid_status` 一律用 `A` 正常、`B` 关闭/作废/禁用。正文 DDL 里出现的 OPEN/CLOSED、NORMAL/CANCELLED、缺 `forbid_status` / `closer_id` / `closed_at` / `canceller_id` / `cancelled_at` / `cancel_prev_status`，实现时按约定补齐。已审核须先反审核才能作废；有下游有效单据禁止反审核（`BIZ_HAS_DOWNSTREAM`）。
4. **模块注册与接口（约定 4.1–4.4）**：模块用 `BillEngineRegistry.registerBill()` 注册；接口前缀 `/api/v1`；响应 `{code,msg,data,traceId,errors?}`，成功 `code` 为字符串 `'OK'`（不是数字 0）。标准单据走 `/api/v1/bills/{form}…`。
5. **反写（约定 6.2、6.5）**：两段反写——保存写关联数量，审核写执行数量；`WritebackRuleConfig.onEvent` 为 `save|audit`，`mode` 为 `add|sub|overwrite`。`srcForm` 是被反写的上游，`tgtForm` 是触发反写的下游。超发用 `issueLimit()`。
6. **字段锁定（约定 FieldLockRule）**：可编辑白名单，不是锁定列黑名单。正文若按黑名单列举，实现时要改写成白名单。
7. **钩子（约定 2.2）**：beforeSave / afterSave / beforeAudit / afterAudit / beforeUnaudit / afterUnaudit / beforeCancel / afterCancel / beforeDelete / rowGuards。生产模块代码目录约定为 `apps/api/src/prd/`。
8. **库存入口（与 WP10 对齐）**：库存更新只走 WP10 `InventoryService.applyTxn` / `rollbackTxn` 等进程内服务，即时库存表为 `scm_inventory`，流水为 `scm_inv_txn`；卷盘主档为 `bc_barcode_master`（Q05 每盘一码），不使用 `bas_` / `bd_` 前缀。
9. **WP02 自定义业务事件（反重力 2026-11-13 确认）**：WP02 将提供自定义业务事件（如 `inspect_complete`），反写规则可挂在事件上，与事件同事务执行，撤销时反冲；分录级钩子尽量提供。正文中“质检完成触发反写”“入库达下限自动完工”“首次领料自动开工”“ECN 生效同步在制用料清单”等非 save/audit 触发的动作，统一按 **依赖 WP02 扩展，接口待定** 处理，正文里出现 `onEvent` 取 save/audit 以外的值、或行级事件触发处，以本条为准。
10. **与 WP10/WP11 定稿方向对齐**：① 库存冻结/解冻一律走 WP10 的 D46 库存状态转换单，不直接写 `scm_inventory.lock_qty`；② 库存流水 `scm_inv_txn` 只增不删，反审核写反向流水（唯一键：单据类型+单据ID+分录ID+方向+审核批次），正文中“删除流水”“回滚删除”的说法按此改为写反向流水；③ 日期码 D/C（YYWW）按 ISO 周；④ 让步接收按 R29 入库，单独统计。WP05–07 中生产/委外入库、领退料、MSL 超时、检验不合格等涉及处按以上执行。

async afterAudit(db: DbService, bill: SubPick, mode: 'audit') {
  for (const row of bill.entries.sort((a,b)=>a.id-b.id)) {
    const ppbom = await db.findOne('sub_ppbom_entry', { id: row.ppbom_entry_id }).forUpdate();
    const subEntry = await db.findOne('sub_order_entry', { id: ppbom.sub_entry_id }).forUpdate();

    // 1) 前置校验（C-23）：订单分录 下达/开工/完工 且未挂起；用料清单已审核
    assert(['RELEASED','STARTED','FINISHED'].includes(subEntry.biz_status) && !subEntry.is_suspended, 'BIZ_SUB_ORDER_NOT_RELEASED');
    assert(ppbom.status === 'AUDITED', 'BIZ_SUB_PPBOM_NOT_AUDITED');

    // 2) 可领数量校验（R24 同 R06）
    const canPick = ppbom.need_qty - ppbom.pick_sel_qty + ppbom.good_ret_qty + ppbom.inc_bad_ret_qty;
    assert(row.apply_qty <= canPick, 'BIZ_SUB_PICK_QTY_EXCEED');

    // 3) 超发上限（L3 issueLimit）
    assert(issueLimit(subParam.overIssueMode, ppbom.need_qty, ppbom.std_qty, ppbom.scrap_rate, ppbom.min_issue_qty)
           >= row.actual_qty, 'BIZ_SUB_ISSUE_LIMIT');

    // 4) 卷盘发料（Q05，每盘一码，L5 只能调 bc.*）
    for (const reel of row.reels) {          // sub_pick_reel【扩展】【建议】
      await bc.pickReel({ reel_id: reel.reel_id, qty: reel.qty, mslCheck: true, db });
    }

    // 5) 库存扣减/转保管（L5 只能调 InventoryService；去向方案见第 1 节【待确认】）
    await inventory.applyTxn({
      form: 'sub_pick', bill_id: bill.id, entry_id: row.id,
      material_id: row.material_id, qty: row.actual_qty, io_direction: 'OUT',
      wh_id: row.wh_id, lot_no: row.lot_no,
      keeper_type: subParam.stockToKeeper ? 'SUPPLIER' : null,  // 【待确认】
      db
    }, db);

    // 6) 反写（L3：审核写执行数量，增量 UPDATE，上游行 id 升序 FOR UPDATE 已持锁）
    await db.increment('sub_ppbom_entry', { id: ppbom.id },
      { picked_qty: row.actual_qty, pick_sel_qty: -row.sel_qty_delta });  // sel 保存时已反写
    // 7) 领料状态（R24 反写 sub_order_entry.pick_status）
    const totalPicked = ppbom.picked_qty + row.actual_qty;
    const pickStatus = totalPicked <= 0 ? 'NOT_PICKED'
      : totalPicked >= subEntry.qty ? 'OVER_PICKED' : 'PART_PICKED'; // 全部领料按用料清单应发汇总【建议】
    await db.update('sub_order_entry', { id: subEntry.id }, { pick_status: pickStatus });

    // 8) 首次领料自动开工（C-02 / Q23 已确认"可以"）
    if (subEntry.biz_status === 'RELEASED' && totalPicked > 0) {
      await db.update('sub_order_entry', { id: subEntry.id }, { biz_status: 'STARTED' });
    }

    // 9) sys_bill_link 登记（同一事务）
    await db.insert('sys_bill_link', { src_form: 'sub_ppbom', src_bill_id: ppbom.bill_id, src_entry_id: ppbom.id,
      tgt_form: 'sub_pick', tgt_bill_id: bill.id, tgt_entry_id: row.id, rule_code: 'sub_ppbom-sub_pick', db });
  }
}

async beforeClose(db: DbService, entry: SubOrderEntry, opts: { force?: boolean }) {
  // 前置条件（SM-07 / G1a 3.14 委外单据类型参数）
  const ppbom = await db.findOne('sub_ppbom', { sub_entry_id: entry.id });

    // 非返还件结案强度（委外单据类型参数，默认值【待确认】Q41 对照）
    const wip = await calcWip(db, entry.id);

    if (mode === 'IN_LOSS') assert(wip <= lossAllow(entry), 'BIZ_SUB_CLOSE_WIP_OVER_LOSS');
    if (mode === 'IN_LOSS_MIN_BATCH') assert(wip <= lossAllow(entry) + minIssueBatch(entry), 'BIZ_SUB_CLOSE_WIP_OVER');
  }
  // 结案时子项损耗报失（参数勾选时）
  if (params.closeLossReport && !opts.force) await reportLoss(db, entry.id);
  await setRowBizStatus(db, 'sub_order_entry', entry.id, 'CLOSED'); // 引擎钩子改状态（L1）
}
