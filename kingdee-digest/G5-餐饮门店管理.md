## 1. 功能点

### 门店订货预估（高）`餐饮门店管理_门店订货预估.md`

模块定位：用历史同期用量和单位用量算门店要货需求，提前补料。目录称支持「历史同期用量要货」和「单位用量要货」。操作手册列三项智能要货：历史物料用量要货、历史食品销量要货、门店周期要货；预估处理单据是物料预估要货单；参数是门店订货需求系统参数。历史食品销量要货的正文在 `餐饮门店管理_门店销售预测.md`，本文件只有链接。整体流程图为 `[图:门店订货预估整体流程图.png]`，未 OCR。

**历史物料用量要货**

- 按历史同期算要货，生成预估要货单。同期维度原文列出：最近一天要货、上周同期、上月同期、上年同期、固定日期。
- 取数口径（字段说明原文）：
  - 最近一天要货：要货组织最近一天要货申请单的要货物料和数量。
  - 上周同期：要货组织上周同一星期的要货物料和数量汇总。
  - 上月同期：要货组织上月同一天的要货物料和数量汇总。
  - 上年同期：要货组织上年同一天的要货物料和数量汇总（原文「汇总生物」为笔误）。
  - 固定时间：按设定的固定时间，要货组织同一天的要货物料和数量汇总。
- 输入：要货组织、要货日期、物料分组（用来精确选某类物料并过滤）。
- 输出按钮：生成预估要货单；生成预估要货单（汇总）。
- 下推规则：只具配送属性的物料预估要货单只能下推门店要货申请单；只具自采属性的只能下推采购申请单或采购订单。
- 使用前提：门店要货申请、采购申请单、采购订单。
- 原文没有写多个同期维度同时勾选时如何加权、求和或取最大。流程图 `[图:历史物料用量要货流程图.png]` 未 OCR。

**物料预估要货单**

- 由历史物料用量要货和历史食品销量要货算出预估要货量后生成。系统应用原文：「通过智能要货模型计算物料的预估需求，生成自采或配送计划。」
- 表头：单据类型、单据编码、预估日期、单据状态、要货组织、配送组织、申请日期、要货部门、备注；以及创建/修改/审核/关闭人与日期、关闭状态。
- 表体：物料编码（智能要货计算生成）、名称、规格型号、物料类别、单位、预估数量（智能要货计算生成）、现有库存（申请组织）、安全库存、最小库存、净需求（「通过参数设置公式计算」，公式正文未给出）、配送、自采、辅单位、预估数量（辅单位）、净需求（辅单位）、备注。
- 下游：参数勾选「物料预估要货单审核时自动生成门店要货申请单」时，审核按预估单的单据类型自动生成对应单据类型的门店要货申请单；不勾选则手工下推，相同单据类型的物料预估单可下推成一张门店要货申请单。生成下游时「取实际订货量携带到下游单据」。本页字段表没有「实际订货量」列。

**门店周期要货**

- 功能说明两句并列：一是参考盘盈单、盘亏单、食品材料耗用单的历史数据生成物料预估用量单；二是根据订货周期和历史营业销售数据（预估营业总额、物料万元用量、食品成本卡）算出各物料的预估销售数量。
- 使用前提：三种单据在来源时间段内至少有一种有数据。
- 明确写明：预估营业额取用户手工新增的预估营业额，不会取销售预测自动计算的预估营业额。
- 步骤：新增门店预估营业额 → 门店周期要货选择参考日期 → 生成物料预估要货单。
- 其他原文：有物料类别和过滤方案保存；历史时间段默认当前日期的前一个月；默认赋值界面「组织」；「安全系为只读状态，实际订货数）可以进行修改，默认取(预估数量）的值」（原文残缺）；输入组织与参考历史起止日期后取门店数据并更新右边数据。
- 没有给出由盘盈/盘亏/耗用或由万元用量展开到预估数量的计算公式。流程图未 OCR。

**门店订货需求系统参数**

- 预估要货单审核时，配送物料可自动生成门店要货申请单（不勾选则不生成）。
- 物料预估要货单默认取整，三选一：进位、四舍五入、舍位。
- 预估要货单审核时，自采物料自动生成的下游为单项选择：采购申请单、采购订单、门店采购入库单，或三个都不选。自采/配送属性取自「物料—餐饮—智能要补货控制（配送/自采）」。
- 历史食品销量按部门审查物料预估：勾选后按部门分单（业务说明又写作「历史食品销量要货按部门生成物料预估」，并携带部门）。
- 门店食品预估方案上传按部门分单：勾选后不同部门生成不同的门店食品预估方案；业务说明写生成的物料预估单会携带部门。
- 默认供应商取自采购组织或要货组织。未设置需求供给委托关系时，采购组织与要货组织是同一组织。历史食品销量要货生成物料预估要货单时，按所选组织取该组织下的默认供应商。

### 门店销售预测（高）`餐饮门店管理_门店销售预测.md`

模块自述：整个模块服务历史食品销售要货，单据是基础资料，不能独立使用。索引分五块：销售预测计算（销售预测计算助手、门店预估营业额、食品万元销量表）、自定义食品万元销量、影响因子（特殊事件、营销活动）、食品销量预估方案（门店食品销售量预估）、报表（预估与实际营业额对比表）。流程图即万元用量要货流程图，未 OCR。食品销售清单被库存模块称为销量预测计算助手的原始数据来源（见 `餐饮门店管理_门店库存管理` 食品销售清单页）。

**历史食品销量要货（算法与输入输出的主页面）**

概述：根据历史营业销售数据统计历史平均营业总额，算出各菜品平均销售份数、平均日销售金额；可手工输入预估营业总额；按各菜品预估营业额与平均营业额的比值，算出各菜品预估销售数量及预估销售金额；再按食品成本卡算原材料，生成物料预估要货单。参数可选择预估食品销量方案。参考范围：本组织历史时段，或参考其他门店（单选一个组织）。

六条使用路径（正文有步骤，配图未 OCR）：

1. 新增门店食品销量预估方案 → 按预估食品销量方案要货。
2. 生成食品销售清单 → 按食品销售清单要货。使用前提写明需要食品销售清单数据、门店预估营业额等。
3. 参考组织生成食品销售清单 → 按参考组织的食品销售清单要货。
4. 销售预测计算助手 → 生成门店预估营业额和食品万元销量表 → 打开食品销量要货时自动勾选「按销售预测要货」。
5. 自定义食品万元销售 → 按自定义食品万元销量计算。
6. 设置特殊事件和营销活动 → 取影响因子计算要货。

选择参数字段：组织、部门（必须为要货组织下的部门）、预估要货日期、历史起始日期（≤要货日期）、历史截止日期（≤要货日期且≥起始日期）、选择星期。

生成食品用量预估的字段与公式（字段表原文）：

- 统计天数：参考历史天数。
- 历史日均营业额 = 历史总营业额 / 总天数。
- 要货天数：默认配送路线中的要货周期；没有则默认为 1。配送路线的设置页不在本领域文件中。
- 预估营业额：要货天数对应的预估营业额之和。
- 食品：取万元用量表中的食品明细，或按食品销售清单的计算规则获取。
- 万元用量：取万元用量表中对应食品的万元用量。
- 预估销售份数 =（预估营业额 × 万元用量）/ 10000。
- 日均销售份数 = 预估销售份数 / 要货天数。
- 按销售预测要货：当前日期对应的万元用量表和预估营业额有数据则自动勾选。
- 同一字段表另有一行「预估销售份数」：根据预估营业额和千元用量计算食品预估份数，再按食品预估份数及食品成本卡计算物料预估订货量。万元与千元两套说法并存，千元用量没有单独公式。
- 选择影响因子：弹出当前组织有效期内的影响因子；勾了自动计算的置灰不可改，未勾的可手工选。
- 总系数：默认单据头安全系数。选了单品促销影响因子则调整对应单品的安全系数。预估销售份数 = 安全系数 × 原预估销售份数；预估销售额 = 预估销售份数 × 销售单价；万元用量 = 预估销售份数 / 总预估营业额 × 10000。

业务说明中的计算与展开规则：

- 参考其他组织为单选。要货组织已有营业数据又选了参考组织时提示是否继续；选「是」则取参考组织营业数据。进入下一步后，历史营业额和食品销量都是被参考组织的，组织字段仍默认当前要货组织。
- 第二步点下一步时提示是否生成方案。
- 输入组织、部门和历史起止日期后，查食品销售清单中有无对应组织、部门、营业日期：有则标「有」，没有标「无」。
- 历史起止日期默认取后台服务的统计天数。例：设 365 天，则起止为当前日期往前 365 天；右边营业数据按该区间默认勾选。
- 统计天数默认后台服务的统计天数。历史日均营业额取预估营业额中的参考营业额均值。要货天数取要货组织所在配送路线的订货周期，未设置则默认为 1，可编辑。预估营业额取要货天数对应预估营业额之和，可编辑；安全系数算出或手工调整后，预估营业额相应调整。安全系数默认 1；点计算系数进入影响因子列表，系数 = 1 +（各因子影响值之和）。
- 影响因子若是维护了食品明细的营销活动，该因子不参与系数，改为调整该食品的预估销售额，再重算预估销售份数。
- 万元用量取后台服务计算结果。预估销售份数 = 由万元用量算出的日均销售份数 × 要货天数，不可编辑。「调整后预估销售份数」默认等于预估销售份数，可编辑。最终按调整后预估销售份数和食品成本卡分解成物料预估要货单。
- 参数页选了门店预估食品销量方案时，把方案中的食品加入食品用量预估页，与营业额算出的食品明细分开；该类型食品数量不参与任何计算。
- 按食品展开成本卡生成物料预估单时，只取食品成本卡上物料设置了「订货」字段属性的物料。
- 展开时先找该食品的默认食品成本卡；没有默认成本卡时，若该食品是由物料转为食品的，则按对应物料展开，食品预估数量即物料预估用量。

**销售预测计算助手**

- 自动生成门店预估营业额和食品万元用量表。
- 预测区间：从当前日期起往后几天。
- 参考历史天数：参考多少天营业数据。
- 勾选按星期类型，则分别统计参考期内每个星期的数据。
- 「参考历史数据天数扣除期初的几天」：计算万元用量表和预估营业额时扣除输入的那几天。
- 字段：预测区间、任务名称、执行点时间、参考天数、执行间隔、是否按星期几类型来计算、历史营业额数据是否扣除期初几天。
- 没有写出扣除期初之后的回归、平滑或权重公式，只写了按星期分类或按总金额/总天数。

**门店预估营业额**

- 历史食品销量要货和门店周期要货都用它。可手工新增，也可由销售预测计算助手生成。门店周期要货页声明只用手工新增的值。
- 字段：参考历史天数；默认安全用量（手工新增默认 1.1，后台生成默认 1）；数据来源（手工录入 / 系统运算）；参考营业额；预估营业额 = 参考营业额 × 默认安全用量。
- 手工：预估月份默认当前系统月份，可改；默认安全系数 1.1；单据体安全系数默认取单据头；统计天数可空；计算日期默认当天。
- 后台生成：默认已审核；安全用量为 1；数据来源写作「后天计算」（与字段说明「系统运算」不一致）。
- 参考营业额按定时服务每次计算的天数生成。勾选「是否按星期几类型来分类计算」则每日金额按各自星期类型分类；未勾选则总金额/总天数。该字段锁定。业务说明又写「预估营业额默认等于参考营业额，可修改」，与字段公式「参考营业额 × 默认安全用量」并列，原文未解释二者何时生效。

**食品万元销量表**（页面标题写作「食品万元用量表」）

- 历史食品销量要货的一种方式。对应日期有数据时，历史食品销量要货默认勾选按销售预测要货（原文「有相应日期的数据失」）。
- 万元用量 = 食品销售数量 / 总营业额 × 10000。
- 字段「营业额」的说明写作：预估营业额 = 营业额合计 / 天数。
- 数据来源：手工录入或系统运算。数据天数：计算历史多少天。
- 手工新增：营业组织默认当前登录组织，计算日期默认当前系统时间，币别默认人民币，统计天数可不填，万元销量手工录入，销售金额为历史销售金额。
- 明细按定时服务每次计算的天数生成；勾选按星期几则按星期类型分类；未勾选则按全部期间内所有销售的食品。页面在「所有销售的食品」处截断，没有后续句子。

**自定义食品万元销量**

- 万元销量字段说明：销售多少份 / 10000。与万元用量表「销售数量/总营业额×10000」不是同一句话。
- 某一行未设适用门店时，同一食品的其他行有效期可以重叠。单独设了适用门店后，同一门店、同一有效期、同一食品不可重复，保存校验。
- 分配到其他门店后，门店修改不同步创建组织；创建组织修改也不可同步已改过的门店。设了门店则只对该门店生效。同一食品既有指定门店又有适用所有时，默认取指定门店那条。
- 批量添加：每个门店可批量加到多个食品。提交审核前必须先保存。

**特殊事件**

- 用于历史食品销量要货计算日安全系数。类型为辅助资料，系统预置：天气、节假日、商圈活动、营销活动、定台、其他。影响值自定义。自动计算勾选则要货时自动算，不勾选则手工选类型再算。
- 基础资料受组织策略控制，创建组织维护后分配给使用组织。名称及影响值手工必填。
- 要货时自动获取有效期内且带自动计算标志的影响因子，先自动算安全系数。再手工点安全系数时，自动计算项默认选中且灰色不可改，其他因子选中后系数叠加。

**营销活动**

- 同样用于计算日安全系数。活动类型：单品促销、整体促销，必填。
- 单品促销影响值只对对应食品有效，须维护食品明细。整体促销对历史食品销量要货生成的所有食品有效。不维护食品明细时默认整体营销，所有食品营业额上浮或下浮。
- 行禁用后食品明细置灰；取消行禁用后可编辑。活动明细被禁用则食品明细子表同步禁用。
- 活动明细维护活动、有效期、对营业额的影响比例。基础资料为分配型。

**门店食品销售量预估**

- 历史食品销量要货点预估食品销量方案时跳到本列表，生成食品用量预估，用来计算要货和采购。
- 方案类别：普通、酒席。计划销售份数即计划销售数量。计划销售额 = 计划销售份数 × 食品单价。
- 选部门后，食品编码只过滤该部门下的食品。一个食品销量方案会取本资料的值。与历史食品销量要货业务说明一致：方案食品数量不参与营业额那套计算。

**预估与实际营业额对比表**

- 预估营业额：取对应日期的预估营业额。
- 实际营业额：取营收-财务记账单上的账单价税合计。
- 差异 = 实际营业额 − 预估营业额。

### 门店库存管理（中）`餐饮门店管理_门店库存管理.md`

概述：仓库管理、物料流转、库存控制；入库、出库、调拨、库存调整，加批号保质期、盘点、即时库存。流程图多张未 OCR（整体、采购、部门间调拨、分步式调拨、食品报损、餐饮盘点）。期末处理目录为空，没有子页面。

**启用与期初**

- 门店库存启用：只有组织属性为门店的组织可设启用日期。未关账时库存单据日期 ≥ 启用日期；初始库存入库日期必须小于启用日期。修改启用日期的条件：未结束初始化且即时库存无记录；审核更新库存的组织还要求不存在已保存的库存单据。
- 门店初始库存录入：期初数量 > 0。年初数量 = 期初数量 − 本年累计收入数量 + 本年累计发出数量。辅单位同样公式。货主或保管者至少一个等于本库存组织。保质期：输入生产日期可算有效期至，反方向不反算。审核更新即时库存。结束初始化时用初始库存更新期初余额表。已结束初始化的初始库存不允许反审核。
- 结束初始化：不允许存在未审核的初始库存。结束后初始库存不可反审核，并更新期初余额。
- 反初始化：已关账不允许；反初始化删除期初余额表。前提是当前组织已结束初始化。

**调拨**

- 部门间调拨单页的概述写成「调拨申请单」，支持组织内和跨组织。选单上游：加工入库单、生产用料清单、直接调拨单。下推：配送出库单、直接调拨单。同页业务说明描述的是直接调拨：一步式、不管理在途，同时扣调出可用、加调入可用；方向分普通和退货；组织内调拨库存组织与货主不变；跨组织可组织间结算。VMI 要求物料允许库存且勾选是否 VMI。
- 分步式调出单 / 分步式调入单：有在途需求。调出后在途不可用，调入确认后可用，调出数量和调入数量可以不同。调拨类型：组织内、跨组织。在途归属调出方或调入方，决定在途物权，并决定业务日期检查哪一侧关账、关账检查哪张单。调入单可录途损数量和途损责任方，途损冲减在途。同一核算体系下调出货主与调入货主的核算组织不同才产生结算清单。支持 VMI。选单上游含分布式调入单、调拨申请单；下推分布式调入单（原文「分布式/分步式」混用）。

**盘点**

- 盘点方案模板：临时盘点、日盘、周盘、月盘。物料上设日盘、周盘（每周第几天，1–7，且须勾选）、月盘（每月第几天，1–31，且须勾选）。启用自动计划后参与后台服务生成物料盘点作业表；临时盘点不可启动自动计划。可零库存参与、允许作业表手工加物料、禁用物料不参与、实盘数默认等于账存或默认 0、按盘点范围过滤、按分单规则生成多张作业表。
- 物料盘点作业列表：录入实盘，按账存与实存差异生成盘盈或盘亏。前提：库存组织已结束初始化。字段表（账存日期、来源、零库存参与盘点、账存/盘点/盘盈/盘亏数量、盘点误差% 等）说明列为空。业务说明标题下无正文。
- 盘盈单：来源含手工录入、定期盘点、周期盘点、餐饮盘点。盘盈数量 = 盘点数量 − 账存数量。手工时盘点数量 ≥ 0 且大于账存。保存或审核增加即时库存。由物料盘点作业生成的不允许反审核。分录不允许重复。
- 盘亏单：盘点数量 > 0 且小于账存。保存或审核减少即时库存。由作业生成的不允许反审核。字段说明让参考盘盈单。
- 参数：物料盘点作业表审核时可自动更新账存数量。盘点方案控制：盘点时是否检查食品销售清单已上传清机数据，以及是否可下推食品材料耗用单。检查盘点期间业务单据分三档：预警提示、不予控制、严格控制。

**即时库存与用量差异**

- 门店即时库存监控报告（标题又写作「门店即可库存监控报告」）：库存量、未消减耗用量（已下推未审核的食品材料耗用单数量）、实际库存数量 = 库存量 − 未消减耗用量。
- 即时库存校对：只对已结束初始化的组织。已关账：即时库存 = 期初库存 +（上次关账至今）入库 −（上次关账至今）出库。未关账：即时库存 = 结束初始化的期初库存 +（启用日期至今）入库 −（启用日期至今）出库。当前日期小于启用日期或上次关账日期则不校对。可指定物料。目录中的「即时库存」没有独立页面。
- 库存用量差异报告：期初库存 = 起始日前最近一次关账实际结存 + 关账日到起始日入库 − 同期出库。本期收入不含盘盈，本期发出不含盘亏。理论结存 = 期初 + 收入 − 发出。实际结存 = 期初 + 收入 − 发出 + 盘盈 − 盘亏。实际用量 = 期初 + 收入 − 结存。理论用量 = 查询期内食品销售清单展开的物料数量。差异 = 实际用量 − 理论用量。金额 = 最新入库价 × 数量。实际用量单据范围：生产领料单、简单生产领料单、其它出库单、分布式调出单、食品材料耗用单、报损出库、盘亏单、直接调拨单。另有一句：实际耗用等于其他所有出库单据数量 − 盘盈单数量。期初单价来源：期初加权平均价、最新入库成本价、最新出库成本价、期末加权平均。收入发出单价来源：成本价、组织间结算价、期初单价来源。

**采购入库、退货与要货执行**

- 门店采购入库单：确认入库及所有权转移。保存或审核更新即时库存（由库存更新方式决定），按实收数量，携带批号、保质期、仓库、仓位等。关联收料单时还扣减收料库存。可下推退料单，条件为已审核且实收数量大于退料关联数量；合并条件：供应商、收料组织、采购组织、货主、结算组织、结算币别相同；退料类型只能是库存退货；数量不能大于实收与退料关联数量之差。支持保质期检查、批号、查询采购费用（费用应付单）、委外倒冲领料。成本价由存货核算反写。
- 门店采购退货单：检验或生产发现不合格退供应商。实退数量更新库存。可下推采购订单，数量不能大于补料数量 − 关联数量；合并条件：供应商、退料组织、采购组织、结算币别相同。
- 门店采购入库单与应付单差异表：看已审核入库单哪些没下推应付。差异数量 = 入库数量 − 应付数量；差异单价 = 入库单价 − 应付单价；差异金额原文写「入库金额 − 差异金额」（自指，公式不成立）。
- 门店要货执行情况表：要货组织、物料、是否直拨、是否统配、加工车间（自制物料可在要货申请汇总设加工车间）、要货数量（申请数量）、批准数量（要货申请汇总）、收货数量（门店收货单应收数量）、剩余收货数量 = 配送出库单发货数量 − 门店收货单实收数量、异常数量 = 应收数量 − 实收数量、退货数量。
- 收/退货统计：金额 = 配送价 × 数量；成本金额 = 结算币别入库成本价 × 数量。入/退库统计：金额 = 入库金额总和 − 退货金额和。明细表有计价数量、含税单价、成本价由存货核算反写。采购入库汇总表（按供应商）几乎只有「进仓 = 物料分组」。

**餐饮耗用（行业专用，见第 4 节）**

- 食品销售清单：数据交换销售报数、食品销售清单接口、POS 账单接口可自动生成，也可手工。单据类型：食品销售清单、员工餐清单。类型：正常单、取消单。数据来源：POS 账单生成、接口生成、POS 上传、手工录入。是销量预测计算助手的原始数据。下推食品材料耗用单。正数合并为正常单，负数合并为取消单；招待、出品取消仍按正常单。无默认成本卡且食品由物料转来时，销售数量即物料用量。支持委托扣库（销售-扣库 / 受托扣库）。
- 食品材料耗用单：单据类型分食品材料耗用单、员工餐耗用单。库存方向：普通、退货。选单上游：食品报损单、食品销售清单、物料清单、简单生产入库单。可勾选不参与成本核算。扣减方式参数：按库存可用量（默认，不足时按生成当时的即时库存可用量，并走替代料）或按标准用量（按成本卡标准用量，不足则扣减失败）。取消单生成退货方向并退回库存，若当天扣过替代料则优先退替代料。支持保质期拣货。即时生成日志：勾选即时生成后，销售清单生成（手工录入导入除外）进日志，多线程生成，日志不可手工增删。生成方案可限定近几天，不超过 30 天。
- 食品报损单：质量问题或点餐做好后退单。审核后按部门分单生成食品材料耗用单，按成本卡 + 规格成本比率 + 口味要求成本卡展开，主料不足取替代料。
- 报损出库单：配送到店后因质量或其他原因不能使用。选单上游字段写采购入库单、配送退货单、其他入库单；业务说明写其他入库单、外购入库单、销售退货单，且均须已审核。更新库存规则与入库单对称（减少库存）。支持保质期、批号。

**收发报表**

- 餐饮物料收发汇总表：一段时间期初、收入、发出、结存，按库存组织 + 货主类型 + 货主分页，数据来自各库存单据。期初数量算法与关账/启用日期衔接，同差异报告的期初思路。期初单价来源四种：最新入库价、最新出库价、期初加权平均价、期末加权平均价，并写了本位币换算（原币单价 × 汇率）。收入/发出单价可选「同期初单价」或「库存单据成本价」。
- 餐饮物料收发明细表：期初、收入、发出、结存明细，字段说明让参考汇总表。
- 餐饮物料收发日报表：概述写统计各种业务类型汇总且只统计数量不统计金额（标题是日报，概述又写汇总表）。可按库存组织或货主分页，可隐藏无发生数量。

**库存参数其余项**

- 食品材料耗用单生成方式：勾选即时生成则 POS 账单生成的销售清单或接口上传的销售清单自动生成耗用单。
- 食品材料耗用单扣减库存方式：按库存可用量、按标准用量。

### 门店外卖管理（低）`餐饮门店管理_门店外卖管理.md`

- 两部分：外卖账单对账、外卖订单对账。平台只有美团、饿了么。账单：美团支持新增、导入；饿了么支持新增、导入、下载。订单：美团和饿了么只支持导入和下载。
- 订单对账步骤：收款账户设置 → 对账字段配置 → 外卖对账参数 → 下载外卖订单 → POS 账单 → 外卖对账工作台-订单。账单对账步骤类似，终点原文写作「外卖账单工作台_订单」。
- 对账工作台支持多组织、多日期。点对账按条件匹配并生成已审核对账记录。差异状态五种：无差异已审核、有差异未审核、有差异已审核、无差异未审核、未对账。差异对账金额 = 平台外卖订单金额 − 门店 POS 外卖金额。确认对账金额 = 已审核对账记录的确认对账金额总和。
- 对账记录：确认对账金额、自动对账金额（默认可改）、订单流水号、平台单号、POS 单号、两侧结算金额、差异有/无、差异说明（缺少 POS 账单或缺少外卖账单）。账单侧页面标题为「对卖对账记录单-账单」，概述仍称外卖账单对账记录单，字段与订单记录几乎相同。
- 原始单：外卖订单-美团、外卖订单-饿了么（平台单号唯一；外卖账户取结算方式为美团或饿了么的收款账户）、外卖账单-美团（页面标题写成「外卖账单-美图」；订单号是结算流水号）、外卖账单-饿了么（入账日期通常 T+3，结算金额为客户实际付款）。下载日志只说明后台按执行计划自动下载，无字段表。
- 参数：外卖账单对账是否关联外卖订单对账差异数据（默认不勾，勾选则账单对账取订单对账调整后的数据）；POS 账单金额为 0 是否不参与对账。参数界面为图，未 OCR。
- 收款账户、对账字段配置的正文在营业对账文件，本模块只链接。

### 门店营业对账（低）`餐饮门店管理_门店营业对账.md`

- 两大块：现金对账；微信与支付宝线上对账。现金：门店把当天或若干天现金存银行，在云之家录入门店缴款单，总部在门店现金存款查询看缴款凭证。线上：微信/支付宝原始流水与数据交换或第三方接口上传的 POS 账单对账，分自动和手工；对上的生成对账记录，没对上的可以生成 POS 差异账单调整单（该调整单无字段页）。
- 线上步骤：营业对账系统参数 → 收款账户设置 → 对账字段配置 → 下载微信/支付宝交易账单 → 上传 POS 账单 → 交易对账工作台 → 交易对账记录单。自动对账条件在操作流程页写为结算方式、金额、流水号。成功后生成创建状态的对账记录，再提交审核；结果不对可取消对账重勾。
- 交易对账工作台：按门店和时间查出数据，勾选后点对账。结算方式名称包括微信和支付宝。差异对账金额 = 前台 POS 与第三方流水之差。有差异时确认对账金额默认等于第三方交易流水账单金额。差异状态：差异未审核、无差异已审核、有差异已审核、未对账、无差异未审核。支持差异数据批量赋值。
- 微信交易账单、支付宝交易账单：新增、接口上传、导入。微信可按多个收款账户同一日期下载。字段含订单号、商户订单号、退款、手续费/服务费、优惠、费率等，属支付渠道流水，不是物料单据。
- 收款账户设置：同时服务营业对账和外卖。结算方式含微信支付、支付宝、美团、饿了么、线上支付宝、微信。可定时下载。一个账户可绑多个门店，多个门店可共用一个账户，不同支付平台也可共用账户。微信/支付宝用账户标识、秘钥、账单服务器地址、到账间隔（微信/支付宝 1 天，美团/饿了么默认 3 天）、原始单字段/区分方式/区分条件做门店分单，可设子账户。美团/饿了么还可设第三方中台（餐行键、智龙）、中台标识和服务器、外卖平台地址、外卖订单到账间隔、第三方平台门店 id。账户标识和秘钥由企业把参数交给金蝶云餐饮配置后回传。账号类型：金蝶子商户、第三方子商户、直连（自有微信/支付宝）。
- 对账字段配置：预置美团、饿了么、微信、支付宝四套，配置原始账单字段与 POS 账单字段的对应，可改。
- 交易流水下载定时任务日志：收款账户、执行时间、交易日期、成功/失败及失败原因。须在收款账户勾选定时下载。
- 系统参数：门店 POS 账单笔数或门店 POS 营业金额为空时是否允许对账。不勾选则不允许。原文「营业余额」与「营业金额」混用。
- 门店收银状况一览表：各支付方式收款，支持多门店、时间段、工作站，以及本月/上月/昨天/去年/今天。数据由前端营业后经数据交换上传。字段只写了转更状态（已转更/未转更）、操作员、现金充值、现金短缺（现金抹零），且「1.2 字段说明」重复一次。其余支付方式无字段。
- 门店现金存款查询：八步操作，配图未 OCR。涉及金蝶食神注册（shishen.kingdee.com）、商户编码、云之家门店缴款、上传缴款凭证。

### 门店营业分析（低）`餐饮门店管理_门店营业分析.md`

餐饮营业报表，从账单、食品、员工、房台、收银出数。使用前提几乎都是：已有营业数据，并经门店数据交换或门店日结上传。汇总报表可穿透明细；可用分组依据做自定义分组并保存方案。多组织可共享模板或隔离编制。部分汇总要先做报表数据清洗。图片均未 OCR。

目录九组：

- 营业报表：营业汇总报表、营业明细报表、清机交班报表、长短款查询、时段营业额报告、营业状况一览表。
- 账单明细：账单查询、账单食品明细查询、账单结算明细查询、账单上传异常数据。
- 食品类别：食品类别营业汇总/明细。
- 食品：销售明细静态、销售汇总、销售明细、销售排行、取消汇总/明细、赠送汇总/明细、套餐销售汇总/明细。
- 房台：房台营业汇总报表。
- 绩效：服务员业绩汇总/明细。
- 财务：收银员汇总/明细。
- 财务集成：营业账单定时处理任务、营业与财务对账单列表、营收-财务记账单、POS 账单、营收-财务对账工作台、卡充值单、POS 账单-食品销售清单报表。
- 门店定金管理。

可核对的数量关系（多张报表重复）：销售数量 = 下单数量 − 取消数量；销售金额 = 下单金额 − 取消金额；净售数量 = 销售数量 − 招待数量（部分表用赠送数量）；净售金额 = 销售金额 − 招待金额（套餐表写成再减优惠）；食品净额金额 = 下单金额 − 取消金额 − 招待金额；收入净额 = 实收金额 − 找赎；人均消费 = 收入净额 / 人数，人数为 0 则为 0；客付金额（换算）= 客付金额（原币）× 汇率；结算金额 = 客付金额（换算）− 找赎。礼券折扣是实际可抵金额，礼券面额是券面。食品进位差、账单进位差由金额小数不等于 2 位产生，账单进位差公式在原文中自引用，未给出可执行定义。

时段与渠道拆分：时段营业额报告按小时，含 TC 百分比 = 时段内账单次数 / 总账单数，堂食 TC = 账单数 − 外卖 TC − 外带 TC。营业状况一览表写死早市 05:00–10:30、午市 10:30–15:00、晚市 15:00–05:00，并拆堂食/外卖/外带；长短金额 = 清点金额与系统账单金额的差额。午市营业额、晚市营业额的字段说明写成「账单数量」，与「金额之和」不一致。

长短款查询：正数少收，负数多收。清机交班报表含部门出品、结算方式、会员存款/消费、盲交、预付订金、渠道来源；并写明 POS 清机上传后要用金蝶 AI 星空客户端才能看。营业汇总报表写明须经过报表数据清洗；双击按组织+营业日期打开明细。食品销售明细静态报表也要先清洗。食品销售汇总可双击按组织+食品打开明细。

财务集成：营收-财务对账工作台比较营业汇总与财务记账的账单数、金额，差异状态有/无，可补录记账数据。营收-财务记账单有账单价税合计、服务费价税合计、税额、不含税金额；销售预测的「实际营业额」即取这里的账单价税合计。营业与财务对账单列表展示收入、原单、发票、食品净售、进位差、服务费、渠道、结算方式。营业账单定时处理任务用于数据与日结小票不一致时重新生成营业账单。账单上传异常数据记录 POS 账单上传失败的食品编号和异常信息。卡充值单只列收款组织、结算方式、金额。POS 账单及食品销售清单报表是上传后的账单查询，账单类型示例为外卖、堂食。

门店定金管理：预付定金的客户、操作时间、预计使用时间、定金金额；概述还提到已退金额、已用金额，字段表未列这两项。需开启订金选项，在收银界面录入并上传。

收银员汇总报表的功能概述与明细报表相同，未另写汇总口径。

### 门店营业设置（低）`餐饮门店管理_门店营业设置.md`

门店数据管理是 POS 端基础：营业基础资料、食品管理、房台、门店权限、营业日志。支持单体组织共享和多组织控制策略分配。POS 功能列举：开台、点菜、厨房、折扣、结账、付款、转更、清机，适用于酒楼、快餐。开台、点菜、结账等操作页只有链接，没有正文。

## 3. 可复用机制（面向电子元器件 ERP）

- 历史要货同期补货：按最近一天、上周同星期、上月同日、上年同日、固定日，取要货申请的物料和数量生成预估要货，并可按物料分组过滤、生成明细或汇总。多维度如何合成没有公式。相关度 **高**（`餐饮门店管理_门店订货预估.md`）。
- 预估单到执行单：物料预估要货单审核后，配送属性自动或手工下推要货申请，自采属性在采购申请、采购订单、采购入库中三选一或不生成。相同单据类型可合并成一张下游。取整：进位、四舍五入、舍位。相关度 **高**。
- 净需求字段位：预估数量旁边有现有库存、安全库存、最小库存、净需求。净需求「通过参数设置公式计算」，公式未给出，不能当成已定义的补货公式。相关度 **高**（字段模型），公式本身是缺口。
- 配送/自采双路径：物料餐饮属性「智能要补货控制」决定下游；要货申请再用直拨/统配限制单据类型，标准要货不受限。对应分仓配送与网点自购。相关度 **高**（`餐饮门店管理_门店订货预估.md`、`餐饮门店管理_门店订货管理.md`）。
- 销售预测驱动要货：计算助手按预测区间、参考天数、可选按星期、可扣期初天数，生成预估营业额和万元用量表；历史食品销量要货在两者有数时自动走预测。基准：历史日均 = 历史总额/天数；未按星期时参考营业额 = 总金额/总天数；按星期则分星期类型。预估销售量 =（预估营业额 × 万元用量）/ 10000，或 = 日均销售份数 × 要货天数。要货天数来自配送路线订货周期，缺省 1。安全系数默认 1，手工预估营业额的默认安全系数/安全用量为 1.1，后台为 1；系数 = 1 + 影响值之和；预估销售份数 = 安全系数 × 原预估销售份数。相关度 **高**（把「营业额/菜品」换成「销售额/SKU」后，结构可复用）。源：`餐饮门店管理_门店销售预测.md`。
- 影响因子：特殊事件（天气、节假日、商圈、营销、定台、其他）与营销活动（整单比例 vs 单品只调指定物料）分开。自动计算项锁定，手工项叠加。单品活动不进总系数，改该品预估销售额再重算数量。相关度 **高**（促销、节假日、异常事件对预测的修正）。
- 预测与实际对比：差异 = 实际 − 预估；实际取财务记账单价税合计。相关度 **高**（`餐饮门店管理_门店销售预测.md`，实际值来源在 `餐饮门店管理_门店营业分析.md` 的营收-财务记账单）。
- 参考店复制：新店或无营业数据的组织可单选一个参考组织的历史销量；本组织已有数据时须确认。方案食品（计划份数）与模型食品分开，方案数量不参加模型计算。相关度 **中**（新品/新仓冷启动），输入仍是食品销售清单。
- BOM 式展开要货：预估销售数量经配方只展开勾了「订货」的子项；无默认配方且成品由物料转来时，成品数量即物料用量。相关度 **高**（成品预测 → 原料/组件净需求），配方载体在原文是食品成本卡。
- 周期要货与预测脱钩：门店周期要货只用手工预估营业额，不用计算助手结果，并要求盘盈、盘亏、耗用至少一种有历史。相关度 **中**。算法句子不完整。
- 要货申请合并与汇总：同类型、同配送组织、同需求组织、无源单的创建态申请可合并；已审核申请按物料、配送组织、到货日期分组下推汇总单，并反写关联数量、汇总数量。相关度 **高**（多网点要货汇总统配）。
- 要货执行跟踪：要货数量、批准数量、收货应收、剩余收货 = 配送出库发货 − 实收、异常 = 应收 − 实收、退货数量、直拨/统配、加工车间。相关度 **高**（`餐饮门店管理_门店库存管理.md`）。收货单、配送出库单、汇总单的单据正文不在本领域或缺失。
- 要货时间窗：允许提交时段，超过截止后不可反审核、不可取消。相关度 **高**。
- 收货财务与异常：收货审核按参数生成创建/审核中/已审核应付；异常数量生成异常通知单；退货审核可生成配送退货单和补货要货。退货方式含补货、扣款、不退货只扣款。相关度 **高**。异常通知单无页面。
- 订货模板：总部分配到门店，要货时引出导入。相关度 **中**。无字段。
- 渠道资金池：储值余额 + 信用剩余 = 总余额；要货等业务在流水里体现冻结、取消冻结、扣减、退还、充值。信用初始化与调整（调整须再生效，调整后额度有下限）。充值下推收付款，提现只动储值、审核即扣、下推后才打款。提现次数、单次上下限、付款组织、使用组织。相关度 **高**（分销商订货账户，不是会员积分）。支付通道在原文是微信/支付宝。
- 移动要货门户：按用户-部门-部门仓库隔离；价格与图片开关；在线支付必须先显示价格；公告和广告按组织发布。相关度 **中**（分销商门户的信息架构；界面是餐饮移动订货）。
- 库存启用、期初与关账：门店属性才可设启用日；年初数量 = 期初 − 本年收入 + 本年发出；结束初始化锁期初并写期初余额；已关账不可反初始化。相关度 **高**（分仓上线）。
- 即时库存重算：关账后从上次关账期初加出入库；未关账从启用日期期初加出入库。相关度 **高**。
- 一步调拨与分步在途：直接调拨同时改双方可用量；分步调出形成在途，归属决定物权和关账检查侧，调入可记途损并冲在途；跨货主核算组织不同才组织间结算。相关度 **高**（分仓调拨、在途、途损）。
- 周期盘点：日/周/月/临时，物料级盘点日，后台自动生成作业，分单规则，零库存与禁用料开关，实盘默认账存或 0；盘盈盘亏调账且作业生成的单不可反审核。相关度 **高**。作业字段说明为空。
- 理论用量 vs 实际用量：理论用量由销售清单按配方展开；实际用量 = 期初 + 收入 − 结存；差异 = 实际 − 理论；单价来源可配。相关度 **中**（配方倒冲与实耗差异对元器件委外/组装有用，原文驱动单据是食品销售清单）。
- 批号、保质期、生产日期、有效期至贯穿入库、退货、报损、初始库存、耗用拣货。相关度 **中**（元器件批次与有效期），大量规则写「同收料单/外购直拨单」而那些规则不在本领域正文。
- 入库与应付差异：数量、单价、金额差；已审核入库是否已下推应付。相关度 **中**。差异金额公式在原文中自相减，不能当算法。
- 替代料与按可用量扣减：主料不足扣替代料，取消则优先退替代料；另一参数改为按标准用量、不足即失败。相关度 **中**（缺料替代），触发器是菜品销售。
- 委托扣库：组织业务关系决定发料组织与仓库（未委托则出品组织+部门仓库；已委托且仓库有对应组织则取对应仓库；已委托但仓库无对应组织则发料组织的物料默认仓库，无仓库不许下推）。相关度 **中**（跨组织发料）。
- 对账字段映射 + 自动匹配：平台流水与内部账单按可配置字段匹配，多组织多日期，差异五态，确认金额可改，有差异时营业对账默认确认金额取第三方。0 金额可排除。账单对账可改取订单对账调整后的数。相关度 **中**（渠道结算对账的骨架）。落地对象是美团、饿了么、微信、支付宝、POS，见第 4 节。
- 收款账户分单：一账户多门店，用原始单字段和区分条件把流水拆到门店；到账间隔；定时下载与失败日志。相关度 **中**（平台资金账户与门店归属）。
- 经营指标逐级分解：集团年度 → 门店 → 部门 → 部门月度，用来和实际营收比。相关度 **中**。无指标项、无分解公式，列表页几乎只有图（`餐饮门店管理_门店营业设置.md`）。
- 主数据下发与一致性监控：分配型基础资料；数据交换条数/金额不一致标红并指令重传；上传异常清单。相关度 **中**（门店/渠道主数据与交易上传），监控对象是 POS 账单。
- 报餐日历与配额：日期类型控制能否报量；餐次人数未设则保存失败；标准指标、上周同星期参考、当前预估并列；超出占比可控制；计划可生成预估要货。相关度 **低**（对象是食堂餐次和菜品）。若只抽「日历开关 + 配额 + 参考同期 + 计划转需求」，相关度可视为 **中**，原文没有抽象成通用计划单据。

## 4. 不宜照搬 / 行业专用

本期/二期不必把下列能力做成电子元器件 ERP 的功能。它们绑定堂食、菜品、外卖平台或食堂，抽机制即可，不要搬单据和字段。

- 食神 POS：开台、点菜、转台、清机、转更、厨显、出品单、印机、咨客、房台状态（空台/脏台/坏台）、楼层、服务费、房费、最低消费、口味加价、酒席套餐、称重食品、时价菜、棋牌计时、快餐/酒楼/火锅组别、O2O 菜品发布、点菜笔、iPad 显示。相关度 **低**（`餐饮门店管理_门店营业设置.md`）。
- 营业分析全套菜品/房台/收银员/服务员提成报表，早午晚市写死时段，堂食/外卖/外带 TC，礼券、找赎、盲交、会员存款消费。相关度 **低**（`餐饮门店管理_门店营业分析.md`）。电子元器件不需要上座率、人均消费、出品取消。
- 微信、支付宝、通联、金蝶金融、云之家缴款、金蝶食神商户号这一套门店收银对账。支付流水对账骨架可另做，不要按餐饮 POS 账单实施（`餐饮门店管理_门店营业对账.md`）。相关度 **低**。
- 食品销售清单、食品成本卡、口味成本卡、规格成本比率、食品材料耗用单、员工餐耗用单、食品报损单、扣炖量。这是菜品售卖倒冲食材，不是元器件工单领料。相关度 **低**。理论与实际用量差异若要做，应接 BOM 和销售出库，而不是这套单据。

- 万元用量、千元用量、食品销售份数、方案类别「酒席」是餐饮销量单位。复用时应改成 SKU 销量或金额占比，不要保留「万元菜品份数」。
