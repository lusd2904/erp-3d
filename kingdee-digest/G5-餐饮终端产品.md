## 1. 功能点

### 1.1 云店通（`餐饮终端产品_云店通.md`）

轻餐，分 Android 与 Windows。正餐 Android 只有目录链接，本文件没有该页。正餐 Windows 页只有标题「云店通正餐Windows」，原文几乎为空。

- 定位：食神云店通用于轻餐饮。模块：前台点餐、收银管理、订单管理、快速营销、门店后台。Android 跑在安卓 POS 上，依赖金蝶 AI 星空 Cloud、食神 CRM、食神商户平台；环境准备写 V7.5。Windows（云店通 vue）同样依赖这三套系统，环境准备写 V7.6。
- 系统配置：商户平台 `http://shishen.kingdee.com/portal/` 注册；设备特征码（SN）由金蝶运维/食神实施绑定到商户；AppID、AppSecret 绑到 Cloud【基础管理】—【公共设置】—【金蝶食神开发者参数配置】。基本配置填在线平台地址 `http://shishen.kingdee.com/`、AppID、密钥。Cloud 参数配置填 Cloud 地址、用户名、密码。要用微信点餐（Windows 页写微信点餐和会员），再配【线上点餐参数配置】和【线上会员参数配置】，接口地址同上，客户端 ID、密钥来自 CRM【系统设置】—【开发者信息】。
- 设备绑定：商户平台【设备管理】可见设备名称、序列号。POS 首次登录绑定所在门店，设备名称可自定义或自动生成；Android 写加载当前用户对应的组织，Windows 写显示用户下面的组织。
- 主数据在 Cloud 维护后发布到商户平台，供设备使用：组织机构、用户、角色、营业设置、取消原因、食品大类、食品、口味要求、门店权限项、结算方式。用户有「最大折扣率」（单个食品或整单）。营业设置含门店类型、营业日期、服务费类型、费率、税率，以及抹零规则、取餐号规则；一个组织只能一条，可新建、修改、发布、禁用。取消原因：勾选「出品取消」时，退单不更新食品库存。食品勾选「折扣率」和「全单折」才可参与打折。口味要求可做整单常用备注；Windows 另注「口味加、乘计价」，计价规则无文字。结算方式须先发布 O2O，微信点餐账单才能推送。折扣率/常用默认项：单个食品和整单的折扣率；Windows 写默认项折扣率超出用户最大折扣率时，不允许在 POS 展示。
- 小票（Android，商户平台→设备管理→小票设置）：多个方案不可以含有共同门店。可定制商家 logo、小票下方二维码（开票二维码与其他二维码二选一）、最下方欢迎语。副屏：不点单轮播大图，点单时半边是点单收款、半边是小图（Windows 前台写不下单时副屏全屏图片）。
- Android 前台：按食品大类点菜，暂存到点餐列表；可设口味、折扣、是否赠送、整单备注和整单折扣。闪结用于现金快速结账。口味可多选，可一键清除。单品折扣不能超出该用户最大折扣率，折率值由常用默认项控制，超过最大折扣率的值不显示。
- 订单：接收、处理、展示第三方订单，主要支持微信点餐、口碑点餐、外卖订单。微信账单推到云店通前，CRM 要设推送，且结算方式已发布 O2O。
- 收银记录：本机订单，支持退单、重印、查看详情。微信支付超时可刷新顾客支付状态；未输入支付密码时刷新会提示输入。
- 营销方案：门店端快速入口，支持打折、满减、满送、买送。客户折扣优惠方案：某个商品或类别打折；某个商品或类别不参与；特定蛋糕类别参与、其他类别不参与。满减、满送、买送的门槛和赠品规则无文字。
- 沽清（Windows 前台称售罄）：售卖状态可售/沽清；可为单个商品设库存量，降到 0 自动沽清。另有「云店通前台对微信点餐商品的沽清」和「微信点餐获取云店通菜品库存」，库存（扣炖量）控制写在 CRM，界面在图中。
- 会员：查会员、查余额；充值支持现金、微信、支付宝；支持激活、禁用、退订会员卡；云店通开卡后可在对应 Cloud 看到该会员。积分规则无文字。
- 班次：可看当前班次/当前营业日。Android「更多」做交班/日结、开钱箱。Windows 把日结、交班分成两项，并可切换小屏/全屏。设置项含门店绑定状态、当前营业日期、打印、电子秤、收银、抹零、取餐（Windows 设置文案未写抹零与取餐的先后，两项都有）。
- 系统日志上传：用于分析问题，无字段。
- 云店通助手轻应用：数据来自云店通数据中心，用户来自商户平台；用星空云 ERP 用户手机号、密码登录，默认密码为手机号后 6 位，可在商户平台用「忘记密码」修改。《日结报表》：营业数据实时查、单店与所有门店、监控各门店异常数据、付款方式占比。《门店销售排行》：连锁门店销售 top5 及占比，各门店本期、同期及增长率。《商品销售排行》：单店或连锁的商品销售排行及占比。指标口径无文字。

### 1.2 前台 POS（`餐饮终端产品_前台POS.md`，两段 chunk 合全文）

手册名「金蝶 AI 星空食神餐饮 POS 用户手册」，版本写 V7.3。模块：前台管理、收银管理、门店后台管理、出品监控。最低配置为 Windows 2000、SQL Server 2005，属原文环境表，不作为本期技术要求。

房台颜色（默认）：白色空台可开台；浅黄色预订台可看预订；橘黄色酒席预订台可看酒席预订；蓝色已开台可点菜、取消、厨房、结账、转房、查单、账单、折扣；粉色结账台做收银；红色结账超时台做收银。

- 点菜：按食品大类、组点菜，可设口味和顾客位置。按钮：加份、减份、取消全部、清除当前食品或口味要求、口味、要求、食品单位、位置、先送（成功后变红）、数量、查看、送单（传菜至相应部门）。
- 取消：可退回或取消，取消行以红色字体显示在列表最后一行；数量大于 1 时输入取消数量并选取消原因，生成红色对冲记录。另有招待、改数量、改价钱；不可招待、不可改数量、不可改价钱时弹出提示。
- 折扣：全单折，应付金额 = 食品总价 × 全单折；折扣率，应付金额 = 食品总价 ×（1 − 折扣率）；折扣价，应付金额 = 食品总价 − 折扣价；服务费可收可不收；会员按会员折扣率；大类折扣按大类、分部门打折，该员工要有相应部门的最大打折率。
- 结账：可不分账直接结账，生成结账单，房台变粉红色。分账时为食品分配坐位号，再按 AA 帐输入坐位号生成结账单。
- 厨房：叫起（暂不做，显示「*」）、全叫起、起菜、全起菜、追单（催某一道，次数显示 1、2…）、追台（催全部已点菜）。
- 转房：输入转入房台号。空台则提示是否开台；已开台则并台。消费随房台转走。
- 账单：分单按钮为「1」（一次一份）、「数量」、「一项」（不论份数全部送走）。复制是把一个房台的菜复制到另一个房台，按钮有一项、全部、修改、全修改、取消、全取消，确认后送单。分单页的「功能简介」原文抄了转房的句子，见第 5 节。
- 收银账单：未付款账单为绿色字。付款方式：现金、刷卡、签单、储值卡、积分代金券（输入客付金额后确定，再「埋脚」打印收款单）、挂帐（选合约编号和签单人）、会员消费（刷会员卡）。付款后房台恢复空台（白色）。
- 转更：统计本班次收入并打印汇总；可重印。清机：营业结束后统计一天数据、打印清机报表，营业日期调到第二天；可印分层单。签离退出收银。找赎按客付金额算应找金额。寻找按账单号定位并跳到账单页。
- 会员：按会员卡号/编号或刷卡查询；会员存款可输入金额并选赠送方式。
- 收银报表（第 6、7 节正文相同）：清机报表、员工取消、取消账单、食品暂停、员工分单、食品销售、会员资料、重印资料、暂时单。
- 账单解锁：结账时账单会锁死。路径为账单→异常账单→解锁。Cloud 选项 `OptHaveAbnormalBill` 设为 1、`OptCustomDisc` 设为 1，再做数据交换（原文写 could）。
- 后台登录预置用户，密码等于用户名：系统管理员 ADM、B 账用户 AB、前台管理员 88888、后台管理员 99999。主界面模块名：系统管理、食品管理、房台管理、权限管理、账单管理、其它管理、报表管理、供应链管理、客户管理、预订管理。后三个模块在本文件没有操作页。
- 营业设置：设分店公司编号、是否连锁、公司名称、服务费率、帐单、食品价格、每日应清机时间。本页「功能简介」原文抄了收银未付款账单的句子。同文另有「图需修改」副本，正文相同。选项配置、数据整理、工作站配置同样各有一份「图需修改」副本。
- 选项配置：按名称、备注、代号查找，可修改、取消修改、刷新。说明是「配置前后台的工作设置」，选项清单不在文字里。
- 数据整理：清空营业数据前在输入框输入 `DATACLEAN` 确认，再执行清空；另可清除出品单。
- 工作站配置：删除、修改、取消。用途是看某台机器做什么、在什么位置。字段无清单。
- 出品监控：蓝色图标表示该房台有菜未上，橙色表示全部已上或没有要上的菜。未上菜操作：全上菜、分量上（数量不能大于总数量）、催菜、暂停（停止销售且变红）、恢复、返回。已上菜操作：全取消、取消部分；该页「暂停」「恢复」的按钮说明与按钮名对不上，见第 5 节。
- 咨客：公司简介、厅房介绍（最多九个厅房）、近期推介食品、礼品信息、其他图片、退出。排位管理：员工操作是排队叫号，路径〖排位管理〗→〖员工操作〗，输入员工编号和密码；客人操作是自助取号，前提是已添加排位类型。
- 数据交换：先在总部启动服务端，门店后台连锁认证成功后，再启动客户端。服务端只配侦听 IP 与端口。客户端下载总部基础设置、食品资料、房台资料、会员关系管理；上传分店账单信息和 POS 操作日志。任务可设名称、发生频率、持续时间；树节点可单独启动或关闭调度。

附录术语（与前台按钮对应，多出前台按钮页未写的项）：来得/全来得（叫起之后可以上菜）、免做/全免做（厨房已出品，补单不再做）、外卖、整单加快、更次（第几班）、客付、总价、小账（客付 − 总价）、消单、扣炖（限量，如 10/20 表示剩余/总供应）、时价、价钱 1/2/3（三个时段）、埋脚（确定付款方式并已付款，打印确认收款单）。出品沽清：该项食品卖完后显示沽清。

附录印单：点菜送单后厨房、传菜部打总单，档口打出品单（一种菜一张）。取消打取消总单和取消单，印单上有取消原因（举例「出品沽清」）。另有分单、转房单、叫起总单/叫起单、来得总单/来得单、追单总单/追单、追台总单/追台单。印单上的房台人数、印机号、操作员、时间是举例，不是字段字典。

### 1.3 微信点餐（`餐饮终端产品_微信点餐.md`）

单页「新版微信点餐」。

- B 端：前台 POS（收订单、收款、同意退款）、移动 POS（收订单、收款）、CRM（建商户、菜品上下架、会员卡、生成二维码）。C 端：微信公众号（原文写 android，iso）用于点餐、提交订单、付款、申请退款。
- 关系：客户关注公众号或扫码提交订单，商户看点了哪些菜；客户可再次扫码、进公众号或到前台结款；微信支付后客户申请退款，商户审批，同意则退回。
- 架构文字：C 端选项由 B 端 CRM 控制；B 端 POS 选项由 Cloud 控制（原文 could），POS 部分接口调用 CRM，中间层属于门店端同时也控制 C 端，POS 数据库在本地 PC；CRM 专门控制 C 端微信点餐。三张架构图未 OCR。
- 「新版 CRM 参数选项说明」写：红框内选项对新版微信不再控制，红框以外都可控制。红框内容在图中，被排除的选项名称未知。
- 前台按钮：选项配置把 `OptKDOTOInterface`、`OptO2OListExportFunc`、`OptO2OListExportNew` 设为 1，`OptKDOTOBListExopt` 设为 0，保存分配；再到综合服务—数据交换—执行选项任务。之后前台 POS 出现微信点餐按钮。
- 餐前支付：系统设置—参数设置勾选「微信餐前支付」。可预订点餐，不必扫二维码，选好菜后提交。原文写「支付后，餐后支付会出现一个取餐码」（句子出现在餐前支付节）。前台微信按钮中，已支付订单为红色。确认订单时可选择或输入房台号开台。原文注：餐前支付即使扫了桌台码也不会自动开房台，只能确认订单后手动开房台。
- 餐后支付：勾选「微信餐后支付」。须扫二维码才能提交；另一种入口右下角为「到店扫码」，选菜后扫入房台再提交。门店信息—对应门店—二维码管理—普通类型，输入桌台号码生成桌台码。扫入桌台码后前台直接开台。结账两条路：前台结账埋脚；或微信餐后支付，付完房台清台，恢复未开台。扫码支付步骤在三张图里。

### 1.5 移动 POS（`餐饮终端产品_移动POS.md`）

手册名「餐饮移动 POS 用户手册」。业务模式：中餐（酒楼）、快餐、纯收银。运行在安卓设备，依赖门店 POS、门店端数据库、门店中间层服务。设备举例：安卓手机、安卓平板、旺 POS、拉卡拉、新大陆星 POS、联迪、汇卡、商米 Sunmi。支付：代金券、会员卡储值、聚合支付（微信、支付宝、云闪付二维码）。纯收银没有单独页面，前台配置写「快餐版和纯收银版与酒楼版操作相似」。

- 许可：Cloud 门店许可 7.2 及以前，先在 Cloud 配【线上点餐参数配置】（接口地址、客户端 ID、秘钥），门店服务器配置工具点「读取配置」拉到本地。7.3 及以后，在 Cloud 建该门店的移动 POS 工作站，应用类型选【移动 POS】，下载到综合服务—加密服务器。
- 服务器：客户端配置的数据库地址、端口、账套、用户名、密码与金蝶 AI 星空管理中心的数据中心一致。应用基础配置：数据库服务器、门店账套、启用的 Cloud 账套、Cloud 登录账号、启用门店。高级设置：加密服务器地址、门店中间层服务、移动点菜设置（工作站先在 Cloud 维护）、数据交换、补丁自动更新、OTO 接口（可读取配置）。综合服务启动门店中间层和移动点餐服务，并启动数据交换，上传门店营业数据、下载 Cloud 食品等基础资料。移动 POS 与门店服务器要在同一网络。

- 中餐房台：白色空台、蓝色开台就餐、粉色结账、红色结账超时。没有前台 POS 里的预订台、酒席预订台。开台：选房台，输入就餐人数，进入点餐。

- 统配收货：Cloud 链路为门店【门店要货申请单】→集配中心【门店要货申请汇总单】→集配中心【配送出库单】→门店【门店收货单】。移动端不能新增门店收货单，只取 Cloud 已有收货单。可按全部、待收货、已收货过滤。编辑时可改收货数量、收货仓库；物料启用批号管理时选批号。保存后确认收货，数据反写 Cloud，成功后对应仓库库存增加。可扫码、语音。收货单上点申请退货，直接下推门店退货单。
- 统配退货：可新建门店退货单（加商品、选仓库、退货原因、上传图片、保存、确定退货），也可从待退货编辑后再确认。支持由门店收货单下推。与 Cloud 门店退货单列表同步。退货成功后对应仓库库存减少。可选批号。图片最多 9 张，Cloud 在附件页签查看。移动端退货成功不能退款，要到 Cloud 门店退货单上点退款。
- 账户中心：前提是 Cloud「餐饮门店管理—门店订货管理—门店移动订货参数设置」，原文写具体配置方法见 3.1；本文件 3.1 是许可管理，参数设置页未收录。可用余额为当前可使用余额。冻结金额为当前组织已下单未配送的订货单总金额。账户总额 = 可用余额 + 冻结金额。可查余额流水。未启用在线支付时，充值和提现按钮灰色不可点。Cloud 勾选允许提现后才显示申请提现，进入提现至银行卡。支持储值账户和信用账户；信用账户的剩余额度即可使用额度。支付设置里拖动调整账户抵扣顺序。
- 账户充值：页面标题写「这个版本暂时不支持支付宝」；操作说明却可选微信支付/支付宝；功能说明又写支持微信支付和支付宝支付。三处并存，见第 5 节。直接充值，或要货余额不足时从下单页前往充值。界面默认显示 500，档位为 100、300、500、1000、1500、2000，也可自定义。启用在线支付且余额不足时，跳转金额为差额，另有一句「充值金额等于下单金额 − 当前余额」。充值成功后 ERP 自动生成充值单，金额和充值方式由移动端反写。
- 配送方式设置：路径餐饮配送与加工→总部配送管理→基础资料→配送方式设置。组织编码从组织机构选择，必填；组织名称携带且锁定。配送上门、门店自提可同时勾选。配送上门要计算配送费，门店自提不计算。
- 配送费计算规则：同一基础资料路径下。原文写「设置配送方式选择门店配送时」的规则（用词是门店配送，不是上一页的配送上门）。字段：生效日期、失效日期（须大于等于生效日期）、标准收费数量、标准单位（计量单位）、标准收费金额、每续件、加收金额；规则行的生效日期默认单据头日期，且不能大于单据头日期范围。举例：标准收费数量 2、单位 kg、收费金额 10、每续件 1、加收 3，表示重量小于等于 2kg 收 10 元，每超过 1kg 加收 3 元。
- 采购入库：Cloud 侧在供应链—采购管理—采购管理系统参数勾选「采购订单审核后自动入库」，并写新增采购申请单、下推采购订单。移动端可新建采购入库单（加商品、选仓库、保存、完成入库），也可处理待完成单据。支持新增、支持 Cloud 采购订单下推的采购入库、同步 Cloud 新增的采购入库单。可选供应商、仓库、采购组织、采购数量、批号，可语音。采购入库单可直接下推采购退货单。
- 采购退货：可新建或编辑待完成单。支持新增、由移动端采购入库下推、同步 Cloud 新增和下推的采购退货单。可选供应商、仓库、采购组织、采购数量、批号，可语音。

## 3. 可复用机制（面向电子元器件 ERP）

- 门店要货门户（目录 + 模板/手工 + 回写申请单）：**中**。切换组织后看物料目录（编码、名称、规格、描述、图片、订货单位、单价、安全库存、本组织即时可用量），过滤下架和禁用；模板订货或手工订货进入订货车，备注限 150 字并回写门店要货申请单备注；订单列表与该申请单同步。电子元器件的分公司/经销商向总部要货，可以沿用「门户订单 = ERP 申请单」而不是另做一套订单。单位来源原文是物料餐饮属性的订货单位，元器件应改为销售单位或包装单位，不要保留餐饮属性页（`餐饮终端产品_门店移动订货.md`）。
- 统配收货与退货闭环：**中**。链路是门店要货申请单 → 集配中心要货汇总 → 配送出库 → 门店收货。移动端只确认 Cloud 已生成的收货单，可改收货数量和收货仓库，启用批号则选批号，确认后反写并增加库存；收货单可下推退货单。退货可新建，原因加最多 9 张图，图在 Cloud 附件可见，库存减少，但退款必须回到 Cloud 退货单。分销收货差异、批号、退货留痕可以借鉴；「集配中心/总店」是餐饮配送组织，元器件对应总部仓或区域仓即可（同文件）。电子秤里的同名链路是过秤，不增加规则（`餐饮终端产品_电子秤.md`）。
- 订货资金账户：**中**。启用在线支付时，要货申请单下单即扣减金额，且要先有基础账户。账户中心：可用余额、冻结金额（当前组织已下单未配送的订货单总金额）、总额 = 可用 + 冻结。储值账户与信用账户并存，信用看剩余额度。抵扣顺序可拖动。余额不足时充值差额（下单金额 − 当前余额），成功后生成充值单并反写金额和方式。允许提现才显示提现至银行卡；未启用在线支付则充值和提现不可点。订单上有已抵扣金额和还需支付金额，还需支付为 0 即视为支付成功。这是渠道预存款/信用的一种门店实现，比完整资金池少分录和授信调整单正文（调整单、初始化、流水表只有目录名）。二期若做经销商订货账户，可参考这三项余额和「下单占用、未发货冻结」；支付宝是否可用以原文三处互相矛盾，不能当接口范围（`餐饮终端产品_门店移动订货.md`）。
- 订货取价与申请单一致：**中**。商品单价取配送价，来源写明配送价目表或库存平均价，受配送管理参数的「配送价优先级」控制，并与门店要货申请单含税单价一致。门户价和后台申请单价用同一套来源，这条约束可复用。优先级顺序、价目表字段不在本文件（同文件）。
- 配送费首量续件：**低**。生效期、标准收费数量、标准单位、标准收费金额、每续件、加收金额；举例 2kg 内 10 元、每超 1kg 加 3 元。配送上门计费，自提不计，两种方式可同时勾选。结构是简单运费，路径和例子都是餐饮门店配送。元器件干线运费不必建这张餐饮基础资料；若以后要运费，只够参考这六个数字，没有地区、承运商、材积（同文件）。
- 目录上的安全库存与可用量：**低**。只展示物料安全库存和当前门店即时库存，没有建议订货量、日均、在途、订货倍数或要货公式。不能当成要补货或销售预测（同文件）。概述里的「库存预警」没有页面。
- 收货/入库选批号：**低**。统配收货、统配退货、采购入库、采购退货支持选批号；收货要求物料已启用批号管理。没有批次策略、效期、先进先出。元器件批次应在库存模块设计，这里只有选择动作（同文件）。
- 现场采购入库：**低**。移动端可按供应商、仓库、采购组织、数量、批号完成采购入库，并可下推采购退货；Cloud 参数有「采购订单审核后自动入库」。没有检验、序列号、条码解析。来料不要照餐饮门店采购页做（同文件）。
- POS 折扣上限与三套折扣公式：**低**。云店通单品折扣不能超过用户最大折扣率，超出的默认项不在 POS 显示；食品要勾选才能参与折扣率和全单折（`餐饮终端产品_云店通.md`）。前台 POS：全单折直接乘系数，折扣率乘（1 − 折扣率），折扣价做减法；大类折扣还要部门最大打折率（`餐饮终端产品_前台POS.md`）。移动 POS 全单折、减免金额分别受服务员折扣权限、减免权限控制，付款页登录的会员卡不能再享受会员折扣（`餐饮终端产品_移动POS.md`）。这是收银权限，不是促销引擎。云店通的打折、满减、满送、买送没有门槛和叠加规则。
- 班次交接与日结：**低**。前台转更打本班汇总，清机打当日报表并把营业日期改到次日；云店通有交班、日结、开钱箱。对象是餐饮收银现金，不是仓库日结（`餐饮终端产品_前台POS.md`、`餐饮终端产品_云店通.md`）。
- 总部主数据下发、门店营业数据回传：**低**。前台 POS 在连锁认证后下载食品、房台、会员，上传账单和操作日志，任务有频率。云店通把组织、用户、角色、食品、结算方式发布到商户平台。移动 POS 用综合服务做同样方向的交换。模式是门店本地库加中间层，资料内容是菜品和房台（三份 POS 文件）。
- 称重结果生成下游单据：**低**。电子秤上传后执行状态为未执行，手工生成或定时任务生成生产汇报、检验单、生产入库单；失败可反审核退回未执行。采购入库称重后财务收单。销售出库要求先保存、称完变为已审核。加工领料要求实发 ≤ 应发。这是餐饮过秤回写，不是元器件点数、卷盘或序列号采集（`餐饮终端产品_电子秤.md`）。
- 微信退款审批状态：**低**。申请后状态「已申请退款」，同意则退回并推送，拒绝则「退款申请不通过」且允许再申请。单据是微信点餐订单，没有金额拆分和部分退规则（`餐饮终端产品_微信点餐.md`）。
- 公告强制阅读：**低**。倒计时结束前不能关。可作门户公告的一种交互，与订货计算无关（`餐饮终端产品_门店移动订货.md`）。

本领域没有：促销与返利的条件、累进和结算；要货/补货计算公式；销售预测或订货预估；配送路线和车辆；独立的渠道资金池科目；会员积分规则（「启用积分支付」只有图）。有门店订货账户，没有资金池分录。

## 4. 不宜照搬 / 行业专用

- 前台 POS、移动 POS、云店通、微信点餐是堂食/轻餐收银：房台颜色、开台人数、酒席预订、点菜口味、先送、叫起、追单、出品监控、咨客厅房、排位取号、取餐号、沽清/扣炖、蛋糕类别折扣、口碑与外卖订单。电子元器件没有桌台和后厨。本期、二期都不必做 POS、扫码点餐、会员储值点餐。
- 印单（总单、出品单、叫起单、追台单等）和清机、转更、埋脚、找赎、小账，是餐饮班次现金。不要做成仓库交接或销售日结。
- 微信餐前/餐后支付、桌台码自动开台、取餐码、限制多人同时点菜、支付宝与微信不能同时点餐，是餐厅 C 端。退款状态词可以以后另做售后时再对，不要把这套公众号点餐搬过来。
- 电子秤的中央厨房、加工工艺、标准出成率、分拣贴纸、按公斤称重，是食品加工和门店配送过磅。标准出成率只有「填写」二字，没有产量公式，不能当成工序良率。采购/销售/领料/入库若需要数量确认，应走条码或序列号，不接餐饮电子秤程序。
- 门店移动订货虽然机制可参考，外壳仍是餐饮：应用名「餐饮_移动订货」、单位取餐饮属性、配送费例子用 kg、组织角色是门店和集配中心、路径在餐饮配送与加工。二期若做经销商订货，只取第 3 节里标中的四条，不复制 CYMobile、云之家/企微/钉钉/小程序的安装步骤、补丁号和金蝶侧发布联系人。
- 概述中的调拨、报损、盘点、盘盈盘亏、库存预警、待办任务没有规则。不要用这些标题补写一套门店库存方案。
- 云店通、移动 POS、微信点餐里的会员开卡、储值、积分、折扣券、菜品券，是餐饮消费者会员。没有积分比率和清零规则。渠道积分不要从这里设计。
- 前台 POS 预置账号（密码等于用户名）是食神手册的登录示例，不能作为元器件系统的账号策略。
