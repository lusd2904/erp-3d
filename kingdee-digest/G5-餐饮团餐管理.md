## 1. 功能点

### 启用与总览（`餐饮团餐管理_网点运营管理.md`）

- 用 administrator 登录，搜索「餐饮参数设置」，基本参数勾选「启用餐饮团餐管理（新）」后，才显示餐饮团餐管理子系统及菜单。
- 「整体框图」「整体框图(菜谱)」页只有图占位（`1.png`、`2.png`、`3.png`；菜谱侧 `18.png`、`19.png`），无流程文字。

### 网点运营（`餐饮团餐管理_网点运营管理.md`）

- 报餐日历：带组织基础资料，控制策略默认共享，可改为分配、私有。按单据头日期范围展开每一天；报餐选项默认工作日勾选、休息日或节假日不勾选；餐次从【供应餐次】多选；可勾选提醒，在信息中心提醒报餐。
- 管控规则：路径【报餐管控】—【管控规则】。规则类型：菜品份数、菜品份量、人均费用。默认不允许超标；允许超标时「超出比例(%)」必填。份数必录人均份数；份量必录人均食用份量和份量单位；人均费用必录人均费用。生效日期范围内只能有一个管控规则，生效日期不可重叠。规则明细同一餐次只能一条。
- 网点运营系统参数：网点报餐单取菜品 BOM 的来源，枚举为报餐组织、配送组织，默认报餐组织；来源组织没有菜品 BOM 时按空处理。按该来源取菜品 BOM 及 BOM 上的成本价，计算成本金额、毛利率。
- 网点报餐单：报餐周期为按日、按周、按月，默认按日。报餐日期必须落在报餐日历内。预估份量 = 菜品单位份量 × 数量（数量精度由单位精度控制）；份量单位取菜品。预估成本 = 子单据体展开 BOM 的成本金额合计。毛利率% =（金额 − 预估成本）/ 金额 × 100%。物料按菜品展开 BOM 子项；单位用量取 BOM；预估用量 = 菜品数量 × 单位用量；成本金额 = 成本价 × 预估用量。食材明细即 BOM 子项；营养成分取菜品上的实际营养成分。
- 按预计人数点「计算」时，取有效期内管控规则，按餐次规则类型回写：
  - 人均数量：（预计人数 × 人均数量）/ 日期餐次内菜品总个数 = 每个菜品数量；预估份量 = 菜品份量 × 数量。
  - 原文写「管控规则设置的是人均份量」时，公式却使用「人均份数」：（预计人数 × 人均份数）/（餐次内菜品总份量之和）× 每个菜品单价 = 每个菜品的预估份量；数量 = 预估份量 / 菜品份量。
  - 人均费用：原文以「则人（预计人数 × 人均费用）/（日期餐次内菜品总单价之和）× 套餐内单个菜品的单价」得到每个菜品金额，再按单价算数量和预估份量。
- 保存时按管控规则检查是否允许超标；人工修改后超出标准且不允许超标，则不允许保存。
- 引入菜谱：按报餐周期跳到对应菜谱列表选菜，返回报餐日期、餐次、菜品。套打可打餐次、菜品、单位、成本金额。
- 食材预估要货单：报餐单审核后下推；把 BOM 展开的物料按物料分组汇总；配送组织默认带报餐单单据头的配送组织。报餐单已生成预估要货单后，不可再生成食材要货申请单。
- 食材要货申请单：同样由审核后的报餐单下推，按物料分组汇总，配送组织同样携带。已生成要货申请单后，不可再生成食材预估要货单。两张下游互斥。
- 留样：菜品留样记录单的留样类型枚举为菜品留样、食材留样。餐次取供应餐次。留样样品：菜品留样取菜品，食材留样取物料。留样人取员工；样品放置位置取仓库；保存方法、处理方法取辅助资料。食材留样记录单写明功能与菜品留样记录单基本一致，本页只重复了留样样品的取值规则。
- 网点收入上报单：上报网点默认当前登录组织；上报档口、档口取部门（档口限定使用组织为上报网点的部门）；餐次取供应餐次；收入分类、收入项目取辅助资料，收入项目是收入分类的下级。
- 网点费用上报单：上报网点、上报档口同上；费用分类、费用项目为上下级辅助资料；数量不允许负数和 0。
- 网点收入明细表：取网点收入上报单。人均消费定义为某一网点、某一日期、某一餐次的人均消费，未给计算公式。
- 网点费用明细表：日期、网点、档口、餐次、费用分类、费用项目、单位、数量、金额取费用上报单。默认按某一网点某一日期分组，汇总数量、金额。
- 网点食材成本明细表：取网点报餐单。数量为相同物料预估用量，且转换成订货单位；估算成本价为报餐单上物料估算成本价，转换成订货单位成本价；估算成本金额 = 数量 × 估算成本价。
- 网点利润分析表：营业收入 = 收入上报单中「营业收入」分类下各分类名称收入之和；其他收入 = 除营业收入以外分类的收入之和；营业费用 = 费用上报单费用总金额；食材成本 = 报餐单物料成本金额之和。总收入 = 营业收入 + 其他收入；总成本 = 营业费用 + 食材成本；毛利润 = 总收入 − 总成本；毛利率% =（总收入 − 总成本）/ 总收入。

「报餐处理」页只有三个链接：网点报餐单、食材预估要货单、食材要货申请单，无额外规则。

### 菜谱综合管理（`餐饮团餐管理_菜谱综合管理.md`）

- 供应餐次：带组织，控制策略默认共享，可改为分配、私有。创建组织取控制策略，使用组织默认等于创建组织。预置早餐、午餐、晚餐、夜宵，可修改、可删除。
- 营养成分：同样是带组织基础资料，共享/分配/私有。计量单位必填。系统预置可修改、不可删除。
- 营养成分预警规则：成份编码从使用组织下「营业成分列表」选已审核未禁用的营养成分（原文用「营业成分」，未解释是否即营养成分）。最高含量、最低含量为数值，精度由单位精度决定，不允许负数和 0；最高不可小于最低，最低不可大于最高。
- 菜品：原文写单据功能基本与「物料」一致。必须勾选餐饮团餐属性。物料设为菜品时物料属性必须为自制；在菜品中录入时默认自制。菜品属性页签只在菜品库子菜单打开时显示，从物料入口打开不显示。供应餐次可多选，逗号隔开。菜品类型取辅助资料。标签分类有值时标签明细必填。营养成分从使用组织的营养成份列表选择（原文「成份」）。
- 菜品 BOM：功能基本与「物料清单」一致，且只显示物料类型为菜品的物料清单。从菜品 BOM 打开时，主产品增加零售价、总成本、毛利润、毛利率；从物料清单入口打开则不显示这些字段。售价取菜品上的售价。总成本 = 子项成本金额之和。毛利润 = 零售价 − 总成本。毛利润% = 毛利润 / 零售价。子项增加单位用量、成本价、成本金额、成本占比。单位用量 = 当前行用量分子 / 用量分母。成本价默认取日期最近的采购订单单价，采购组织为当前 BOM 使用组织。成本金额 = 单位用量 × 成本价。成本占比 = 本行成本金额 / 总成本。批量更新成本：勾选 BOM 后重取成本价，并更新成本金额、成本占比、总成本、毛利润、毛利率（此处写「毛利率」，主产品字段名写「毛利润%」）。
- 营养套餐：套餐菜品、套餐类型（辅助资料）、明细菜品（不能选单据头那道菜）。售价默认菜品售价，可改。估算成本默认 = 该菜品最新 BOM 总成本 × 数量，可改。成本占比为当前行占全部行成本的百分比。营养成分按明细菜品汇总；数量按营养成分合计。达标勾选为枚举：达标、不达标、空。判定：汇总营养成分后对照预警规则，高于最高值或低于最低值为不达标，介于最高与最低之间为达标，未设预警规则则为空。工具栏「生成菜品 BOM」：父项为套餐菜品，父项单位按物料清单规则取值；子项为套餐明细菜品（不是原料）；生成后物料清单生成状态为「已生成」，BOM 版本写回营养套餐。
- 编制规则：带组织，控制策略默认共享，可改为分配、私有。餐次从本使用组织下已审核未禁用的供应餐次选择。类型从辅助资料菜品类型选择。标签分类从食品标签辅助资料选择。必选菜品从物料类型为菜品、且供应该餐次、已审核未禁用的菜品库选择。设置必选菜品前必须先设规则条件。必选菜品数量 + 附属规则数量之和，不可大于该餐次该类型的总数量。附属规则的字段页未单独展开。
- 菜谱编制工作台：菜谱类型为日菜谱、周菜谱、月菜谱。周菜谱日期范围必须是整周，月菜谱必须是整月。菜谱规则从编制规则选择。勾选「计算时不允许食品重复」后，除必选菜品外计算过程不可重复；计算后手工调整允许重复。勾选「按报餐日历编制」则只在报餐日历的报餐日期生成菜谱。按钮「计算」按规则计算；按钮「生成菜谱」按类型生成对应菜谱。
- 日菜谱：菜品只能选本使用组织、对应该餐次、已审核未禁用的菜品。售价取菜品售价，未设置则为空。成本金额取该菜品 BOM 的总成本。原文写创建菜谱基础资料后发布三个菜单：日菜谱、周菜谱、月菜谱。月份字段仅月菜谱显示（格式举例 2021.3）；星期为一至日，仅周菜谱、月菜谱显示，并随日期显示。周菜谱、月菜谱两页均写「单据功能与日菜谱基本一致」，无额外字段。
- 目录还有「菜谱成本查询」，本文件没有该页正文。

## 3. 可复用机制（面向电子元器件 ERP）

- 配方按最新采购价滚成本：**中**。菜品 BOM 的成本价取「采购组织 = BOM 使用组织」的最新采购订单单价；成本金额 =（分子/分母）× 成本价；总成本为子项合计；毛利润 = 零售价 − 总成本；支持批量重取价。电子元器件的套件/模组报价可借鉴「最新采购价 → 子项成本 → 占比 → 毛利」，对象不要用菜品（`餐饮团餐管理_菜谱综合管理.md`）。原文未写损耗、替代、阶梯，这套公式比加工用料清单简单。
- 需求展开后汇总要货：**中**。网点报餐单审核后，按菜品 BOM 展开物料，按物料分组汇总，配送组织取单据头，下推食材预估要货单或食材要货申请单，且两张下游只能生成一张。这是「计划/预测单 → 汇总要货」的结构，可对标分销要补货；触发条件、餐次、菜品 BOM 本期不做（`餐饮团餐管理_网点运营管理.md`）。预估用量在报餐单上 = 菜品数量 × 单位用量，成本明细还要换成订货单位，换算规则未给出。
- BOM 来源组织参数：**中**。报餐取 BOM 可指定报餐组织或配送组织，缺 BOM 则空，不用跨组织硬找。多组织配方以哪个组织的 BOM 计价，这个开关可参考（同文件，及系统参数页）。
- 主数据控制策略：**中**。报餐日历、供应餐次、营养成分、营养成分预警、编制规则默认共享，可改为分配或私有；创建组织取控制策略，使用组织默认等于创建组织。这是星空基础资料的通用分发方式，与餐饮无关，但本文件没有分配操作步骤（两文件中多页重复同一句）。
- 规则生效期不重叠：**低**。管控规则在生效期内全局只能有一条，日期不可重叠，同一餐次明细只能一条，允许超标时超出比例必填，保存时拦截超标。规则引擎的「有效期互斥 + 维度唯一」可借鉴；维度是人均餐标，二期不必做团餐管控（`餐饮团餐管理_网点运营管理.md`）。
- 据点损益四段式：**低**。收入分类拆营业收入/其他收入，加费用上报，加食材成本，得毛利和毛利率。结构普通，取数锁死在收入上报单、费用上报单、报餐单。元器件若要网点或客户损益，应取应收、费用、出库成本，不建这三张餐饮上报单。
- 上下限预警判定：**低**。营养套餐把明细营养汇总后，高于最高或低于最低为不达标，区间内为达标，无规则则为空。形式像指标窗，内容是营养素，本期不必做。
- 规则计算后生成单据：**低**。编制工作台按规则计算，再生成日/周/月菜谱；可要求整周/整月、排除非报餐日、计算时除必选项外不重复、生成后允许手工改重复。工作台形态通用，输入输出全是菜谱，不必迁移。

## 4. 不宜照搬 / 行业专用

- 供应餐次（早餐、午餐、晚餐、夜宵）、报餐日历、按日/周/月报餐、人均份数/份量/费用、档口、留样（保存方法、处理方法、样品放仓库）是食堂与团餐合规，电子元器件生产与分销没有对应业务。本期、二期都不必做。
- 日菜谱、周菜谱、月菜谱、编制规则、必选菜、食品标签、菜谱编制工作台是排菜，不是销售预测，也不是产品配置 BOM。不要把它做成订货预估。
