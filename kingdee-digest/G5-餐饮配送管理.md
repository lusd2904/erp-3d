## 1. 功能点

### 1.1 配送路线管理（`餐饮配送管理_配送路线管理.md`）

- 定位：门店订货排班、路线、车辆。订货按规则发生；路线和车辆用在配送出库单、门店收货单上跟踪物流（概述页）。
- 使用顺序（操作手册文字）：门店订货日规则设置 → 门店订货日排班助手 → 订货排班表 → 配送路线 → 车辆管理。另有报表「门店订货情况监控表」、参数「配送路线管理系统参数」。两张流程图只有文件名，未 OCR。
- 门店订货日规则：类型为固定周期、固定日期、单双日、星期。固定周期时规则锁定为固定周期，周期必填、正整数、最多 3 位，且（有限期至 − 有限期从 + 1）/ 订货周期必须整除（原文写「有限期」）。固定日期为每月某一天。单双日为双数日或单数日，单选。星期可多选。同一门店同一有效期只能有一条规则，不同有效期可以不同。规则变更后须手工「更新订货排班表」：保留更新日期之前的排班，只重算该日之后。
- 门店订货日排班助手：跟配送路线自动生成订货排班表。任务可「恢复任务为准备状态 / 设置任务为停止状态」、立即执行，并设执行时间。
- 订货排班表：可按配送路线或按门店过滤，二者互斥（选路线则门店不可选）。订货周期取门店订货规则中符合条件的规则，按有效期生成。每个有效期最后一次订货时间，作为下一个订货期间有效期的起始日期。门店按配送路线上的顺序显示。
- 配送路线：配置有效期内集配中心与门店的路线。基础资料，受组织策略控制，共享类型。有效期从默认当前操作时间，有效期至默认 2100-1-1（原文该句后粘连「.4.」）。允许门店出现在多个路线或同一路线，但有效期不可重叠；同一配送组织下同一门店的有效期不可重叠。路线中的门店或订货周期变更时，同样要手工更新订货排班表，保留更新日之前的记录。门店地址默认取组织信息中的地址，可改。同组织下路线名称重复时提示是否继续保存。
- 车辆管理：管每条路线的车辆。基础资料，共享类型，受组织策略控制。同一配送组织、同一配送路线，不允许有效期重叠的车辆记录。配送出库单生成时取有效期内车辆。出库单配送信息增加配送路线、车牌号、驾驶员、驾驶员联系方式；门店收货单表头增加配送信息页签，这些字段由出库单携带。三张界面图未 OCR。
- 参数：勾选后，只有排班允许的日期才能做对应订货，否则打开单据提示无法订货。受控对象：门店要货申请单、历史物料用量要货、历史食品销量要货、门店周期要货。后三者的字段页不在本文件。
- 门店订货情况监控表（页内标题写成「门店情况监控表」）：排班状态 = 日期是否落在该门店订货排班日；订货状态 = 业务日期为当天且存在已审核门店要货申请单则为已订货。已排班且未订货用红色，未排班已订货用蓝色。单据编号、业务日期取门店要货申请单。

### 1.2 总部配送管理（`餐饮配送管理_总部配送管理.md`）

概述出现两套入口文案：一页称「金蝶云食神餐饮中央配送」，一页称「K/3Cloud 中央配送」。能力清单一致：门店要货、申请汇总、总部配送出库、门店收货、配送异常、门店退货、配送价格；可单独跑，也可接供应链与应付款。主要功能列举：门店要货处理、门店收货处理、门店退货处理、配送异常处理、总部配送出货处理、总部配送退货处理、配送价格管理。

业务类型（概述文字；流程图均未 OCR）：

- 直拨配送：门店只提要货，配送中心负责采购、加工、物流。货从供应商直达无采购权的门店仓库或门店客户。不从总部仓库发出，不影响总部仓库库存；总部形成对供应商的应付；分部只增加库存账或应收账款，不形成对供应商的应付。
- 统配配送：集中采购的物料或加工品先入本地仓库（通常是总部仓库），再统一送到各门店。分原材料统配、加工品统配。原材料入总部仓库后由总部形成对供应商的应付。中央厨房加工品入总仓后再配送。
- 配送退货：质量、运输损坏、发运错误等，把门店收到的货退回配送中心。在途损耗、损毁、货单不符走配送异常。概述写退料一般包括退货申请、退料出库。
- 采购衔接（「采购流程业务」页，图未 OCR，图旁有文字）：采购申请单、采购订单、采购入库单增加单据类型直拨采购申请、直拨采购订单、直拨采购入库。汇总单按「要货申请汇总-采购申请/采购订单（统采直拨）」转换时，整单生成则汇总单整单关闭，单行生成则该行关闭；按「统采统配」转换时行状态不可关闭。统采直拨生成采购订单时只可生成门店采购入库。

要货入口（中央配送页只有短述或空链接，无字段表）：

- 历史物料用量要货：按历史同期计算门店需求。要素写明：最近一天要货、上周同期、上月同期、上年同期、固定日期。无字段页。
- 历史食品销量要货：用历史营业额算出历史平均营业总额、各菜品平均销售份数、平均日销售金额；可手工输入预估营业总额，按预估营业额与平均营业额的比值得到菜品预估销量与金额，再经食品成本卡算物料需求。无字段页。
- 物料预估要货单：只有标题和链接，正文空。
- 门店要货申请单：短述为门店提交要货，总部按需求与库存配送；依据包括门店食品消耗计划、食品需求；审核后才能配送。取价规则在「配送价格管理」页有一段，无本单据字段表。
- 智能要补货：用历史物料用量要货、历史食品销量要货两个维度估算要货数量并生成需求；区分门店自采需求与统配需求。流程图未 OCR。

智能要货参数（组织参数，修改只影响之后新增的业务）：

- 预估要货单审核时，配送物料可自动生成门店要货申请单；不勾选则手工下推。
- 预估要货单审核时，自采物料可自动生成采购申请单或采购订单。
- 要补货方案公式：净需求 = 毛需求 − 现有库存 + 最小库存 + 安全库存。

备料计算：按历史的门店要货申请单 / 门店要货申请汇总单 / 加工计划单 / 物料清单，预估并生成采购订单、加工计划单、门店要货申请单。采购物料的申请或汇总可生成采购申请单或采购订单；加工物料的申请或汇总可生成加工计划单或加工订单；自制物料的加工计划单 / 物料清单可生成门店要货申请单或采购申请单（在配送管理参数里选）。选单来源即上述四类。库存组织：申请/汇总取配送组织，加工计划单取加工组织，物料清单取使用组织。勾选「考虑安全库存与可用库存」时，仅当可用库存数 − 安全库存数 − 毛需求 < 0 才生成单据，净需求取该差值的相反数，且只展示净需求大于 0 的结果（同一单元格后半句又写「小于 0 的物料不会显示」，见第 5 节）。辅助属性勾选则不同辅助属性求和，不勾选则当成不同物料。可只汇总自制件、只汇总采购件，或汇总全部。

物料上下架申请单：申请类型为上架或下架。下架且执行状态为已执行的物料，不能再走要货、配送等供应链流程。执行状态分已执行、未执行。行作废状态分正常、已作废：未到执行日期可作废，已到执行日期且已执行则不可作废。单内已有物料到执行时间并变更状态，则整单不可反审核。

门店要货申请汇总（同文有两页：`门店要货申请汇总` 与 `门店要货申请汇总单`，字段主体相同，路径不同）：

- 路径其一：【餐饮配送与加工】—【总部配送管理】—【门店要货处理】—【门店要货申请汇总】。路径其二：【中央配送】—【门店要货】—【门店要货处理】—【门店要货申请汇总】。
- 用途：汇总各门店物料需求，看库存，决定采购、加工或配送。配送组织须有库存职能。
- 单据类型原文写「预设 3 种」，紧接着列出 4 个：标准要货汇总（默认）、直拨要货汇总、原材料统配要货汇总、加工品统配要货汇总。物料配送属性只勾直拨时只能进直拨汇总；只勾统配时只能进统配汇总；两者都勾则可进直拨或统配；标准要货汇总不受该属性限制。
- 数量：申请数量、批准数量；需采购数量、需加工数量默认等于批准数量。辅单位及批准数量（辅单位）按物料换算方向。到货日期为送到门店的日期。申请组织为要货门店。
- 供应商：取默认采购价目表。价目表上门店不为空时优先取该供应商，否则取门店为空的默认价目表。列表上可做「指定供应商」，无价目表则为空。
- 货源页：采购组织须有采购职能，有委托则须与当前配送组织存在委托采购关系；加工计划组织、加工组织须有加工职能，有委托则须存在委托加工关系。
- 汇总页：相同物料按库存单位合计申请总数量、批准总数量、库存总数量。缺货数量 = 库存总数量 − 批准数量（原文公式如此）。
- 执行追踪：申请/采购关联数量、申请/采购数量、计划/加工关联数量、计划/加工数量、发货关联数量、发货数量。剩余数量 = 批准数量 − 发货数量。另有业务关闭、业务终止、源单类型、源单单号。
- 下游（已审核、未关闭、业务状态正常才能转；可手工下推或按参数自动生成）：
  - 直拨要货汇总 → 采购申请单或采购订单。需采购数量默认等于批准数量。供应商为空或物料属性为「需申购」时：审核生成采购申请、不生成采购订单。供应商不为空或物料属性不是「需申购」时：看参数勾的是采购申请还是采购订单，二者互斥（原文条件用「或者」，存在重叠，见第 5 节）。申请/采购关联数量 ≥ 申请数量不能再下推采购申请；关联数量 ≥ 订单数量不能再下推采购订单。多张汇总合并时，供应商、收货组织、配送组织、需求组织、结算组织、结算币别相同才能并到一张采购申请或采购订单。审核把数量累加到汇总单【申请/采购数量】，反审核扣回。
  - 加工品统配要货汇总 → 加工计划单或加工订单。参数勾自动生成配送出库单时，审核按批准数量生成配送出库单，再按「要货汇总加工物料自动生成」勾选结果，用需加工数量生成加工计划单或加工订单。合并条件是计划组织相同。审核累加【计划/加工数量】，反审核扣回。
  - 原材料统配或加工品统配 → 配送出库单。总仓有库存可配送的物料可下推或由出库单选单。参数勾选时审核按批准数量自动生成。合并条件是配送组织相同。审核累加【发货数量】，反审核扣回。

配送拣货单：统计各门店要货申请汇总，并按配送路线看各门店物料。多个要货组织时，按配送路线表的顺序倒序排列。选路线后过滤该路线下的要货组织。数据来源为已审核的门店要货汇总单，并过滤掉允许直拨的物料。物料数量 = 批准数量 − 已发货数量。可改拣货数量并保存。拣货完成把数量反写到汇总单的已拣货字段，之后才能「生成配送出库单」。字段说明写生成暂存状态的配送出库单；业务说明写生成保存状态的配送出库单。须先给配送组织下的物料设默认仓库。查询报表只取已做拣货完成的拣货单，无其他字段。

配送出库单：总部配送中心或仓储中心向门店发货。路径：【餐饮配送与加工】—【总部配送管理】—【总部配送出/退货处理】—【配送出库单】。业务日期须大于 max（库存组织关账日期，货主关账日期）。表头有承运商（选供应商）、运输单号、发货组织（须有库存职能）、发货部门、库存组、仓管员、收货组织/部门。配送信息页另有收货员、配送组织、配送部门、配送组、配送员（收货组织/部门在两处重复出现）。财务页：结算组织、结算币别（默认人民币）、结算方式、收款条件、本位币（锁定，按结算组织会计政策）、货主（默认发货组织，关联时携带上游）、汇率类型、汇率。表体：应发数量（关联时 = 上游数量 − 关联出货数量；原文又写按出库单取系统日期前的计划发货数量）、实发数量、仓库、仓位、库存状态（须为可用）。物料数据：启用 BOM 编号辅助属性则必录；批号、生产日期、保质期单位、保质期、有效期至、辅助单位及数量。保质期按日则到期日 = 生产日期 + 保质期；按年或月则顺推，输入到期日不反算生产日期。货主与结算组织不一致时产生组织间结算清单，细节指向【组织间结算—跨组织销售业务】，本文件无该页。

配送退货单：质量不合格、价格不正确，或与门店要货条款不符时，配货单位把货退回。路径：【餐饮配送与加工】—【总部配送管理】—【配送出/退货处理】—【配送退货单】。字段结构与出库单同类，另有退货组织、退货原因、退货部门、退货员。可由配送出库单下推，或在退货单上选配送出库。货主与结算组织不一致时产生内部调拨出入库，再生成组织间结算清单。同样指向组织间结算专章，本文件无正文。

配送异常通知单：质量、价格或与要货/合同条款不符时的通知，审核后再退货。选单来源为有异常数量的门店收货单。异常多收 = 实收数量 − 应收数量；异常少收 = 应收数量 − 实收数量；异常金额 = 异常数量 × 单价。处理结果两处写法相反，见第 5 节。处理状态分已处理、未处理。

配送价格：

- 价格来源概述写两类：配送价目表、入库价。价目表可由上级统一定价再分发，也可各配送组织自定。调价可走调价单，或在价目表上对行做反审核后直接改。
- 取价用于配送出库单，也用于门店要货申请单。匹配顺序：价格对象（物料时找到物料）→ 辅助属性（启用且影响价格）→ 单位（与价目表单位相同，或物料计价单位与价目表单位相同，再按换算回填）→ 计价数量段（无数量段则不看数量）→ 有效期（定价时点必须落在价目分录有效期内）。匹配到唯一价格或匹配不到。
- 含税时净价写入含税单价和系统定价；不含税时写入单价和系统定价；无匹配则不携带。入库成本价：按批号对应的入库成本写出库价（参数页另有「库存平均价」说法，见第 5 节）。
- 改结算币别且与价目表币别不一致则清空价目表；改数量则按价目表重取价。
- 限价只控制配送出库。强度在价格管理页写为禁止交易、预警提示、不予控制；参数页写为不予控制、预警提示、强制。禁止/强制时不能保存，预警则确认后可保存。
- 价目表为私有资料，须分发后业务组织才能用，目标组织不能改；可取消分发、分发查询。整单失效/反失效；分录业务失效/业务反失效。只有未失效且未业务失效的分录起作用。
- 价目表头：配送组织、编码（唯一）、名称、价目表对象（物料或物料类别）、币别、状态、生效日、失效日。表体：定价单位（原文写销售计价单位）、数量从、数量至、含税单价、税率、不含税单价、最低限价、行生效/失效、业务失效。对象为物料类别时物料编码锁定。
- 调价表（页名「配送调价方案」，路径末级为配送调价表）：调价原因取辅助资料。调后单价 = 调前单价 × 调价幅度；调价幅度 =（调后单价 − 调前单价）/ 调前单价。生效规则按「物料 + 单位 + 辅助属性 + 数量区间」：价目表没有则插入；有效期相同则改价格和上下限；新生效日 ≤ 原生效日则提示失败；新生效日落在原区间内则插入新行并把原行失效日改成新生效日；新生效日 ≥ 原失效日则另插一行。新行生效/失效不能超出价目表头。多张价目表并成一张调价表时，配送组织和价目表对象必须相同。只有已审核、未失效、未业务失效的价目表能下推。
- 配送加成：按地域或门店类型对配送价加成。出库单按配送组织、加成对象、是否默认加成表匹配；组织一致且加成表为默认时，再按分录顺序匹配并取加成。表体有加成类型、结算方式（折扣率或折扣额）、加成/折扣率%、加成/折扣价、数量从/至、物料类别（存货类别）。分发、整单失效、行业务失效与价目表相同。字段说明多处仍写成「价目表」，见第 5 节。

配送管理参数有两页，口径不完全相同（第 5 节）。共同项：允许超申请数量配送；配送退货且补料方式为「创建补料订单」时，可自动生成补货要货申请；要货汇总有货可自动生成配送出库单；要货汇总的采购数量可自动生成采购申请单或采购订单；加工数量可自动生成加工计划单或加工订单。参数修改只影响之后新增的单据。

仅「配送管理参数设置」页还有：允许超申请时取物料收发上限（原文「收发上线」）；配送价优先来源四选（优先配送价目表、优先库存平均价、只取配送价目表、只取库存平均价）；自制物料备料的原料需求生成门店要货申请单或采购申请单；配送出库单审核自动生成门店收货单，状态可选创建、提交、审核，门店未设默认仓库时为暂存；金额为 0 时控制门店订货单、门店收货单、门店退货单、采购入库单、采购退货单，强度为预警提示、不予控制、禁止交易（禁止则不可提交）。参数名写「是否显示金额为 0 的单据」，说明正文写的是提交控制。

仅「配送管理系统参数设置」页的配送价来源是勾选配送价目表或入库价，没有四选优先级，也没有收发上限、自制备料下游、自动收货单、零金额控制。

基础资料：配送组、配送员。路径在【基础设置】—【基础资料】—【公共资料】的业务组列表、业务员列表。类型分别选「配送组」「配送员」。业务组织须有配送职能（配送员页的使用前提写的是库存职能，字段说明写配送职能）。未启用不能被引用。业务员可挂业务组，且只能有一个默认业务组。

报表（多数只有一句用途）：

- 配送出/退货明细表：记录配送出库单、配送退货单的物料信息。无字段。
- 配送出/退货统计表：统计上述两单的物料信息。无字段。
- 配送出退库汇总报表：一段时间内总部发给门店及门店退回总部的合计发货、退货。无字段。
- 配送在途差异表：门店收货、配送异常、门店退货、配送退货、收货在途、退货在途。勾选「收/退货在途全部为 0 不显示」则全 0 时不显示。无数量公式。
- 配送毛利润报表：反映一段时间内配送收入、配送成本、配送利润，可按物料、门店分组。勾选「包含跨组织结算生成单据」则计入跨组织结算生成的单据。字段「配送毛利润」= 配送单价 × 配送数量。

公共界面说明：列表过滤的方案、条件、高级条件、排序、显示列，以及提交、审核、分配、引入引出、批号、整单关闭、财务收单等按钮。以食品成本卡列表为例。属星空列表壳，无配送业务规则。

### 1.3 加工数据管理（`餐饮配送管理_加工数据管理.md`）

- 定位：集中管理产品设计、生产计划、加工制造、物料管理要共享的工程数据，并做动态维护和更改控制。范围写明：物料清单（BOM）、树形维护、工作日历、物料替代；并称这些是计划管理、生产控制的基础。特性清单：阶梯用量及损耗、多种物料清单查询、BOM 子项有效期、基于方案的替代与组合替代、工作日历、物料清单和工艺路线在组织间分配与共享、维护生产线生产基础数据。
- 使用流程：先在【基础管理】—【基础资料】建单位、物料、仓库、供应商；再在【餐饮配送与加工】—【加工数据管理】建资源、工作中心、作业、基本活动、工序控制码、车间公式、班次、班制、工作日历模板、工作日历。日常路径写成【餐饮配送与加工】—【加工数据数据】—【物料清单】或【替代方案】（「加工数据数据」为原文）。目录还链接了正查、反查、汇总查询、班次、班组、加工数据参数，这些页的正文不在本文件。
- 已展开页的功能路径大多仍是【生产制造】—【工程数据】，与餐饮菜单并存。
- 物料清单：表达制成品所需原材料、零部件、半成品的层次。单据类型控制必录、打印、审核、流程。BOM 版本唯一。分类：标准 BOM、配置 BOM。用途：自制、委外、通用、组装。父项物料属性为外购时，子项只能是外购件。成品率：投入与合格成品的比率，原文例「投入 100 套原材料，能产出多少套成品」。父项单位默认生产单位。
- 联副产品：类型为联产品或副产品；数量是生成单位主产品时的产出；成本权重默认 100；勾选倒冲领料则入库/汇报时生成倒冲领料；另有产出工序、产出作业、辅助属性（影响计划时必录）。
- 子项：项次相同表示同一组替代。子项类型在物料清单页为标准件、替代件、返还件；产品配置页写普通件、替代件、返还件。供应类型「指定当前子项生成计划订单的投放类型」，未给枚举。用量类型：固定（与父项数量无关）、变动（按父项比例）、批量（父项落在不同区间时子项取不同值）。用量 = 分子 / 分母。固定损耗与父项用量无关；变动损耗率与父项用量成比例。跳层勾选后展开为下级子项。供应组织建议在有委托加工时维护，维护后才能改子项 BOM 版本。
- 阶梯用量：起始数量、截止数量不可重叠；单位锁定为子项单位；另有固定损耗、变动损耗率、分子、分母。
- 物料控制：发料方式为直接领料、直接倒冲、调拨领料、调拨倒冲、不发料。父项为生产线生产模式时，原文写子项只能是「调拨倒冲、发料」。倒冲时机：汇报倒冲、入库倒冲；生产线模式下再次设置无效，倒冲时点都是汇报倒冲。发料组织须有库存职能。超发控制：允许超发、最小发料批量、不允许超发。最小发料批量一般为最小包装量。是否发损耗控制投料是否计损耗。提前期偏置相对第一道工序开工，负数表示开工前备料，时间单位为天、时、分、秒。另有是否关键件、工序（正整数）、作业、位置号（原文写插件位置）、货主类型（业务组织/客户/供应商）及货主。配置 BOM 才维护可替换、可修改、可选择。替代策略：混用替代（主料与替代料同时作供给和预计量，比例由库存和预计量决定）、手工替代（按用户指定比例）、整批替代（同一笔需求要么主料要么替代料）。替代方式：替代（需求不能满足时仍产生主料供给）、取代（需求不能满足时产生替代料供给）。替代优先级供 MRP；替代主料用于 MPS/MRP 判断是否产生替代。拆卸成本比例用于拆卸时原材料占成本的比例。
- BOP：把子项明细拆到生产线的工位/工序。同一生产线、相同项次的分子之和必须等于子项明细的分子。新增 BOP 时只插入用量类型为变动且发料方式不是不发料的行，工位默认该生产线的送料工位。同步 BOP：子项增行或改数量、物料后同步；删行自动同步删除；已按工位拆分的数量不自动改，只标颜色。数据校验：项次是否都在 BOP 中、相同项次分子是否一致。复制行只能改工位/工序和分子。
- 替代设置限制：配置件作子项、特征件作子项、特征件的子项、返还件、虚拟件，都不能设替代。
- 同步更新：更新在制的生产/委外用料清单（树形维护页写「生产\委外用料清单」）和计划 BOM。物料清单页写到 3.4 即止。
- 树形维护：左树右单，可对选中的产品或半成品新增、维护 BOM。选项可「不显示原材料」（不显示物料主文件未勾「可为主产品」的物料）。支持批量提交、批量审核、选单、暂存、保存、修改（状态为暂存、创建、重新审核）、复制。保存后若有 BOM 版本，反写到父项的子项 BOM 版本。有分配策略时，已审核清单可分配/取消分配。通用树形维护页还有批量分配、同步更新、树形复制（整体或部分升版）；餐饮_树形维护页没有这三项。字段说明指向物料清单。
- 产品配置：对预先定义的可配置产品组合组件。可改物料清单上勾了可修改、可替换、可选择的子项。场景原文是电脑：主板、CPU、硬盘、内存，接单后才定型号；显卡作为可选择的例子，内存作为可修改用量的例子。同一内容出现两页（餐饮_产品数据管理、餐饮_产品配置）。选项为「全部物料」或「可配置物料」。保存时配置件 BOM 版本为空则生成新的标准 BOM 并反写父项。仅配置件允许新增行；新增行用量类型不能为阶梯，子项类型不能为替代；只有配置界面新增的行能删。提交、审核、反审核为批量。
- 替代方案：生产中用其他物料替代。路径：【生产制造】—【工程数据】—【替代方案】。策略、方式、替代主料含义与 BOM 子项相同。替代类型：BOM 替代（BOM 子项）、订单替代（成品不同辅助属性之间）。生效日期 ≤ 失效日期，同一组替代物料日期相同。主物料与替代物料的属性只能是自制、外购或委外。分子、分母、优先级（数值越小越高）、BOM 版本、辅助属性。唯一性：不允许物料编码 + 辅助属性（影响计划）+ BOM 版本（影响计划）相同的分录。一个方案只对一个或一组主物料。可设组合替代和非组合替代。主物料有且仅有一个替代主料；同优先级的替代物料有且仅有一个替代主料；MPS/MRP 按替代主料的供给判断，非替代主料随替代主料成套替代。场景原文列举：订单取消、工程变更、客户需求变化、预测或计划不准导致呆滞，为降库存或降成本或及时响应而替代。查询页极短：看某物料的替代物料；替代主料「主料会自动勾选，替代料不会勾选」。
- 工作日历：自然日历去掉非工作日后顺序编排，用于主生产计划、物料需求计划、能力计划、工序计划。标准日历套工作日历模板，可把工作日与非工作日互改，且只能改当前日期以后。个性日历的适用对象类型：组织机构、部门、工作中心、资源。继承条件同时满足才继承：上级已设个性日历、下级与上级用同一标准日历、下级自己没做个性设置。流程图未 OCR。名称字段的说明写成「标准工作日历的编码」。
- 页名「餐饮_工作日历模板」的正文是班制，不是日历模板：由班次组成，日工作小时为各班次之和且不超过 24；序号、开始/结束、工作小时数自动带出不可改。班次、班组、真正的日历模板字段、加工数据参数均无正文。工作日历设置页只重复了日历模板、适用对象类型、班制和同一套继承条件。

## 3. 可复用机制（面向电子元器件 ERP）

- 渠道订货窗口：**高**。固定周期、固定日期、单双日、星期四种规则，一店一有效期一条规则；后台任务生成排班；排班之外禁止要货。规则或路线变更时只重算未来、保留历史。电子元器件对经销商、分公司的叫货日可直接对标。受控单据里的「历史食品销量要货」不必做（`餐饮配送管理_配送路线管理.md`）。
- 订货执行监控：**高**。已排班未订货、未排班已订货分色；已订货的判定是当天已审核的要货申请。可用于渠道是否按窗口下单（同文件）。
- 配送路线主数据：**高**。有效期、组织内共享、同一节点有效期不重叠、地址取自组织并可改、节点按路线顺序展示。把「门店」换成经销商仓或寄售仓即可。集配中心对总仓/区域仓（同文件）。
- 车辆与在途承运信息随单携带：**高**。出库单生成时取路线有效期内的车牌、驾驶员、联系方式，收货单页签原样携带。适合元器件干线/市配，不依赖餐饮（同文件）。
- 直拨与统配两种供给：**高**。直拨：需求节点无采购权，货不进总仓库存，总部对供应商挂应付，节点只增库存或应收。统配：先入总仓再配送，总部对供应商挂应付。对应元器件的供应商直发客户/分销仓，与区域仓统配。中央厨房、加工品统配不取（`餐饮配送管理_总部配送管理.md`）。
- 统采直拨的关闭与入库落点：**中**。统采直拨转换可整单关闭或按行关闭，且采购订单只生成门店采购入库；统采统配的汇总行不可关闭。单据类型名为直拨采购申请、直拨采购订单、直拨采购入库。规则可用，流程图未 OCR，入库单本身无字段页（同文件）。
- 多节点要货汇总：**高**。按配送属性把需求分成直拨汇总、统配汇总，标准汇总不受属性限制。总部改批准数量；需采购、需加工默认等于批准数量；剩余 = 批准 − 已发。按物料看库存合计。缺货数量公式原文是库存总数量减批准总数量，引用时要连公式一起看，不要只看「缺货」二字。供应商取默认采购价目表，门店专属价目优先于门店为空的价目。这是渠道要货与总部分货最接近的现成结构；原文没有名为「分货单」的单据（同文件）。
- 汇总单一单多下游：**高**。直拨走采购申请或采购订单；加工品统配走加工计划或加工订单，并可同时按批准数量走出库；原材料统配走出库。合并维度分别为结算与供应方一致、计划组织一致、配送组织一致。下游审核回写、反审核回冲。元器件可把「加工」换成自制工单或委外，保留「有货即发、不足转采购/生产」的分叉。自动生成依赖参数，参数两页不一致，落地前要先定一版（同文件）。
- 按路线拣货再出库：**高**。拣货数据只来自已审核汇总，排除允许直拨的物料，数量 = 批准 − 已发，顺序按路线倒序，拣货完成反写已拣货数量后再生成出库单。这是把要货变成发运批次的机制。暂存还是保存，原文两处不一致（同文件）。
- 出库、退货、批号与效期：**高**。应发/实发、可用库存状态、关账日之后才能做业务日期、承运商与运输单号、批号与保质期推算到期日。元器件对应批次、日期码、湿敏或质保截止。跨组织时货主 ≠ 结算组织才产生组织间结算，细则不在本文件（同文件）。
- 收货差异闭环：**中**。异常单从有异常数量的门店收货单选出；多收、少收、异常金额有公式。处理后生成配送补货单或配送退货单，但两处对多收/少收的去向写反了，不能直接编码。门店收货单本身无字段页（同文件）。
- 退货补货：**中**。退货单由出库单关联生成。参数「配送退货时自动创建补货申请」只在补料方式为「创建补料订单」时，自动生成补货要货申请。补货申请单无字段页（同文件）。
- 配送价目表与限价：**高**。按物料或物料类别、数量段、含税/不含税、有效期、影响价格的辅助属性取价；取不到不带价。限价三档：不控制、预警、禁止保存。上级定价后分发，使用组织不能改；可整单失效或按行业务失效。元器件对经销商的供货价、阶梯价可对标。币别变更清价目表、改数量重取价，同样通用（同文件）。
- 调价切段：**高**。调价单审核后按物料 + 单位 + 辅助属性 + 数量区间插入或截断原价目有效期，避免两段重叠；新生效日早于原生效日则失败。适合协议价变更留痕。调后单价与调价幅度两条公式互相定义，实施时要定哪一个是输入（同文件）。
- 加成/折扣：**中**。默认加成表 + 分录顺序匹配，按折扣率或折扣额、数量段、物料类别。可用于区域或客户类别的加价。表头字段说明大量复制价目表措辞，加成对象如何对应到「门店类型」只有场景句、没有字段枚举（同文件）。
- 净需求与安全库存：**中**。要补货参数：净需求 = 毛需求 − 现有库存 + 最小库存 + 安全库存。备料计算：仅当可用 − 安全 − 毛需求 < 0 时，净需求取相反数，并只显示大于 0。两式不完全相同（有无最小库存、库存用「现有」还是「可用」）。备料还可按自制/采购过滤，辅助属性可合并或拆开。历史食品销量这条链路不取。历史物料用量的「同期」要素可以借鉴，但没有计算公式页（同文件）。
- 预估审核后的分流：**中**。预估要货单审核时，配送物料生成要货申请，自采物料生成采购申请或采购订单。预估单本身无字段。自采/统配的分流对分销商门户有用（同文件）。
- 渠道物料上下架：**高**。下架且已执行则不能要货、不能配送；执行日到达后不可反审核、不可作废未执行行以外的已执行行。适合停产物料、受控物料在渠道目录中的生效日（同文件）。
- 超发与零金额闸门：**中**。超申请配送可关，打开时还写明取物料收发上限（仅较新的那页参数）。金额为 0 可预警、不控制或禁止提交，覆盖订货、收货、退货、采购入退。参数名与说明不一致，且另一参数页没有这两项（同文件）。
- 出库审核生成收货单：**中**。状态可落到创建、提交或审核；节点没有默认仓库则只能暂存。收货单字段不在本批，只能确认有这个自动下推（同文件）。
- 配送组织职能分离：**中**。配送组织要库存职能；采购组织要采购职能；加工组织要加工职能；有委托时还必须存在委托采购或委托加工关系；配送员/配送组挂在有配送职能的组织上。元器件多组织可保留「履约组织 / 采购组织 / 生产组织」分离，星空的职能名称不必照搬（同文件）。
- BOM、阶梯用量、损耗、发料与倒冲：**高**（生产工程，不是配送二期）。固定/变动/批量（阶梯）用量、分子分母、固定损耗与变动损耗率、成品率、联副产品成本权重、跳层、关键件、最小包装发料、超发控制、直接领料/倒冲/调拨、汇报倒冲与入库倒冲、提前期偏置、货主。位置号原文写「插件位置」，可作装机位号的线索，本文件没有位号规则。这些页的路径仍指向生产制造工程数据（`餐饮配送管理_加工数据管理.md`）。
- 配置件选配：**高**（生产接单配置）。可替换、可修改、可选择；配置结果生成标准 BOM 并回写版本。原文例子是电脑主板、CPU、硬盘、内存、显卡，与元器件整机/模组配置同构，与菜谱无关（同文件）。
- 替代与组合替代：**高**。混用、手工、整批；替代与取代；BOM 替代与订单辅助属性替代；生效区间；替代主料成套；影响计划的辅助属性和 BOM 版本参与唯一性。配置件、特征件、返还件、虚拟件不能设替代。适合元器件缺料替代、AVL（同文件）。

- 工作日历继承：**中**。标准日历加个性例外，下级在同模板且未单独设置时继承上级。需求日、能力日可复用。模板页正文错挂成班制，模板字段缺失（同文件）。
- 班制 24 小时约束：**中**。日工作小时为班次之和且不超过 24。班次、班组无正文（同文件）。
- 加工执行与领料差异：**中**。计划、汇报、请检、检验、完工、合格/不合格/返工入库、完成百分比与合格率；领料套数与领料比例；应领/已领/倒冲差异；来料不良、作业不良、补料、报废分列。业务状态到结案、结算。适合元器件工单达成和用料差异。加工订单本体不在本文件，报表列不能反推订单字段（`餐饮配送管理_餐饮加工管理.md`）。
- 不良与自动入库参数：**中**。来料不良退料、作业不良退料、不合格品入库、报废品入库各有默认库存状态。检验完成或不良品处理审核可自动生成加工入库。反审核可按在制是否变负做弱控、强控或不控制。拣货扣减未审核领料和补料。关账前下达的订单是否允许变更、拆分可配置。这些单据页均未收录，只能当参数清单（同文件）。
- 套件组装拆卸：**中**。按 BOM 级次展开，可选是否含损耗、是否只带需发货子项；组装成本 = 子件 + 费用；拆卸费用按成本拆分比例分摊；允许父项与子项同编码、只改变辅助属性。促销捆绑是原文对组装的定义句，机制本身是库存套件，可用于模组捆套、拆解回收。销售订单生成组装单的字段映射没有展开（同文件）。

- 净需求两套公式并存。智能要货参数：净需求 = 毛需求 − 现有库存 + 最小库存 + 安全库存。备料计算：可用库存数 − 安全库存数 − 毛需求 < 0 时，净需求为该式的相反数，且只展示大于 0；同一字段说明后半段重复且把「如果勾选」写了两次。备料计算没有「最小库存」。
- 缺货数量 = 库存总数量 − 批准总数量。库存大于批准时该值为正，原文仍称缺货，没有再解释。
- 配送毛利润字段 = 配送单价 × 配送数量。概述写报表反映收入、成本、利润，字段说明没有减成本。
