# 财务会计／合并报表系统

## 1. 功能点

**总体流程**

合并报表系统覆盖子公司个别数采集、调整抵消、多口径合并并行出具全流程，支持多会计准则、多报表样式、多合并结构并行。

**基础资料与参数设置**

- 维护报表项目、项目数据类型、金额单位、抵消类型、交易种类、报告维度等基础资料
- 管理取数参数（参数类型：基础资料、辅助资料、日期、整数、文本）及自定义函数（自定义SQL / 自定义接口两种扩展方式）
- 配置项目取数公式、项目外币折算方案、调整分录模板、抵消分录模板
- 设置合并报表系统参数（全局参数 / 合并方案级参数）

**合并准备**

- 维护股权关系（直接持股、间接持股、交叉持股，支持自动计算）
- 新增、启用、变更合并方案，执行股权关系检查
- 支持"统一在控股公司核算"与"逐层核算"两种权益核算方法
- 外币折算：维护外币折算方法与外币折算方案，折算子公司外币报表

**报表模板**

- 制作报表模板（预置5张常用报表样式）、定义模板样式方案
- 报表模板分发：提交→审核→分发给各组织或合并范围
- 个别报表模板修改（限"允许修改"的模板，修改后需重新提交审核）

**个别报表编制与上报**

- 编制固定样式和动态样式两类个别报表
- 个别报表检查（表内勾稽和项目勾稽关系，支持单张和批量）
- 个别报表上报（支持一表多报）→ 个别报表接收 → 个别报表反接收
- 上报报表进度看板、个别报表催报、催报设置

**调整与抵消**

- 报前调整分录：子公司统一会计政策调整，编制调整分录作用于调整报表
- 集团调整：手工新增或自动生成权益类 / 非权益类调整分录
- 往来抵消：基础设置→上报往来明细报表数据→往来数据查询与核对→自动生成抵消分录
- 权益抵消：基础设置→上报内部权益投资明细报表数据→维护持股比例→自动生成抵消分录
- 交易抵消：基础设置→上报明细数据→往来核对→自动生成抵消分录
- 内部会计事项自动抵消（基于预置权益/往来/交易抵消分录模板）

**汇总与合并报表编制**

- 汇总报表编制（子集团 / 总集团对个别报表加总）
- 工作底稿编制（汇总个别报表数据，经调整、抵消计算合并数）
- 合并报表编制（已接收个别报表加总后经调整、抵消计算合并数）
- 动态罗列表编制

**查询分析与期末**

- 合并构成分析（项目构成查询分析）
- 动态罗列项目数据查询、项目数据查询
- 合并报表关账 / 反关账
- 合并报表导出（列表信息、EXCEL格式、Fml格式，支持多合并范围批量导出）
- 合并报表数据授权

## 3. 状态流转、下推和反写

**个别报表完整状态链：**

```
编制中 → 提交 → 审核 → 上报 → 接收
```

- 撤销上报前提：状态为"上报"且未接收，撤销后返回编制中
- 反接收前提：状态为"接收"，反接收后返回"在制的上报状态"
- 上报前提：报表已审核；若系统参数【上报报表报前必须检查】启用，则上报前还须完成勾稽检查

**报前调整备份：**

- 参数【报前调整备份调整前报表】勾选后，上报前做报前调整会产生调整备份报表，【调整备份】字段值为"是"，该备份报表不可编辑及删除；如需操作须先删除报前调整数据

**调整分录状态：**

- 调整分录支持新增、查询、修改、删除、审核操作
- 已审核的调整分录通过【重算】更新到当前报表
- 反审核已重算到报表的调整分录后，通过【重算】系统自动扣减相应报表项目数据
- 操作顺序要求：先报表重算→确认数据无误→执行报前调整→做调整分录界面重算→保存、审核报表；已做报前调整后慎用报表客户端【重算】，否则会覆盖调整分录重算结果

**抵消分录：**

- 自动生成后需【审核】，审核后方可参与合并报表计算

**工作底稿编制前提：**

- 个别报表已接收、调整分录已审核、抵消分录已审核

**调整报表编制前提：**

- 合并方案已启用、个别报表已接收、调整分录已审核

**汇总报表：**

- 子集团的汇总报表将作为集团的个别报表参与集团的汇总

**报表模板流程：**

```
提交 → 审核 → 分发
```

- 个别报表模板修改流程：反审核报表模板 → 修改 → 提交 → 审核

**合并方案启用状态：**

- 新增时默认"未启用"→【启用】→"已启用"→【反启用】→"未启用"
- 已启用的合并方案才可使用；合并方案启用是设置系统参数的操作前提

**合并方案版本变更：**

- 调整合并结构后执行【变更】，向导式流程：①设置新版本启用日期及变更原因 → ②删除新版本启用日期当期及之后期间的汇总报表、工作底稿、合并报表（删除不可恢复） → ③完成
- 支持版本比较、版本差异对比、报表回滚（回滚到上个版本）；新版本启用日期早于旧版本启用日期时不支持回滚

**合并报表关账：**

- 以合并方案 & 周期类型 & 合并期间为单元进行关账或反关账
- 关账后，所属合并范围的报表、调整分录、抵消分录只可查看不可编辑

**重算操作：**

- 工作底稿、调整报表、汇总报表均通过【重算表页】或【全部重算】（快捷键F9）进行数据计算，保存完成编制

**集团调整：**

- 自动生成路径：【自动生成】→【生成权益类调整分录】/【生成非权益类调整分录】
- 借贷允许不平衡保存

## 5. 与电子元器件制造的相关度

**判断：低**

理由：

1. 合并报表系统定位为企业集团层面的合并财务报表编制工具，核心使用场景是母子公司合并、内部交易抵消、权益核算，而电子元器件制造企业自研ERP的初期核心诉求通常集中在生产计划、物料管控、成本核算、供应链协同，而非集团合并报表。
2. 本模块对生产、供应链单据（如生产领料单、完工入库单、采购订单、销售订单）的直接依赖原文未见，仅通过自定义函数间接可取应收款、存货余额等核算结果数据，属于下游消费而非直接对接。
3. 该模块的启用前提是已存在多法人/多组织的合并报表需求；单一法人的制造企业无需使用本模块。
4. 电子元器件制造企业如存在上市合规或集团管控场景，未来可能需要本模块，但属于中后期需求。

**若未来需对接本模块，生产/供应链单据需预留的字段或接口（仅有笔记依据的）：**

- 存货相关单据需能向**存货余额表**提供标准核算数据，供合并报表取数公式引用
- 应收款相关单据需能向**应收款余额表**提供标准核算数据（原文自定义SQL示例已引用 `t_AR_receivable`、`t_AR_receivableEntry`，字段 `FALLAMOUNTFOR` 价税合计）
- 应付款相关单据需能向**应付款余额表**提供标准核算数据
- 物料主档需支持按**物料编号范围**过滤（原文自定义SQL过滤条件已涉及）
- 组织/部门主档需支持按**部门编号范围**过滤（原文自定义SQL过滤条件已涉及）
- 采购、销售业务需能关联**采购价目表**、**销售价目表**，以支持合并报表取数来源引用
