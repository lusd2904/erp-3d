## 【页面】html5主页
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=html5%E4%B8%BB%E9%A1%B5

====== 1 功能描述 ======
金蝶云系统支持HTML5端的应用。可以在跨平台的各种移动设备上使用，同时支持各主流浏览器使用。
金蝶云系统提供了HTML5的主页布局，更加聚焦工作以及社交。

**使用前提**
HTML5端支持的浏览器，如下：
    1）	Internet Explorer 简称IE,微软公司旗下浏览器。版本11及以上。
         官网网址: http://windows.microsoft.com/zh-cn/internet-explorer/
    2）	Google Chrome浏览器, 简称Chrome,Google旗下浏览器。版本37及以上。 
        官网网址: http://www.google.cn/chrome/
    3）	Firefox浏览器,简称FF浏览器,Mozilla公司旗下浏览器。版本35及以上。 
        官方网址: http://www.firefox.com.cn/download/#more
    4）	Safari浏览器,苹果公司旗下浏览器。版本5及以上。（已停止对windows系统的支持）
        官方网址: http://www.apple.com/cn/safari/
    5）	Opera浏览器,Opera旗下浏览器。 版本27及以上。
        官方网址: http://www.opera.com/zh-cn
        

====== 2 HTML5登录======
  - HTML5登录网址：http:机器IP：端口号/k3Cloud /html5/Index.aspx；
  - HTML5端提供HTML5的专属登录界面，聚焦用户及其密码。

====== 3 HTML5主页 ======
金蝶云对HTML5端应用，提供了专属的主页。
具体介绍如下：
=====3.1 快速查找=====
快速查找是查看业务单据的统计数据，例如：未审核销售订单、我的客户；
  - 快速查看提供了三个自定义配置内容；
  - 在业务单据列表设置了过滤方案，并将其【发布到快速查看】；
  - 用户重新登录金蝶云系统后，即可查看统计数据；
  - 通过【编辑】实现快速查找方案的编辑、显示顺序调整。

=====3.2 常用功能=====
  - 展示用户从主控台菜单添加的菜单内容；
  - 通过【编辑】可以进行常用功能的顺序调整、删除和修改；
  - 常用功能的允许修改名称；
  - 常用功能的允许修改图标，可以选择预置图标或者自定义图标（需要手工录入图标的名称）。

=====3.3 我的云之家=====
  - administrator登录，则展示云之家团队的开通情况，以及如何开通的操作步骤指引；
  - 普通用户登录，如果云之家已经开通，则可以直接进行交流。

注意：HTML5主页暂不支持布局的大小和内容的调整。

## 【页面】html5流式布局
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=html5%E6%B5%81%E5%BC%8F%E5%B8%83%E5%B1%80

====== 1 功能描述 ======
金蝶云系统支持HTML5端的应用。可以在跨平台的各种移动设备上使用，同时提供了单据流式布局应用，通过导航控制栏来控制页签的展示和定位，通过上下滚动条查看内容，让操作更加流畅，更加符合互联网的使用习惯。


**使用前提**
HTML5端支持的浏览器，如下：
    1）	Internet Explorer 简称IE,微软公司旗下浏览器。版本11及以上。
         官网网址: http://windows.microsoft.com/zh-cn/internet-explorer/
    2）	Google Chrome浏览器, 简称Chrome,Google旗下浏览器。版本37及以上。 
        官网网址: http://www.google.cn/chrome/
    3）	Firefox浏览器,简称FF浏览器,Mozilla公司旗下浏览器。版本35及以上。 
        官方网址: http://www.firefox.com.cn/download/#more
    4）	Safari浏览器,苹果公司旗下浏览器。版本5及以上。（已停止对windows系统的支持）
        官方网址: http://www.apple.com/cn/safari/
    5）	Opera浏览器,Opera旗下浏览器。 版本27及以上。
        官方网址: http://www.opera.com/zh-cn
        

====== 2 HTML5单据流式布局特性======
  - 提供单据流式布局应用，更新符合互联网的使用习惯；
  - 通过右侧边栏页签勾选配置，可以快速调整单据展示内容；
  - 点击右侧栏的导航节点，可以精准定位页签内容，便于快速查找和录入数据；
  - 支持用户自定义个性化的界面布局。

====== 3 HTML5单据流式应用 ======

  - 流式布局的侧边栏，通过勾选菜单，可以快速调整单据内容，展开或者隐藏相应单据页签；
  - 流式布局的侧边栏，通过点击菜单，可以快速导航内容，精准定位到相应单据页签；


====== 4 HTML5单据流式配置 ======

通过流式布局配置，可以实现单据界面的个性化设置，满足用户个性化应用需求。

 系统预设了默认的布局，可以基于预置方案进行个性化配置，配置入口：【单据工具栏】->【选项】->【流式配置】。
  
  - 表单视图：表单视图默认准确读取当前单据使用的视图，参考https://vip.kingdee.com/article/352953716783126528，可以根据实际应用单据类型调整视图；
  - 启用配置：启用配置是采用流式布局方式显示，不启用则用的是框架布局方式；
  - 启用序号：可以调整单据页签的显示顺序；
  - 启用标题：设置单据页签的显示名称；
  - 初始可见：设置单据是否显示当前页签；
  - 控制板定位：可以点击后直接定位到该页签，方便快速查看内容；
  - 启用控制板：可以通过右侧的控制栏控制该页签的可见性、定位等

HTML5流式布局支持全局批量配置
  - 目前Html5界面下单据可以支持全局性设置流式布局，包括基础资料和单据，比如：在BOS中，对基础资料如客户或者供应商添加了多个字段后，发现在Html5中打开对应界面，部分字段显示不全，需要统一调整流式配置。
  - 若用户自己配置了流式配置，则优先按自己自定义的配置方式显示。否则对所有用户都是调整后的效果。

HTML5流式布局的单据支持导航记忆布局
  -单据界面，比如采购订单，在侧边控制栏勾选“付款计划“，关闭重新打开采购订单后“付款计划”保留之前的勾选效果，提升操作效率。
  -流式布局单据，打开右侧导航栏，勾选调整显示与隐藏页签后，关闭再打开可以记忆调整后的状态

====== HTML5登录身份 ======

HTML5端提供四种用户身份认证，分别是我是财务人员、我是供应人员、我是销售人员、一般员工，HTML5端新登录用户可以自行认证身份，系统自动匹配对应的卡片主页内容。方便新增用户通过用户身份认证后，可以在主页快速查找、执行自己的业务，给予清晰正确的引导。

需要注意：新增用户只有一次选择机会，一旦选择后，后续再不能调整身份认证。


====== HTML5二维码登录 ======

HTML5支持金蝶云账号、云之家扫码、金蝶AI星空账号三种登录方式。

**金蝶云账号:**

  - 当前用户必须为注册用户；
  - 使用注册用户的手机号和密码登录；
  - 第一次登录需要通过找回密码设置登录密码；
 
**二维码登录使用前提:**

  - 当前数据中心启用移动应用服务；
  - 当前数据中心配置了对应的云之家团队；
  - 用户在此云之家团队存在，且已与云之家用户映射。


**二维码登录**

  - 当前的注册用户模式下，新用户需要先用命名用户身份方式登录，激活改用户；
  - 激活后，切换到当前移动数据中心对应的云之家团队，扫一扫，金蝶云系统自动登录。
  
**温馨提醒**

  - 二维码30s自动失效，若二维码已失效，请点击刷新即可；
  - 必须先开通云之家集成服务，才能使用二维码登录。

====== KPI管理 ====== 

**功能说明**

定义企业用于绩效考核的KPI指标，为KPI指标量身定制取数公式，目的是支持KPI指标从财务及各业务系统中获指标数据。


**功能路径**

打开【财务会计】－>【报表】－>【移动KPI】－>【KPI管理】功能，新增KPI指标。



 ====== 字段说明 ======

|字段||说明|
|KPI指标||设置KPI指标的名称。|
|项目数据类型||为KPI指标指定项目数据类型，此项目数据类型与公式表达式的函数的项目数据类型一致。|
|指标类型||可以对KPI指标进行分类管理。此处可以新增KPI指标类型，如：企业盈利能力、长期偿债能力。|
|公式设置||选择适合KPI指标的取数函数设置取数公式。|

## 【页面】openapi开发
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=openapi%E5%BC%80%E5%8F%91

====== OpenAPI开发 ======

OpenAPI开发支持用户以零代码配置的方式，将企业版业务对象（如单据、基础资料）的操作（查询、保存、提交、审核、下推等）一键发布为 OpenAPI。发布的 OpenAPI 采用扁平化的出入参结构，严格遵循页面字段配置及 RESTful 规范，系统自动生成服务接口地址及服务契约，便于灵基调用。

===== OpenAPI开发操作说明 =====

新增 OpenAPI：点击“新增”进入 API 维护界面，录入 API 编码、API 名称、API 类型（标准API/自定义API）、业务对象、操作方式（新增/提交/审核/单据查询/查看/修改/工作流审核）、详细描述。
发布状态、版本号、请求地址 /v1/{isv}/{appId}/{formId}/{serviceName} 根据配置自动生成。

  请求参数:
   通过请求体定义入参，支持从业务对象字段批量添加或手工新增；可配置参数名称、参数类型、是否必填、默认值、说明、层级（参数在业务对象中所在层级，如：若参数为分录中的参数，则层级为2）及参数示例。

  返回参数：
   支持从业务对象批量添加返回字段，配置参数名称、参数类型、说明、示例、层级；若选择分录/子分录字段，必须同时选择分录标识。

  OpenAPI测试：
   OpenAPI保存后默认状态为“未发布”，用户可在维护界面点击“API 测试”打开弹窗，系统自动拼接 URL 并渲染请求参数，普通管理员用户无需 token 即可在系统内模拟调用，查看格式化返回结果。
   如果当前登录用户是administrator，则需要使用普通用户登录以后方可进行测试

====== OpenAPI操作日志 ======

通过操作日志可监控 OpenAPI 的调用情况，查看每次请求的详细信息，包括业务对象、接口路径、方法名、耗时、状态码等，用于排查异常和审计追溯。

日志列表包含以下字段：

| **字段**       | **说明**            |
| 业务对象       | API 操作的业务对象名称，如"采购申请单""采购订单""物料"等 |
| 请求时间       | API 调用的时间戳，格式为 yyyy/MM/dd HH:mm:ss |
| 客户端IP       | 调用方的 IP 地址 |
| 登录组织       | 调用时登录的组织名称 |
| 日志分类       | 日志类型分类，分为"业务"和"系统"两种类型 |
| 是否成功       | 调用结果："是"表示成功，"否"表示失败 |
| 请求ID         | 每次请求的唯一标识 |
| 数据中心ID     | 请求所属的数据中心标识 |
| 用户名         | 发起调用的用户名 |
| 应用ID         | 调用方所属应用标识 |
| 接口路径       | API 请求的 URL 路径 |
| HTTP方法       | 请求的 HTTP 方法，如 POST、GET |
| 服务类         | 处理请求的后端服务类名 |
| 方法名         | 调用的具体方法，如 BillQuery、View、Save、Audit、Push |
| 操作用户       | 实际执行操作的用户名称 |
| 耗时(ms)       | API 调用的响应时间（毫秒） |
| 状态码         | HTTP 状态码 |

## 【页面】业务数据日志明细
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%95%B0%E6%8D%AE%E6%97%A5%E5%BF%97%E6%98%8E%E7%BB%86

====== 1 功能概述 ======

通过查看明细、对比差异操作，打开“业务数据日志”等方式，都会打开数据日志的明细界面，按照不同方式传入的条件，展示对应的修改记录。

====== 2 操作说明 ======

字段：显示"单据实体名称.字段名称”的格式。

旧值：显示本次修改之前的旧值。

变更值：显示本次修改的变更值。

实体序号：依据修改日志中的分录内码ID，动态匹配该分录在当前最新数据中对应的分录序号。如果分录未开启序号或者单据头实体字段，则实体序号列显示 /，表示无法获取其分录序号。

注意：
  * 业务数据日志明细表因为可以批量查询多个单据多笔修改记录，因此会等待异步服务进行差异分析计算的结果（计算会有延时，测试时立即查看会出现旧值不显示）
  * 变通办法是使用业务数据日志汇总表或单据上配置“查看业务数据日志”操作，这2种方式因为只能查询一张单据的2笔数据的差异，系统发现异步服务未计算完成会自动转为实时方式分析差异数据。
  * 对于基础资料、辅助资料字段会采用显示编码或名称、下拉列表显示枚举名称的方式，便于用户阅读。
  * 系统还提供了旧值内码、变更值内码字段，默认是隐藏，可以通过选项配置显示。如果基础数据在使用过程中发生了名称修改，可以通过内码确定后台存储的真正数据值变化情况。

## 【页面】业务监控清理规则设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E7%9B%91%E6%8E%A7%E6%B8%85%E7%90%86%E8%A7%84%E5%88%99%E8%AE%BE%E7%BD%AE

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。

====== 操作步骤 ======
Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

## 【页面】主控台我的业务
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%BB%E6%8E%A7%E5%8F%B0%E6%88%91%E7%9A%84%E4%B8%9A%E5%8A%A1

======= 1 功能描述 =======

  - 我的业务主要是将业务数据转化为图表形式呈现，方便业务人员直观、形象地观察、分析业务的变化。例如：采购员可以通过业务图查看入库率或退货率的情况。
  - 目前业务图主要针对业务单据，提供了二维数据的显示，支持四种图表类型：柱状图、折线图、饼状图、透析图。业务图支持用户自定义配置，支持图表方案分享给其他人使用。
  - 业务图支持自定义配置，采用向导方式引导。支持图表方案共享，按用户的功能权限获取查看有权限的图表内容。
  - 系统预设角色已内置了对应的业务图表供用户选择使用。

**功能路径**

【首页】→【我的业务】→【更多】按钮

======= 2 操作说明 =======

=====2.1 配置图表方案 =====

业务图表方案配置采用向导的形式，配置流程分三步

**第一步 选择数据源**
  - 可以选择用户有权的业务单据作为数据源；
  - 若需要对图表方案进行共享，勾选【共享图表】选项，其他用户即可看到。

**第二步 图表方案配置**
       1、设置图标类型，柱状图、折线图、饼状图、透析图
       2、设置图标统计方式，分为默认、按月度及按状态
           选择默认只需设置X和Y，选择按月度和按状态，不仅需设置X和Y，还需设置统计字段。
           1）默认只需选择X和Y的就可以，X和Y选择来源于业务单据的字段。 
              比如：要统计采购订单按供应商的采购金额，那么X选择供应商，Y选择价税合计即可。
           2）选择按月度，统计字段可以选择单据上日期相关字段。
              比如：要统计采购订单按供应商月采购金额，需要按照采购日期的月度汇总显示数据，那么X选择供应商，Y选择价税合计，统计字段设置为采购日期；
           3）选择按状态，统计字段可以选择单据上状态相关字段。
             比如：要统计关闭状态采购订单按供应商的采购金额，需要按照关闭状态汇总显示数据，那么X选择供应商，Y选择价税合计，统计字段设置为关闭状态；
**第三步 设置数据范围**
  - 支持时间围、数据范围的设置以及高级过滤，支持组织隔离。
  - 时间范围根据单据日期字段来设置起始时间和截止时间；
  - 数据范围根据单据上面的状态字段、基础资料字段或用户字段等来设置具体的数据范围；
  - 高级过滤采用通用过滤条件。
  - 务必配置数据范围，缩小图表的展示数据，以避免影响用户登录系统的体验性；

**注意**
  - 由于图表是使用控件自带的图表统计功能，只能满足简单的二维报表数据的图形化展示。多维度的取数以及更多内容的分析，建议通过经营分析平台解决。
  - 业务图表的配置尽量以5个为佳，以避免登录时图表方案取数的性能损耗，影响用户使用系统。
  - 业务图表的来源仅支持业务单据，报表不支持，建议可以使用经营分析平台解决。

=====2.2 查看图表方案 =====

  - 点击【更多】打开业务图表列表查看用户可以使用的业务图表方案。 
  - 点击【获取共享图表】，可以看到系统预设的图表和其他人分享的图表，前提是用户有该图表对应单据的查看权。
  - 系统预置了图表方案，与预置角色绑定，当前登录用户具有该角色即可看到图表方案；
  - 用户可以根据个人需要调整或者删除图表方案；

=====2.3 图表展示 =====

  - 用户登录金蝶云系统后，系统根据当前用户的功能权限以及业务图表方案的取数规则进行取数，并展示对应的图表；
  - 在我的业务通过翻页符查看下一图表的数据
  - 如果当前用户没有图表方案中业务对象的功能权限，即使有图表方案，系统也不会取数。

## 【页面】主页方案
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%BB%E9%A1%B5%E6%96%B9%E6%A1%88

====== 1 功能描述 ======
主页管理是新版主页功能，为Html5端和GUI客户端主页定制提供功能。主页管理包括：卡片类型管理、卡片管理、主页方案管理。

**功能路径**

【系统管理】→【门户管理】→【主页管理】

====== 2 卡片类型管理 ======

卡片类型支持新增、修改、删除、禁用，用户可根据需要维护卡片类型。

系统根据企业需求预置了多个卡片类型，包括：数据汇总类卡片、向导式卡片、单据列表卡片、轻分析卡片、信息中心卡片、星空Live卡片，支持企业根据需要自定义卡片类型。

   - 数据汇总类型卡片是针对单据列表方案统计单据数卡片，设置显示名称，选择单据和方案接即可。最多支持设置三个汇总，可以是同一个单据的不同方案，也可以是不同单据的方案；
   - 向导式卡片是引导卡片，用户可根据业务需要定义业务流程引导，方便新员工或是初次使用系统员工快速应用系统。向导式卡片支持功能引导、文字引导、外部链接引导，每一种引导方式都支持设置帮助文档，针对当前引导节点的帮助说明。
   - 单据列表类卡片可显示单据简要信息，用户可根据需要设置单据列表的单据显示字段，选择单据和方案，选择显示字段即可在卡片展示单据信息；
   - 轻分析卡片为数据分析图表卡片（需要购买轻分析许可，客户端暂不支持），通过制作卡片向导创建轻分析卡片，并且选择到主页即可；
   - 信息中心卡片为原提供待办、在办、已办、流程、监控、普通消息内容，用户可选择待处理任务列表及其过滤方案，并且设置显示字段即可；
   - 卡片类型新增，定义卡片类型对象，设置关联对象即可，具体可参考预置卡片类型；
   - 星空Live卡片是数据分析卡片，以指标化的方式查看金蝶AI星空的业务单据和数据指标。另外，出厂预置丰富分析主题，支持自定义业务指标。


====== 3 卡片管理 ======
卡片支持新增、修改、删除、禁用、分配，用户可根据需要维护卡片。

系统预置了多个卡片，包括：常用功能、常用功能分组卡片、待办任务、监控消息、人人报销、企业新闻、管理员引导、我的成长、热门活动、星空Live卡片，用户可根据需要自定义卡片。

支持管理员制作卡片分配给用户和角色，也支持用户个性化制作卡片。
   - 新增卡片，选择卡片类型，设置卡片内容，审核即为有效卡片；
   - 分配卡片，选择已审核卡片分配，支持分配用户或是角色，分配后用户才能看到该卡片并选择到主页；
   - 用户制作卡片，用户主页点击编辑，通过制作卡片可新增卡片，并且选择到自己的主页；


====== 4 主页方案管理 ======
主页方案支持新增、修改、删除、禁用、分配，用户可根据需要维护主页方案。

系统预置了普通用户主页，包括:常用功能、待办任务、监控消息、人人报销、企业新闻、我的成长、热门活动卡片；

系统预置了管理员主页，包括：常用功能、待办任务、监控消息、企业新闻、管理员向导、我的成长、热门活动卡片；

   - 新增主页方案，选择主页需要展示卡片，并设置主页显示顺序。建议在Html5端创建主页方案，支持可视化调整，可鼠标拖动调整卡片位置；
   - 分配主页方案，选择已审核主页方案，分配给用户或是角色，支持分配为默认方案，分配后用户登录主页即为默认主页方案；
   - 用户个性化设置主页方案，用户从主页点击编辑，可通过制作卡片新增卡片，也可通过添加卡片选择已有卡片到主页，完成即为保存为用户主页；

====== 5 用户端主页管理 ======
用户可根据需要自定义主页内容，支持制作卡片、添加卡片、移除卡片、编辑卡片等。

用户登录显示为默认主页，可通过主页编辑维护自己主页；

   - 制作卡片，制作卡片跟管理员制作一致，但是用户只能选择到自己有权限的菜单等方案；
   - 添加卡片，用户能选择到分配给自己的卡片和自己创建的卡片；
   - 移除卡片，可选择需要移除的卡片点击移除即可；
   - 编辑卡片，有些卡片是可编辑卡片，用户可点击编辑维护卡片内容；
   - 调整位置，支持卡片拖拽移动到其他位置，从而调整主页展示；
   - 刷新，数据汇总卡片为后台执行计划计算，如急需查看可点击刷新按钮刷新数据。待办等信息中心卡片为页签切换刷新；（基于性能考虑）


新版主页定制可参考帖子：https://vip.kingdee.com/article/245501273703662848

## 【页面】云报告
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BA%91%E6%8A%A5%E5%91%8A

====== 1 功能描述 ======

系统管理员生成的云报告都可通过云报告列表进行云报告的查看，上传和获取专家诊断服务等。

**功能路径**
【数据中心管理】→【数据中心列表】→【云盾】→【云报告】

====== 2 字段说明 ======

  - 报告名称：云报告的名称；
  - 创建时间：云报告的创建时间；
  - 上传时间：云报告的上传时间；
  - 报告状态：云报告的状态，包括创建中，已创建，上传中，已上传，已诊断。


====== 3 功能操作 ======


===== 3.1 生成 =====
打开云报告生成向导，可按照步骤生成系统本地的云报告。

===== 3.2 查看 =====
已经生成的云报告，在列表选中其中一份云报告后，点击查看，可打开云报告进行查看和分析，只要是演示版就可以使用。

===== 3.3 上传 =====
已导入正式许可的环境，在列表选中其中一份云报告后，点击上传可上传到云健康中心。

===== 3.4 专家诊断 =====
上传云报告后，可提单反馈，以便服务部同事对云报告的情况和指标进行相关分析和处理建议，给予官方解决方案，系统管理员可根据专家建议进行优化处理。

## 【页面】云短信old
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BA%91%E7%9F%AD%E4%BF%A1old

======1 云短信概述 ======

===== 1.1 云短信概述 =====

云短信内容在V8.2版本下架。

在实际业务运作中，经常需要短信服务的支持，通过金蝶云的金蝶云短信服务，可以对金蝶云业务提供短信提醒，方便及时通知关键人员进行业务处理，让问题处理更顺畅。

===== 1.2 系统特性 =====
 
本系统主要包含以下应用：

  - 支持短信服务配置；
  - 支持短信套餐的余额查询；
  - 支持申请企业自定义短信签名；
  - 支持业务应用，包括业务单据操作、工作流、审批流的消息节点、系统广播消息等
  - 支持配置接收人，可以选择用户、单据上的用户以及自定义手机号；
  - 云短信配置的消息内容增加可以选择单据字段。

  
====== 2 云短信操作手册 ======


===== 2.1 短信服务配置 =====


[[短信服务配置]]，可以选择短信服务的提供商以及短信余额查询。

===== 2.2 云短信业务应用 =====

==== 2.2.1 业务单据操作 ====

**云短信单据参数配置**    
  - 产品路径：【基础管理】→【公共设置】→【单据设置】→【单据参数配置】；
  - 打开单据参数配置界面，选择业务单据，选择“云短信配置”页签；
  - 针对业务操作启用云短信，并配置云短信的接收人和默认内容；
  - 云短信接收人，可以多维度选择，包括：用户、参与人变量、手机号字段；用户来源于未禁用的用户列表；参与人变量是单据中用户属性字段及业务员属性字段，比如制单人、采购员等；手机号字段来源于单据头字段；
  - 云短信默认内容，可以直接输入，如需获取单据内容，可以采用“{”选择单据字段，目前支持单据头字段选择；
  - 可配置自动发送，操作后会自动发送短信给设置接收人。


**云短信的单据应用**
  - 云短信单据参数配置完成后，业务单据执行完成操作后就会弹出云短信界面，设置接收人（不仅可以选择系统内用户，还可以手工输入手机号），并设置短信内容，就会按所选所填的内容发送云短信；
  - 弹出云短信界面中接收人字段主要针对的是系统内用户，默认显示的是云短信配置的接收人，可在此重新选择系统内接收人；其他手机号可以手工补充追加接收手机号；
  - 弹出云短信界面中短信内容，默认是云短信配置的短信内容，可在此调整短信内容；
  - 注意，必须已购买云短信套餐，并在[[短信服务配置]]中启动云短信服务。
    比如：针对销售订单的保存操作启用云短信后，在实际执行保存销售订单后发送云短信，可以及时知会相应人员。
    
**温馨提醒**
  - 通过云短信单据参数配置，执行业务单据操作时弹出云短信界面是自动触发，不受权限控制；
  - 用户也可以在业务单据列表（比如销售出库单列表）增加【发送短信】按钮，进行人工操作发送云短信，若有此类操作需要，需在BOSIDE给将给业务对象扩展一个操作，绑定“发送短信”的点击事件，并为用户授予该操作的权限。


==== 2.2.2 审批流、工作流消息节点 ====

  - 在审批流消息节点，消息动作页签配置：通知方式勾选【发短信】；
  - 消息节点的接收人，在走到当前流程节点时，会接收云短信。

    比如：张三的采购订单获得审批通过后，通过配置云短信，张三会立即接收云短信，方便后续业务处理。
        张三收到云短信内容：【金蝶云】您发起的采购订单***已经审批通过，请知悉。
        
==== 2.2.3 系统广播消息 ====

  - 路径：【门户管理】→【系统广播】→【发布广播消息】，系统广播消息配置：发送方式勾选【云短信】；
  - 广播消息的接收，系统中未禁用的用户都可以收到云短信；
  - 注意：金蝶云短信未启用，系统广播消息不能发送云短信。

==== 2.2.4 B2B用户发送验证码 ====

  - B2B用户修改密码，可以发送短信验证码，输入后才完成修改密码的操作。

===== 2.3 短信发送查询 =====

  - [[短信发送]]，记录短信发送成功的情况；
  - [[短信发送异常日志]]，记录短信发送失败的情况。

## 【页面】初始化实施服务
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%88%9D%E5%A7%8B%E5%8C%96%E5%AE%9E%E6%96%BD%E6%9C%8D%E5%8A%A1

======1 初始化实施服务概述 ======

===== 1.1 初始化实施服务概述 =====
 
针对金蝶云上线的新客户，由于对产品熟悉不够，实施需要反复操作加上多方咨询才能完成，往往初始化周期过长。

面对企业的上线困境，金蝶云推出业务初始化实施向导，引导客户自行实施，帮助企业快速上线。

目前提供了总账初始化，通过总账初始化向导，实现总账常用基础资料及常用核算维度来源基础资料的梳理与维护，总账管理参数的设置、科目初始化数据的维护，一气呵成地完成整个初始化工作。


===== 1.2 系统特性 =====
 
本系统主要包含以下应用：

  - 提供初始化向导（总账），按照初始化步骤及顺序提供；
  - 提供初始化基础资料清单；
  - 支持每个步骤完成状态标识，以及可视化，初始化结束后子系统状态自动为完成；
  - 支持单组织和多组织的初始化。
  
====== 2 初始化实施服务操作手册 ======

下面介绍总账的初始化实施过程，主要包括基础资料维护、总账参数设置、科目初始余额、结束初始化四个步骤。

产品路径：【基础管理】→【初始化管理】→【财务管理】→【总账初始化向导】。

若是多组织，需先选择具体的组织机构，若是单组织则直接按下面步骤操作：

第一步：基础资料维护

基础资料维护用于管理总账常用基础资料及其维护情况。

  - 点击【基础资料维护】图标，打开“基础资料维护”界面，即可看到总账实施的所有基础资料，并且是按照先后顺序展示的；
  - 每个基础资料都提供了超链接，点击后直接打开对应基础资料列表，方便维护，注意当前用户需要有此基础资料的维护权限；
  - 基础资料的【数据情况】用于标记是否存在了数据，可作为维护时数据参考信息，“是”表示有数据，注意预置数据也认为是有数据；
  - 基础资料维护完成后，执行【确认完成】操作，完成状态会自动更新为“是”，若发现有遗漏需要重新补充，可以进行【反确认】操作，并重新维护基础资料。
  - 若账簿和科目数据都是已审核未禁用，该基础资料不能进行确认完成，其他基础资料则不做此要求；
  - 所有基础资料维护完成并进行了标记确认后，向导中的【基础资料维护】图标显示标记（V），表示当前环节已确认完成。


第二步：总账参数设置

总账参数设置方便配置总账相关系统参数。
 
  - 点击【总账参数设置】图标，打开“总账管理参数”界面，直接总账参数，注意要求当前用户需要有对应操作权限；
  - 设置完成后回到向导界面，鼠标滑过向导中的【总账参数设置】图标，点击右上角浮出的【确认完成】按钮，则【总账参数设置】图标显示标记（V），表示当前环节已确认完成；
  - 要求要给当前账簿设置本年利润或利润分配科目，否则不能确认完成。

第三步：科目初始余额

科目初始余额方便维护科目的初始化余额。
 
  - 点击【科目初始余额】图标，打开“科目初始余额”界面，直接录入科目初始数据并确保试算平衡，注意要求当前用户需要有科目初始数据录入权限；
  - 科目初始余额录入完成后回到向导界面，鼠标滑过向导中的【科目初始余额】图标，点击右上角浮出的【确认完成】按钮，则【科目初始余额】图标显示标记（V），表示当前环节已确认完成；
  - 要求当前账簿的科目初始数据在综合本位币下必须试算平衡，否则不能确认完成。


第四步：结束初始化

结束初始化节点管理总账相关的结束及反结束初始化。

  - 点击【结束初始化】图标，打开“总账初始化”界面，直接进行总账的结束初始化或者反初始化，注意要求当前用户要有总账初始化操作权限；
  - 结束初始化操作完成后回到向导界面，当所有账簿都已经结束初始化，则【科目初始余额】图标显示标记（V），表示当前环节也已确认完成；


**温馨提醒**

  - 向导中“基础资料维护”和“结束初始化”环节，若所有内容都维护或者确认完成，本节点也自动完成确认，若对部分内容反确认，本节点会去掉确认完成标记（V）， 向导中“总账参数设置”和“科目初始化余额”环节，对应内容录入完成后，需要手动在本节点进行【确认完成】操作，同时也可随时执行【反确认完成】操作；
  - 启用多组织后，必须先设置好“组织机构”，不允许为空，要求当前组织属性=核算组织，且操作用户在当前组织下有基础资料维护、总账参数设置、科目初始化录入、结束初始化的操作权限；
  - 多组织下，基础资料需要注意基础资料控制类型，对于分配型，建议设置控制策略并进行分配；对于共享型，建议根据需要建控制策略并在创建组织维护数据，

## 【页面】初始化快速引入
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%88%9D%E5%A7%8B%E5%8C%96%E5%BF%AB%E9%80%9F%E5%BC%95%E5%85%A5

======1 功能描述 ======

企业新上线星空系统，需完善上线前的基本基础资料，快速建设期初单据，用户可手动在系统中逐一新增或利用系统原有的引入功能，由于原有的引入功能对引入的模板要求较高，使用较复杂，故，逐一新增或原有引入效率都较低，现推出【初始化快速引入】工具帮忙企业快速完成上线工作，提高企业实施效率。

**功能路径**

【基础管理】→【实施平台】→【实施管理】→【初始化快速引入】(用户赋予【初始化快速引入】功能权限）

======2 功能操作 ======

=====2.1 支持引入的业务对象=====

基础资料：员工、业务员、部门、供应商、客户、物料

期初单据：期初采购入库单、期初退料单、期初销售出库单、期初销售退货单、初始库存、期初应收单、期初其他应收单、期初收款单、期初收款退款单、期初应付单、期初其他应付单、期初付款单、期初付款退款单、科目初始数据、现金期初、银行存款期初、期初应收票据、期初应付票据


=====2.2 引入数据步骤 =====
1 选择引入对象--》2 选择引入模板--》3 选择数据状态--》4 字段映射（引入字段与星空字段）--》5 指定关键字段--》6 引入数据--》7 引入结果

引入条件：系统已启用期初日期/已启用模块，但未结束初始化

引入限定：只支持追加式引入，不支持覆盖式引入

## 【页面】区域格式
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%8C%BA%E5%9F%9F%E6%A0%BC%E5%BC%8F

====== 区域格式 ======
===== 功能说明======

国际化设置中区域格式的参数设置，便于统一管理，用户也可根据实际业务设置所需的区域格式。

===== 使用前提 =====

系统已预置了国际标准的区域格式列表，国际化设置中区域格式默认为中文（简体，中文）。用户也可根据实际业务需要设置对应的区域格式。

===== 功能路径 =====

区域格式列表：【基础管理】→【基础资料】→【区域格式列表】

===== 字段说明 =====
1.数字分组主要字段说明 
  * 小数点： 数字按照小数点分隔整数部分和小数部分，与数字分组符号互斥，不允许为空值。 
  * 数字分组符号： 数字按照数字分组符号分组，与小数点符号互斥，不允许为空值。
  * 数字分组： 定义数字分组，下拉选择。
  * 负号： 定义数字的负号。
  * 负数格式 定义数字的负号格式，下拉选择。
2.日期分组的主要字段说明 
  * 日期： 定义日期格式，下拉选择 
3.时间分组的主要字段说明 
  * 时间： 定义时间格式，下拉选择 

===== 操作说明 =====
区域格式设置 

  - 进入数据业务中心，点击主控台【国际化设置】菜单，打开国际化设置界面，点击【区域格式】按钮或者F8，弹出的区域格式设置列表中选择所需的区域格式作为系统级默认区域格式；
  - 点击【保存】按钮，设置成功。 
我的格式和时区设置 

  - 进入数据业务中心，当前用户下拉菜单中的【我的格式和时区】菜单，打开我的格式和时区设置界面，点击【我的格式】按钮或者F8，弹出的区域格式列表中选择所需的区域格式作为用户级的区域格式，
  - 点击【保存】按钮，设置成功。

注意：各业务系统单据、列表等所有界面上使用到数字、日期、货币、时间类型的字段需要首先按照我的格式设置中设定的格式输入和输出显示，如果我的格式未进行设置则按照系统格式的设置进行输入和输出显示。

## 【页面】实施项目
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%AE%9E%E6%96%BD%E9%A1%B9%E7%9B%AE

====== 1 功能描述 ====== 

引导Administrator进行定义实施项目，并分配实施任务到个人用户。

**功能路径**

【基础管理】→【实施平台】→【实施管理】 

 ====== 2 功能操作 ======

 ===== 2.1 主要功能 ===== 

ERP实施项目创建：

  - 项目定义
  - 选择子系统范围
  - 选择组织范围
  - 检查实施任务列表

ERP实施项目管理：

  - 实施任务下达
  - 实施任务执行
  - 实施任务完成/关闭，详见【[[实施任务|实施任务]]】介绍


===== 2.2 新增 =====

点击【创建实施项目】菜单，打开向导，逐步引导Administrator完成实施项目的定义与任务安排。

第一步： 项目定义

Administrator在此输入项目的编码、名称、计划上线日期，并可以在此输入项目的详细描述。点击【下一步】，进入“选择子系统范围”界面。

第二步：选择子系统范围

系统会自动获取许可文件的范围显示企业订购的子系统；如果还没有安装软件授权，则显示全部的子系统。Administrator选择需要实施的子系统。

点击【下一步】，进入“选择组织范围”界面。

第三步：选择组织范围

## 【页面】批改日志清理规则参数设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%89%B9%E6%94%B9%E6%97%A5%E5%BF%97%E6%B8%85%E7%90%86%E8%A7%84%E5%88%99%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。



====== 操作步骤 ======
Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

## 【页面】数字大屏链接设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E5%AD%97%E5%A4%A7%E5%B1%8F%E9%93%BE%E6%8E%A5%E8%AE%BE%E7%BD%AE

====== 1 数字大屏概述（V7.7新增） ======
===== 1.1 数字大屏概述 =====
 
为满足企业的数字看板投放、展示需求，方便管理层、客户及时了解业务数据，V7.7新增数字大屏相关功能，用户可通过设置生成大屏链接，复制到浏览器打开即可免登看板。

===== 1.2 系统特性 =====
 
本系统主要包含以下特点：

  - 大屏链接是通过第三方系统登录授权生成的。选择一个用户作为大屏用户（即使用这个用户生成免登链接），选择这个用户有权的看板即可生成大屏链接。
  - 复制链接到浏览器打开即可免登查看数字看板，链接可重复访问，不受用户超时退出和踢出影响，一直保持在线。
  - 一个大屏用户可生成多个大屏链接，同一个大屏链接可在多个屏幕上同时打开。
  - 基于安全考虑，大屏链接第三方系统登录授权需要启用白名单，并把大屏设备的IP地址加入到IP白名单。（V8.0新增）
  - 数字大屏功能是免费的，支持用轻分析自定义看板生成大屏链接，大屏用户有轻分析许可即可。
  - 数字看板由轻分析应用生成，大屏用户需要看板的权限，可以在轻分析应用授权里面修改看板的指定角色和指定用户。

## 【页面】数据瘦身向导
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E7%98%A6%E8%BA%AB%E5%90%91%E5%AF%BC

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。


====== 操作步骤 ======

使用清理向导，定制清理服务，选择清理项，执行时间和时长限制，勾选清理高级选项，以确保清理过程少产生日志。

进入清理向导，首先看到的是清理前的温馨提醒信息，并可以查看设置[[日志清理规则参数设置|日志清理规则参数设置]]，接着按向导步骤及流程执行。

第一步：

  - 系统会自动计算当前数据中心的的空间占用情况，并预估可清理空间大小；
  - 确定清理方案名称；
  - 根据需要选择清理项目，包括上机操作日志清理、监控执行情况清理、分配执行情况清理、临时表清理、批改日志清理
  - 注意：确保所有清理项目已经设置好[[日志清理规则参数设置|日志清理规则参数设置]]，特别是上机操作日志备份路径不能为空。另外所选清理项中至少有一个选项的清理空间大于0，否则不能建立清理计划。

第二步：

  - 确定清理时间和清理时长，可以选择立即执行，但是数据清理尽量选择在业务空闲期间执行；
  - 勾选选项【清理任务执行时，恢复模式修改为简单】，这样可以大大减少日志产生，避免日志文件过度膨胀；
  - 勾选选项【数据后，收缩数据库】，，以便回收数据文件占用空间，注意此过程耗时较长；
  - 点击下一步，进行瘦身清理计划确认。

第三步：

  - 清理参数确认，包括清理时间、清理时长限制等；
  - 已选清理项确认；
  - 点击下一步，确认保存瘦身清理计划，可打开瘦身服务清理执行情况查看结果。

## 【页面】日志清理规则参数设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%97%A5%E5%BF%97%E6%B8%85%E7%90%86%E8%A7%84%E5%88%99%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。
====== 操作步骤 ======
Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

## 【页面】清理向导提醒
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%B8%85%E7%90%86%E5%90%91%E5%AF%BC%E6%8F%90%E9%86%92

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。

====== 操作步骤 ======

使用清理向导，定制清理服务，选择清理项，执行时间和时长限制，勾选清理高级选项，以确保清理过程少产生日志。

进入清理向导，首先看到的是清理前的温馨提醒信息，并可以查看设置[[日志清理规则参数设置|日志清理规则参数设置]]，接着按向导步骤及流程执行。

第一步：

  - 系统会自动计算当前数据中心的的空间占用情况，并预估可清理空间大小；
  - 确定清理方案名称；
  - 根据需要选择清理项目，包括上机操作日志清理、监控执行情况清理、分配执行情况清理、临时表清理、批改日志清理
  - 注意：确保所有清理项目已经设置好[[日志清理规则参数设置|日志清理规则参数设置]]，特别是上机操作日志备份路径不能为空。另外所选清理项中至少有一个选项的清理空间大于0，否则不能建立清理计划。

第二步：

  - 确定清理时间和清理时长，可以选择立即执行，但是数据清理尽量选择在业务空闲期间执行；
  - 勾选选项【清理任务执行时，恢复模式修改为简单】，这样可以大大减少日志产生，避免日志文件过度膨胀；
  - 勾选选项【数据后，收缩数据库】，，以便回收数据文件占用空间，注意此过程耗时较长；
  - 点击下一步，进行瘦身清理计划确认。

第三步：

  - 清理参数确认，包括清理时间、清理时长限制等；
  - 已选清理项确认；
  - 点击下一步，确认保存瘦身清理计划，可打开瘦身服务清理执行情况查看结果。

## 【页面】用户业务对象权限报表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%94%A8%E6%88%B7%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E6%9D%83%E9%99%90%E6%8A%A5%E8%A1%A8

====== 1 功能描述 ====== 
用户业务对象权限报表主要从用户和业务对象的维度来查询用户业务对象+权限项+角色的情况，即展示用户具有哪些业务对象的哪些权限，便于管理员对用户的具体业务功能权限进行有效管控和综合分析。

**功能路径**
【系统管理】→【系统管理】→【权限报表】→【用户业务对象权限报表】

 ====== 2 字段说明 ======
  - 用户：符合查询条件的用户名称；以名称升序展示；
  - 业务领域：业务对象所属的业务领域
  - 子系统名称：业务对象所属的子系统；
  - 业务对象：符合查询条件的业务对象名称；
  - 权限项：业务对象的权限项名称；
  - 权限状态：权限项组的状态，分为：有权、无权、禁止；默认查询有权和禁止状态；
  - 角色：显示当前业务对象权限是由哪个角色所带来的。

 ====== 3 功能操作 ======
===== 3.1 查询 =====
  - 同一个权限项有多行数据，是因为用户的多个角色都有相同权限项的情况；
  - 建议查询时，尽量设置过滤条件，以减少查询数据，避免对服务器的性能带来影响；
  - 预置了【按权限名称】的查询方案，可以直接按照选择的权限项名称查看用户的业务对象权限情况。

===== 3.2 业务对象功能授权 =====
通过用户的业务对象权限报表，发现某个角色的业务对象权限有问题，可以直接对报表选中行次的角色进行业务对象功能授权，减少重复选择主控台菜单的操作。

## 【页面】自动分配清理规则参数设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%87%AA%E5%8A%A8%E5%88%86%E9%85%8D%E6%B8%85%E7%90%86%E8%A7%84%E5%88%99%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE

====== 功能概述 ======

金蝶AI星空运行过程中，存在一定的情况会堆积一些没有回溯意义的历史日志数据，比如：上机操作日志、监控执行情况、分配执行情况、临时表、批改日志等。

一般情况下，用户会关注最近一段时间的执行的日志情况。对于历史久远的日志情况，会随着时间的流逝，对这些记录的查看和回溯的概率越来越低；而这些数据存储在数据库中导致数据中心的容量越来越大，需要更大的物理存储空间，需要更多的时间进行日常索引的重建和优化，给系统运维带来更多的困难。数据瘦身服务就是协助企业系统运维人员解决这个问题的。

运维人员先对数据中心进行完整备份，利用服务器的闲时（例如：凌晨时段），确定瘦身规则（例如：设置保留最近3个月的数据），定制数据瘦身计划对数据中心的历史数据进行清理。


====== 操作步骤 ======
Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

## 【页面】角色业务对象权限报表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%A7%92%E8%89%B2%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E6%9D%83%E9%99%90%E6%8A%A5%E8%A1%A8

====== 1 功能描述 ====== 
角色业务对象权限报表主要从角色和业务对象的维度来查询角色的业务对象+权限项的情况，即展示角色具有哪些业务对象的哪些权限，便于管理员对角色的具体业务功能权限进行有效管控和综合分析。

**功能路径**
【系统管理】→【系统管理】→【权限报表】→【角色业务对象权限报表】

 ====== 2 字段说明 ======
  - 角色：符合查询条件的角色名称；以名称升序展示；
  - 业务领域：业务对象所属的业务领域
  - 子系统名称：业务对象所属的子系统；
  - 业务对象：符合查询条件的业务对象名称；
  - 权限项：业务对象的权限项名称；
  - 权限状态：权限项组的状态，分为：有权、无权、禁止；默认查询有权和禁止状态。

 ====== 3 功能操作 ======
====== 3.1 查询 ======
  - 建议查询时，尽量设置过滤条件，以减少查询数据，避免对服务器的性能带来影响；
  - 预置了【按权限名称】的查询方案，可以直接按照选择的权限项名称查看角色的业务对象权限情况。

====== 3.2 业务对象功能授权 ======
通过角色的业务对象权限报表，发现某个角色的业务对象权限有问题，可以直接对报表选中行次的角色进行业务对象功能授权，减少重复选择主控台菜单的操作。

## 【页面】配货向导之订单选择
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%85%8D%E8%B4%A7%E5%90%91%E5%AF%BC%E4%B9%8B%E8%AE%A2%E5%8D%95%E9%80%89%E6%8B%A9

**功能说明：**

分销配货平台用作供货机构按需配货，下达发货通知。

分销配货平台采用向导式：

  - 分销配货平台采用向导式：1 订单选择－>仓库选择－>配货录入－>配货清单。
  - 打开配货平台选择配货渠道，根据配货渠道选择未配货的销售订单或要货申请单。
  - 设置配货渠道的配货仓库及优选顺序：仓库取供货渠道档案的仓库信息。
  - 根据订单需求和配货库存信息自动配货，允许修改配货信息；
  - 根据配货录入信息生成配货清单，下达发货通知。

**功能路径：**【电商与分销】->【要补货管理】->【配货管理】->【分销配货平台】

**使用前提：**供货渠道需要有要货渠道向其要货的销售订单生成。

**业务说明：**多组织下应用，按销售订单来自动配货，下达生成发货通知单；

渠道根据将需求转化为供货渠道的要货需求后，供货渠道按销售订单发货。供货渠道产品入库后，通过分销配货平台将要货渠道的要货需求，将库存进行分配，进行统一出库配送的功能。

注：此为3.0版本的功能，不建议使用，高版本的要补货集中处理完全覆盖此项功能。

## 【页面】钩稽日志查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%92%A9%E7%A8%BD%E6%97%A5%E5%BF%97%E6%9F%A5%E8%AF%A2

====== 1 自动钩稽核算 ======
 

自动钩稽核算是指由标准应付单审核时自动建立与对应入库单（退料单）的钩稽关系，并根据钩稽关系核算入库成本。

===== 1.1 使用前提 =====


存货核算系统必须已结束初始化，且已勾选参数“采购应付单审核时自动进行入库成本核算”。

===== 1.2 操作说明 =====


入库单（退料单）下推标准应付单后审核时自动进行钩稽核算。以及当勾选系统参数“应付单与发票核销产生的差异计入存货成本”时，应付单与采购发票核销产生的应付调整单自动钩稽关联入库单（退料单）并重新核算入库成本。

===== 1.3 业务说明 =====


自动钩稽触发的核算只是针对“法人核算体系+核算组织+默认会计政策”下入库成本核算。


====== 2 钩稽日志查询 ======
 

在钩稽日志查询表中可以对采购入库单（退料单）与应付单自动钩稽核算及采购费用分配后的结果进行查询。

===== 2.1 功能路径 =====


【成本管理】－>【存货核算】－>【存货核算】－>【钩稽日志查询】

===== 2.2 字段说明 =====

|**字   段**||**说 明**|
|币别 ||取入库单（退料单）上的结算币别|
|本次钩稽数量 ||本次钩稽的基本单位数量|
|本次钩稽金额 ||本次钩稽金额（注：勾稽的是结算币别金额），对入库单表示本次钩稽的实际成本，对应付单表示本次钩稽的不含税金额。|
|本次钩稽金额本位币 ||本次钩稽金额（本位币），对入库单表示本次钩稽的实际成本，对应付单表示本次钩稽的不含税金额。|


===== 2.3 操作说明 =====


钩稽日志查询可以对采购费用分配结果通过“反勾稽”取消，但不能取消自动钩稽核算的结果。

  - 精简版包括常用功能和信息中心，体现了精致、简约的理念。

====== 2 主页菜单 ====== 
=====2.1 主页菜单 =====
  - 数据中心名称：显示当前登录的数据中心名称
  - 用户名称：显示当前登录的用户名称；下拉菜单内容见1.2的描述；
  - 组织名称：显示当前用户登录组织名称；下拉菜单显示当前用户的组织范围；可以随意切换组织；
  - 帮助：“帮助”可以查看金蝶云的帮助手册；“关于”可以查看金蝶云的演示版\正式版、产品版本、金蝶网址、版权所有等信息；
  - 注销：退出金蝶云并返回登录界面；浏览器登陆模式退出系统务必采用这个模式，才可以正确的释放站点；
  - 搜索：支持对主控台菜单的搜索，快速定位菜单内容；支持手工录入文字或者菜单名称的第一个字母；
  - 搜索：支持对社区知识的搜索，切换到知识页签输入关键字搜索对应的知识文档或是课程，链接可免登录到社区并打开相应的知识；
  - 【田】：显示当前用户有权限的主控台菜单。

=====2.2 用户下拉菜单 =====
  - 个人信息：显示当前用户对应员工的信息；可以维护移动电话以及电子邮箱；
  - 修改密码：修改当前用户的登录密码，只对命名用户身份的登录方式有效；
  - 我的组织和角色：显示当前用户的组织及其角色信息，便于用户查看自己的情况；
  - 我的功能权限：显示当前用户在组织范围内全部组织下有权的功能权限情况；
  - 我的字段权限：显示当前用户在组织范围内全部组织下无权和禁止的字段权限情况；
  - 我的企业需求：显示当前用户创建的企业需求内容；
  - 我的后台任务：显示当前用户可以查看的后台执行任务；
  - 我的格式和时区：可以设置用户的时区，系统会根据用户时区在进行业务操作涉及时间记录时进行相关的换算；可以设置用户的格式，主要针对正负数、日期、时间格式按照用户的习惯方式展示；
  - 本地配置：用户可以根据个人喜好设置的内容，内容见1.3的描述；
  - 主控台菜单显示模式：全部组织（默认）、当前组织；内容见用户的描述；
  - 个性主页：默认、精简；可以切换；门户主页方案选择用户后，用户会显示该方案；
  - 下载中心：客户端下载的入口。

=====2.3 本地配置 =====
**字段说明**
  - 通知消息（3）秒关闭：业务操作时出现提醒消息的停留时间；可以手工调整时长；
  - 表格选中行颜色：涉及表格的业务，选中行展示的颜色；可以根据喜好选择颜色；
  - 表格单元格数据拷贝组合键Ctrl+（C）：针对表格单元格复制的快捷键设置；
  - 表格启用渐进效果：就是在列表刷新时数据逐步展示；
  - 启用整行复制（Ctrl+C）：选择后可以对表格中整行数据进行复制；
  - 打印无需提示：当前用户进行打印时，无需提示启动打印；
  - 使用本地打印机设置：使用当前电脑的打印机设置；
  - 列表分组：就是利用控件自带的分组功能，实现列表上的分组汇总展示；勾选后对列表查询性能有一定影响；
  - 列表选择列固定：就是在列表左右滚动时，选择列始终锁定，方便查看后面内容后在勾选。

**工具栏**
  - 恢复缺省值：将本地配置的内容恢复为出厂时的状态；
  - 导出/导入：可以通过导出/导入实现本地配置内容的跨端跨电脑的应用，不用重复配置。

**业务说明**
  - 本地配置只对当前电脑的当前登录模式有效；
  - 如果切换登录模式，则需要重新设置。

## 【页面】零售门店系统参数设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%9B%B6%E5%94%AE%E9%97%A8%E5%BA%97%E7%B3%BB%E7%BB%9F%E5%8F%82%E6%95%B0%E8%AE%BE%E7%BD%AE

==== 零售门店系统参数 ====
  * 门店系统参数设置按照组织进行隔离设置，不按照门店区分；
  * 条码设置参数：条码规则校验、条码唯一性校验、条码必录校验；
  * 基本参数：主要是控制POS收银的基本信息：如POS授权方式、是否允许无销售开钱箱、促销是否可选择、POS付款自动填入金额、取消销售是否打印小票、默认零售客户、是否记录营业员（销售员）、电子秤格式、称重商品重量小数位、金额小数位、抹零方式、前台保留小数位、微信、支付宝混合支付；
  * 小票打印参数：打印地址、联系方式、应收金额、折扣金额、打印会员信息等；
  * 销售控制参数：控制POS端商品销售的相关参数，如：无库存不允许销售，库存扣减未日结零售单等；
  * 会员参数：定义会员相关的参数，主要适用于POS收银调用；
