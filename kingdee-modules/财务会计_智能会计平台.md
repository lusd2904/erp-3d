## 【页面】下载凭证云模板
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8B%E8%BD%BD%E5%87%AD%E8%AF%81%E4%BA%91%E6%A8%A1%E6%9D%BF

====== 下载凭证云模板 ======
===== 功能说明 =====
按科目表以及不同记账模式提供配套的凭证模板，可以随时在线上更新，不受产品版本限制，可以快速应对会计准则的变化更新或者追加场景对应的凭证模板和科目。
用户可以在智能会计平台下载凭证云模板，选择对应的记账模式，将云模板科目表、分录类型和凭证模板快速应用到系统，减少凭证模板实施工作量，并且规范记账。

===== 操作前提 =====

订阅凭证模板服务。

H5环境管理员登录--》星空云服务---》增值云服务---》会计云模板服务---》凭证模板服务申请订阅

===== 功能路径=====

【财务会计】—>【智能会计平台】—>【智能会计工作台】—>【下载凭证云模板】
 
===== 操作说明 =====

第一步：选择记账模式

1、目前按期间费用科目不同，提供两套科目表。

2、采购、应付、销售、付款等把记账模式提供不同的凭证模板，模板文件和记账模式可以在线随时追加 。

3、可以查看记账模式说明，选择适合的科目表和记账模式。

第二步：下载云模板文件

1、可以按模块分类和记账方式两种分类查看模板文件。

2、可以查看模板简介和预览凭证模板详细设置。

3、选择需要的模板文件下载编码开头为PRE是科目表文件，编码开头为AOAE是分录类型文件，编码开头为TOAV是单据凭证模板。

第三步：引入科目表

有三种方式：
1、按云模板科目表创建的科目表，适用于新建账套。

2、引用现有科目表，适用于追加凭证模板。

3、引用现有科目表，并按云模板科目表追加新的科目，适应新加的业务，需要添加了新的科目和凭证模板。

第四步：引入分录类型

两种引入方式：追加和覆盖，覆盖引入是会覆盖相同编码且未审核状态的分录类型。如果不需要下载则可以取消勾选

第五步：生成凭证模板

选择需要的凭证模板文件引入到系统。

如果系统已存在相同单据、相同适用账簿、相同来源核算组织和相同科目表的凭证模板，可选择引入时自动禁用系统现有模板。

第六步：生成凭证模板报告

可以查看生成成功和失败的情况

## 【页面】业务凭证
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%87%AD%E8%AF%81

**功能概述**

业务凭证是本产品引入的新概念，由业务单据一对一生成业务凭证，再由业务凭证一对一或汇总生成总账凭证。业务凭证详细记录每一笔经济业务的会计信息，帮助企业更好地落实精细化管理。

本功能主要用于查询和管理业务凭证，可以对业务凭证进行查看、修改、打印、生成总账凭证、联查单据和总账凭证等多个操作。

**使用前提**

业务单据已经生成业务凭证。

**功能路径**

【财务会计】－>【智能会计平台】－>【账务处理】－>【业务凭证查询】；
除智能会计平台外，在应收款管理、应付款管理、出纳管理、存货核算、产品成本核算和资产管理系统中也提供了【业务凭证查询】入口，方便用户查询特定来源系统的业务凭证。


**字段说明**

主要字段说明 

| **字段 **      || **说明**                                                               |
| 账簿         || 业务凭证所属账簿。                                                              |
| 来源系统        || 生成业务凭证的业务系统。                                                              |
| 来源单据         || 生成业务凭证的业务单据种类。                                                              |
| 来源单据号         || 生成业务凭证的业务单据编号。                                                              |
| 期初业务凭证        || 科目初始数据从业务系统引入，系统将业务系统的单据生成业务凭证再把业务凭证的余额引入到总账科目初始数据。\\ 科目初始数据从业务系统引入时生成的业务凭证会自动勾选此标识。 \\ 期初业务凭证不需要生成总账凭证。                                                             |


**操作说明**

未生成总账凭证的业务凭证允许修改凭证字、摘要、科目、维度、结算方式和结算号。

## 【页面】业务单据对账
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%8D%95%E6%8D%AE%E5%AF%B9%E8%B4%A6

====== 业务单据对账 ======

=====1 功能说明 =====

在日常会计工作中，难免会发生各种差错或账实不符的情况；为了保证会计记录的正确性，就有必要进行对账。对账的内容主要包括账证核对、账账核对、账实核对。此处的对账功能主要是账账核对，即总账与各业务系统明细账之间的核对。

=====2 操作前提 =====

对账方案已设置。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【业务单据对账】

=====4 字段说明 =====

| **字段**       || **说明**                                                                                    |
| 账簿           || 选择对账的账簿，总账数据以该条件进行过滤，业务单据以账簿对应的核算组织进行过滤。                                                  |
| 对账方案         || 选择对账的方案，总账和业务单据以该条件进行过滤和展示。                                                               |
| 年度、期间        || 选择对账的年度和期间，总账和业务单据表以该条件进行过滤。                                                               |
| 币别           || 选择对账的币别，总账和业务单据以该条件进行过滤。                                                                  |
| 包含未过账凭证      || 是否包含未过账凭证，总账以该条件进行过滤。                                                                     |
| 总账本期增加       || 当对账项目的余额方向为借方时，总账本期增加=借方科目的借方发生+贷方科目的借方发生；\\ 当对账项目的余额方向为贷方时，总账本期增加=贷方科目的贷方发生+借方科目的贷方发生。   |
| 总账本期减少       || 当对账项目的余额方向为借方时，总账本期减少=借方科目的贷方发生+贷方科目的贷方发生；\\ 当对账项目的余额方向为贷方时，总账本期减少=贷方科目的借方发生+借方科目的借方发生。   |
| 业务系统本期增加     || 业务单据的本期增加。                                                                                |
| 业务系统本期减少     || 业务单据的本期减少。                                                                                |


=====5 业务说明 =====
 
1、业务单据对账为”发生额对账”，即使用业务数据的增加项、减少项与总账科目的借贷发生额进行对账；

2、对账界面默认按发生额汇总进行对账，可以联查【明细对账】，明细对账界面可以联查【业务凭证】、【总账凭证】和【业务单据】；

3、明细对账实现思路为按总账凭证与其对应的业务单据进行明细借贷方金额核对，明细对账同样支持显示对账结果及不平原因。

4、当总账和业务系统的本期增加或本期减少数有差异时，系统提供【本期发生额差异分析】的关联操作，分析并列示可能导致差异的原因，具体如下：

  * 单据未生成凭证：方案设置来源于单据，若这些单据若未生成凭证，可能会造成差异。 
  * 单据生成的凭证不包含指定科目：对账方案中指定的会计科目与方案来源单据生成的凭证科目应该是一致的，若单据生成的凭证科目不包含指定科目而是其他科目，可能会造成差异。 
  * 凭证手工录入：单据通过智能会计平台生成凭证，这样二者的数据是一致的；若对账科目的凭证为手工录入（含自动转账、期末调汇和结转损益等来源系统为总账的凭证），可能会造成差异。 
  * 凭证的来源单据不是指定单据：科目凭证来源单据不属于方案设置的来源单据。

## 【页面】业务单据对账方案
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%8D%95%E6%8D%AE%E5%AF%B9%E8%B4%A6%E6%96%B9%E6%A1%88

====== 业务单据对账方案 ======

=====1 功能说明 =====

对账方案用于设置总账科目和业务单据之间的对账关系。


=====2 操作前提 =====

科目表、会计科目已定义。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【业务单据对账方案】。

=====4 字段说明 =====
主要字段说明 

| **位置**   | **字段　**           | **说明**                                                                            |
| 单据头      | 适用账簿              | 选择该凭证模板适用的账簿；若为空，则表示该凭证模板适用于所有账簿。                                                 |
| :::      | 显示余额              | 勾选参数对账结果界面显示期初余额、本期增加、本期减少和期末余额，不勾选参数只显示本期增加和本期减少的对账结果。（2021年5月份补丁发布的）            |
| :::      | 原币金额必须与总账期末对账平衡   | 勾选参数时，总账期末结账时检查业务单据对账方案原币对账结果是否平衡，如果不平衡则不允许结账。（2021年9月份补丁发布的）                     |
| :::      | 本位币金额必须与总账期末对账平衡  | 勾选参数时，总账期末结账时检查业务单据对账方案本位币对账结果是否平衡，如果不平衡则不允许结账。（2021年9月份补丁发布的）                    |
| :::      | 不包含结转损益凭证         | 用于损益科目对账，排除总账期末结转损益凭证。\\ 勾选时，业务单据对账结果总账数据不包含结转损益凭证。\\ 不勾选时，业务单据对账结果总账数据包含结转损益凭证。  |
| 科目及核算维度  | 科目编码              | 选择需要对账的科目，支持多选。                                                                   |
| :::      | 方向                | 对账项目的余额方向，会影响总账本期增加、总账本期减少的取数规则。                                                  |
| :::      | 核算维度              | 若选择核算维度，对账结果按核算维度明细展开；若不选择核算维度，则一个对账项目列示一行。                                       |
| 单据取值设置   | 来源单据              | 选择科目来源单单据。                                                                        |
| :::      | 业务数据增减项           | 设置增减项，影响业务系统本期增加和本期减少取数规则。                                                        |
| :::      | 单据取值条件            | 选择单据上的字段设置过滤条件。                                                                   |
| :::      | 核算维度对应单据字段        | 选择核算维度来源字段。                                                                       |
| :::      | 核算组织              | 选择单据上的组织为核算组织。                                                                    |
| :::      | 日期                | 选择单据上的日期为业务数据发发生日期。                                                               |
| :::      | 币别                | 选择单据上币别为记账币别。                                                                     |
| :::      | 原币金额              | 选择单据上的金额字段为业务发生原币金额。                                                              |
| :::      | 本位币金额             | 选择单据上的金额字段为业务发生本位币金额。                                                             |

=====5 操作说明 =====
1、支持系统中配置了凭证模版的业务单据做为单据取值范围；系统自动解析每种单据的所有元数据（含用户自定义字段），并且单据上的所有字段可以做为单据数据范围过滤条件；

2、每种单据及其字段过滤条件可通过增加项、减少项进行业务数据发生额规则设置，避免业务报表那样写死为固定的增加或减少项，便于用户按总账科目的余额方向灵活配置对账方案；

3、科目若存在多个核算维度，可分别设置核算维度与单据对应字段匹配关系，系统将自动支持多核算维度取数及对账，可解决用户单据添加自定义字段后的记账及对账个性化需求；

4、自动按业务单据在凭证模版设置默认的记账规则识别并匹配核算组织、业务日期、币别、金额等字段做为单据数据筛选，用户可按实际记账规则及核对需求灵活修改；

5、存货核算类单据支持多会计核算体系 + 多会计政策下的成本取值，可满足用户按不同暂估模式记账及对账需求。

## 【页面】业务单据对账结果查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%8D%95%E6%8D%AE%E5%AF%B9%E8%B4%A6%E7%BB%93%E6%9E%9C%E6%9F%A5%E8%AF%A2

====== 业务单据对账结果查询 ======

=====1 功能说明 =====

业务单据对账结果查询用于查询已执行保存的业务单据对账数据；因总账系统和业务系统相互独立，为确保总账数据和业务数据的一致性，财务于月结前必须进行对账。

若对账方案勾选必须与总账期末对账平衡，则总账期末结账时直接调取对账结果（对应方案勾选与总账对账平衡）进行校验，若对账结果平衡则允许结账，若对账结果不平衡则不允许总账期末结账。

=====2 操作前提 =====

账务已处理、对账方案设置、参数勾选保存对账结果、对账结果已保存。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【业务单据对账结果查询】

=====4 字段说明 =====

| **字段**       || **说明**                 |
| 账簿           || 选择账簿，若不勾选取总账科目最新余额，则总账科目金额取对账结果保存的数据；如勾选则取总账最新科目金额。                                                  |
| 对账方案         || 选择要查询的业务单据对账方案，如有保存对账结果，则点击确定后显示保存后的明细对账数据。                                                               |
| 年度、期间        || 选择要查询的账簿对应年度和期间，已保存的对账结果将以该条件进行过滤。                                                               |
| 币别           || 选择要查询的对账结果查询币别，已保存的对账结果将以该条件进行过滤。                                                                  |
| 方案编码         || 显示对账保存的方案编码。           |
| 方案名称         || 显示对账保存的方案名称。           |
| 科目编码         || 显示对账结果保存的科目编码。         |
| 科目名称         || 显示对账结果保存的科目名称。         |
| 核算维度编码       || 显示对账结果保存的核算维度编码。       |
| 核算维度名称       || 显示对账结果保存的核算维度名称。       |
| 总账期初余额       || 显示对账结果保存的总账期初余额。       |
| 业务系统期初余额     || 显示对账结果保存的业务报表的期初余额。    |
| 期初余额差异       || 显示对账结果保存的期初余额差异。       |
| 总账本期增加       || 显示对账结果保存的总账本期增加金额。     |
| 业务系统本期增加     || 显示对账结果保存的业务报表的本期增加金额。  |
| 本期增加差异       || 显示对账结果保存的本期增加差异金额。     |
| 总账本期减少       || 显示对账结果保存的总账本期减少金额。     |
| 业务系统本期减少     || 显示对账结果保存的业务报表的本期减少金额。  |
| 本期减少差异       || 显示对账结果保存的本期减少差异金额。     |
| 总账期末余额       || 显示对账结果保存的总账期末余额。       |
| 业务系统期末余额     || 显示对账结果保存的业务报表的期末余额。    |
| 期末余额差异       || 显示对账结果保存的期末余额差异。       |
| 对账结果         || 显示对账保存的对账结果是否平衡。       |

=====5 业务说明 =====
智能会计平台增加“业务单据对账结果查询”（对账结果查询前需先保存数据），系统将最后一次对账结果保存到后台表以便于查询，同时总账期末结账支持对账不平衡不允许结账。

  * 对账结果查询前需要先保存对账结果，而保存对账结果（对账界面 点击保存按钮）前 需要在智能会计平台参数启用“保存总账科目与业务报表的对账结果”。 
  * 执行对账，若对账结果显示的数据确实无误，点击保存（需要注意的是同一对账方案若点击多次保存，系统只保留最后一次对账结果），后续即可在对账结果查询中按不同的对账方案查询。 
  * 业务单据对账方案参数“原币金额必须与总账期末对账平衡”和“本位币金额必须与总账期末对账平衡”，勾选参数，总账期末结账时检查业务单据对账是否平衡，如果不平衡则不允许结账，保证总账数据和业务数据一致。同时若某一对账方案保存了对账结果，则该对账方案不允许删除 ，只能修改。

## 【页面】业务报表对账
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%8A%A5%E8%A1%A8%E5%AF%B9%E8%B4%A6

====== 业务报表对账 ======

=====1 功能说明 =====

在日常会计工作中，难免会发生各种差错或账实不符的情况；为了保证会计记录的正确性，就有必要进行对账。对账的内容主要包括账证核对、账账核对、账实核对。此处的对账功能主要是账账核对，即总账与各业务系统明细账之间的核对。

=====2 操作前提 =====

对账方案已设置。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【对账】

=====4 字段说明 =====

| **字段**       || **说明**                                                                                    |
| 账簿           || 选择对账的账簿，总账数据以该条件进行过滤，业务报表以账簿对应的核算组织进行过滤。                                                  |
| 对账方案         || 选择对账的方案，总账和业务报表以该条件进行过滤和展示。                                                               |
| 年度、期间        || 选择对账的年度和期间，总账和业务报表以该条件进行过滤。                                                               |
| 币别           || 选择对账的币别，总账和业务报表以该条件进行过滤。                                                                  |
| 包含未过账凭证      || 是否包含未过账凭证，总账以该条件进行过滤。                                                                     |
| 总账期初余额       || 当对账项目的余额方向为借方时，总账期初余额=借方科目的期初余额-贷方科目的期初余额；\\ 当对账项目的余额方向为贷方时，总账的期初余额=贷方科目的期初余额-借方科目的期初余额。  |
| 总账本期增加       || 当对账项目的余额方向为借方时，总账本期增加=借方科目的借方发生+贷方科目的借方发生；\\ 当对账项目的余额方向为贷方时，总账本期增加=贷方科目的贷方发生+借方科目的贷方发生。   |
| 总账本期减少       || 当对账项目的余额方向为借方时，总账本期减少=借方科目的贷方发生+贷方科目的贷方发生；\\ 当对账项目的余额方向为贷方时，总账本期减少=贷方科目的借方发生+借方科目的借方发生。   |
| 总账期末余额       || 总账本期余额=总账期初余额+总账本期增加-总账本期减少。                                                              |
| 业务系统期初余额     || 业务报表的期初余额。                                                                                |
| 业务系统本期增加     || 业务报表的本期增加。                                                                                |
| 业务系统本期减少     || 业务报表的本期减少。                                                                                |
| 业务系统期末余额     || 业务系统本期期末=业务系统本期期初+业务系统本期增加-业务系统本期减少。                                                      |


=====5 业务说明 =====
 

当总账和业务系统的本期增加或本期减少数有差异时，系统提供【本期发生额差异分析】的关联操作，分析并列示可能导致差异的原因，具体如下：

  * 单据未生成凭证：业务报表的数据均来源于单据，若这些单据若未生成凭证，可能会造成差异。 
  * 单据生成的凭证不包含指定科目：对账方案中指定的会计科目与组成业务报表的单据生成的凭证科目应该是一致的，若单据生成的凭证科目不包含指定科目而是其他科目，可能会造成差异。 
  * 凭证手工录入：业务报表的数据来源于单据，单据通过智能会计平台生成凭证，这样二者的数据是一致的；若对账科目的凭证为手工录入（含自动转账、期末调汇和结转损益等来源系统为总账的凭证），可能会造成差异。 
  * 凭证的来源单据不是指定单据：业务报表的单据是既定的，例如应收款明细表来源于应收单、其他应收单、收款单、收款退款单、应收核销单等；若对账科目的凭证不是来源于这些单据，而是由其他单据生成的，也有可能会造成差异。
  * 业务凭证与总账凭证金额匹配：若过滤出来的总账凭证金额与业务凭证金额不一致，则检查结果为不通过；反之则通过。此处的校验规则为：总账凭证关联业务凭证后按关联对账科目借贷金额差异进行计算，如存在差异则相应的总账凭证显示在差异明细项目中，差异结果明细直接调用总账凭证列表并显示对应的总账凭证。
  * 单据与业务凭证金额匹配：若“过滤出来的单据”的金额与业务凭证金额不一致（明细金额差异或者合计金额差异有一项不一致，即视为不通过），则检查结果为不通过；反之则通过。此处的校验规则为：按单据的出入库序列、调拨方向、存货类别及对账设置的科目与业务凭证进行比较，单据出入库序列为“出库”且调拨方式为“普通”时 业务凭证的存货科目金额应在贷方（出库序列但调拨方向为“退货”时应生成贷方负数的存货凭证分录），同理出入库序列为“入库”且调拨方向为“普通”时业务凭证存货科目金额应在借方（退货方向应生成借方负金额的存货凭证分录）。若对账关联科目对应的业务凭证借方或者贷方金额与单据对应出入库序列金额不一致则体现在明细差异列，若业务单据总金额与凭证总金额不同，则显示合计金额差异。---只适用存货对账  


特别要说明的是除了上述分析项，还有其他原因会导致对账差异，例如手工修改业务系统生成的凭证的科目和金额、对账方案设置错误以及其他异常，这些情况系统没有办法控制，需要进一步的人工分析。

详细知识：https://vip.kingdee.com/article/170263?productLineId=1&isKnowledge=2

## 【页面】业务报表对账方案
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%8A%A5%E8%A1%A8%E5%AF%B9%E8%B4%A6%E6%96%B9%E6%A1%88

======业务报表对账方案======
 
=====1 功能说明 =====

对账方案用于设置总账科目和业务报表之间的对账关系。

=====2 操作前提 =====

科目表、会计科目已定义。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【对账方案】

=====4 字段说明 =====

| **字段　**        || **说明**                                                                                                                                                    |
| 对账项目           || 设置要对账的对账项目；目前已支持的对账项目有：应收款、应付款、存货、资产原值、累计折旧、减值准备、资金、应付暂估。                                                                                                 |
| 方向             || 对账项目的余额方向，会影响总账本期增加、总账本期减少的取数规则。                                                                                                                          |
| 科目             || 选择对账的科目，可以多选。                                                                                                                                             |
| 核算维度           || 若选择核算维度，对账结果按核算维度明细展开；若不选择核算维度，则一个对账项目列示一行。                                                                                                               |
| 业务报表           || 选择对账项目对应的业务报表，业务报表按对账项目联动，且只能查看、选择与对账项目相关的业务报表。目前已支持的业务报表有：应收明细表、应付明细表、存货收发存汇总表、资产价值变动表、现金日记账、银行存款日记账、应收票据余额表、应付未开票明细表、应收按发票对账、应付按发票对账、入库勾稽汇总表、应收未开票明细表。  |
| 往来单位类型         || 当业务报表为应收明细表、应付明细表、应收票据余额表、应付未开票明细表、应收按发票对账、应付按发票对账、入库勾稽汇总表时，需要指定是与哪一类的往来单位类型进行对账。                                                                         |
| 报表过滤           || 设置报表取数的过滤条件，例如存货收发存汇总表可以设置“存货类别为原材料”的过滤条件，那么对账时系统会根据该条件进行筛选。                                                                                              |
| 核算维度对应报表字段     || 若选择核算维度，则必须指定该核算维度对应报表上的哪个字段。                                                                                                                             |

=====5 操作说明 =====
对账项目支持存货、暂估应付、应付款、应收款、资金、固定资产；

勾选“必须与总账期末对账凭证”，可以控制总账科目余额必须和业务系统数据平衡才允许结账；

## 【页面】业务报表对账结果查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%8A%A5%E8%A1%A8%E5%AF%B9%E8%B4%A6%E7%BB%93%E6%9E%9C%E6%9F%A5%E8%AF%A2

====== 业务报表对账结果查询 ======

=====1 功能说明 =====

对账结果查询用于查询已执行保存的对账数据；因总账系统和业务系统相互独立，为确保总账数据和业务数据的一致性，财务于月结前必须进行对账。

若对账方案勾选必须与总账期末对账平衡，则总账期末结账时直接调取对账结果（对应方案勾选与总账对账平衡）进行校验，若对账结果平衡则允许结账，若对账结果不平衡则不允许总账期末结账。

=====2 操作前提 =====

账务已处理、对账方案设置、参数勾选保存对账结果、对账结果已保存。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【对账结果查询】

=====4 字段说明 =====

| **字段**       || **说明**                 |
| 账簿           || 选择账簿，若不勾选取总账科目最新余额，则总账科目金额取对账结果保存的数据；如勾选则取总账最新科目金额。                                                  |
| 对账方案         || 选择要查询的对账方案，如有保存对账结果，则点击确定后显示保存后的明细对账数据。                                                               |
| 年度、期间        || 选择要查询的账簿对应年度和期间，已保存的对账结果将以该条件进行过滤。                                                               |
| 币别           || 选择要查询的对账结果查询币别，已保存的对账结果将以该条件进行过滤。                                                                  |
| 方案编码         || 显示对账保存的方案编码。           |
| 方案名称         || 显示对账保存的方案名称。           |
| 科目编码         || 显示对账结果保存的科目编码。         |
| 科目名称         || 显示对账结果保存的科目名称。         |
| 核算维度编码       || 显示对账结果保存的核算维度编码。       |
| 核算维度名称       || 显示对账结果保存的核算维度名称。       |
| 总账期初余额       || 显示对账结果保存的总账期初余额。       |
| 业务系统期初余额     || 显示对账结果保存的业务报表的期初余额。    |
| 期初余额差异       || 显示对账结果保存的期初余额差异。       |
| 总账本期增加       || 显示对账结果保存的总账本期增加金额。     |
| 业务系统本期增加     || 显示对账结果保存的业务报表的本期增加金额。  |
| 本期增加差异       || 显示对账结果保存的本期增加差异金额。     |
| 总账本期减少       || 显示对账结果保存的总账本期减少金额。     |
| 业务系统本期减少     || 显示对账结果保存的业务报表的本期减少金额。  |
| 本期减少差异       || 显示对账结果保存的本期减少差异金额。     |
| 总账期末余额       || 显示对账结果保存的总账期末余额。       |
| 业务系统期末余额     || 显示对账结果保存的业务报表的期末余额。    |
| 期末余额差异       || 显示对账结果保存的期末余额差异。       |
| 对账结果         || 显示对账保存的对账结果是否平衡。       |

=====5 业务说明 =====
智能会计平台增加“对账结果查询”（对账结果查询前需先保存数据），系统将最后一次对账结果保存到后台表以便于查询。同时总账期末结账支持对账不平衡不允许结账（对账方案须勾选“必须与总账期末对账平衡”）：

  * 对账结果查询前需要先保存对账结果，而保存对账结果（对账界面 点击保存按钮）前 需要在智能会计平台参数启用“保存总账科目与业务报表的对账结果”。 
  * 执行对账，若对账结果显示的数据确实无误，点击保存（需要注意的是同一对账方案若点击多次保存，系统只保留最后一次对账结果），后续即可在对账结果查询中按不同的对账方案查询。 
  * 对账方案 增加选项“必须与总账期末对账平衡”，勾选此选项的对账方案 在执行对账并保存了对账结果之后，若对账不平衡，总账期末结账校验无法通过。同时若某一对账方案保存了对账结果，则该对账方案不允许删除 ，只能修改。

## 【页面】凭证模板
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%87%AD%E8%AF%81%E6%A8%A1%E6%9D%BF

**功能概述**

凭证模板用于设置凭证各要素的取值规则，如凭证日期、凭证字、摘要、科目、借贷方向及金额等。

系统预置了日常经营活动常用的凭证模板，用户可以根据企业的实际情况修改或细化。

**使用前提**

科目表、账簿、凭证字、币别、汇率类型和结算方式已定义。

分录类型已定义。

**功能路径**

【财务会计】－>【智能会计平台】－>【基础资料】－>【凭证模板】

**字段说明**

| **字段 **           || **说明**                                                                                                                                    |
| 来源单据              || 选择业务单据。                                                                                                                                   |
| 科目表               || 选择科目表。                                                                                                                                    |
| 适用账簿              || 选择该凭证模板适用的账簿；若为空，则表示该凭证模板适用于所有账簿。                                                                                                         |
| 核算组织来源            || 选择单据上的组织字段作为凭证的核算组织来源。                                                                                                                    |
| 凭证日期              || 用于单据生成总账凭证取单据上的日期作为记账日期。                                                                                                                  |
| 业务日期              || 用于单据生成总账凭证业务日期取来源业务单据上的日期，可选单据上的单据头日期字段。凭证上的业务日期用于往来科目总账账龄分析。                                                                             |
| 凭证生成取账簿默认凭证字      || 凭证模版增加复选框“凭证生成取账簿默认凭证字”，若勾选则凭证生成时凭证的凭证字取值账簿默认凭证字，不勾选则按凭证模版设置的凭证字及凭证字取值条件执行，此参数勾选与否不影响凭证字现有的设置及控制。                                         |
| 总账凭证日期取系统当前日期     || 凭证模版增加复选框“总账凭证日期取系统当前日期”，若勾选则凭证生成时总账凭证日期取当前凭证生成操作的系统时间，不勾选时按现有处理规则执行。                                                                     |
| 总账凭证日期取期间最后一天     || 用于业务单据生成总账凭证日取最后一天。\\ 当勾选参数时，业务凭证日期还是按凭证模板凭证日期设置的来源日期字段取值，而业务凭证生生成总账凭证的凭证日期取为对应期间会计日历的最后一天。                                               |
| 总账凭证分录合并          || 默认选择值为“取智能会计平台参数”，选中此选项时总账凭证分录合并与否保持和智能会计平台参数一致；若选中“分录行合并”或者“分录行不合并”，则总账凭证分录合并与否按凭证模板的设置取值，不再考虑智能会计平台参数的设置；                               |
| 摘要不一致合并           || 默认值为“取智能会计平台参数”，若凭证模板上“总账凭证分录合并”选中为“分录行合并”时此选项可以设置；具体摘要合并控制规则有四种：显示固定摘要、显示第一行摘要、显示最后一行摘要、显示所有分录行摘要，如选中显示所有分录行摘要，则凭证生成时按总账凭证摘要字段长度限制自动截取。  |
| 凭证排序来源            || 用于单据批量生成凭证时，按单据上字段排序，可选单据头字段为文本型、基础资料、短日期和长日期（如创建日期）。                                                                                     |
| 分类条件              || 若业务单据需要拆分成不同的类别生成不同的凭证分录，则在此处进行定义。业务单据表头的任意字段均可作为分类依据。                                                                                    |
| 必须生成总账凭证          || 若该类单据必须生成总账凭证，则勾选此标识。\\ 勾选此标识，总账结账时会检查该类单据是否已生成总账凭证，若未生成总账凭证则不允许结账。                                                                       |
| 分录类型              || 选择分录类型。                                                                                                                                   |
| 科目                || 定义凭证分录行的会计科目（核算维度、现金流量项目）的取值规则以及科目影响因素的来源字段。\\ 在科目设置界面设置了现金流量项目后，生成凭证时会自动指定现金流量。                                                          |
| 分录行生成条件           || 定义凭证分录行生成的前提条件，不满足条件则不生成该分录行；\\ 一般情况下不需要设置。                                                                                               |
| 业务凭证分录合并          || 定义业务单据生成业务凭证的过程中，业务单据的分录行是否合并生成业务凭证的分录行。                                                                                                  |
| 业务编号              || 用于单据生成的凭证业务编号取单据上的字段，可选单据文本字段。凭证上的业务编号是用于往来科目总账账龄分析。                                                                                      |

 

操作说明

系统预置的凭证模板支持【恢复系统预置】功能，点击该功能按钮，凭证模板将还原成出厂时的状态。**需要注意的是如果账套实际科目与系统预设的科目差异很大时，建议不要再使用此功能。**

业务说明

凭证模板设置完成后，若用户对【科目】基础资料进行了修改，则建议对凭证模板的科目字段进行相应修改，不修改可能会导致生成凭证失败或错误。 
系统预置的应收款科目初始数据、应付款科目初始数据、现金科目初始数据、银行存款科目初始数据、资产科目初始数据和存货科目初始数据凭证模板供总账模块【科目初始数据引入】使用，在【凭证生成】向导中不生成凭证。

 存货类单据凭证模版（凭证生成）注意事项：
  * 存货对账取值业务报表为“存货收发存汇总表”，而存货收发存汇总表所涵盖的单据范围为存货核算---核算单据查询所核算到的单据，核算单据查询可以看到单据的出入库序列及调拨方向；
  * 凭证模版上存货类科目借贷方向应保持和单据在存货收发存（核算单据查询）里面的出入库序列保持一致，整体原则为：
    * 若单据出入库序列为“出库”且调拨方式为“普通”，设置凭证模版时存货科目方向设置应在贷方（出库序列但调拨方向为“退货”时凭证模版上存货科目方向仍旧为贷方，金额设置为 0 - 对应成本金额字段，此时生成贷方负金额的存货凭证分录）；
    * 若单据出入库序列为“入库”且调拨方向为“普通”，设置凭证模版时存货科目方向设置应在借方（入库序列但调拨方向为“退货”时凭证模版上存货科目方向仍旧为借方，金额设置为 0 - 对应成本金额字段，此时生成借方负金额的存货凭证分录）。

====== 分录类型 ======

**功能概述**

分录类型是按业务对会计科目的抽象和提炼，通过一定的规则映射到会计科目。它可以被多个凭证模板引用。

凡是在由业务单据生成凭证时需要用到的会计科目均应该归类，并在此进行定义。

系统预置了日常经营活动常用的分录类型，用户可以根据企业的实际情况增加或细化。

**使用前提**

科目表、会计科目已定义。

**功能路径**

【财务会计】－>【智能会计平台】－>【基础资料】－>【分录类型】

**字段说明**


| **字段**       || **说明**                                                |
| 科目影响因素设置     || 科目影响因素是影响科目取值的业务要素；也可视作科目取值的前提条件。\\ 此处用于指定科目影响因素的取值。  |
| 科目取值         || 科目影响因素的取值不同，对应的会计科目也不同。\\ 此处用于指定对应的会计科目。              |
| 优先级          || 优先级是凭证生成过程中判断科目取值的先后顺序。\\ 不能手工编辑，用户可以通过【上移】、【下移】来调整。  |

 

 

**举例说明**

日常业务中，往往能通过存货类别来判断物料应该归属的科目：当存货类别=原材料或辅料时，对应的会计科目为原材料；当存货类别=自制半成品、委外半成品或产成品时，对应的会计科目为产成品。

在系统中，我们把会计科目“原材料”和“产成品”抽象成分录类型“物料估价”，把“存货类别”视作科目影响因素，通过对科目影响因素设置不同的取值来映射到不同的会计科目。

  *增值税发票扫描录单提供两个入口，这里讲的是增值税发票单据的“扫描录单”功能：开始操作之前需要点击“初始化扫描仪”，在此之前需要将扫描仪和电脑进行正确连接并打开扫描仪。

  *选择需要的识别模版，因扫描识别程序内置了“增值税发票”识别模版，用户需要扫描的单据若为增值税发票则可直接使用，如为其他单据需要自定义识别模版。

  *选择需要的识别模版后，将发票按正确顺序放入扫描仪，点击扫描识别，系统将自动生成增值税发票扫描识别结果。

  *若识别结果无误则直接生成增值税发票单据，若扫描扫描识别结果确实或关键信息无法准确识别，系统只生成增值税发票扫描识别不生成增值税发票单据，用户可手工修改增值税发票识别，保存后点击生成单据，系统将自动生成对应的增值税发票单据。

  *用户也可通过增值税发票识别联查生成的增值税发票单据，以及扫描影像。



**使用前提**

扫描仪已注册、已制作扫描识别模板（增值税发票无需制作模板）。

**功能路径**

【财务会计】－>【智能会计平台】－>【扫描记账】－>【增值税发票单据】。

**字段说明**

| **字段**     || **说明**                                                                                                                    |
| 单据编号       || 扫描录单生成的增值税发票单据对应的单据编号。                                                                                                    |
| 发票代码       || 通过扫描录单功能将增值税发票上的发票代码显示在增值税发票单据上。                                                                                          |
| 发票号码       || 通过扫描录单功能将增值税发票上的发票号码显示在增值税发票单据上。                                                                                          |
| 开票日期       || 通过扫描录单将增值税发票上面的开票日期显示在增值税发票单据上。                                                                                           |
| 业务日期       || 通过扫描录单将增值税发票上面的业务日期显示在增值税发票单据上。                                                                                           |
| 联数         || 扫描识别时读取的增值税发票联数。\\ 需要注意的是：抵扣联可以通过扫描产生增值税发票识别，但不能产生增值税发票单据；因为只有记账联和发票联才允许记账。\\ 若发票联数为记账联则为销售方记账判断依据，若发票联数为发票联则为购买方记账判断依据。  |
| 购买方类型      || 通过扫描录单自动生成增值税发票上的购买方类型；\\ 发票联数为记账联时，购买类型默认为客户；发票联数为发票联时，购买类型默认为组织机构并且与核算组织保持一致。                                           |
| 购买方        || 通过扫描录单及增值税发票识别自动增值税发票上的购买方企业名称转换为系统中对应的基础资料（客户、供应商、组织机构）；\\ 若无对应基础资料，则在扫描录单及识别过程中系统将自动创建对应基础资料。                           |
| 销售方类型      || 通过扫描录单自动生成增值税发票上的销售方类型；\\ 发票联数为记账联时，销售方类型默认为组织机构并且与核算组织保持一致；发票联数为发票联时，销售方类型默认为供应商。                                        |
| 销售方        || 通过扫描录单及增值税发票识别自动增值税发票上的购买方企业名称转换为系统中对应的基础资料（客户、供应商、组织机构）；\\ 若无对应基础资料，则在扫描录单及识别过程中系统将自动创建对应基础资料。                           |
| 票据类型       || 枚举值，区分为普票和专票两种。                                                                                                           |
| 核算组织       || 按发票联数自动识别生成，记账联则核算组织为发票上的销售方；发票联时核算组织为发票上的购买方。\\ 核算组织需要做为凭证模板上面的核算组织来源判断记账到对应账簿下。                                         |

## 【页面】扫描识别模板管理
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%89%AB%E6%8F%8F%E8%AF%86%E5%88%AB%E6%A8%A1%E6%9D%BF%E7%AE%A1%E7%90%86

**功能概述**

  *扫描识别模板管理，主要是针对已经在本地制做好的识别模板（扫描仪系统预置了增值税发票识别模板，无需单独制作，可直接使用），通过扫描识别模版管理引入的金蝶云系统中。

  *扫描识别模板制作，是将企业需要用的票据或单据，制作成可进行扫描识别的识别模板，同时定义单据上需要进行识别的内容和字段。增值税发票的识别模板已经内置好了，不需要用户自己制作，其他的票据，只要是票据的板式和纸张大小是固定的，都可以制作成识别模板。做了识别模板之后，才能在后续的凭证模板设置及扫描记账中使用。

## 【页面】智能会计平台
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%99%BA%E8%83%BD%E4%BC%9A%E8%AE%A1%E5%B9%B3%E5%8F%B0

====== 1 智能会计平台概述 ======

===== 1.1 智能会计平台概述 =====

 智能会计平台是系统提供的自动生成凭证的工具，基本实现方式是根据定义好的凭证模板，对业务系统的单据生成业务凭证和总账凭证。它与各业务模块紧密集成，能够更加准确、便捷地采集企业的经济活动信息；并由系统自动生成凭证，有效提高账务处理工作的质量和效率。此外，智能会计平台还提供对账管理功能，以确保账簿记录的真实性和正确性。


===== 1.2 智能会计平台总体流程图 =====

[图:fin_智能会计平台整体应用流程_new.png]


===== 1.3 系统特性=====

**智能会计平台主要提供以下应用：**

  *  凭证模板设置灵活，可以满足企业的个性化需求； 
  *  系统自动匹配凭证模板、自动获取单据生成凭证；   
  *  凭证生成支持批量操作，能同时对多个账簿、多种单据生成凭证；
  *  通过凭证自动生成方案可实现"单据审核自动生成凭证"或者"定时生成凭证"； 
  *  支持凭证与业务单据的联查，做到财务分析可追溯； 
  *  提供凭证生成情况查询功能，清晰展现单据生成凭证的情况； 
  *  支持对账功能。

===== 1.4 与其他系统接口=====

  * 与业务系统的接口各业务系统的单据设置凭证模板后，均可通过智能会计平台自动生成凭证。

  * 与总账系统的接口智能会计平台生成的总账凭证在总账系统进行凭证管理。

====== 2 智能会计平台操作手册 ======




===== 2.1 使用流程 =====

**第一步，设置基础数据**

在系统使用前，我们需要先设置基础数据。

  * 首先，设置公共的基础档案，包括核算体系、账簿、凭证字、币别、汇率体系、汇率、科目表、科目、核算维度、结算方式等。 
  * 其次，依次设置本系统基础资料，包括分录类型和凭证模板；进入【财务会计】－>【智能会计平台】－>【基础资料】。 
  * 最后，设置业务系统凭证参数；进入【财务会计】－>【智能会计平台】－>【系统设置】－>【智能会计平台参数】。
**第二步，日常业务操作**

日常操作包括凭证生成、凭证生成情况查询、业务凭证查询和总账凭证查询。
进入【财务会计】－>【智能会计平台】－>【账务处理】。

## 【页面】智能会计平台参数

**功能概述**

用于设定生成凭证的过程中，对生成方式的控制方法和策略。
参数的取值定义后，允许再次修改。修改后对以往凭证不做修改，仅对未来生成的凭证产生影响。

**功能路径**

【财务会计】－>【智能会计平台】－>【参数设置】－>【智能会计平台参数】。

**参数说明**

| **参数**                  || **说明**                                                                                                                                                                                                                                               |
| 尾差允许范围                  || 控制业务单据生成凭证时尾差的允许范围；对于范围内的尾差，系统将自动进行调整。                                                                                                                                                                                                               |
| 尾差调整方式                  || 控制业务单据生成凭证时尾差的调整方式；默认为“调整至金额最大的分录行”。                                                                                                                                                                                                                 |

## 【页面】自动对账方案
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%87%AA%E5%8A%A8%E5%AF%B9%E8%B4%A6%E6%96%B9%E6%A1%88

====== 自动对账方案 ======

=====1 功能说明 =====

自动对账方案用于设置业务报表对账方案在空闲时间定时自动对账。

=====2 操作前提 =====

对账方案已设置。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【自动对账方案】

=====4 字段说明 =====

| **字段**     || **说明**                                    |
| 执行频率       || 可选月、周、天                                   |
| 执行时间设置     || 根据选择的执行频率，设置具体的自动对账执行时间。                  |
| 账簿         || 选择对账的账簿，总账数据以该条件进行过滤，业务报表以账簿对应的核算组织进行过滤。  |
| 报表对账方案     || 选择对账的方案，总账和业务报表以该条件进行过滤。                  |
| 币别         || 选择对账的币别，总账和业务报表以该条件进行过滤。                  |
| 会计期间       || 选择对账的期间。                                  |
| 入库开始时间     || 勾选启用检查项且勾选检查项，此字段值需要选择。                   |


=====5 业务说明 =====
 
自动对账执行计划将获取非禁用的自动对账方案按设置的执行时间自动进行对账或者对账检查，对账完成后自动保存对账结果，并支持联查对账结果。

## 【页面】自定义单据识别
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%87%AA%E5%AE%9A%E4%B9%89%E5%8D%95%E6%8D%AE%E8%AF%86%E5%88%AB

**功能概述**

  *自定义单据识别是除了增值税发票之外，用户通过设置扫描识别模版后可以进行扫描录单前的识别结果归集，系统预置了银行回单（收款）、银行回单（付款）两个单据的识别模版；备注：银行回单是以民生银行银行回单为例制作的，不同银行回单格式可能不同，如有需要，可自行制作扫描识别模板。

  *自定义单据识别提供两个入口，一是在自定义扫描识别 点击“扫描录单”（另外一个入口 在银行回单（收款） 、银行回单（付款），详见后续章节），然后需要点击 初始化扫描仪，在此之前需要将扫描仪和电脑进行正确连接并打开扫描仪。。

  *选择需要的识别模版后，将银行回单按正确顺序放入扫描仪，点击扫描识别，系统将自动生成银行回单（收款） 、银行回单（付款）单据。

  *若识别结果无误则直接生成银行回单（收款） 、银行回单（付款）单据，若扫描扫描识别结果缺失或关键信息无法准确识别，系统只生成自定义扫描识别，不生成银行回单（收款） 或者 银行回单（付款）单据，用户可手工修改自定义扫描识别，保存后点击生成单据，系统将自动生成银行回单（收款） 或者 银行回单（付款）单据。

  *用户也可通过自定义单据识别联查生成的银行回单（收款） 或者 银行回单（付款）单据，以及扫描影像。



**使用前提**

扫描仪已注册、已制作自定义扫描识别模板。

**功能路径**

【财务会计】－>【智能会计平台】－>【扫描记账】－>【自定义单据识别】。

**字段说明**

| **字段**     || **说明**                    |
| 单据编号       || 自定义单据识别产生的单据编号。           |
| 识别模板       || 记录自定义单据识别所使用的扫描识别模板。      |
| 识别结果       || 记录自定义单据识别结果。              |
| 已生成单据      || 反写标识，判断自定义单据识别是否产生了对应单据。  |

## 【页面】银行回单付款
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%93%B6%E8%A1%8C%E5%9B%9E%E5%8D%95%E4%BB%98%E6%AC%BE

**功能概述**

  *银行回单付款扫描录单提供两个入口，这里要讲的是银行回单付款的扫描入口，点击“扫描录单”然后点击初始化扫描仪，在此之前需要将扫描仪和电脑进行正确连接并打开扫描仪。

  *按银行回单的收款或付款类型，自动生成到对应的单据，系统预置两种单据：银行回单收款 或者 银行回单付款。

  *若识别结果无误则直接生成银行回单单据，若扫描扫描识别基础结果信息缺失或关键信息无法准确识别，系统只生成扫描识别基础而不生成银行回单收款 或者 银行回单付款，用户可手工修改自定义单据识别，保存后点击生成单据，系统将自动生成对应的银行回单收款 或者 银行回单付款。

  *用户也可通过自定义单据识别联查生成的银行回单，以及扫描影像。



**使用前提**

扫描仪已注册、已制作扫描识别模板（增值税发票无需制作模板）。

**功能路径**

【财务会计】－>【智能会计平台】－>【扫描记账】－>【银行回单付款】。

**字段说明**

| **字段**     || **说明**                                                      |
| 单据编号       || 扫描录单生成的银行回单付款单据对应的单据编号。                                     |
| 业务日期       || 扫描录单生成的银行回单付款单据上的业务日期，默认保持和交易日期一致。                          |
| 交易流水号      || 扫描录单生成的银行回单付款单据上的交易流水号，此流水号来源为银行回单对应识别字段，如无则留空。             |
| 交易日期       || 扫描录单生成的银行回单付款单据上的交易日期，日期来自银行回单上的交易日期。                       |
| 核算组织       || 扫描录单生成的银行回单付款单据上的核算组织，默认取值为银行回单上的付款人。                       |
| 币别         || 扫描录单生成的银行回单付款单据上的币别，默认取值为银行回单上的币别。                          |
| 本位币        || 银行回单付款单据上的本位币币别，默认取值为核算组织所在默认会计核算体系 + 默认会计政策下的主币别。          |
| 汇率类型       || 默认取值为核算组织所在默认会计核算体系 + 默认会计政策下的汇率类型。                         |
| 汇率         || 按业务日期 + 汇率类型获取对应的汇率。                                        |
| 收款人类型      || 通过扫描录单自动生成银行回单上的收款人类型，此字段为多类别基础资料，默认为供应商，除此之外还可以为客户、银行、员工。  |
| 收款人名称      || 扫描录单生成的银行回单付款单据上的收款人名称，系统按不同收款人类型显示其对应的基础资料。                |
| 收款人开户行     || 收款人对应银行账号的开户行。                                              |
| 收款人账号      || 收款人对应银行账号。                                                  |
| 付款人名称      || 扫描录单生成的银行回单付款单据上的付款人名称，自动与系统中的组织机构进行匹配。                     |
| 付款人开户行     || 付款人对应银行账号的开户行。                                              |
| 付款人账号      || 付款人对应银行账号。                                                  |
| 金额         || 扫描录单生成的银行回单付款单据上的金额。                                        |
| 金额本位币      || 按“金额+汇率+币别”换算后的本位币金额。                                       |
| 摘要         || 扫描录单生成的银行回单付款单据上的摘要，默认取值为银行回单上的备注字段。                        |

| 收款人名称      || 扫描录单生成的银行回单收款单据上的收款人名称，自动与系统中的组织机构进行匹配。                     |
| 收款人开户行     || 收款人对应银行账号的开户行。                                              |
| 收款人账号      || 收款人对应银行账号。                                                  |
| 付款人类型      || 通过扫描录单自动生成银行回单上的付款人类型，此字段为多类别基础资料，默认为客户，除此之外还可以为供应商、银行、员工。  |
| 付款人名称      || 按不同付款人类型显示其对应的基础资料。                                         |
| 付款人开户行     || 收款人对应银行账号的开户行。                                              |
| 付款人账号      || 收款人对应银行账号。                                                  |
| 金额         || 扫描录单生成的银行回单收款单据上的金额。                                        |
| 金额本位币      || 按“金额+汇率+币别”换算后的本位币金额。                                       |
| 摘要         || 扫描录单生成的银行回单收款单据上的摘要，默认取值为银行回单上的备注字段。                        |
