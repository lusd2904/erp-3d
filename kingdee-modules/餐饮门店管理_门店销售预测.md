====== 1.历史食品销量要货 ======

===== 1.1功能概述 =====

  * 根据历史营业销售数据，统计出历史平均营业总额，计算出各菜品的平均销售份数，平均日销售金额，可手工输入预估营业总额，根据各菜品的预估营业额与平均营业额的比值，算出各菜品的预估销售数量及预估销售金额。

  * 根据算出的预估销售数量和销售金额，通过食品成本卡计算需要的原材料，生成物料预估要货单。

  * 历史食品销量要货参数设置可以选择预估食品销量方案。
一、参考本组织历史时间段的销量数据。
二、参考其他门店的。

===== 1.5 业务说明 =====
 
  * 参考其他组织字段，为单选，只可选择一个组织。当选择的组织有营业数据，又选择了参考其他组织，则提示要货组织有营业数据，是否继续参考其他组织.点击是，则获取参考组织的营业数据。  
  * 选择了参考其他组织后，则获取被选组织的营业数据，进入下一步之后，获取的历史营业额及食品销量信息都是被参考组织的。但是前面的组织字段默认是当前要货组织。 
  * 历史食品销量要货：第二步点击下一步的时候，需要提示是否生成方案，是则自动生成方案，否则不生成 
  * 历史食品销量要货时，输入组织，部门和参考的历史起止日期之后，取门店对应的数据之后，更新右边数据，查询到食品销售清单中有对应组织，部门，营业日期的营业数据的为有，未查询到的为无
  * 历史食品销量要货中，根据食品销售数量展开食品成本卡时，先去判断该食品是否有对应的食品成本卡，如有默认的食品成本卡，则根据默认的食品成本卡展开物料。如未找到默认的食品成本卡，则判断该食品是否是由物料转为食品的，如是，则去找对应的物料展开，食品的预估数量，则是物料的预估用量。
  * 历史起始日期/历史截止日期默认获取后台服务设置的统计天数。如，天数设置的是365天，则起始及截止日期是当前日期往前365天的起始和截止日期；右边的营业数据按起始及截止日期取的数据，默认勾选。可直接下一步。 
  * 生成食品用量预估页面---统计天数默认取后台服务计算设置的统计天数。历史日均营业额获取预估营业额中参考营业额均值。要货天数获取要货组织所在的配送路线中设置的订货周期。如未设置时，默认为1，可编辑；预估营业额取要货天数对应的预估营业额之和，可编辑，当安全系数计算得出或手工调整后，预估营业额相应调整。安全系数默认为1，点击计算系数，进入影响因子的列表，选择后，系数1+（各因子影响值之和）。                       
  * 当影响因子选择的是维护了食品明细的营销活动，则该因子影响值，不参与系数计算。而是调整该食品的预估销售额，从而重新计算预估销售份数。                           
  * 数据取后台服务计算得出的万元用量。预估销售份数根据万元用量计算得出的日均销售份数*要货天数得出，不可编辑。“调整后预估销售份数”，默认等于预估销售份数，可编辑。最终按调整后预估销售份数及食品成本卡，分解成物料预估要货单。                     
  * 当参数选择页面中选择了门店预估食品销量方案时，将该方案的食品加入到食品用量预估页面中，与营业额计算出的食品明细分开。该类型的食品数量不参与任何计算。   
  * 历史食品销量要货根据食品展开成本卡生成物料预估单时，取食品成本卡上物料设置了“订货”字段属性的物料，按此类物料展开进行计算订货数量

## 【页面】特殊事件
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%89%B9%E6%AE%8A%E4%BA%8B%E4%BB%B6

[[门店销售预测|<< 返回门店销售预测]]

====== 1.特殊事件 ======
===== 1.1 功能概述 =====
特殊事件主要是在历史食品销量要货中计算日安全系数，如果勾选了自动计算，那么在历史食品销量要货中会自动计算安全系数值，如果不勾选的话，则需要手工勾选才会自动计算。
===== 1.2 字段说明 =====
^ 字段名称  ^ 字段说明                              ^
| 类型    | 系统预设置天气，节假日，商圈活动，营销活动，定台，其他       |
| 影响值   | 每种类型对历史食品销量要货的影响，自定义。             |
| 自动计算  | 如果勾选，历史食品销量要货会自动计算，不勾选则手工选择类型再计算  |
===== 1.3 业务说明 =====
  * 基础资料类型，受组织策略控制，由创建组织统一维护后，分配给使用组织
  * 单据体中的类型取自辅助资料，单据体中的名称及影响值，手工录入，必填
  * 历史食品销量要货时，自动获取有效期内的特殊事件的影响因子，且有自动计算的标志。自动计算安全系数。
  * 自动计算之后，手工点击安全系数，进入影响因子列表时，自动计算的影响因子默认是选中且灰色显示，不可修改。其他影响因子被选择后，系数叠加计算。

====== 1.自定义食品万元销量 ======

===== 1.1 功能概述 =====

当某一行食品万元销量设置未设置适用门店时，其他同一个食品万元销量行可与它有效期重叠。若单独设置了适用门店，同一个门店同一个有效期同一个食品不可有重复的万元用量，保存时校验并提示用户。在同一个时间段内出现两个万元用量，不可保存，请先检查后重新设置。提交审核前必须先保存。 
===== 1.2 字段说明 =====
^ 字段名称 字段说明  ^                                                                                                                                                 ^
| 万元销量       | 销售多少份/10000                                                                                                                                     |
| 门店         | 自定义食品万元用量分配到其他门店时，分配后，门店修改，不同步修改创建组织的。\\ 若门店允许修改，并已修改,则创建组织修改时，不可同步修改门店的。\\ 当用户设置了门店，则该条万元用量只对该门店生效。\\ 当同一个食品即设置了门店，又设置了适用所有。则默认取设置了门店的该条万元用量。  |
| 批量添加       | 每个门店可以批量添加到多个食品中                                                                                                                                |

## 【页面】营销活动
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%90%A5%E9%94%80%E6%B4%BB%E5%8A%A8

[[门店销售预测|<< 返回门店销售预测]]

====== 1.营销活动 ======
===== 1.1 功能概述 =====
营销活动主要是在历史食品销量要货中计算日安全系数，如果勾选了自动计算，那么在历史食品销量要货中会自动计算安全系数值，如果不勾选的话，则需要手工勾选才会自动计算。营销活动分为单品营销和整单营销，在历史食品销量要货中会取相应食品的影响值来计算安全系统
===== 1.2 字段说明 =====
^ 字段名称   ^ 字段说明                  ^
| 活动类型   | 单品促销和整体促销             |
| 行禁用    | 禁用选中的行，食品明细置灰         |
| 取消行禁用  | 取消选中的行的禁用，食品明细可编辑     |
| 单品促销   | 单品促销影响值只对单品促销对应的食品有效  |
| 整体促销   | 历史食品销量要货中生成的所有食品都有效   |

===== 1.3 业务说明 =====
  * 活动明细维护各种营销活动及活动的有效期，以及对营业额的影响比例
  * 食品明细是活动明细的子表，
  * 如活动为单品促销时，需要维护哪些单品促销
  * 营销活动不维护食品明细时，默认是整体营销。所有食品营业额上浮或者下浮
  * 营销活动基础资料，受组织策略控制，类型为分配型。
  * 单据体中的食品明细为活动明细页签的子表体。当活动明细的明细行被禁用之后，食品明细页签同步被禁用。
  * 在活动名称前增加一个活动类型，字段值枚举两个：单品促销，整体促销。必填。选择单品促销的时候，食品明细必填

====== 1.销售预测计算助手 ======

===== 1.1 功能概述 =====
销量预测计算助手会自动生成门店预估营业额和食品万元用量表，预测区间表示生成从当前日期开始的几天后的门店预估营业额和食品万元用量表。参考历史天数表示参考多少天的营业数据。参数中按照星期类型来计算，如果勾选的话，就会分别统计参考历史天数时段的每个星期的数据。参考历史数据天数扣除期初的几天，表示在计算万元用量表和预估营业额时会扣除输入的那几天。
===== 1.2 字段说明 =====
^ 字段名称             ^ 字段说明                       ^
| 预测区间             | 定义计算未来几天的营业额               |
| 任务名称             | 该定时服务的名称                   |
| 执行点时间            | 定义该定时服务在什么时间点执行            |
| 参考天数             | 定义参考历史多少时间段的营业额            |
| 执行间隔             | 定义该服务多久执行一次                |
| 是否按星期几类型来计算      | 定义营业数据是否按星期类型来分类计算历史日均营业额  |
| 历史营业额数据是否扣除期初几天  | 定义营业数据是否需要扣除期初营业数据         |

====== 1.门店预估营业额 ======

===== 1.1 功能概述 =====
门店预估营业额在历史食品销量要货和门店周期要货都会使用到，是作为预估门店要货的重要参考值，门店预估营业额可以手工新增，也可以通过销售预测计算助手自动生成。
===== 1.2 字段说明 =====
^ 字段名称    ^ 字段说明                    ^
| 参考历史天数  | 定义参考历史多少时间段的营业数据        |
| 默认安全用量  | 手工新增，默认为1.1，后台生成默认为1    |
| 数据来源    | 手工时显示手工录入，后台服务生成显示系统运算  |
| 参考营业额   | 参考历史的营业额                |
| 预估营业额   | 参考营业额 * 默认安全用量          |
===== 1.3 业务说明 =====
  * 后台服务生成时，数据来源为后天计算；手工新增时，数据来源为手工录入
  * 手工新增时，预估月份默认当前系统月份，可手工修改。默认安全系数为1.1
  * 当手工录入时，单据体安全系数值默认取单据头的值。统计天数默认为空，非必填。
  * 计算日期默认当前系统日期。 
  * 后台服务生成时，默认已审核状态，安全用量系统为1，          
  * 单据体中的参考营业额，根据定时服务中设置的每次计算的天数生成。如果后台服务中勾选了参数“是否按星期几类型来分类计算” ，则每日的金额按照各自的星期类型来分类计算。如果未勾选，则按照总金额/总天数计算。且该字段锁定，不可修改。预估营业额默认等于参考营业额，可修改。

====== 1.食品万元用量表 ======

===== 1.1 功能概述 =====
食品万元用量表是历史食品销量要货的其中一种方式。当门店的食品万元用量表中有相应日期的数据失，历史食品销量要货会默认勾选按销售预测要货。
===== 1.2 字段说明 =====
^ 字段名称  ^ 字段说明                      ^
| 数据天数  | 计算历史多少天的数据                |
| 营业额   | 预估营业额=营业额合计/天数            |
| 数据来源  | 手工新增显示手工录入，后台生成显示系统运算     |
| 万元用量  | 食品万元用量=食品销售数量/总营业额*10000  |


===== 1.3 业务说明 =====
  * 单据允许新增时，营业组织默认当前登录组织，计算日期默认当前系统时间，币别默认获取人民币。统计天数可不填。食品名称由食品编码选择后携带，万元销量手工录入，销售金额为历史销售金额。
  * 单据体中的明细，根据定时服务中设置的每次计算的天数生成。如果后台服务中勾选了参数“是否按星期几类型来分类计算”，则按照各自的星期类型来分类计算。
  * 如果未勾选，则按照全部期间内所有销售的食品
