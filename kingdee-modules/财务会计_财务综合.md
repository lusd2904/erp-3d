## 【页面】业务凭证查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%87%AD%E8%AF%81%E6%9F%A5%E8%AF%A2

**功能概述**

业务凭证是本产品引入的新概念，由业务单据一对一生成业务凭证，再由业务凭证一对一或汇总生成总账凭证。业务凭证详细记录每一笔经济业务的会计信息，帮助企业更好地落实精细化管理。

本功能主要用于查询和管理业务凭证，可以对业务凭证进行查看、修改、打印、生成总账凭证、联查单据和总账凭证等多个操作。

**使用前提**

业务单据已经生成业务凭证。

**功能路径**

【财务会计】－>【智能会计平台】－>【账务处理】－>【业务凭证查询】；
除智能会计平台外，在应收款管理、应付款管理、出纳管理、存货核算、产品成本核算和资产管理系统中也提供了【业务凭证查询】入口，方便用户查询特定来源系统的业务凭证。


**字段说明**

| **字段**     || **说明**                                                                                                   |
| 账簿         || 业务凭证所属账簿。                                                                                                |
| 来源系统       || 生成业务凭证的业务系统。                                                                                             |
| 来源单据       || 生成业务凭证的业务单据种类。                                                                                           |
| 来源单据号      || 生成业务凭证的业务单据编号。                                                                                           |
| 期初业务凭证     || 科目初始数据从业务系统引入，系统将业务系统的单据生成业务凭证再把业务凭证的余额引入到总账科目初始数据。\\ 科目初始数据从业务系统引入时生成的业务凭证会自动勾选此标识。\\ 期初业务凭证不需要生成总账凭证。  |

 

**操作说明**

未生成总账凭证的业务凭证允许修改凭证字、摘要、科目、维度、结算方式和结算号。

## 【页面】付款
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BB%98%E6%AC%BE

*功能说明

对已结账的账单进行付款操作。
 
 *界面展示

[图:付款.png]


 *操作说明

付款：选择结算方式输入金额，最后点击【埋脚】完成付款操作，账单对应房台变为空台。

功能路径：【收银】→【账单】→【付款】

 

消单：因某些原因对账单进行消单，如收银员所选的结算方式错误。消单有两种情况：对已付款埋脚的账单消单，操作后将去除原结算方式的金额，账单变为结账状态；对已结账的账单消单，账单将变为正常状态，同时房台变为占用状态，从而可以更改账单的食品等。

功能路径：【收银】→【账单】→【消单】 

 

开发票：对选择的账单进行开发票操作，取消发票请输入0。

功能路径：：【收银】→【账单】→【开发票】

## 【页面】借款移转单
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%80%9F%E6%AC%BE%E7%A7%BB%E8%BD%AC%E5%8D%95

**功能概述**

借款转移单主要用于记录员工借款转移的过程。该单据主要适用于以下场景，例如：
1. A员工离职，需将借款直接转移给接手的B员工（这样处理的目的在于不需要A员工将款项退回公司，B员工再向公司申请借款，公司再将款项支付给B员工，以减少流程的繁琐性，减少工作量）。

**功能路径**

【员工服务】－>【人人报销】－>【费用/借款移转】－>【借款转移单】

**字段说明**
|**字段**||**说明**|
|转出组织||员工借款转出的组织|
|转出人||借款转出的员工|
|转入人||借款接手的员工|
|币别||转出借款的币别|
|事由||借款转出的原因|
|转出申请单||选择往来单位为转出人且币别与所选币别一致的存在借款余额的申请单|

**特殊说明**

借款移转只支持组织内员工之间互转，不支持跨组织借款移转

## 【页面】凭证录入
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%87%AD%E8%AF%81%E5%BD%95%E5%85%A5

====== 1.功能说明 ======

用户根据原始单据录入记账凭证，系统在凭证录入界面提供多个选项设置，用户自定义数据校验规则以及录入时的编辑控制等。

使用凭证查询功能查询和管理已录入的凭证，可以对凭证进行整理、冲销、联查单据和业务凭证等多个操作。

用户可以录入凭证时指定现金流量，也可以在凭证查询列表界面选择凭证指定现金流量。

具体指定的操作可参见凭证指定现金流量。

**操作前提**

设置账簿、科目、凭证字以及总账管理参数等基础信息。

**功能路径**

【财务会计】－>【总账】－>【凭证管理】－>【凭证录入】

| 摘要             || 录入凭证分录的备注信息，可从基础资料摘要库中选择，也可手工录入。                                                                                                                 |
| 科目编码           || 录入凭证分录的科目。                                                                                                                                       |

| 借方金额、贷方金额      || 录入科目对应的金额信息，每条凭证分录只允许录入借方金额或贷方金额。                                                                                                                |

## 【页面】凭证汇总
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%87%AD%E8%AF%81%E6%B1%87%E6%80%BB

**报表功能**

系统提供【财务会计】－>【总账】－>【凭证管理】－>【凭证汇总表】功能，将记账凭证按照用户指定的范围和条件汇总至指定级别的科目借贷方发生额上。用户可以根据需要设置不同的汇总条件，查询对应的会计信息。

**过滤条件**

用户选择需要查询的账簿，设置会计年度期间以及凭证字范围等过滤条件，系统根据用户设置的条件查询取数。

## 【页面】合并报表编制
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%90%88%E5%B9%B6%E6%8A%A5%E8%A1%A8%E7%BC%96%E5%88%B6

**功能说明**

合并报表由企业集团中对其他企业由控制权的控股公司或母公司编制，它是在对纳入合并范围的个别报表的数据进行加总的基础上，通过编制调整、抵销分录将企业集团内部的经济业务对个别报表的影响予以抵销，然后合并个别报表各项目的数据编制而成的。

**操作前提**

子公司和子集团的个别报表已接收；调整分录、抵消分录已审核。

**操作说明**

【新增】：打开【财务会计】－>【合并报表】－>【合并报表】功能，选择某个合并报表模板新增合并报表。

合并报表重算：打开新建的合并报表，单击【数据】－>【重算表页】或【全部重算】（使用快捷键F9），系统会自动对各项目进行调整、抵消后计算出合并数，保存即完成合并报表的编制。

如果用户不需要查看各项目的具体调整、抵消情况，可以不需要编制工作底稿，合并报表重算时会对各项目的数据进行调整、抵消后汇总，从而得出各项目的合并数。

【上报】：子集团的合并报表将作为集团的个别报表参与集团的合并。

## 【页面】向导式期末调汇

====== 1.功能说明 ======

**操作前提**

期末调汇必须满足下列条件才能执行调汇操作：

1) 账簿已经结束初始化；
2) 币别基础资料中已启用外币；
3) 账簿科目表中存在已启用期末调汇的科目。


**功能路径**

【财务会计】→【总账】→【期末处理】→【期末调汇】→【向导式期末调汇】

====== 2.操作说明 ======

用户在向导功能中选择调汇的账簿，系统会对账簿进行调汇前相关检查，检查通过后，用户需要设置本次调汇的汇率以及凭证生成的相关选项，进行调汇操作，调汇完成后，系统将自动生成期末调汇记账凭证。

^ 参数               |^ 说明                                                                                                               ^

====== 1.功能说明 ======

本系统提供的结转损益功能，是将账簿内各损益类科目的余额转入本年利润科目，并生成一张结转损益记账凭证，以反映企业在一个会计期间内实现的利润或亏损总额。

1) 账簿系统参数已设置<本年利润科目>、<利润分配科目>；

系统支持选择更多账簿和当前账簿同时结转，更多账簿的科目表和当前期间必须与当前账簿完全一致。

## 【页面】对账
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%AF%B9%E8%B4%A6

**功能概述**

在日常会计工作中，难免会发生各种差错或账实不符的情况；为了保证会计记录的正确性，就有必要进行对账。对账的内容主要包括账证核对、账账核对、账实核对。此处的对账功能主要是账账核对，即总账与各业务系统明细账之间的核对。

**使用前提**

对账方案已设置。

**功能路径**

【财务会计】－>【智能会计平台】－>【对账管理】－>【对账】

**字段说明**

| **字段**       || **说明**                                                                                    |
| 账簿           || 选择对账的账簿，总账数据以该条件进行过滤，业务报表以账簿对应的核算组织进行过滤。                                                  |
| 对账方案         || 选择对账的方案，总账和业务报表以该条件进行过滤和展示。                                                               |
| 年度、期间        || 选择对账的年度和期间，总账和业务报表以该条件进行过滤。                                                               |
| 币别           || 选择对账的币别，总账和业务报表以该条件进行过滤。                                                                  |
| 包含未过账凭证      || 是否包含未过账凭证，总账以该条件进行过滤。                                                                     |
| 总账期初余额       || 当对账项目的余额方向为借方时，总账期初余额=借方科目的期初余额-贷方科目的期初余额；\\ 当对账项目的余额方向为贷方时，总账的期初余额=贷方科目的期初余额-借方科目的期初余额。  |
| 总账本期增加       || 当对账项目的余额方向为借方时，总账本期增加=借方科目的借方发生+贷方科目的借方发生；\\ 当对账项目的余额方向为贷方时，总账本期增加=贷方科目的贷方发生+借方科目的贷方发生。   |
| 总账本期减少       || 当对账项目的余额方向为借方时，总账本期减少=借方科目的贷方发生+贷方科目的贷方发生；\\ 当对账项目的余额方向为贷方时，总账本期减少=贷方科目的借方发生+借方科目的借方发生。   |
| 总账期末余额       || 总账本期余额=总账期初余额+总账本期增加-总账本期减少。                                                              |
| 业务系统期初余额     || 业务报表的期初余额。                                                                                |
| 业务系统本期增加     || 业务报表的本期增加。                                                                                |
| 业务系统本期减少     || 业务报表的本期减少。                                                                                |
| 业务系统期末余额     || 业务系统本期期末=业务系统本期期初+业务系统本期增加-业务系统本期减少。                                                      |


**业务说明**

 

当总账和业务系统的本期增加或本期减少数有差异时，系统提供【本期发生额差异分析】的关联操作，分析并列示可能导致差异的原因，具体如下：

  * 单据未生成凭证：业务报表的数据均来源于单据，若这些单据若未生成凭证，可能会造成差异。 
  * 单据生成的凭证不包含指定科目：对账方案中指定的会计科目与组成业务报表的单据生成的凭证科目应该是一致的，若单据生成的凭证科目不包含指定科目而是其他科目，可能会造成差异。 
  * 凭证手工录入：业务报表的数据来源于单据，单据通过智能会计平台生成凭证，这样二者的数据是一致的；若对账科目的凭证为手工录入（含自动转账、期末调汇和结转损益等来源系统为总账的凭证），可能会造成差异。 
  * 凭证的来源单据不是指定单据：业务报表的单据是既定的，例如应收款明细表来源于应收单、其他应收单、收款单、收款退款单、应收核销单等；若对账科目的凭证不是来源于这些单据，而是由其他单据生成的，也有可能会造成差异。

 存货对账增加两项新的差异分析项：
   * 单据与业务凭证金额匹配：若“过滤出来的单据”的金额与业务凭证金额不一致（明细金额差异或者合计金额差异有一项不一致，即视为不通过），则检查结果为不通过；反之则通过。此处的校验规则为：按单据的出入库序列、调拨方向、存货类别及对账设置的科目与业务凭证进行比较，单据出入库序列为“出库”且调拨方式为“普通”时 业务凭证的存货科目金额应在贷方（出库序列但调拨方向为“退货”时应生成贷方负数的存货凭证分录），同理出入库序列为“入库”且调拨方向为“普通”时业务凭证存货科目金额应在借方（退货方向应生成借方负金额的存货凭证分录）。若对账关联科目对应的业务凭证借方或者贷方金额与单据对应出入库序列金额不一致则体现在明细差异列，若业务单据总金额与凭证总金额不同，则显示合计金额差异。  
   * 业务凭证与总账凭证金额匹配：若过滤出来的总账凭证金额与业务凭证金额不一致，则检查结果为不通过；反之则通过。此处的校验规则为：总账凭证关联业务凭证后按关联对账科目借贷金额差异进行计算，如存在差异则相应的总账凭证显示在差异明细项目中，差异结果明细直接调用总账凭证列表并显示对应的总账凭证。

特别要说明的是除了上述分析项，还有其他原因会导致对账差异，例如手工修改业务系统生成的凭证的科目和金额、对账方案设置错误以及其他异常，这些情况系统没有办法控制，需要进一步的人工分析。

**特殊说明**

报销单列表，增加了几个重要字段：已付款金额、冲借款金额（含：历史借款、申请单）、冲销金额（尾差核销金额）、匹配核销金额、报销未付款金额（费用金额-已付款-冲借款-冲销金额-匹配核销金额），这些字段由系统根据下游单据的审核或核销状态自动填列，能直观地反映费用报销的后续跟踪信息，也是相关报表的数据分析来源。

报销单新增界面，增加“收票信息”页签“选择发票”按钮，能通过手机端（扫码收票、拍发票上传、微信卡包收票、直接导入我收到的发票、手工添加发票）或者PC段（支持PDF、图片、excel模板导入，支持手工录入）选择发票、也可扫描枪或者扫描仪扫描发票。选择发票后，相关信息会自动填写至收票信息页签。

报销单有多个收款人及账号的处理方式：在基本信息勾选“多收款人”复选框，勾选后，即可显示多收款人页签，填写多个收款人的银行信息。

报销单走审批流，业务单据的日期受下游应付、出纳系统影响。当下游系统与费用报销模块在同一期间，则单据提交、审核时仍取申请日期；若下游系统早于费用报销系统结账，则报销单提交/审核时取系统当期日期。

报销系统关账，则不允许新增关账日期之前的单据。关账时存在未审核的单据，则根据下游应付、出纳系统是否结账，来影响下游单据的业务日期。

报销单存在多行分录，只有部分分录需要付款时，在报销单列表联查下游单据，需勾选上付款的行，才能联查到。

**业务说明**
  * 报销单同步其他应付单
提交或审核通过的费用报销单同步生成应付模块的其他应付单，且同步生成的单据为审核状态，不允许反审核。
反审核费用报销单，系统会同时删除已同步生成的应付模块的其他应付单。
同步生成的其他应付单，在应付系统只能进行查看。
费用报销单勾选了“实报实付”，不会产生其他应付单。

  * 报销单自动下推生成付款申请单
勾选申请付款时，审核通过的费用报销单，系统自动下推生成付款申请单，生成的单据为创建状态。
  * 报销单自动下推生成付款退款单
勾选申请退款时，审核通过的费用报销单，系统自动下推生成付款退款单，生成的单据为创建状态。

  * 报销单自动下推生成进项费用增值税发票

勾选报销单审核时自动生成进项费用增值税发票，则审核时自动产生下游发票；不勾选，则需手工下推。生成的单据为创建状态。
  * 报销单自动下推生成付款单

勾选借款/报销付款审核时自动生成付款单，则审核借款申请单或者是费用报销单时，自动生成付款单。不勾选，则需手工下推。自动生成的付款单，我方银行账户存在默认值时，为创建状态；取不到值，则为暂存状态。  
  * 报销单增加作废功能

对于系统新增的报销单，或者是打回到发起人，状态为重新审核的单据，希望记录在系统，但不参与后续的业务和报表，则增加作废功能按钮。作废后的单据记录在系统，不参与业务。
  * 费用报销支持财务共享
启用财务共享，报销单走工作流或者审批流时，发起人提交单据，会启用打印封面的消息，提供打印封面和查看影像的功能。

  * 查看借款
单据录入【往来单位】后，用户可点击【查看借款】按钮，查看该往来单位当前的借款状况。
借款信息的数据来源提供两种：借款单（含历史借款），以及报销类付款单（含历史借款、退款），默认以后者作为数据来源，用户变更数据来源时借款信息会按数据源重新计算。查看借款的取数规则与 “借款跟踪表”的规则是一致的，详细完整的说明请查看报表章节的描述。
 
  * 查看付款
单据审核后，用户点击关联查询-查看付款，可以查看该报销单银行付款的情况，该功能只能针对网银支付的报销。

  * 自动核销
出差申请借款，出差回来后进行费用报销的场景：
先做出差申请借款，下推付款单，获取借款。出差回来后，做报销单，报销单审核时，付款单，其他应付单会自动核销，产生核销记录。

|单据编号|| 开票单单的单据编号，编号必须唯一，符合编号规则 |
|开票日期|| 开票单的单据日期 |
|发票号|| 手工录入需开票的发票号 |
|会员编号|| F8选择会员基础资料 |
|会员名称|| 根据会员编号携带 |

|操作人密码 ||当前开票的操作员密码 |
|备注|| 补充说明 |

**表头其他字段** 

|**字段**||**说明**| 
|创建人|| 指创建开票单的人员 |
|创建日期|| 指创建开票单的日期 |
|修改人|| 指最后修改开票单的人员 |
|修改日期|| 指最后修改开票单的日期 |
|审核人|| 指审核开票单的人员 |
|审核日期|| 指审核开票单的日期 |

**表体明细字段** 

|**字段**||**说明**| 
|会员卡号|| 表头录入客户后，只能选择该客户对应的会员卡；如果表头没有录入客户，选出来是所有的会员卡| 
|卡身编号|| 根据会员卡携带| 
|本金余额|| 根据会员卡携带 |
|开卡组织|| 根据会员卡携带 |
|开票金额|| 手工录入，开票金额不允许大于未开票金额|

2、已开票金额 = 已开票金额 + 开票金额\\     未开票金额 = 未开票金额 – 开票金额                                

3、开票必须针对会员卡。                                                  

4、已审核的开票单据允许反审核，反审核后原来已更新的已开票金额和未开票金额需要还原成审核前的金额。

## 【页面】总账初始化向导
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%80%BB%E8%B4%A6%E5%88%9D%E5%A7%8B%E5%8C%96%E5%90%91%E5%AF%BC

====== 1.功能说明 ======

通过总账初始化向导，可以实现总账常用基础资料及常用核算维度来源基础资料的梳理与维护，总账管理参数的设置，科目初始数据的维护，一气呵成地完成整个初始化工作。

**操作前提**

相关组织的账簿尚未结束初始化，当然，也可以通过总账初始化向导执行反初始化操作。

**功能路径**

【财务会计】→【总账】→【总账初始化向导】
====== 2.操作说明 ======

    * 基础资料维护：总账常用基础资料及其维护情况，总账基础资料确认完成的前提是存在已审核未禁用的账簿及科目，否则不允许确认完成。
    
    * 总账参数设置：配置系统参数，标记该节点完成时需要检查总账参数是否已经设置完整，当没有设置本年利润或利润分配科目时，不允许确认完成。

    * 科目初始余额：维护科目的初始化余额，确认完成时需要检查科目初始数据在综合本位币下是否已经试算平衡，试算不平衡时不允许确认完成。

    * 结束初始化：结束及反结束初始化，当选中组织所有账簿都已经结束初始化时，该节点的状态自动显示为已完成。

**功能概述** 

手工核销包括手工匹配核销、手工特殊核销。手工匹配核销是根据系统设定的核销方案进行核销（例如往来单位一致、币别一致、承担部门一致）。手工特殊核销可以针对不同往来单位的付款单与报销单进行核销。

  - 设置需要核销单据的核销金额。进行【核销】，系统会根据单据情况自动判断是否生成核销单。该核销单为已审核状态。

由于报表项目可被多个报表所引用，因此报表项目勾稽关系检查实际是与报表无关的。


**功能路径**

【财务会计】→【报表】→【基础资料】→【报表项目勾稽关系】

**报表项目勾稽关系分配列表**

    项目勾稽关系定义完成后，需要将勾稽关系分配给需要进行相应检查的组织。

    功能路径：【财务会计】－>【报表】－>【基础资料】－>【报表项目勾稽关系分配列表】

    在报表项目勾稽关系分配列表界面，点击【新增】来将勾稽关系分配给需要检查的组织。

| 字段                  || 说明                                                                                                                                                                                                     |
| 编码                  || 报表项目勾稽关系编码，唯一标识，手工录入。                                                                                                                                                                                  |
| 名称                  || 报表项目勾稽关系名称。                                                                                                                                                                                            |

| 提示内容                || 报表项目数据检查不满足勾稽关系时，提示的内容。\\ 如：管理费用明细不等于管理费用总和。                                                                                                                                                           |

在“报表项目勾稽关系”列表中，还可以进行勾稽关系的分配、删除、打印、引出、禁用/反禁用等操作。

===== 2 数据说明 =====

## 【页面】财务分析

====== 1 财务分析概述 ======

**使用价值**

财务分析是评价财务状况及经营业绩的重要依据，既是财务预测的前提，又是对过去经营活动的总结。而财务报表是企业财务状况和经营成果的信息载体，对系统分析和评价企业的财务状况、经营成果和现金流量状况有着非常重要的作用。 系统预置8张财务报表（即分析页面）和相关财务数据分析模型，企业可以直接使用或进行个性化修改，快速满足企业不断变化的需求。通过对财务的重要指标进行分析，促进企业经营活动按照企业价值最大化目标运行，帮助投资者做出正确的投资决策，提高企业竞争力，获取更高效益。

**功能路径**

【经营分析】→【财务分析】→【财务主题】

**报表清单**
  - 经营大盘
  - 损益分析
  - 资产负债分析
  - 经营效率
  - 资金分析
  - 应收分析
  - 费用分析
  - 科目多维度分析

====== 2 报表分析  ======

===== 2.1 经营大盘 =====

  * 经营大盘选取毛利润率、净利润率、资产负债率、净利润增长率、净资产收益率等关键指标，直观展现企业的经营状况，帮助企业做出正确地决策，提高企业的经营效率。
  * 具体见【[[经营大盘]]】的介绍。

===== 2.2 损益分析 ===== 

  * 对损益的分析，帮助企业洞悉财务状况和经营成果，使企业能够有效运用其经济资源和资本获取更多利润，让企业利润和价值最大化。
  * 具体见【[[损益分析]]】的介绍。

===== 2.3 资产负债分析 ===== 

  * 通过对资产、负债、所有者权益的分析，帮助企业对财务结构稳健性和清偿债务的实际能力进行分析，揭示企业举债的合理程度与举债经营的效果。
  * 具体见【[[资产负债分析]]】的介绍。

===== 2.4 经营效率 ===== 

  * 对现金周转天数、存货周转天数、应收账款周转天数、应付款周转天数等关键营运能力分析指标进行分析，帮助企业分析其利用资金效率，为企业管理者深入认识企业盈利能力和风险水平提供有用的信息，提高企业管理水平。
  * 具体见【[[经营效率]]】的介绍。

===== 2.5 资金分析 ===== 

  * 资金分析主要是分析企业中考察的关键的资金流量指标和资金余额情况，帮助企业分析资金的流向，引导企业采取合适的资金管理方法，提高使用效率，降低企业财务风险。
  * 具体见【[[资金分析]]】的介绍。

===== 2.6 应收分析 =====

## 【页面】费用报销单_实报实付

**功能概述**
费用报销单（实报实付）主要用于费用报销实报实付业务，企业针对当月报销当月付款报销可使用此类报销单。建议直接手工新增费用报销单（实报实付），也可由费用申请单（无借款）/出差申请单（无借款）通过单据转换下推生成。此类报销单不会产生其他应付单，不参与核销。

**功能路径**
【财务会计】－>【费用报销】－>【我的报销工作台】－>【我的费用报销（实报实付）】

| 发票类型       | 支持普通发票和增值税发票的报销。\\ 增值税发票和普通发票均可录入税率，费用金额不含税金额，最终的报销金额为含税金额。                                                                                            |
| 费用金额       | 费用的实际发生额。必须大于零和小于零。\\ 费用报销单下推费用移转单时，使用“费用金额”下推。                                                                                                        |

 **特殊说明**
费用报销单列表，增加了几个重要字段：已付款金额、冲借款金额（含：历史借款、申请单）、冲销金额（尾差核销金额）、报销未付款金额（费用金额-已付款-冲借款-冲销金额），这些字段由系统根据下游单据的审核或核销状态自动填列，能直观地反映费用报销的后续跟踪信息，也是相关报表的数据分析来源。

费用报销单新增界面，增加“收票信息”页签“选择发票”按钮，能通过手机端（扫码收票、拍发票上传、微信卡包收票、直接导入我收到的发票、手工添加发票）或者PC段（支持PDF、图片、excel模板导入，支持手工录入）选择发票。选择发票后，相关信息会自动填写至收票信息页签。

报销单有多个收款人及账号的处理方式：一张报销单，选择一个收款人及收款账号，下推至付款单后，修改分录行对应的银行账号信息。

费用报销单走审批流，业务单据的日期受下游应付、出纳系统影响。当下游系统与费用报销模块在同一期间，则单据提交、审核时仍取申请日期；若下游系统早于费用报销系统结账，则报销单提交/审核时取系统当期日期。

费用报销系统关账，则不允许新增关账日期之前的单据。关账时存在未审核的单据，则根据下游应付、出纳系统是否结账，来影响下游单据的业务日期。

费用报销单存在多行分录，只有部分分录需要付款时，在报销单列表联查下游单据，需勾选上付款的行，才能联查到。

**业务说明**
  * 费用报销单（实报实付）不产生其他应付单
不需产生其他应付单，也不参与核销

  * 费用报销单自动下推生成付款申请单
勾选申请付款时，审核通过的费用报销单，系统自动下推生成付款申请单，生成的单据为创建状态。

  * 费用报销单自动下推生成进项费用增值税发票

勾选报销单审核时自动生成进项费用增值税发票，则审核时自动产生下游发票；不勾选，则需手工下推。生成的单据为创建状态。
  * 费用报销单自动下推生成付款单

勾选参数借款/报销付款审核时自动生成付款单，则审核借款申请单或者是费用报销单时，自动生成付款单。不勾选，则需手工下推。自动生成的付款单，我方银行账户存在默认值时，为创建状态；取不到值，则为暂存状态。  
  * 费用报销增加作废功能

对于系统新增的报销单，或者是打回到发起人，状态为重新审核的单据，希望记录在系统，但不参与后续的业务和报表，则增加作废功能按钮。作废后的单据记录在系统，不参与业务。
  * 费用报销支持财务共享
启用财务共享，报销单走工作流或者审批流时，发起人提交单据，会启用打印封面的消息，提供打印封面和查看影像的功能。

  * 查看借款
单据录入【往来单位】后，用户可点击【查看借款】按钮，查看该往来单位当前的借款状况。
借款信息的数据来源提供两种：借款单（含历史借款），以及报销类付款单（含历史借款、退款），默认以后者作为数据来源，用户变更数据来源时借款信息会按数据源重新计算。查看借款的取数规则与 “借款跟踪表”的规则是一致的，详细完整的说明请查看报表章节的描述。

====== 阿米巴利润表 ======
======1 报表功能 ======

系统提供阿米巴利润表功能，用户可查询的阿米巴单在某一期间的经营收入、经营成本、经营利润、投入时间、时间附加值和计划达成率。

======2 过滤条件 ======

[[阿米巴利润表过滤|阿米巴利润表过滤条件]]

======3 操作说明 ======

按明细显示支持双击明细行联查经营流水账。

系统支持查询结果的打印、引出和刷新等通用操作，用户可以点击菜单的【参数设置】按钮，设置查询的数据列为零是否显示、数据列尾零是否显示以及查询时是否首先弹出过滤界面等。

## 【页面】阿米巴自定义分摊规则
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%98%BF%E7%B1%B3%E5%B7%B4%E8%87%AA%E5%AE%9A%E4%B9%89%E5%88%86%E6%91%8A%E8%A7%84%E5%88%99

====== 1.功能说明 ======

本功能用于自定义新增阿米巴分摊规则。

**功能路径**

【管理会计】－>【经营会计】－>【基础资料】－>【阿米巴自定义分摊规则】。
====== 2.字段说明 ======

| **位置**     || **字段**  | **说明**                                |
| 表头基本信息     || 名称      | 设置自定义分摊规则名称。                          |
| 表头基本信息     || 账簿      | 为空表示所有账簿均可使用该分摊规则，录入账簿信息则表示仅该账簿可以使用。  |
| 表体         || 分摊公式    | 用于编辑分摊规则公式，必录。                        |
| 表体         || 公式描述    | 不可编辑，系统自动处理显示为分配规则的计算公式对应的文本描述，必录。    |

====== 3.操作说明 ======

打开【管理会计】－>【经营会计】－>【基础资料】－>【阿米巴自定义分摊规则】功能，新增和维护阿米巴自定义分摊规则。

已被阿米巴自定义分配标准引用的阿米巴自定义分摊规则不允许删除。

系统预置阿米巴自定义分摊规则，可直接被阿米巴自定义分配标准引用，也可自定义分摊规则时引用。
| **预置分摊规则**     || **说明**                                             |
| 实际收入占比         || 当前阿米巴当期实际收入合计除以分配标准全部阿米巴实际收入合计。                    |
| 计划收入占比         || 当前阿米巴当期计划收入合计除以分配标准全部阿米巴计划收入合计。                    |
| 上期发生数占比        || 费用分摊的经营科目类，当前阿米巴上期费用支出数除以分配标准全部阿米巴上期该费用经分类的支出合计数。  |
| 投入时间占比         || 当前阿米巴投入时间数除以分配标准全部阿米巴投入时间数。                        |
