====== 2 字段说明 ======

^ 字段名   ^ 说明                                ^

====== 内部应收清理 ======

====== 1 功能说明 ======

对于组织间交易产生的内部往来，有时候不需要实际的现金收付或者开具发票，年末或者年中统一清理掉,所以应收款管理模块提供了内部应收清理功能，清理后生成相应[[内部应收清理单|内部应收清理单]]和[[内部应收清理记录]]。

内部应收清理包括无需收款清理和无需开票清理。通过“内部应收清理”可以进入“无需收款清理”界面，在该界面上通过“无需开票清理”按钮进行切换。

===== 1.1 无需收款清理 =====

无需收款清理是指该内部应收单不需要实际的现金收付，用户可以用该功能清理掉，清理时还可以指定应收清理单的业务日期。

清理后可以通过内部应收清理记录查询清理情况，选择清理记录还可以进行反清理。 

===== 1.2 无需开票清理 =====

无需开票清理是指该内部应收单不需要实际的开具发票，用户可以用该功能清理掉。

清理后可以通过内部应收清理记录查询清理情况，选择清理记录还可以进行反清理。

====== 坏账处理 ======

  * 企业需根据企业会计准则和财政部发布的《应用指南——会计科目和主要账务处理附录》规定,对有客观证据表明应收款项发生减值的,应确认减值损失（或信用减值损失）,计提坏账准备.由于应收款项净值的准确程度受坏账损失的直接影响,企业应视自身情况,合理的选择坏账准备的计提与核算方式并进行账务处理。目前系统只支持在总账手工做计提坏账损失及进行坏账处理的凭证， 新功能增加了自动计提坏账功能，通过在业务系统进行坏账损失处理、计提坏账，从而生成总账凭证。

  * 操作指引：[[https://vip.kingdee.com/article/182340?productLineId=1&isKnowledge=2]]

[[应收收款核销#定时核销|<<返回应收收款核销界面]]

===== ****应收收款定时核销方案**** =====


====== **1.1 应用场景** ======


主控台菜单【财务会计】-【应收款管理】-【应收收款】下增加【应收收款定时核销】功能菜单，点击【应收收款定时核销】进入应收收款定时核销列表界面。


====== **1.2 菜单位置** ======


在应收收款核销中，需要按不同的单据编号、不同的单据类型、不同的部门进行组合查询过滤，更好更精准的查询单据后进行自动定时核销，减少手工操作，提高工作效率。


====== **1.3 参数说明** ======


[图:qq图片20190926143218.png]

执行周期、执行日、执行时间三者之间存在联动如下： 

（1）执行周期默认值为每日。当执行周期选择了每月，执行日可录范围为整数1-31（默认值为1），执行时间可录范围为：00：00：00 – 23：59：59（默认值为00：00：00）；

（2）当执行周期选择了每周，执行日可录范围为整数1-7（默认值为1），执行时间可录范围为：00：00：00 – 23：59：59（默认值为00：00：00）；

（3）当执行周期选择了日，执行日则为灰色不可编辑，执行时间可录范围为：00：00：00 – 23：59：59（默认值为00：00：00）；

（4）执行周期进行切换时，应当自动清空之前设定的执行日、执行时间并自动显示为默认值，定时执行人默认为当前用户，支持手工修改指定。明细分录行单据、过滤方案为必录字段，备注为非必录字段。定时核销方案业务操作提供禁用、反禁用操作功能。表体字段“单据”只允许选择“应收单”、“收款单”；支持应收单（正）VS应收单（负）、应收单VS收款单定时核销。表体分录在保存时进行校验不允许单据重复设置。

===== 2.4 显示选项 =====

  * 包括未审核单据，默认不勾选
  * 按客户分页显示，默认勾选

====== 应收单 ======


====== 1 功能说明 ======

应收单是对销售应收的管理。

====== 2 字段说明 ======

^ 字段名   ^ 说明                                ^
| 业务日期  | 业务日期必须大于结账日期，如果没有结账日期则必须大于等于启用日期。  |
| 单据类型  | 系统预设多种单据类型：标准应收单、资产调拨应收单、费用应收单、转销应收单，用户可以根据企业情况进行增加。  |
| 结算组织  | 应收单的主业务组织，只有启用了应收款管理系统的组织才可以作为结算组织。  |
| 收款组织  | 该笔应收业务的收款组织，会决定下推的收款单的收款组织。  |
| 收款条件  | F8可以选择系统里的收款条件，应收单根据该收款条件自动计算收款计划。  |
| 到期日  | 到日期通过收款条件计算而来，基本页签的到期日与收款计划页签的第一行到期日保持一致。  |
| 到期日计算日期  | 默认为业务日期，可以手工修改，系统根据该字段和收款条件自动计算到期日。  |
| 按含税单价录入  | 勾选该选项，说明以含税单价为计算标准；不勾选该选项，则以单价为计算标准。企业的实际业务中可能存在不同的报价方式，用户可以根据每单的实际情况对该选项进行选择。  |
| 立账类型  | 当应收为业务应收模式时，立账类型为业务应收；当应收为暂估应收模式时，立账类型为暂估应收或财务应收。  |
| 价外税  | 勾选该选项，税额计算为价外税计算的逻辑；不勾选该选项，税额计算为价内税计算的逻辑。  |



====== 3 操作说明 ======

===== 3.1 快速新增 =====

通过点击【应收单快速新增】菜单可以实现应收单的快速新增。在该功能下，系统分类展示出所有还未生成应收单的销售出库单、销售退货单和销售订单，使用户集中、快速的生成应收单。

===== 3.2 自动生成 =====

  - 如果勾选“出库单审核时自动生成应收单”，则在出库单审核时，会自动生成应收单，生成的应收单如果必录字段完整，则为创建状态，如果必录字段不完整，则为暂存状态。
  - 如果勾选“应收单审核时自动生成销售发票”，则在应收单审核时，系统会根据客户基础资料中的发票类型自动生成增值税专用发票或者普通发票。 

====== 4 业务说明 ======

===== 4.1 多日期管理 =====

通过应收单的收款计划页签，系统支持一张应收单多到期日的管理，用户可以根据自己的管理需求，针对应收单设置不同的到期日及不同到期日的应收金额。

===== 4.2 客户的多方交易 =====

系统支持客户多方交易的场景，即客户的结算方、订货方、收货方和付款方可以不同。 

===== 4.3 内部结算 =====

内部结算的应收单必须通过供应链的组织间结算清单下推生成，而不能手工新增。内部结算的应收单表头的会计核算体系字段不为空，而一般的应收单该字段为空。

应收单上的会计核算体系字段默认隐藏，如果用户有内部结算的业务，可以通过单据类型将该字段放开。

[[应收款管理#应收单跟踪表|<<返回应收款管理界面]]

====== 应收单跟踪表 ======

====== 1 报表功能 ======


应收单跟踪表是用来查询与应收业务有关的各种信息的报表，例如应收单的订单情况、出库情况、开票情况、收款情况等等。

====== 2 操作说明 ======


===== 2.1 核销 =====


由于应收单跟踪表会同时显示应收单的开票和收款情况，所以系统提供了开票核销和收款核销两个功能。

===== 2.2 联查单据 =====


由于应收单跟踪表的一行可能有多种单据，例如可能同时有订单、出库单、收款单等，所以联查单据时需要将光标定位在单据编号上。

===== 2.3 包含未审核单据选项 =====


勾选“包含未审核单据”选项，指的是与应收单有关的其他单据需要查询出没有审核的单据。

在系统中，应收开票手工核销提供【手工核销】及【特殊核销】功能。

手工核销及特殊核销前可以设置生成的应收单的业务日期。

====== 1.1 手工核销 ======


应收开票的手工核销通过菜单“应收开票手工核销”中的【手工核销】进行。

手工核销可以选择满足核销方案的单据进行核销。


====== 1.2 特殊核销 ======


应收开票的特殊业务核销通过菜单“应收开票手工核销”中的【特殊核销】进行。

特殊业务核销可以对任何单据进行核销，但是建议仅在需要对单据尾数冲销或者不同往来单位的应收单和发票核销时才使用该功能。

====== 应收开票核销 ======

====== 1 功能说明 ======

应收开票核销包括关联关系核销、匹配条件核销和手工核销、定时核销。

一般情况下通过关联关系核销、匹配条件核销可以将用户多数的单据核销完毕。手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何的单据核销，但是建议用户仅在需要对单据尾数冲销或者不同往来单位的应收单与发票核销时才使用。

====== 2 操作说明 ======

===== 2.1 关联关系核销 =====

关联关系是指通过单据转换功能，通过上游单据生成下游单据，在下游单据审核时，系统会自动执行核销。例如通过应收单生成销售增值税专用发票，在销售增值税专用发票审核时，系统会自动对应收单和销售增值税专用发票进行应收开票核销。

关联关系核销是优先级最高的核销，如果单据间有关联关系，则系统一定执行关联关系核销。

由于关联关系核销是在下游单据审核时系统自动执行，所以没有单独的菜单。

===== 2.2 匹配条件核销 =====

匹配条件核销是指系统根据用户选择的核销方案，对系统单据进行批量的核销。在系统中，应收开票的匹配条件核销通过菜单【应收开票核销】进行。

该功能为向导式功能，用户首先需要在向导界面中选择核销方案，有关核销方案的说明请参见[[应收开票核销方案|应收开票核销方案]]。用户同时可以选择多个核销方案，系统会按照核销方案的优先级，自动执行多次匹配条件的核销。

在向导界面中还可以设置参与核销的单据范围和核销过程中产生的应收单的业务日期。

在单据间没有关联关系的情况下，匹配条件核销为用户的最主要核销方式。通过匹配条件核销，应该可以对用户大多数的单据核销完毕。

===== 2.3 手工核销 =====

在系统中，应收开票手工核销提供【手工核销】及【特殊核销】功能。

手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何单据进行核销，但是建议仅在需要对单据尾数冲销或者不同往来单位的应收单和发票核销时才使用该功能。


详细描述请见：[[应收开票手工核销]]
===== 2.4 反核销 =====

在【[[应收开票核销记录]]】界面，系统提供了反核销功能，选择一组或多组核销记录，点击【反核销】按钮，系统将自动反核销。

====== 1 应收收款核销方案 ======

应收收款核销方案主要是为匹配条件核销设置核销关系、核销匹配条件和核销顺序。系统预设了一个核销方案，用户可以根据实际应用增加。

在匹配条件核销向导界面，用户可以选择多个核销方案，并设置优先级，系统会根据用户的设置多次执行匹配条件核销。

===== 1.1 核销关系 =====

系统现支持如下核销关系：

  * 应收单VS收款单/收款退款单
  * 应收单(正)VS应收单(负)
  * 收款单VS收款退款单 
  * 应收单VS应付单
  * 应收单VS收款单（预收）
  * 其他应收单VS收款单/收款退款单
  * 其他应收单(正)VS其他应收单(负)
  * 其他应收单VS其他应付单
===== 1.2 核销顺序 =====

核销顺序指应收收款核销中，当参与核销的单据为应收单、应付单、其他应收单或者其他应付单时，单据的优先顺序。系统支持如下核销顺序：

  * 按到期日从前往后核销
  * 按业务日期从前往后核销
说明：收款单、收款退款单因为只有业务日期，所以核销顺序均为按业务日期从前往后核销

====== 1 应收款管理概述  ======


===== 1.1 应收款管理概述  =====


系统将应收款管理分为四个基本业务环节，构成应收款管理完整的业务循环，包括应收款确认、到期收款、收款核销、期末处理。这四个业务环节，基本涵盖应收款管理日常业务处理流程。

应收款管理主要处理两方面的业务：销售应收和其他应收。

本手册将以应收款四个业务环节为主线，从销售业务应收和其他业务应收两方面，详细说明各个业务节点可以实现的功能和操作方法，为您能够更加高效、灵活的使用本系统提供帮助。

===== 1.3 系统特性 =====

应收款管理主要处理两方面的业务：销售应收和其他应收。主要功能包括：

  * 通过应收单管理销售业务应收。
  * 通过其他应收单管理其他业务应收。
  * 应收单与销售发票彻底分离，应收账款通过应收单确认，应收单是债权成立的标志。
  * 支持“暂估应收”和“业务应收”两种立账模式。
  * 应收单的快速新增功能。 
  * 出库单审核时自动生成应收单功能。
  * 支持客户的多方交易。 
  * 按角色区分的应收单、其他应收单新增功能。 
  * 支持一张应收单的多到期日管理。
  * 应收单支持按照含税单价或者不含税单价不同的录入方式。
  * 应收单支持价内税和价外税两种税额计算逻辑。
  * 应收单到收款单，支持按收款计划收款。
  * 收款单支持现金折扣和手续费的应用场景。
  * 收款退款单支持手续费的应用场景。
  * 可以针对客户、订单预收。
  * 有关联关系的应收单/其他应收单与收款单自动核销。
  * 有关联关系的应收单与发票自动核销。  
  * 支持无关联关系的应收单/其他应收单与收款单匹配条件核销。
  * 支持无关联关系的应收单与发票匹配条件核销。
  * 支持应收单/其他应收单与应付单/其他应付单核销。
  * 特殊业务核销支持任意单据的核销，包括：单据尾数的冲销、不同往来单位的应收单/其他应收单与收款单的冲销等。
  * 支持内部应收清理功能。
  * 所有业务单据都可以通过智能会计平台生成业务凭证、总账凭证。
  * 提供各种报表查询功能，具体包括：应收款汇总表、应收款明细表、账龄分析表、到期债权表、往来对账明细表、应收单跟踪表、客户对账单、应收未开票明细表、应收单开票核销明细表、已出库未应收明细表。
  * 风险管理上，支持对应收坏账风险进行预测、预警，风险详情查看。
  * 支持应收催收跟踪、催收协同管理。

====== 2 应收款管理业务专题 ======

应收款管理主要处理两方面的业务：销售应收和其他应收。这两项业务仅是在应收确认环节区别较大，确认后的收款、报表查询等方面都是相同的。本部分主要包括如下内容：

===== 2.1 销售应收 =====

销售应收主要处理企业有关产品销售产生的应收款项。

**业务场景**

各个企业确定销售应收款项的环节不一样，有的企业发货后确认，有的企业根据订单确认。为了满足不同企业的应用方式，本系统通过应收单来确认销售产生的应收款项。在系统中应收单是企业对销售应收进行管理的唯一单据，销售业务是否开票、是否收款以及账龄分析等都是以应收单为依据。

===== 2.2 其他应收 =====

其他应收主要处理的是企业除了产品销售外产生的应收款项。

**业务场景**

除了产品销售，企业还会有很多其他原因产生的应收款项，例如对客户、供应商的罚款等。本系统通过其他应收单来确认除销售业务外产生的应收款项。该部分应收款项确认是通过其他应收单来实现的。在系统中其他应收单是企业除销售业务外应收账款管理的依据。

===== 2.3 预收款 =====

预收款是客户预先支付货款的业务行为，预收款主要有如下两种场景：

  * 针对客户预收：与客户商定先预先支付一定的货款，之后客户发出的订单不允许超过该预收金额的一定比例。
  * 针对订单预收：在与客户签订的订单的条款中规定，客户必须先预先支付一定比例的款项才会执行该订单。

===== 2.4 应收开票 =====

**业务场景**

企业可以根据自己的实际情况在发货后、收到订单后等时点确认应收，确认应收后还需要开具销售发票，这个过程即为应收开票。 

由于企业确认应收的时点与开具发票的时点会有差异，所以应收单与发票的金额可能会存在差异，但是最后的应收款项应该以发票为准，所以还需要将应收单与发票进行核对，根据发票金额对应收金额进行调整，系统因此提供了应收开票核销功能，有关该功能的介绍请参见应收开票核销。

**特别说明：**应收开票业务仅用于销售应收业务，其他应收业务不需要开票。

===== 2.5 到期收款 =====

**业务场景**

及时收款是保证企业良好运作的关键因素，而应收款在确认时，就已经同时确定了收款计划，即明细到期日，一般销售业务人员在款项快到期时，会向客户催款，以保证资金能够按期收回，而具体的收款一般是由出纳负责的。

在系统中收款是通过收款单实现的。

  * 应收收款核销

应收款的账龄分析是很重要的业务资料。为了提供准确的账龄分析表，需要准确的知道每一笔应收款项的回收情况，即将应收单与收款单相对应，因此需要进行应收收款核销，有关该功能的介绍请参见[[应收收款核销|应收收款核销]]。

  * 应收转销

由于企业更名等原因，对A客户的应收需要转为对B的应收，后续收款、对账都针对B客户进行，此时需要用到应收转销功能，有关该功能的介绍请参见[[应收转销|应收转销]]。
===== 2.6 组织间交易 =====

除了企业外部的交易业务，集团型企业内部不同法人之间、利润中心之间、甚至部门之间也经常会存在交易，这即是组织间交易。当组织间交易发生的两个组织是需要各自考核的情况下，就会涉及内部结算。如下图：

[图:fin_组织间交易.png]

如上图：蓝海公司下各车间存货的流转都属于组织间交易，铸造车间、组装车间属于同一核算组织，不需要单独的考核，所以一般不需内部结算；而铸造车间、组装车间与精密制造属于不同核算组织，那么铸造车间与精密制造之间的交易需要内部结算。
===== 2.7 内部往来清理 =====

对于组织间交易形成的内部往来，有时需要实际的现金收付或者开具发票，有时不需要实际的现金收付或者开具发票。针对不需要实际的现金收付或者开具发票的情况，很多企业都是在年末或者年中进行清理，即内部往来清理。在系统中分为内部应付清理和内部应收清理。

===== 2.8 立账模式 =====

支持“暂估应收”与“业务应收”两种不同的立账模式。“暂估应收”立账模式是根据发票确认应收账款的原则，如果没有开票，则确认为暂估应收，如果开票了，则确认为财务应收，同时红冲暂估应收；“业务应收”立账模式是货物转移来确认应收账款的原则，如果货已发出，则确认应收账款，不记暂估应收，后续开票，如果确认的应收账款与发票有差异，则进行调差处理，生成差异应收单。

===== 3.3 业务初始化=====

为了保证应收款管理系统使用前后数据的衔接，本功能提供录入系统启用前已存在的各种单据的功能。

第一步：[[应收款启用日期|启用日期设置]]

任何结算组织需要使用应收款管理模块前首先要设置启用日期。启用日期设置后如未有业务发生，则可以修改；否则不再允许修改。

第二步：录入期初单据

期初单据包括：期初应收单、期初其他应收单、期初收款单、期初收款退款单。各单据的录入功能与正常业务期间的单据相同，只是业务日期必须早于启用日期。

第三部：[[应收结束初始化|结束初始化]]

当期初单据全部录入完毕后，就可以结束初始化了。结束初始化后不可以再录入期初单据。

结束初始化后尚未结账之前可以[[应收反初始化|反初始化]]。

详细描述请见：[[应收转销]]

到期债权列表反映截止到指定日期止，已经到期的未核销应收款及过期天数、未到期的应收款及未过期天数。

往来对账对账明细表所展示的数据与应收款明细表基本相同，只是当往来单位既是客户有是供应商时，往来对账对账明细表可以将与该往来单位的所有往来都列示出来。

==== 3.14.6 应收单跟踪表 ====

应收单跟踪表是用来查询与应收业务有关的各种信息的报表，例如应收单的订单情况、出库情况、开票情况、收款情况等等。

客户对账单提供应收的原始金额、已收款金额、未收款金额和对应的账龄分析，主要用来传递给客户进行对账。

应收未开票明细表反映企业当期应收的未开票情况，包括本期未开票情况，截止日期未开票情况，支持按物料明细显示。

====== 应收款管理使用流程 ======
**第一步，基础设置**

在系统使用前，我们需要先做基础设置。
  * 首先，设置公用资料。包括：客户、币别、结算方式、物料、销售部门、销售组、销售员、组织信息、账簿信息、汇率体系等。该部分数据如果用户由于已经使用供应链、总账等模块已经设置，则在使用应收款模块时不需要单独设置。
  
  
  * 其次，设置系统参数。
进入【财务会计】－>【应收款管理】－>【参数设置】－>【应收款管理参数】
  
 
  * 最后，需要维护基础资料。
进入【财务会计】－>【应收款管理】－>【基础资料】－>【收款条件】、【应收收款核销方案】、【应收开票核销方案】 
 
**第二步，初始化**

  * 首先，设置系统启用日期。
进入【财务会计】－>【应收款管理】－>【初始化】－>【启用日期设置】
  * 其次，录入期初单据，包括期初应收单、期初其他应收单、期初收款单、期初收款退款单。
进入【财务会计】－>【应收款管理】－>【初始化】－>【期初应收单】（期初其他应收单、期初收款单或者期初收款退款单）
  * 最后，结束初始化。
进入【财务会计】－>【应收款管理】－>【初始化】－>【结束初始化】
结束初始化工作在第一次结账前进行即可，即录入初始单据和录入第一期单据可以同时进行。

**第三步，日常业务操作**

  * 日常业务操作包括录入应收单、其他应收单、收款单、收款退款单等。
  * 应收单：进入【财务会计】－>【应收款管理】－>【销售应收】－>【应收单新增】
  * 其他应收单：进入【财务会计】－>【应收款管理】－>【其他应收】－>【其他应收单新增】
  * 收款单：进入【财务会计】－>【应收款管理】－>【收款】－>【收款单】、【收款退款单】

来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E6%94%B6%E6%AC%BE%E8%B4%A6%E9%BE%84%E5%88%86%E6%9E%90%E8%A1%A8

====== 应收款账龄分析表 ======


====== 1 报表功能 ======

应收款账龄分析表反映的是截止到某一时间点，往来款项余额的时间分布。

此报表的数据来源于应收收款核销未完毕的应收单、收款单、收款退款单。
====== 2 操作说明 ======

===== 2.1 核销 =====

因为核销会影响报表数据的准确性，因此系统在报表展示界面提供了调用核销的功能。

===== 2.2 分组汇总 =====

系统提供分组汇总功能。分组汇总依据包括：往来单位、币别、结算组织、收款组织、物料编码、物料名称、订单编号等。

===== 2.3 账龄分组设置 =====

系统提供用户自定义账龄分组功能。通过该功能用户可以自由定义自己需要报表显示的账龄区间。

===== 2.4 账龄计算标准 =====

账龄计算标准分为按照业务日期计算和按照到期日计算。



===== 2.5显示选项 =====

报表显示选项包括：

  * 包括未审核单据，默认不勾选
  * 按单据显示，默认不勾选
  * 包含暂估应收
  * 仅显示暂估应收
  * 截止日期的单据余额   [[https://vip.kingdee.com/article/538757872528465920?productLineId=1&lang=zh-CN]]
 
以上选项用户可以根据自己的应用选择。

[[应收款管理#应收转销|<<返回应收款管理界面]]

====== 应收转销 ======

====== 1 功能说明 ======

由于某种原因（例如公司更名），用户需要将A往来单位的应收转为B往来单位的应收，此时需要使用应收转销的功能。转销后收款、对账都需要与B往来单位进行。


转销功能支持应收单、预收单、其他应收单、费用应收单的转销。
====== 2 操作说明 ======

该功能为向导界面。

===== 2.1 转销设置 =====

在转销设置界面，用户设置转销的币别、单据（应收单\预收单）、结算组织\收付组织、转出客户、转入客户。

结算组织必须为用户有权限的、已经启用应收款管理的结算组织。

===== 2.2 转销数据 =====

根据转销设置，转销数据界面会列示转出客户所有没有收款的应收单。用户手工修改转销金额、转入业务日期和转入到期日。

转销金额必须小于等于未收款金额。

转入业务日期默认等于系统当前时间，可以手工修改，但是必须大于当前结账日期。

转入到期日默认等于原应收单的到期日，可以手工修改。

===== 2.3 转销记录 =====

通过[[应收转销记录]]可以查看所有的转销结果。

===== 2.4 反转销 =====

转销记录上有反转销功能，通过反转销可以取消转销。

======  收款条件 ======

收款条件主要是用来设置预收比例、到期日计算日期、收款方式及到期日确认方式。

  * 到期日计算日期系统预设为订单日期、出库日期和应收单业务日期。用户可以根据企业的实际业务增加单据上的其它日期为到期日计算日期。
  * 收款方式包括：按到期日收款、按订单收款、按物料明细收款三种。
  * 到期日计算需要设定设置标准和确认方式。设置标准可以是比例或者金额；确认方式包括交易日、月结、X天后和固定日四种。

    四种到期日确定方式解析说明之三 : 月结	 https://vip.kingdee.com/article/13941

  * 系统预设四种收款条件：货到收款、30天后收款、月结30天和多到期日（按金额）。用户可以根据实际需要，参照系统预设的收款条件进行设置。

======核销字段自动化配置 ======
