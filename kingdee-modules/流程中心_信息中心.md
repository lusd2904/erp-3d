## 【页面】信息中心
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83

====== 1 概述 ======
信息中心以当前用户为核心，列示当前用户的任务、消息、流程，以工作流为驱动搭建一个个人工作平台，通过任务、消息、流程的查询处理，实现统驱动用户完成需要处理的事项，进而提高工作效率。
====== 2 任务 ======
任务中展示了当前用户的待处理任务和已处理任务的情况，这里的任务一般都有工作流运行时产生的，给用户提供了一个集中处理任务的平台。

## 【页面】信息中心_在办流程
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83_%E5%9C%A8%E5%8A%9E%E6%B5%81%E7%A8%8B

====== 在办流程，流程查询 ======
[[信息中心|返回信息中心]]
===== 功能概述 =====
工作流应用过程中，用户可能发起一个流程也可能是某个流程某个环节的参与人，用户有时需要查看自己经手的所有流程，信息中心提供了这样的一个查询平台，在此可以查看当前用户发起和参与的所有流程。查询分为：在办流程、流程查询：

  * 在办流程：提供查询当前用户已发起但是没有处理完毕的流程，以便用户及时了解流程的进度情况； 
  * 流程查询：提供查询当前用户发起和参与的所有流程。
===== 操作步骤 =====
  * 进入【信息中心】→【流程】→【在办流程】/【流程查询】，选择流程点击【查看单据】可以连查流程单据信息，点击【查看流程图】可以查看流程处理情况。
===== 字段说明 =====

在办流程列表 

  - 流程名称： 发起流程的名称。 
  - 流程实例： 发起流程产生的流程实例编码。 
  - 状态： 工作流状态包括：运行中、完成、挂起、终止、暂停，此处显示状态由流程运行状况决定；
  - 在办流程中列示运行中、暂停、挂起的流程。 
  - 发起时间： 流程发起时间。 
  - 当前节点： 在办流程流转到的当前节点名称。 
  - 主题： 流程所在节点产生待办任务的审批动作的标题。 
  - 当前处理人： 在办流程流转到的当前处理人，与审批动作中设置的参与人保存一致。 
  - 任务到达时间：记录流程流转到当前节点的时间。 
流程查询列表

  - 流程名称： 发起流程的名称。 
  - 流程实例： 发起流程产生的流程实例编码。 
  - 状态： 工作流状态包括：运行中、完成、挂起、终止、暂停，此处显示状态由流程运行状况决定； 在办流程中的列示运行中、暂停、挂起的流程。 
  - 发起人： 发起流程的用户名。 
  - 发起时间： 流程发起时间。 
  - 完成时间： 流程处理完成时间。 
  - 组织： 发起流程的组织。 
  - 单据名称： 列示流程对应模板的单据名称。 
  - 单据类型： 列示流程模板中设置的单据类型 
===== 操作说明 =====
查看单据 
  * 打开流程关联的单据，单据状态显示为查看。

查看流程图 
  * 查看流程实例的流程图，方便用户查看流程运行情况。
流程催办
  * 在办流程支持对流程进行催办. 
  * 选择需要进行催办的任务，系统自动取出当前流程对应的流程节点以及流程处理人，支持对流程分节点进行催办. 
  * 点击流程催办默认发送流程消息给催办人，同时支持选择邮件、短信、云之家等几种催办方式. 
  * 被催办的流程，对应的待处理任务列表中字段“催办状态”改为“是”，任务处理人可以根据“催办状态”查询紧急催办的任务.

## 【页面】信息中心_已办任务
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83_%E5%B7%B2%E5%8A%9E%E4%BB%BB%E5%8A%A1

====== 已处理任务 ======
===== 1.功能概述 =====
  * 列示所有已处理任务，可以查看已处理任务的具体信息，也可以通过已处理任务查看对应流程的流程图及已处理环节。

===== 2.操作步骤 =====
  * 进入【信息中心】-【任务】-【已处理任务】，选择要查看的任务点击【查看】。
===== 3.字段说明 =====
  * 发送人： 待办任务的发送人，数据来源于流程上一步的处理人： 
  - 若待处理任务是流程中第一个审批节点产生的待处理任务，即待处理任务为提交流程所产生，则发送人为流程提交用户； 
  - 若审批策略为多人参与多人投票通过，则发送人列示审批动作执行生效的最后一个参与人的用户名称。
  * 主题： 待处理任务的主题，数据来源于流程节点审批动作中设置的标题。
  * 接收时间： 记录收到待处理任务的时间。 
  * 完成时间： 记录完成待处理任务的时间。 
  * 内容： 待处理任务的内容，数据来源于流程节点审批动作中设置的内容。 
  * 流程名称 ：列示产生待处理任务的流程名称。 
  * 流程实例： 列示产生待处理任务的流程实例名称。 
  * 流程模板： 列示产生待处理任务的流程模板名称。 
  * 已处理项： 列示当前任务被处理时选择的审批项 。
  * 已处理意见 ：列示当前项目被处理时录入的审批意见 。
===== 4.操作说明 =====
查看 

  * 打开已处理任务的查看界面，在此界面只能查看，不能处理任务、不能进行单据操作； 
  * 已处理任务列表中双击打开务查看界面。 
查看流程图 
  * 查看产生任务流程的流程图，方便用户查看流程运行情况。 
查看任务明细 
  * 点击查看任务明细，弹出任务明细信息界面，主要用于任务内容较多时，便于更加直观的查看任务的详细信息及其内容，点击【查看任务明细】后任务的阅读状态为“已读”。

## 【页面】信息中心_待办任务
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83_%E5%BE%85%E5%8A%9E%E4%BB%BB%E5%8A%A1

====== 待处理任务 ======

[[信息中心|信息中心]]
===== 1.功能概述 =====
【信息中心】-【任务】-【待处理任务】节点下显示了工作流、审批流运行时产生的待处理任务，通过处理这些任务即可完成审批事项。

===== 2.操作步骤 =====
  * 方法一：进入【信息中心】→【任务】→【待处理任务】，选择要处理的任务点击【处理】； 
  * 方法二：若单据关联流程实例，支持在单据或者列表中，通过点击相关操作，如：审核，对实例产生的任务进行处理。
===== 3.字段说明 =====
  * 发送人： 待办任务的发送人，数据来源于流程上一步的处理人。 
  - 若待处理任务是流程中第一个审批节点产生的待处理任务，即待处理任务为提交流程所产生，则发送人为流程提交用户名称。 
  - 若审批策略为多人参与多人投票通过，则发送人列示审批动作执行生效的最后一个参与人的用户名称。 
  * 主题：待处理任务的主题，数据来源于流程节点审批动作中设置的标题。 
  * 接收时间：记录当前用户收到待处理任务的时间。 
  * 阅读状态 阅读状态有【已读】和【未读】两种状态，通过双击打开、查看、处理、标为已读可以将一条代办任务的状态改为已读。 
  * 内容： 待处理任务的内容，数据来源于流程节点审批动作中设置的内容。 
  * 流程名称： 列示产生待处理任务的流程名称。 
  * 流程实例： 列示产生待处理任务的流程实例名称。 
  * 流程模板： 列示产生待处理任务的流程模板名称。 
  * 上一步处理项： 取上游节点的处理项。 
  * 上一步处理意见： 取上游节点的处理意见。 
  * 单据摘要： 列示流程设计时流程设置中设计的单据摘要的信息 
  * 委托状态： 由流程委托产生的待处理任务，【委托状态】字段为“是”，否则为“否” 
  * 委托人： 由流程委托产生的待处理任务，【委托人】字段显示任务的委托人 
  * 催办状态： 当前待处理任务是进行过流程催办的，则【催办状态】显示为“是”，否则为“否” 
===== 4.操作说明 =====
4.1处理
  * 待处理任务界面显示为上下两部分区域，上部分为任务处理区域，下部分为单据展示区域； 
  * 打开待办任务的处理界面，在任务处理界面可以选择审批项、录入审批意见，并进行提交；   
  * 任务提交后，此任务显示位置从待处理任务节点变更到已处理任务节点，且任务状态显示为已处理； 
  * 下一步处理人：审批节点属性勾选【允许指定下一步处理人】，流程运行时，可以指定下一步待处理任务的接收人。处理当前节点任务时，【下一步处理人】默认解析出下一节点及处理人，也可以通过点击重新选择下一步处理人；若按照流程引擎解析出的参与人与实际运行时所需要的下一步处理人不相符合，可以【追加参与人】，使得流程运行更为灵活。
4.1.1工作流任务处理 
  * 工作流任务处理界面中的审批项是流程设计时自定义的审批项，工作流运行时，根据所选审批项按照流转条件进行流转，也不能对流程进行驳回处理，若要驳回则需要添加驳回审批项及连线流转条件进行驳回流转； 

4.1.2审批流任务处理 
  * 审批项：审批流审批项在流程设计时固定提供“审核同意”“驳回重审”“终止流程”三项； 
  * 选择“审批同意”则流程可以正向流转，流程流向满足条件的下游节点； 
  * 选择“驳回重审”则流程可以逆向流转，流程可以驳回到已经运行过的上游节点，包括开始节点，若选择驳回至“开始节点”，则发起人会收到一条待处理任务，任务审批项固化为“重新提交”、“终止流程”，此时，单据状态为“审核中”，流程实例状态为“运行中”； 
  * 流程驳回给发起人后，发起人若要对单据进行修改，对于不影响流程运行的字段，可以直接修改，然后“重新提交”，此时流程还是一个实例；若要修改重要字段，特别是涉及流程模板中启动条件的字段，则需发起人选择“终止流程”审批项，终止此流程实例后，完成单据修改，再重新提交流程； 
  * 选择“终止流程” 则终止正在运行的流程，同时流程实例状态变更为 “终止”，单据状态为“重新审核”，同时流程发起人收到一条审核不通过的消息。  
  * 驳回流程：在流程运行时可以选择流程驳回的节点，若在审批节点中没有勾选【允许选择驳回级次】选项，流程运行只能驳回至当前节点的直接上游节点；若勾选【允许选择驳回节点】选项，流程运行时可以选择驳回节点； 
  * 审批流待处理任务界面【指定下一步处理人】按钮控制效果受审批节点属性【允许指定下一步处理人】、【允许选择驳回节点】共同作用，详细说明如下：
1.勾选【允许指定下一步处理人】和【允许选择驳回级次】，流程运行时：
  * 选择“审核同意”，【下一步处理人】按钮亮显，可以选择节点参与人；如不选择节点参与人，则流程流向满足条件的流程节点，待办任务发送给节点所有参与人； 
  * 选择“驳回重审”，【下一步处理人】按钮亮显，可以选择驳回节点，并可以指定所选驳回节点解析出的节点参与人为驳回节点待办任务的接收人；如不选择驳回节点，则流程驳回到当前节点的上一步节点，待办任务发送给上一步节点中的所有参与人。 
2.勾选【允许指定下一步处理人】，不勾选【允许选择驳回节点】流程运行时：
  * 选择“审核同意”，【下一步处理人】按钮亮显，可以选择节点参与人； 
  * 选择“驳回重审”，【下一步处理人】按钮亮显，弹出界面中，“驳回节点”灰显不能选择，但是驳回节点任务接收人策略中的选项【节点执行人】、【节点参与人】可以选择，且默认勾选【节点参与人】，若选择【节点参与人】后，可以选择参与人中的具体用户为驳回任务的接收人；
3.不勾选【允许指定下一步处理人】，勾选【允许选择驳回节点】流程运行时：
  * 选择“审核同意”，【下一步处理人】按钮灰显，不可以选择节点参与人；流程流向满足条件的流程节点，待办任务发送给节点所有参与人； 
  * 选择“驳回重审”，【下一步处理人】按钮亮显，可以选择流程驳回的节点，但是不能选择驳回节点任务的接收人，驳回节点任务接收人策略中的选项【节点执行人】、【节点参与人】灰显不可选，默认驳回节点任务接收人为驳回节点的所有参与人。
4.不勾选【允许指定下一步处理人】，不勾选【允许选择驳回节点】流程运行时：
  * 选择“审核同意”，【下一步处理人】按钮灰显，不会弹出界面选择节点参与人；流程流向满足条件的流程节点，待办任务发送给节点所有参与人； 
  * 选择“驳回重审”，【下一步处理人】按钮灰显，不会弹出界面选择驳回级次和驳回任务接收人流程驳回到当前节点的上一步节点，待办任务发送给上一步节点中的所有参与人。

4.2批量处理 

  * 操作前提：流程设计时，在审批动作中勾选【允许批量处理】； 
  * 批量处理界面加载的是相应单据列表的默认过滤方案，双击打开单据查看单据内容，进行单据上字段的编辑，点【过滤】按钮进行批量处理单据的选择过滤；
  * 批量任务处理界面不需要查看的字段可以通过流程配置-节点配置中的批量字段配置来实现； 
  * 信息中心支持多选任务后点击【批量处理】，将所选任务按照是否相同流程版本、相同节点所产生进行分组，相同的任务列示在一个列表中，可对同一分组的任务批量处理；不同分组的任务可以通过下拉列表进行切换。
4.3转发 

  * 操作前提：流程设计时，在审批动作中勾选【允许转发】； 
  * 将此待处理任务转发至其他用户处理； 
  * 待办任务进行转发成功后，此任务从转发用户的待处理任务列表中移至已处理任务列表中，且在已处理任务列表中的状态标注为【已转发】；同时在接收用户的待处理任务列表中添加一条待处理任务，状态标注为【未处理】； 
  * 转发的接收人列示用户列表，进行转发时不进行验权，即被选中的接收人不具有单据权限也可以处理此任务；转发操作时，一次只能选择一个接收人； 
  * 不支持对已存在任务接收人进行重复转发。
4.4查看流程图 
  * 普通列表项目查看产生待处理任务流程的流程图，方便用户查看流程运行情况。 
4.5查看任务明细 
  * 普通列表项目点击查看任务明细，弹出任务明细信息界面，主要用于任务内容较多时，便于更加直观的查看任务的详细信息及其内容，点击【查看任务明细】后任务的阅读状态为“已读”。 
4.6撤销 
  * 工作流和审批流均支持撤销，需要现在审批节点中配置审批项允许撤销，且配置相应的撤销操作，具体可参考节点配置相关内容. 
  * 允许撤销的情况下，流程发起后，下一步处理人尚未处理时，可在【在办流程】中撤销，同时会在在【草稿箱】中生成一条记录，支持在草稿箱中提交流程。发起人撤销后，重新提交流程，会生成一条新的流程实例，之前的流程实例状态为“终止”，单据状态为“重新审核”； 
  * 允许撤销的情况下，流程运行时，当前用户处理任务后，若下一步处理人尚未处理，则可以在【已处理任务】中撤销已经处理的任务；
4.7传阅 
  * 允许传阅的任务可点击【传阅】将任务传阅给他人，传阅后会在接收人的【流程信息】中产生传阅消息 
  * 传阅接收人可对传阅进行回复，亦可继续传阅给他人 
  * 在【传阅记录】中可看到整个传阅过程以及反馈的意见 
  * 流程传阅不影响流程的正常运行.
4.8加签
  * 允许加签的任务，在点击【加签】按钮时，弹出加签界面，默认前加签，加签人可以选择多个；
  * 前加签：当前待办任务处理之前，添加任务处理人，前加签后，加签人会收到待办任务，当前处理人待办任务消失，等待加签人处理完任务后，当前处理人重新收到待办任务；
  * 后加签：当前待办任务处理完后，添加任务处理人（此时流程仍停留在当前节点），后加签完成后，加签人收到待办任务，加签人处理任务时的选择决定流程的走向；

====== 草稿箱 ======
[[信息中心|返回信息中心]]

===== 功能概述 =====

用户发起但尚未提交的流程可暂存至草稿箱中，后续可以在草稿箱中直接发起流程。

===== 字段说明 =====
  - 模板编号：列示流程模板编号。 
  - 模板名称：列示流程模板名称。 
  - 单据名：列示示流程模板配置的单据名称。 
  - 单据类型：列示示流程模板配置的单据类型。 
  - 创建时间：列示从【流程列表】、【我的收藏】中保存或暂存至草稿箱的流程的创建时间。 
===== 操作说明 =====

处理 

  * 调出流程发起界面，流程可以继续暂存，也可以直接提交。 
删除 

  * 删除草稿箱中暂存的流程，支持批量删除。
===== 数据交互 =====

从【流程列表】、【我的收藏】中暂存至草稿箱的流程，同时会在此流程对应的单据列表中生成一张单据；但是若在单据列表中暂存单据，不会在草稿箱中列示此单据对应的流程。暂存流程在草稿箱或单据列表中进行后续操作，数据又会相互影响：

草稿箱操作 

  * 在【草稿箱】中对暂存流程进行提交，则在列表中流程对应的单据也为提交状态； 
  * 在草稿箱中删除暂存流程时，系统提示：“删除暂存流程，系统是否要同步删除单据？”若用户选择是，则在草稿箱中删除流程的同时会删除流程对应的单据，选择否，则删除草稿箱中的暂存流程不会删除对应的单据。 
单据或列表操作 

  * 在单据列表中提交【草稿箱】中暂存流程对应的单据，提交成功后，【草稿箱】中的暂存流程同步消失； 
  * 若在列表中修改暂存流程对应的单据，使得单据组织≠模板组织，在单据列表中提交工作流，修改后的单据若可以找到对应的流程模板，则工作流提交成功；单据修改后，继而在草稿箱中，点击处理提示：找不到流程模板对应的组织，无法处理流程； 
  * 若在列表中修改暂存流程对应的单据，修改除组织以外的字段，则在草稿箱中可以继续处理此流程； 
  * 在列表中删除暂存单据，草稿箱中的暂存流程不会删除，但在草稿箱中处理此暂存流程时，提示：流程对应的单据已经删除，不能处理。

## 【页面】信息中心处理业务流程
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83%E5%A4%84%E7%90%86%E4%B8%9A%E5%8A%A1%E6%B5%81%E7%A8%8B

[[信息中心|<<返回信息中心]]

====== 1 功能概述 ======

在信息中心的流程消息中通过查看业务流程消息，可以打开对应的上游单据，使用单据上的【下推】操作可以促使业务流程继续流转，从而处理当前用户的业务流程。

当业务流程的单据在审批流中调用[[业务流程推进|推进业务流程]]操作时，则对应消息接收人的收件箱会收到业务流程消息。

====== 2 操作步骤 ======

  - 打开收件箱-流程消息节点，选择业务流程推进发送的消息，点击【查看单据】；打开业务流程消息所在连线的上游单据节点所对应单据编号的单据查看界面。 
  - 在打开的上游单据界面，点击【下推】，生成下游单据，从而促使业务流程继续流转。 
注：处理业务流程还可以从主控台菜单打开单据或列表，通过选单或下推操作生成目标单据，也能够促使业务流程继续流转。 

例如，销售流程中销售订单（编号sell01）审核通过后触发业务流程消息，消息配置从【销售订单到发货通知单】的业务流程节点连线上读取，消息内容就是“销售订单sell01已审核，请处理后续流程！”。此时选择此消息点击【查看单据】，则打开的是连线上游单据（销售订单sell01）的查看界面，处理发货通知单的用户就可以在单据查看界面下推生成发货通知单。

## 【页面】信息中心消息
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BF%A1%E6%81%AF%E4%B8%AD%E5%BF%83%E6%B6%88%E6%81%AF

====== 消息 ======
[[信息中心|返回信息中心]]

4.1功能概述
  * 【信息中心】-【消息】提供用户已收到消息的展示平台，以便用户查看其接收到的消息，支持归档设置，可以按照设置的归档期间展示消息，消息分为：收件箱、废件箱；
  * 收件箱：收件箱流程消息节点中存放工作流及审批流发送的消息，可对收件箱进行归档设置。其中，若流程异常挂起，会给上一步处理人发送一条消息；或者流程运行过程中，终止流程，也会给发起人发送一条消息；或者删除单据时，若单据关联流程实例，删除单据后给流程经手人发送知会消息。 
  * 废件箱：存放从收件箱中移出的消息，同时根据收件箱的归档设置，存放收件箱归档期间外的消息，提供一个所有消息汇总查询的平台，便于用户集中查询消息。 
4.2操作步骤
  * 进入【信息中心】-【消息】-【收件箱】/【废件箱】，选择要查看的消息点击【查看】或双击查看。
4.3字段说明
  * 发送人 记录消息的发送人，消息的发送人来源于流程设计时，消息动作中选择的消息发送人，当流程运行到包含消息动作的节点时，系统会以消息动作的发送人身份发送一条系统消息。
  * 主题 消息的显示主题，数据来源于流程节点消息动作中设置的主题。 
  * 接收时间 记录当前用户收到消息的时间。 
  * 内容 消息的显示内容，数据来源于流程节点消息动作中设置的内容。 
4.4操作说明
4.4.1查看消息 
  * 打开消息的详细信息查看界面，在列表中可双击打开消息查看界面。 
4.4.2查看单据
  * 打开产生此消息的流程实例对应的流程模板的关联单据，单据状态显示为查看； 
  * 工作流引擎发送的消息，消息查看单据时，无单据工具栏； 
  * 业务流程引擎发送的消息，消息查看单据时，显示单据工具栏，且支持操作。 
4.4.3移动到收件箱/移动到废件箱 
  * 将选中的消息从收件箱/废件箱中移到废件箱/收件箱，支持批量移动。 
4.4.4删除 
  * 永久删除选中的消息；删除前进行系统提示，若用户确认同意，则直接从物理上删除选中的消息，然后刷新收件箱/废件箱列表；支持批量删除。.

## 【页面】发起业务流程
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%8F%91%E8%B5%B7%E4%B8%9A%E5%8A%A1%E6%B5%81%E7%A8%8B

[[信息中心|<<返回信息中心]]

====== 1 功能概述 ======

单据保存后能够匹配到对应的业务流程版本，则视作业务流程发起；

====== 2 操作步骤 ======

方法一：在【信息中心】的业务流程节点下的【我的收藏】或【流程列表】中选择业务流程，点击【发起流程】，单据保存后即可发起业务流程；

方法二：在单据或列表界面中，新建业务流程对应的入口单据，单据保存后即可发起业务流程。

**业务流程默认值**

默认值来源于【基础管理】→【基础资料】→【单据类型】，单据类型的【业务流程设置】页签中设置的默认业务流程。当入口单据选择此单据类型值时，则业务流程字段自动设置为对应版本作为默认值。

业务流程字段为空，则表示该数据使用自由流程，不进行业务流程管理，仅依据单据转换规则自由流转。 

====== 3 操作说明 ======

===== 3.1 我的收藏 =====

在流程列表中展示所有的业务流程，通过【添加收藏】操作，可以将常用业务流程添加到我的收藏，以便于下次从我的收藏可以快速发起常用业务流程。

  - 发起流程：选择业务流程，点击【发起流程】，则打开单据新增界面，自动选择流程对应的单据类型及其业务流程版本。
  - 删除收藏：选择业务流程，点击【删除收藏】，则将业务流程从我的收藏中移除。 
  - 业务流程图：选择业务流程，点击【业务流程图】，则弹出页签展示对应的业务流程图。

  - 受托人进行任务处理是以委托人的岗位进行：举例说明，财务经理用户ａ设置委托规则将流程委托给财务主管ｂ，此时通过委托规则转交给ｂ的任务，ｂ在进行任务处理时会以财务经理的岗位进行.

来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%9B%91%E6%8E%A7%E6%96%B9%E6%A1%88

====== 监控方案 ======

===== 1 功能描述 ====== 
通过业务监控，可以对业务进行全方位立体的监控，在业务出现异常时，例如：超出安全库存，销售订单到期未发货，采购订单到期未付款等情况，及时进行业务预警，通过不同的方式发送消息给关键处理人，及时进行业务处理或者跟进情况。
配置监控方案的监控周期，启用后会按照监控周期定时执行监控方案。

**使用前提**
  - 管理中心的当前数据中心属性中，选项【允许执行计划任务】必须勾选，同时还需要在数据中心的执行计划列表中把【业务预警服务提供者】设置为准备状态，这两处影响监控方案的定时执行。
  - 如果需要使用自定义监控对象，则需要先在BOS IDE中新增监控对象，并配置好监控方案，具体见监控对象的描述。

**功能路径**

【基础管理】→【业务监控】→【监控方案】 

 ====== 2 字段说明 ======
===== 2.1 监控条件 =====
====2.1.1 监控条件 ====
通用条件：与监控对象的通用过滤条件一致，直接配置条件内容；
自定义条件：具体监控方案通过插件自行添加的内容，例如：保质期预警监控方案的【距物料的到期日相差N天】。

==== 2.1.2 监控周期 ====
  - 支持设置监控周期开始时间、结束时间；如果始终监控，则选择【无结束日期】；
  - 支持按天/周/月的方式来设置执行周期单位；
  - 在指定周期单位后，可以指定固定时间点执行监控方案；
  - 在指定周期单位后，可以选择执行频率；例如：每隔1周的星期二，星期四；
  - 监控周期说明根据上述配置自动生成；例如：从2016-01-01开始，每1周的星期二，星期四，00:01:00开始执行；
  - 设置监控周期并启用监控方案，后台任务按照监控周期定时自动执行。
====2.1.3 其他字段====
  - 业务领域：监控方案所属的业务领域，选择监控对象会默认带监控对象所在的业务领域；
  - 子系统：监控方案所属的子系统，选择监控对象会默认带监控对象所在的子系统，可修改；
  - 监控对象：可选择BOS平台中已有的监控对象，选择后自动带出可设置的通用过滤条件字段和自定义条件，可配置条件和参数值。在合并主题，标题，正文中可配置字段值；
  - 监控方案编码：监控方案编码，控制数据中心唯一性；
  - 方案状态：新增时默认是停用，启用操作后刷新为启用，停用操作后刷新为停用；
  - 监控级别：默认是提醒，可下拉选择：提醒、警告、紧急；
  - 系统预置：产品出厂预置的方案系统预置状态=是，控制不可删除；自行新增的方案预置状态=否，停用后可以删除。

===== 2.2 消息设置 =====
====2.2.1 发送方式 ====
  - 发送方式：内部消息（默认）、云之家消息、第三方消息、邮件消息
  - 内部消息：在主页的监控消息以及信息中心的监控消息可以查看；如果监控方案配置了后续业务处理的，可以在消息中直接点击【处理】；
  - 云之家消息：当前数据中心已正确配置云之家公共号或者云之家轻应用，可以在对应云之家团队的公共号或者轻应用下的【业务监控】收到监控消息；
  - 第三方消息：第三方消息需对接第三方短信服务；勾选启用第三方消息后，接收人可以在手机端收到监控消息；
  - 邮件消息：支持邮件发送，首先需要配置并启用邮件服务；勾选启用邮件消息后，接收人可以在邮件收到监控消息，支持直接在邮件中跳转到产品中的监控消息列表并进行消息处理。
====2.2.2 发送人====
  - 默认是administrator；
  - 可以选择其他用户作为发送人。

====2.2.3 接收人 ====
  - 提供多维度的选择，包括：用户、角色、任岗员工、岗位、部门、汇报关系以及参与人变量
  - 通过参与人变量支持支持监控对象中用户类型字段，例如：业务员、审核人、创建人等；
  - 多维度内容可以同时存在；例如：可以同时选择指定用户和指定角色；
  - 选项【按权限发送监控消息】：勾选后，接收人在系统中没有对应业务对象的查看权限和数据权限，那么就不会接收到该监控方案中的监控消息，这样保证了接收人只接收了需要自己关注的监控信息。

例如：用户小刘是深圳分公司的应收会计，可以查看和新增客户鑫龙的应收单。
 
配置应收款到期预警的监控方案，在2013-09-03时接收监控消息的情况： 如果不勾选，小刘能接收到客户鑫龙以及其他客户的应收单到期预警信息。 如果勾选，那么小刘只能接收到客户鑫龙的应收单到期预警信息

====2.2.4 明细标题====
  - 设置监控消息中标题内容；
  - 标题支持文本输入；
  - 标题支持变量（使用【{】选择监控对象的字段）的配置以及四则运算；
  - 建议标题说明事务内容即可，不要太复杂；例如：采购订单交货到期预警。

====2.2.5 明细正文====
  - 设置监控消息的明细内容；
  - 支持文本的输入；
  - 支持变量（使用【{】选择监控对象的字段）的配置
  - 支持变量的四则运算；
  - 举例：到期应收款预警的明细正文：单据编号[{单据编号}]的到期应收款为：[({应收金额}-{表头计划 - 收（退）款单关联金额})]元
  - 建议正文内容尽量一句话就说清楚问题所在；例如：单据编码:{单据编号}的采购订单，第{序号}行物料{物料编码}的交货日期{交货日期}即将到期，请及时跟进收货情况。

====2.2.6 监控明细显示设置====
  - 提供显示明细字段和排序方式设置，设置后明细监控消息按此设置动态显示对应字段信息；
  - 明细字段中选择的显示字段取业务对象的字段信息，汇总方式针对金额和数量字段；
  - 排序方式是监控消息默认按哪些字段进行排序，以便更清晰的查看。

====2.2.7 监控卡片设置====
  - 提供监控卡片设置，设置后Html5的监控卡片按此设置显示对应字段信息；
  - 主要设置卡片标题、卡片的汇总字段信息，可以选择显示字段，设置别名、重点显示字段及汇总方式信息；
  - 监控卡片设置，通用使用于移动端业务监控轻应用的卡片显示（V7.6版本开始适用）。

====2.2.8 云之家设置====
通过云之家设置，可以将监控方案与云之家公共号绑定，金蝶云定时将监控消息发送到绑定的轻应用进行查看。（V7.0取消该方式，使用轻应用设置解决，具体见2.3轻应用设置）
  - 云之家公共号：支持F8选择，选择金蝶云中维护的公共号内容；
  - 轻应用标题：支持手工录入；云之家公共号接收监控消息时展示的标题内容；
  - 皮肤颜色：支持下拉选择；云之家公共号接收监控消息时展示的标题底色；
  - 变量字段列表：

1）变量字段：从监控方案的明细正文中获取；不能手工添加，可以不勾选；
2）显示位置：就是变量字段在云之家公共号打开后显示的位置，可以在右边的预览区域看设置效果；
3）变量类型：根据变量字段的属性自动携带，不建议调整；
4）字体颜色：云之家公共号接收监控消息时展示的字体颜色，支持下拉选择；

  - 云之家设置与发送方式【云之家消息】绑定，勾选后才会应用；
  - 云之家设置应用，要求所选的云之家公共号已经设置了编码以及密钥。

====2.2.9 高级设置====
**合并主题**
  - 合并主题以分组和汇总的方式合并监控消息发送给接收人，可以减少单条监控消息中的明细数量；
  - 支持文本的输入；
  - 支持变量（使用【{】选择监控对象的字段）的配置；
  - 支持变量的四则运算
  - 到期应收款预警的合并主题：监控方案:[{方案名称}]，客户:[{分组.客户}]的到期应收款为:[({汇总.应收金额}-{汇总.表头计划 - 收（退）款单关联金额})]
  - 支持分组变量和汇总变量；分组变量是选择按数据源中某个字段进行分组。比如客户，供应商等。汇总变量一般是金额和数量字段。

举例：用户小刘是深圳分公司的应收会计，可以查看和新增客户鑫龙的应收单：

设置合并主题：监控方案:[{方案名称}]，客户[{分组.客户}]的到期应收款为{汇总.应收金额} 
接收人小刘收到监控消息2条，分别是：
监控方案：[应收单到期监控]，客户：[鑫龙]共有3条记录需关注，金额合计：[5000]。
监控方案：[应收单到期监控]，客户：[海天]共有1条记录需关注，金额合计：[1800]。
双击消息即可查看明细内容。

**监控数量**
  - 目的是控制每个监控方案的明细记录数量，以避免对服务器性能产生较大的损耗；
  - 系统默认是10000条，可以调整数量的大小；
  - 在系统计算出监控方案的明细数量超出监控数量，则不会执行该监控方案，发送提示消息给接收人，建议调整监控条件以缩小数据；例如：监控记录数超出上限（10000），请重新设置合理的监控条件。

===== 2.3 轻应用设置 =====

轻应用设置，分为汇总消息和明细消息的设置。具体见【[[业务监控轻应用|业务监控轻应用]]】的介绍，本配置是V7.6版本前的设置方式，V7.6版本后建议采用【[[监控方案#监控卡片设置|监控卡片设置]]】方式配置移动监控的监控卡片信息。

 ====== 3 功能操作 ======
===== 3.1 基本操作 =====
  - 复制:同一监控对象可以有多台监控方案，通过复制可以快速设置；
  - 启用/停用:监控方案需要启用后才可以执行；
  - 手工执行:点击后按照监控方案的条件检查对应内容，并发送监控消息。
  - 清理规则：设置清理规则自动清理冗余数据，避免数据库膨胀影响性能，为客户规避问题；启用后将定期清理监控消息，可以设置保留*月的监控日志，清理内容主要包括监控消息列表、监控执行情况列表及监控执行情况历史记录列表的内容

===== 3.2 GUI和SL监控消息 =====
  - 可以在主页的监控消息页签查看接收的监控消息，此界面为快速处理界面；双击消息即可查看监控明细记录内容，监控明细内容可以按监控方案中监控明细显示设置设置的显示字段动态展示；
  - 可以在消息中心的监控消息节点查看接收的监控消息；双击消息即可查看监控明细记录内容；
  - 监控消息是否需要业务处理与监控方案有关。

===== 3.3 Html5监控消息 =====
  - 可以在主页的监控消息卡片查看最新的接收的监控消息，点击监控每个方案可以查看监控明细记录内容，并支持后续处理； 
  - 提供了监控汇总卡片，统计所有已读、未读消息数
