## 【页面】k3cloud综述
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=k3cloud%E7%BB%BC%E8%BF%B0

====== 1 综述 ======

**欢迎使用金蝶K/3 Cloud产品！**

本着帮助客户成功的经营理念，金蝶公司投入巨资全力打造新一代企业管理服务平台–金蝶K/3 Cloud，以帮助中国制造企业走出经营困境，实现再次腾飞。

金蝶K/3 Cloud是移动互联网时代的新型ERP，是基于WEB2.0与云技术的新时代企业管理服务平台。金蝶K/3 Cloud围绕着“生态、人人、体验”，旨在帮助企业打造面向新时代的生态互联与协同平台，围绕生态中的每个角色，提供随手可得的云服务，最终实现敏捷协同，智慧运营的企业运营新境界。整个产品采用SOA架构，完全基于BOS平台组建而成，业务架构上贯穿流程驱动与角色驱动思想，结合中国管理模式与中国管理实践积累，精细化支持企业财务管理、供应链管理、生产管理、供应链协同管理、人力资源管理等核心应用。技术架构上该产品采用平台化构建，支持跨数据库应用，支持本地部署、私有云部署与公有云部署三种部署方式，同时还在公有云上开放中国第一款基于ERP的协同开发云平台。任何一家使用金蝶K/3 Cloud产品的企业，其拥有的是包含金蝶在内的众多基于同一个平台提供服务的IT服务伙伴。

金蝶K/3 Cloud以其独特的“标准、开放、社交”三大特性为企业提供开放的ERP云平台，支撑企业全生命周期管理需求，是中国“智”造“引擎”。


====== 2 产品特性 ======


===== 2.1 产品适用性 =====

金蝶K/3 Cloud结合当今先进管理理论和数十万家国内客户最佳应用实践，面向事业部制、多地点、多工厂等运营协同与管控型企业及集团公司，提供一个通用的ERP服务平台。K/3 Cloud支持的协同应用包括但不限于：集中/分散销售、集中/分散采购、B2B电商管理、B2C电商中心、供应商协同、多工厂计划、跨工厂领料、跨工厂加工、工厂间调拨、内部交易及结算、集团财务管理、阿米巴经营等。

===== 2.2 产品理念 =====

秉承“帮助顾客成功”的经营理念，经过多年实践与经验积累，结合先进的技术与应用，金蝶K/3 Cloud在帮助企业实现核心业务应用的基础上，进一步提出“社交、标准、开放”的产品理念，为企业构筑开放的ERP云平台。
  * 社交：
金蝶K/3 Cloud深度集成金蝶“云之家”，为企业用户构筑高效、协同的社交门户；通过面向角色的移动应用，为企业及用户搭建跨越空间、时间限制的工作环境；通过面向群组、责任人的社交化流程驱动应用，将移动互联网和社交网络完美融入管理中。
  * 标准：
金蝶K/3 Cloud在总结百万家客户管理最佳实践的基础上，提供了标准的管理模式；通过标准的业务架构：多会计准则、多币别、多地点、多组织、多税制应用框架等，有效支持企业的运营管理；K/3 Cloud提供了标准的业务建模：35种标准ERP领域模型、1046种模型元素、21243种模型元素属性组合，288个业务服务构件，让企业及伙伴可快速构建出行业化及个性化的应用。
  * 开放：
金蝶K/3 Cloud动态构建的多核算体系与业务流程设计模型，为企业提供了适应其动态发展的开放性管理平台；其SOA架构，以及纯Web应用、跨数据库应用、多端支持、云应用等新兴特性，为企业提供了开放的信息化整合平台；K/3 Cloud打造的开放ERP开发云平台，为伙伴、客户提供完整的ERP服务生态圈，为企业提供真正的一站式应用。
金蝶K/3 Cloud旨在通过开放的ERP云平台，为企业构建以人为本的协同应用、开放的产业生态链，以及个性化的协同开发云平台；从管理方法、流程控制、管理对象、应用模式等方面，引导企业从常规管理迈向深入应用，使企业在激烈的竞争环境中不断提升边际利润，实现企业的卓越价值和基业常青。

===== 2.3 K/3 Cloud特性 =====

金蝶K/3 Cloud具有以下突出的特性：

  * 社交化的ERP系统
与金蝶云之家深度集成，并可与微信账号对接，基于社交网络技术，借助企业员工网络、客户网络、供应商网络，实现企业内、外部业务协作，突破组织边界、资源与时空限制。
  * 多组织运营协同
顺应中国企业管理创新理念，从组织、角色、数据、业务流程等多角度出发，构建多地点、多工厂、多事业部的动态业务模型，实现企业内部多业务单元的运营与考核。
通过简约的组织间业务关系定义与隶属关系定义，支持多组织企业内各公司或事业部之间的协同作业，尤其是上下级组织间的战略协同以及业务汇总。通过组织角色授权方式，灵活处理企业内部多组织下的用户权限体系，全面升级用户体验。
  * 业务流程驱动
通过流程管理实现企业业务管理流程的固化及优化；通过基于角色的全流程业务驱动，实现企业业务的规范化运转；通过以事找人的工作方式，加之移动审批轻应用，用户可以通过任务处理的方式完成业务全过程的处理，提升工作效率。
  * 多维管理考核体系
通过建立多个核算体系，支持法人账、利润中心账并行核算，解决多工厂、多法人经营下，多角度利润核算与分析体系，解决多层次会计主体直接式财务核算。
通过阿米巴报表，实现了基于业务信息的阿米巴经营考核的报表输出。
  * 智能会计平台
提供开放的记账平台，支持用户自行设置记账的规则与维度；提供开放的成本核算配置平台：支持用户自行配置核算维度、业务范围、核算方法；通过弹性域技术方案，支持多维度核算，满足多角度核算与考核分析要求。
  * 全程协同供应链
单据类型与弹性域结合，业务流程与业务纬度可自由扩充，构建灵活供应链平台。简约一屏式录入，正常情况无需翻屏，无需切换页签即可完成数据录入，相关信息系统自动分类展示。
提供标准接口，可与各种外部系统轻松对接，实现外部供应、营销、服务三大体系业务协同。
  * 协同制造，敏捷应变
以产品创新设计为核心的全生命周期管理。实现与K/3 PLM产品的对接，打通从产品研发到生产的全过程管理。多版本多用途BOM设计、灵活易用；支持多种业务模式的组合替代；支持阶梯用量、辅助属性、联副产品管理；能够很好的支撑行业特性扩展。
提供基于多工厂、柔性化的智能制造解决方案，支持协同设计、计划、生产、委外加工等业务，并支持全程的质量和追溯管理。
  * 助力企业全球资源配置的国际化平台
通过会计要素与核算规则，满足不同国家、地区会计制度与准则的要求。
易于扩展的税制框架，以及通用的税规则处理，既满足全球各地的应用，又可方便地进行本地化配置。
一个数据中心可同时支持业务信息多种语言的应用，方便不同国籍人员的沟通与协作； 一键式的多语言启用，方便按需配置，以快速跟随企业全球化布局的步伐。
支持跨时区应用，满足企业全球资源配置的运作协同。
国际化设置可方便按需设置不同国家、地区的应用习惯。
基于互联网的翻译平台，轻松完成本地化产品翻译工作。
  * 开放的产业生态链
通过公有云应用，聚合产业链上下游合作方；
通过协同开发云平台，整合随需应用的开发商资源。
  * 个性化的开发云平台
以BOS为核心的协同开发云平台，快速获得个性化应用；
一键式开发环境部署，在线的成果体验，方便二次开发；
未来还可通过应用商城（App Store），结合业务需求随需选用增值开发成果。

## 【页面】业务报表结果查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%8A%A5%E8%A1%A8%E7%BB%93%E6%9E%9C%E6%9F%A5%E8%AF%A2

====== 业务报表结果查询 ======

=====1 功能说明 =====

对账结果查询用于查询已执行保存的对账数据；因总账系统和业务系统相互独立，为确保总账数据和业务数据的一致性，财务于月结前必须进行对账。

若对账方案勾选必须与总账期末对账平衡，则总账期末结账时直接调取对账结果（对应方案勾选与总账对账平衡）进行校验，若对账结果平衡则允许结账，若对账结果不平衡则不允许总账期末结账。

=====2 操作前提 =====

账务已处理、对账方案设置、参数勾选保存对账结果、对账结果已保存。

=====3 功能路径 =====

【财务会计】－>【智能会计平台】－>【对账管理】－>【对账结果查询】

=====4 字段说明 =====

| **字段**       || **说明**                 |
| 账簿           || 选择账簿，若不勾选取总账科目最新余额，则总账科目金额取对账结果保存的数据；如勾选则取总账最新科目金额。                                                  |
| 对账方案         || 选择要查询的对账方案，如有保存对账结果，则点击确定后显示保存后的明细对账数据。                                                               |
| 年度、期间        || 选择要查询的账簿对应年度和期间，已保存的对账结果将以该条件进行过滤。                                                               |
| 币别           || 选择要查询的对账结果查询币别，已保存的对账结果将以该条件进行过滤。                                                                  |
| 方案编码         || 显示对账保存的方案编码。           |
| 方案名称         || 显示对账保存的方案名称。           |
| 科目编码         || 显示对账结果保存的科目编码。         |
| 科目名称         || 显示对账结果保存的科目名称。         |
| 核算维度编码       || 显示对账结果保存的核算维度编码。       |
| 核算维度名称       || 显示对账结果保存的核算维度名称。       |
| 总账期初余额       || 显示对账结果保存的总账期初余额。       |
| 业务系统期初余额     || 显示对账结果保存的业务报表的期初余额。    |
| 期初余额差异       || 显示对账结果保存的期初余额差异。       |
| 总账本期增加       || 显示对账结果保存的总账本期增加金额。     |
| 业务系统本期增加     || 显示对账结果保存的业务报表的本期增加金额。  |
| 本期增加差异       || 显示对账结果保存的本期增加差异金额。     |
| 总账本期减少       || 显示对账结果保存的总账本期减少金额。     |
| 业务系统本期减少     || 显示对账结果保存的业务报表的本期减少金额。  |
| 本期减少差异       || 显示对账结果保存的本期减少差异金额。     |
| 总账期末余额       || 显示对账结果保存的总账期末余额。       |
| 业务系统期末余额     || 显示对账结果保存的业务报表的期末余额。    |
| 期末余额差异       || 显示对账结果保存的期末余额差异。       |
| 对账结果         || 显示对账保存的对账结果是否平衡。       |

=====5 业务说明 =====

 

智能会计平台增加“对账结果查询”（对账结果查询前需先保存数据），系统将最后一次对账结果保存到后台表以便于查询。同时总账期末结账支持对账不平衡不允许结账（对账方案须勾选“必须与总账期末对账平衡”）：

  * 对账结果查询前需要先保存对账结果，而保存对账结果（对账界面 点击保存按钮）前 需要在智能会计平台参数启用“保存总账科目与业务报表的对账结果”。 
  * 执行对账，若对账结果显示的数据确实无误，点击保存（需要注意的是同一对账方案若点击多次保存，系统只保留最后一次对账结果），后续即可在对账结果查询中按不同的对账方案查询。 
  * 对账方案 增加选项“必须与总账期末对账平衡”，勾选此选项的对账方案 在执行对账并保存了对账结果之后，若对账不平衡，总账期末结账校验无法通过。同时若某一对账方案保存了对账结果，则该对账方案不允许删除 ，只能修改。

  - 维度：物料分组，字段取数。
  - 公式说明：
             * 毛利 = 应收单的不含税金额 - 出库单的成本（出库单没有成本时，获取最新出库成本）
             * 毛利率 = （销售收入 - 销售成本）/（销售成本）

===== 3 图表说明 =====

  * 产品销售收入占比：采用饼图展示各类产品的销售收入占比情况。
  * 产品销售收入趋势：根据不同年月，将产品销售收入以折线图的方式展示出来，直观看出销售收入的起伏变化。
  * 根据不同数据来源，统计已经审核（作废、暂存、重新审核的不统计）状态的订单的价税合计。
  * 产品销售分析：采用散点图展示产品销售毛利率和销售收入，可以看到不同销售收入条件下的毛利率大小。
  * 产品销售信息：采用交叉表方式，展示产品销售的相关信息如物料信息、销售数量、同比增长率等。

===== 4 功能与价值 =====

  * 主要功能：展现产品销售额及其占比、毛利、毛利率、产品销售排名等常用分析指标。
  * 业务价值：帮助企业了解产品的市场反应，指导企业制定合理的营销政策进行积极的产品结构调整，以提高企业的竞争力。

  - 其次，进入【基础管理】－>【基础资料】中设置采购参数； 
  - 再次，进入【供应链】－>【采购管理】－>【货源与价格管理】设置采购货源数据，包括供应商、价目表、折扣表、采购目录……等等；

  - 系统启用时，如存在已经下单给供应商，但还未完成收货的采购订单，可以在系统中录入已经下达还未完成收货的采购订单：

  - 维护采购申请单，进入【供应链】－>【采购管理】－>【采购申请】－>【采购申请单】 
  - 如果由采购订单开始采购业务，请直接维护采购订单：
  - 维护采购订单，进入【供应链】－>【采购管理】－>【订单处理】－>【采购订单】 
  - 如果订单在执行过程中需要变更，请维护采购订单变更单：
  - 维护采购订单变更单，进入【供应链】－>【采购管理】－>【订单处理】－>【采购订单变更单】 
  - 如果需要收料单来记录收料情况，请维护收料单：
  - 维护收料单，进入【供应链】－>【采购管理】－>【收料处理】－>【收料单】 
  - 如果物料需入库，请维护入库单：
  - 维护入库单，进入【供应链】－>【采购管理】－>【收料处理】－>【入库单】 
  - 如果有退料业务，需进行退料申请，请维护退料申请单：
  - 维护退料申请单，进入【供应链】－>【采购管理】－>【退料处理】－>【退料申请单】 
  - 完成退料动作，请维护退库单：
  - 维护退库单，进入【供应链】－>【采购管理】－>【退料处理】－>【退库单】

【财务会计】→【报表】→【基础资料】→【分摊方案】

对于常用的分摊方案进行增加，无特殊操作。

======1 在线客服概述 ======

===== 1.1 在线客服概述 =====
 
通过在线客服给金蝶云用户提供在线服务，提升客户满意度和问题解决率。

===== 1.2 系统特性 =====
 
本系统主要包含以下特点：

  - 在线客服无需安装，可以直接应用；
  - 专属的在线客服，一对一解答客户疑惑，最快帮助用户解决难题；
  - 使用金蝶云系统中出现问题时，可以通过在线客服，获取相应问题的解决方案，引导用户自动解决问题。

 
====== 2 在线客服操作手册 ======

在线客服无需安装，用户只需轻轻一点【在线客服】图标，就及时与客服人员进行在线交流。


===== 2.1 在线客服-咨询问题 =====

Silverlight/GUI端，入口在主页右侧的第一个【小云】图标。

Html5端下，入口在首页上方的【小云】图标。

点击【小云】图标后直接打开的云之家轻应用“金蝶服务”，可以快速对接智能人工服务，一对一解答客户疑惑。


===== 2.2 在线客服-系统报错 =====

Silverlight、GUI、Html5端下，当系统出错时，报错信息显示【小云】图标。

点击【小云】图标，直接打开的云之家轻应用“金蝶服务”界面，
  - 若该报错已有解决方案，系统会精准推送对应的解决方案，引导客户自我解决问题。
  - 若还没有，则推荐用户利用产品社区搜索论坛帖子的方案。
  - 如果客户自服务期内，则同时可以快速对接金蝶人工服务，协助解决客户疑难问题。


===== 2.3 Administrator用户的在线客服配置 =====

  - Administrator用户需要绑定注册用户才可以使用在线客服。
  - Administrator点击在线客服的【小云】图标后，会先弹出绑定界面，输入金蝶云或者云之家帐号及其密码，点击【登录】成功后，系统会自动绑定该帐号。
  - Administrator用户绑定某个云之家帐号后，金蝶云中同名的用户则不能使用该帐号进行在线客服设置。

注意：暂未提供解绑功能，需谨慎选择帐号。

===== 2.4 注意事项 =====


  - 支持正式许可、临时许可的注册用户已经自动绑定，可直接使用在线客服进行问题咨询，演示版下不提供在线客服的应用；
  - Administrator绑定帐号对应的用户，其登录金蝶云是无法使用在线客服的，一般建议绑定较高级别的用户（例如：总经理之类的）。

仅为创建、暂存状态的工作站信息可以删除；提交、审核后的工作站信息不允许删除，只允许禁用；

分配与取消分配

工作站信息为分配型的基础资料，如需在组织间使用，用户可在单据或者列表界面进行分配。 

只有在【基础资料控制策略】中分配给了相关的业务组织后，业务组织才能够使用。目标组织可依据权限设置对分配过来的工作站信息进行修改操作。 

用户可对已经分配的工作站信息取消分配，前提是目标组织中的工作站信息没有提交审核。

快餐工作站

在工作站参数中选择110（对应工作站是否有快餐功能），并设置为1即可。

## 【页面】数据规则选项
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E8%A7%84%E5%88%99%E9%80%89%E9%A1%B9

====== 1 功能描述 ====== 
数据权限是基于有功能权限内容的进一步数据范围控制，以缩小关键数据范围，从而保证敏感数据的安全性。

**使用前提**
具备当前业务对象的功能权限。例如：查看、新增等。

**功能路径**
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→数据范围
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→基础资料权限

 ====== 2 字段说明 ======
=====2.1 数据范围 =====

  - 数据范围支持的权限项：查看、修改、删除、审核。
  - 调出数据规则列表进行选择；也可以选择当前业务对象的单据头字段设置新的数据规则；
  - 在设置数据规则时，可以利用业务对象提供的变量，以减少数据规则方案的数量；目前提供的变量有：当前组织（组织属性字段）、当前用户（用户属性字段）、当前用户对应的部门、当前用户对应的业务组、当前用户对应的业务员；
  - 数据范围应用只对单一对象有效，不支持联动控制机制；例如：销售订单的查看时，不会调用销售订单所引用客户基础资料设置的查看数据规则（查看华南区客户）进行筛选，而是使用销售订单查看权限设置的客户查看数据规则（查看珠三角客户）进行处理；
  - 数据规则默认不支持单据体字段的设置，例如：物料、仓库等；
  - V7.6新增参数“单据列表启用单据明细数据权限控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后在数据规则设置时可以选择到单据体字段（只支持单个单据体），单据列表只显示有权限的单据明细行，查看、编辑单据明细数据不做控制。
  - V7.7新增参数“存在无权单据明细不能打开单据”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置哪些单据需要控制，则打开单据时会校验只要存在一行明细没有权限则不允许打开单据。
  - V7.7新增参数“基础资料数据范围联动应用到业务对象”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置基础资料对应哪些业务单据的哪个字段受控，则设置基础资料数据范围后，关联受控的业务单据只能看到有权限的基础资料对应单据。可同时控制单据头和单据体。
  - V7.7新增参数“报表的基础资料数据权限由报表本身的基础资料数据范围控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后报表数据权限完全按照报表的基础资料数据范围控制。
  
=====2.2 基础资料权限=====
  - 此处设置的数据范围，只对当前业务对象新增时有效，且影响该基础资料F8界面展示的数据行数；
  - 显示当前业务对象引用的基础资料列表；
  - 支持单据类型的数据范围，数据规则配置时先要确定单据类型的单据，再选择具体的单据类型；
  - 支持选单的数据范围，影响业务单据新增时，选单的范围；
  - 在数据规则选项勾选了【联动应用基础资料本身的查看数据范围】，则业务单据新增时，基础资料的F8界面优先取基础资料权限设置的数据范围，如没有设置则取该基础资料本身的查看数据范围。
  - V7.7新增在数据规则选项勾选了【基础资料数据范围联动应用到业务对象】，设置基础资料关联业务对象的受控字段，则只能查看有权限的基础资料业务单据。
=====2.3 分组数据权限=====
  - 支持对业务对象新增“分组”权限项，可针对分组设置分组权限数据规则；
  - 分组权限默认只对分组树查看范围有效，如勾选了【分组数据应用到列表数据范围】，则对数据查看范围也有效；
  - 分组也可应用到F8选择，应用规则和列表数据的应用规则一致；
  - 分组可从不同维度设置分组数据规则，多个分组维度同时设置，则数据取交集。
 ====== 3 功能操作 ======
=====3.1 批量应用数据规则 =====
  - 主要便于该数据规则的快速应用，减少多次选择；
  - 在权限项，例如：销售订单的查看，选择数据规则（华南区客户）后，如果其他权限项以及其他角色都是使用该数据的，则可以在当前行点击【批量应用数据规则】，系统调出批量应用的界面，支持选择其他角色，以及当前角色的其他权限项；
  - 执行批量应用，系统自动将数据规则回填所选用户的所选权限项。

====== 4 业务说明 ======
=====4.1数据规则应用 =====
**单据新增**     单据新增时，单据上的基础资料F8范围优先取该单据基础资料权限设置的数据范围，如没有设置则取基础资料本身的查看范围；
     例如：新增采购订单时，单据上部门的F8选择范围，优先取采购订单基础资料权限设置的部门查看范围，若没有设置则取部门基础资料本身的查看范围。

**单据操作**   单据查询、修改、删除、审核应用对应权限对应的数据范围进行显示。    
    例如：一部采购员只能查看一部门的采购订单，在采购订单查看权限的数据范围中设置【部门名称=“一部门”】的数据规则即可。

**变量应用**   需要根据用户的一些身份或者其他一些条件隔离，例如：我的业务单据，我所属部门的业务单据，我所在业务组的业务单据
   设置方案：
   1）可以使用业务单据的字段对应的变量进行设置，例如：我的销售订单（业务单据=销售订单，字段=创建人，比较=当前用户）
   2）供应链提供业务员和业务组隔离的选项设置，选择后系统按照用户对应职员所属的业务员或者业务组进行隔离处理，无需通过数据规则处理（前提：用户必须设置对应的职员信息）。

## 【页面】新增单据防重配置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%96%B0%E5%A2%9E%E5%8D%95%E6%8D%AE%E9%98%B2%E9%87%8D%E9%85%8D%E7%BD%AE

﻿
====== 1 概述 ======

异构系统接入星空业务单据涉及支付需要设置唯一索引，通过“新增单据防重配置”实现指定字段的唯一索引管控。

====== 2 操作入口 ======

入口：系统管理-其他，打开【新增单据防重配置】。

====== 3 功能说明 ======

  - 仅允许选择【单据】对象。
  - 一个业务对象最多允许创建2条防重管控配置（即 最多2个字段进行唯一性管控），创建后是分开各自校验唯一性，不是多个字段组合唯一性管控。
  - 同一个业务对象不允许重复使用相同的校验字段。同一个业务对象最多设置2个不同的校验字段。
  - 内置执行计划“新增单据防重复表的历史数据清理”，将自动清理1年（365天）之前的防重表记录，避免大量历史记录占用存储空间或影响系统性能。
  - 详细功能说明，见下面表格。

| 检验字段            || 1、仅允许选择单据头的“文本”类型字段，表示该字段作为唯一性判断的校验字段。2、配置保存后，将依据 【单据+检验字段】生成对应防重管控记录表。3、新增单据保存时，将“检验字段”纳入唯一性管控，避免并发新增时重复生成。4、注意：谨慎使用单据编号字段作为校验字段，如果作为校验字段，建议配合勾选“WebAPI必录”使用，由第三方系统传入单据编号。必须避免通过星空系统编码规则自动生成单据编号，因自增长流水号生成多个不同编码的单据（实际属于第三方的同一笔业务），达不到防止并发重复创建的管控目的。  |
| 为空不校验           || 1、默认表示为空是校验的，包括1个或多个空格也视作空值。例如，传入2个单据的校验字段都是空值，则视作不满足唯一性，第2张单据新增保存失败。2、若勾选“为空不校验”，则校验字段的值为空时，忽略不校验（即 不记录空值到防重管控表）。                                                                                                                                     |
| WebAPI必录        || 默认勾选，表示有防重管控要求的校验字段，建议在WebAPI接口必录，需传入第三方业务的唯一号。                                                                                                                                                                                                        |
| 附加说明            || 1、异构系统接入星空业务单据涉及支付必须设置唯一索引，以防并发导致数据重复。2、仅对新建配置之后的新增单据数据进行管控，历史已保存数据不进行管控。更换校验字段，需要创建新配置。3、系统预置的单据防重配置不允许删除，企业自建的单据防重配置允许删除。4、单据删除、作废操作，将按检验字段值移除防重表记录。5、新增单据保存、修改校验字段值保存单据、反作废操作，将同步更新防重表记录。                                                           |

## 【页面】方案日历
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%96%B9%E6%A1%88%E6%97%A5%E5%8E%86

====== 方案日历 ======

**功能概述**

方案日历是由方案日历模板已审核后生成或更新而来，用于明细展示各组织各营销活动方案的具体启用日期。查看各组织按营业日期自动执行方案日历下该日期的营销优惠活动。
总体来说，方案日历主要用于查询及展示某组织在某天或某段时间启用并执行哪个或哪几个营销优惠方案。


**使用前提**

已审核的营销方案日历模板生成/更新日历。

**功能路径**

【餐饮客户关系】->【基础设置】->【营销方案日历】->【营销方案日历】



**操作说明**

生成的明细方案日历操作员可根据情况临时修改，也可以禁用（即失效）及反禁用（即生效）所选的方案日历。

## 【页面】方案日历模板
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%96%B9%E6%A1%88%E6%97%A5%E5%8E%86%E6%A8%A1%E6%9D%BF

====== 方案日历模板 ======

**功能概述**

方案日历模板是用于商家根据实际营销计划来设置各营销方案的执行时间，设置好方案日历模板后，可生成明细方案日历，门店营业端将自动按照明细方案日历执行相应的营销活动方案。它有两个目的：
  
1. 定义各营销方案的使用规则：按固定日期、周、月、年、区间等。
  
2. 根据方案日历模板生成各营销方案的具体执行日期。


**使用前提**

已设置各种营销优惠方案，日期类型辅助资料。

**功能路径**

【餐饮客户关系】->【基础设置】->【营销方案日历】->【营销方案日历模板】

**字段说明**

**表头常规信息字段** 
|**字段**||**说明**|
|创建组织||若方案日历模板的基础资料控制类型为分配型，默认为集团总部|
|使用组织||由创建组织自动携带|
|编码||保存时自动生成，不可维护|
|名称||手工录入|
|生效日期||手工设定方案日历模板的生效日期|
|失效日期||手工设定方案日历模板的失效日期|

**表体明细信息字段** 
|**字段**||**说明**|
|优先级||填入正整数，默认1的优先级最高，数值越大，优先级递减|
|规则类型||支持周、日、月、年、区间、固定日期可供选择|
|日期类型||从日期类型辅助资料中选择|
|是否启用||勾选则启用，否则不启用|
|日期||当规则类型选为固定日期时启用，表示仅在某一天执行|
|周||当规则类型选为周时启用，表示仅在每周几执行|
|日||当规则类型选为月时启用，表示仅在第月每几天执行|
|月||当规则类型选为年时启用，表示仅在每年第几月几日执行|
|起始/截止日期||当规则类型选为区间时启用，表示仅在某一段时间区间内执行|
|储值优惠方案||从已设置的储值优惠方案列表中选择。其他方案操作类似|

**操作说明**

1、新建的营销方案日历模板，须依次经过保存－提交－审核，是已审核状态才能生成方案日历。若反审核－修改原营销方案日历模板，也要重新审核后，点击更新日历，才能按现方案日历模板执行。

2、分配型的基础资料控制类型，只有分配到目标门店组织后，这些组织才可生成日历，且无修改方案日历模板的权限。集团总部对方案日历模板反审核修改后，已分配到所有门店组织的同一个方案日历模板将自动修改，保持与集团组织同步一致，同时在门店组织更新日历按新方案日历模板生效执行。

3、规则的起止日期必须在方案日历模板的生效日期、失效日期之内；规则内容相同时，按优先级数执行方案日历，数值越小，优先级越高。

## 【页面】时段
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%97%B6%E6%AE%B5

======1.功能说明======
时段是场所不同的营业时间范围，可以用于设置食品的时段价格，也可以用于报表的时段统计。
======2.使用前提======
无。
======3.功能路径======
【餐饮门店管理】→【门店营业设置】→【营业基础资料】→【时段】
======4.字段说明======
=====4.1表头字段说明=====
|**字段**||**说明**|
|创建组织||时段的创建组织|
|使用组织||使用时段的业务组织|
|时段编码||时段的编码在相同组织下必须具唯一性，不允许重复，系统自动生成|
|时段名称||时段的名称|

=====4.2基本主要字段说明=====
|**字段**||**说明**|
|开始时间||表示时段的开始时间，同一组织下的时间范围不能重叠|
|结束时间||表示时段的结束时间，同一组织下的时间范围不能重叠|
|描述||表示时段的描述说明|

======5.操作说明======
=====5.1删除=====
仅为创建、暂存状态的时段信息可以删除；提交、审核后的时段信息不允许删除，只允许禁用；
=====5.2分配与取消分配=====
时段为分配型的基础资料，如需在组织间使用，用户可在单据或者列表界面进行分配。 

只有在【基础资料控制策略】中分配给了相关的业务组织后，业务组织才能够使用。目标组织可依据权限设置对分配过来的时段进行修改操作。 

用户可对已经分配的时段取消分配，前提是目标组织中的时段没有提交审核。

## 【页面】未完工切换产品_pt-146884
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%9C%AA%E5%AE%8C%E5%B7%A5%E5%88%87%E6%8D%A2%E4%BA%A7%E5%93%81_pt-146884

功能简介

同一作业产品装配过程中，多个用户共同完成装配，每个用户负责装配其中一部分，连续装配；

  * HMI界面按钮配置，增加“切换产品”按钮；
  * 点击“切换产品”后，允许切换未加工完成的产品，继续加工下 一件产品；
  * 若该件产品在该作业已经加工完成，不需要手动“切换产品” ，直接扫描下一件产品条码进行连续加工；


HMI路径

【HMI工作台】—>【柔性产线】—>【产线登录】—>【普通扫描汇报】

## 【页面】查询内部权益
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%9F%A5%E8%AF%A2%E5%86%85%E9%83%A8%E6%9D%83%E7%9B%8A

===== 权益抵消 =====

内部权益投资事项主要涉及集团内部投资、内部利润分配，在抵销时要考虑投资的股权比例等的影响。

**操作说明：**

第一步：基础设置（集团行为）

打开【财务会计】－>【合并报表】－>【合并准备】－>【合并方案】，在合并方案中确定权益核算方法。

打开【财务会计】－>【合并报表】－>【合并准备】－>【股权关系】，维护集团内组织间的实际投资持股比例。

打开【财务会计】－>【合并报表】－>【基础资料】－>【抵消类型】，系统已预设了权益类抵消类型，只需设置与权益类抵消相关联的报表项目。

打开【财务会计】－>【合并报表】－>【合并准备】－>【抵消分录模板】，新增权益类抵消分录模板。

打开【财务会计】－>【合并报表】－>【报表模板】－>【模板样式方案】，定义权益类抵消表样式方案。

打开【财务会计】－>【合并报表】－>【报表模板】－>【抵消报表模板】，新增权益抵消报表模板，填充权益类抵消表模板样式方案保存并分发给子公司。

第二步：上报内部权益投资明细报表数据

打开【财务会计】－>【合并报表】－>【合并控制】，进入所属合并范围的的【个别报表】功能，集团新增用于抵消的权益投资明细报表，编制报表数据保存并上报。子公司编制资产负债表并上报。

打开【财务会计】－>【合并报表】－>【合并控制】，进入所属合并范围的的【报表接收】功能，选择需要接收个别报表进行接收。（集团行为）

第三步：维护持股比例（集团行为）

打开【财务会计】－>【合并报表】－>【合并控制】，进入所属合并范围的【持股比例】，系统自动生成当前范围用于权益抵消的持股比例，用户也可以手工修改持股比例。用户还需对每条持股比例记录指定对应的权益调整分录模板及抵消分录模板。

第四步：自动生成抵消分录（集团行为）

打开【财务会计】－>【合并报表】－>【合并控制】，进入所属合并范围的的【抵消分录】－>【自动抵消】功能，单击【自动生成】即自动生成内部投资与权益的抵消分录。

打开【财务会计】－>【合并报表】－>【合并控制】，进入所属合并范围的的【抵消分录】－>【抵消查询】功能，可以查询当前合并范围的投资与权益抵消分录情况。

抵消分录审核后，就可以参与合并报表的计算。

[图:crrpt_手册_权益抵消流程图.png]

==== 物料分组标准费率维护 ====

## 【页面】短信服务配置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%9F%AD%E4%BF%A1%E6%9C%8D%E5%8A%A1%E9%85%8D%E7%BD%AE

======1 功能描述 ======

注意：V8.2以后版本下架云短信相关内容。

在实际业务运行中，经常需要短信服务的支持，例如：付款需要发送短信验证码，审批流审批通过后发送短信消息等。
使用短信服务需进行短信服务配置。

每个数据中心可分别设置短信服务，主要有两个短信服务：一个是金蝶云短信服务，另一个是维那多短信服务（购买后提供企业的用户帐号和密码）。

**功能路径**

【基础管理】→【公共设置】→【短信服务】→【短信服务配置】

======2 功能操作 ======

=====2.1 金蝶云短信 =====

Administrator登录数据中心，选择功能路径：【基础管理】→【公共设置】→【短信服务】→【短信服务配置】，在短信服务配置界面，勾选“金蝶云短信”，点击【启用】即可完成配置。

  - 使用短信服务前需要先启用，若禁用短信服务，系统将无法使用短信服务；
  - 【查询套餐余额】可以查询短信套餐的余额情况，包括：购买可用数量、累计使用数量（各数据中心使用数量合计）、未使用数量；
  - 【申请自定义签名】可以申请企业自定义的短信签名，提交后需要人工审核（1个工作日即可审核完成），审核通过即自动更新为新签名发送；
  - 需要购买金蝶云短信套餐才可以使用，非正式许可下提供200条云短信免费使用；
  - 要求金蝶云所在服务器可以访问云平台短信服务接口api.kingdee.com。


=====2.2 维那多短信 =====
Administrator登录数据中心，选择功能路径：【基础管理】→【公共设置】→【短信服务】→【短信服务配置】，在短信服务配置界面，勾选“维那多短信”。

  - 购买金蝶短信点卡（维那多短信），即可获取企业的用户帐号和密码，短信服务配置界面输入帐号和密码，点击【启用】按钮即可启用短信服务；
  - 使用短信服务前需要先启用，若禁用短信服务，系统将无法使用短信服务；
  - 点击【修改密码】，可进行密码修改；
  - 点击【查询余额】，可以查询短信套餐的余额情况；

## 【页面】禁用子项查询
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%A6%81%E7%94%A8%E5%AD%90%E9%A1%B9%E6%9F%A5%E8%AF%A2

======1 物料禁用查询======
=====1.1 功能概述=====

在实际业务过程中，有些物料后续不再使用，需要做禁用处理，在禁用前查询下该物料还存在与哪些未关闭的单据中；






=====1.2 使用前提=====
定义【物料】

定义【组织】




=====1.3 功能路径=====
【生产制造】－>【工程数据管理】－>【物料清单查询】－>【物料禁用查询】

             
======2. 业务说明======
====定义====
物料禁用查询：查询已禁用或者准备禁用的物料，还存在于哪些未关闭的单据中

====应用场景==== 
1. 客户禁用物料时，在操作前需要知道该物料已在哪些单据中使用.
2. 客户需要查询当前已禁用物料被哪些单据使用。

====功能说明==== 
  - 查询：根据物料范围查询未关闭的单据以及即时库存
  - 不录入物料进行查询：默认获取查询组织下已禁用的物料进行查询
  - 录入物料进行查询：根据录入的物料进行查询
  - 检查出的结果按单据类型分为三个页签：页签一：物料清单：物料清单，计划BOM，生产用料清单，委外用料清单；页签二：预测单，销售订单, 组织间需求单，计划订单, 采购申请单，采购订单， 生产订单，委外订单；页签三：即时库存

## 【页面】管理中心创建和注册
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%AE%A1%E7%90%86%E4%B8%AD%E5%BF%83%E5%88%9B%E5%BB%BA%E5%92%8C%E6%B3%A8%E5%86%8C

====== 1 功能描述 ====== 

金蝶云产品安装完成后，系统自动进入金蝶云管理中心库创建向导，引导管理中心库的创建，创建完成后，便可登录管理中心创建和维护业务数据中心。

产品使用一段时间后，由于企业的实际需求，在新的服务器进行同版本产品安装和部署，把原有环境的管理中心数据库的注册过来，继续使用。注册完成后，若管理中心的版本过低，需对注册过来的管理中心进行升级处理。

管理中心支持SQL Server和Oracle两种类型的数据库。

**功能路径**

  - 首次登录管理站点会自动进入管理中心创建和注册界面 
  - 浏览器直接访问：管理站点IP或域名:8000/Silverlight/CMC.aspx会进入到管理数据中心创建界面。 

 ====== 2 功能操作 ======

金蝶云安装完毕后，系统自动进入金蝶K3 Cloud管理中心的创建，可以分别进行SQL Server或Oracle管理中心的创建或注册。

===== 2.1 创建管理中心 ===== 

==== 2.1.1 创建SQL管理中心 ====

SQL Sever管理中心创建过程如下：

  1、选择SQL Sever数据库，并选择操作类型为创建，右边会显示SQL Sever管理中心的创建界面。
  
  2、输入数据库服务器。
  
  3、输入数据库管理员用户信息，包括数据库管理员用户和密码，输入后，可以进行【测试连接】确保输入信息有效，数据库管理员用户可以用来创建管理中心实体。
  
  4、输入数据库连接用户信息，包括身份验证方式、数据库连接用户登录名和密码。输入后，可以进行【测试连接】确保输入信息有效，应用服务器将使用数据库连接用户连接到管理中心。
  
     数据库连接用户支持SQL Server身份验证和Windows身份验证两种方式。
     
     1）若选择Windows身份验证，默认从管理站点的应用程序池获取运行账户，管理站点的运行账户在产品安装过程高级中进行设置，在安装后也可在IIS管理站点的应用程序池中修改。
        使用Windows身份验证不需要输入密码，但是数据库服务器中必须存在这个账户。
        
     2）若选择SQL Server身份验证，请输入SQL Server数据库用户名和密码。
     
  5、输入数据库文件，包括数据库实体、数据库文件路径以及数据库日志文件路径。
  
  6、在创建界面中，确认相关信息后，点击【创建】按钮，即可创建管理中心。



==== 2.1.2 创建Oracle管理中心 ====

Oracle管理中心创建过程如下：

  1、选择Oracle数据库，并选择操作类型为创建，右边会显示Oracle管理中心的创建界面。
  
  2、输入数据库服务器信息，包括数据库服务器、实例名、端口、数据库管理员及管理员密码。
  
  3、输入数据库用户信息，数据库用户需选择“使用现有用户”或“新建用户”，两种方式分别介绍如下：
  
   1）选择“使用现有用户”，需要输入Oracle数据库中已存在的用户名及其密码；
   
      注意采用“使用现有用户”方式需要提前使用Oracle系统自带工具创建用户，且在Oracle数据库中创建用户时，应授予该新建用户DBA的权限，
      还需为新建用户关联数据库表空间，以保证使用该用户创建出来的管理中心各个功能正常；
      
   2）选择“新建用户”，需输入在数据库中新建的用户名称、密码以及确认密码，还需选择默认表空间和临时表空间。
   
  输入后，可以进行【测试连接】确保输入信息有效。
  
  4、在创建界面中，确认相关信息后，点击【创建】按钮，即可创建管理中心。

===== 2.2 创建管理中心 ===== 

==== 2.2.1 注册SQL管理中心 ====

SQL Sever管理中心注册过程如下：

  1、选择SQL Sever数据库，并选择操作类型为注册，右边会显示SQL Sever数据库的注册界面。
  
  2、输入数据库服务器。
  
  3、输入数据库连接用户信息，包括身份验证方式、数据库连接用户登录名和密码。输入后，可以进行【测试连接】确保输入信息有效，应用服务器将使用数据库连接用户连接到管理中心。
  
     数据库连接用户支持SQL身份验证和Windows身份验证两种方式。
     
     1）若选择Windows身份验证，默认从管理站点的应用程序池获取运行账户，管理站点的运行账户在产品安装过程高级中进行设置，在安装后也可在IIS管理站点的应用程序池中修改。
        使用Windows身份验证不需要输入密码，但是数据库服务器中必须存在这个账户。
        
     2）若选择SQL身份验证，请输入SQL数据库用户名和密码。
     
  4、输入数据库文件，主要是选择数据库实体，且必须选择管理中心类型的数据库实体，不能选择数据中心类型的数据库实体。
  
  5、在注册界面中，确认相关信息后，点击【注册】按钮，即可注册管理中心。

==== 2.2.2 注册Oracle管理中心 ====

Oracle管理中心注册过程如下：

  1、选择Oracle数据库，并选择操作类型为注册，右边会显示Oracle数据库的注册界面。
  
  2、输入数据库服务器相关信息，包括数据库服务器、实例名、端口、数据库管理员及管理员密码。
  
  3、输入数据库用户信息，包括数据库用户和密码。
  
     数据库用户需录入Oracle数据库中已存在的用户名及其密码，并且该用户必须是注册管理中心对应的用户，而不能是注册数据中心对应的用户，输入后，可以进行【测试连接】确保输入信息有效。
  
  4、在注册界面中，确认相关信息后，点击【注册】按钮，即可注册管理中心。

===== 2.3 升级管理中心 =====
 
  - 在注册完成后，若管理中心的版本过低，会提示注册过来的管理中心的版本过低，需要进行升级。点击升级按钮后，进行管理数据中心的升级，升级完成并重启应用服务器的IIS服务后，即可登录管理站点。 
  - 管理中心升级支持SQL Server和Oracle两种类型的数据库。

 ===== 2.4 登录管理中心平台 ===== 

  - 管理中心创建完成后，单击【完成】按钮，可自动进入管理中心的登录界面，输入用户名和密码即可登录，用户名是Administrator（SQL Server下不区分大小写，Oracle下区分大小写）， 登录管理中心后，即可进行数据中心创建和数据中心管理。
  - 金蝶云安装后，桌面会建立“金蝶K3 Cloud管理站点”的快捷方式，双击即可进入管理中心，也可以通过站点“机器IP：端口号/”登录。 
  - 管理中心的版本和管理站点的产品版本需保持一致，用户登录系统时会自动检查管理中心和版本，若管理中心版本低于或高于产品版本，须相应升级后才能正常进行管理站点的登录和使用。


 ====== 3 其他说明 ====== 

  - Oracle数据库中每个用户只能对应一个管理中心，不能重复使用； 
  - 建议数据库文件路径以及数据库日志文件路径采用英文路径； 
  - 如果系统管理员要进行管理数据中心的快速重建或注册，可直接访问：管理服务器IP或计算机名:8000/silverlight/CMC.aspx

## 【页面】结算价目表自定义字段匹配设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%93%E7%AE%97%E4%BB%B7%E7%9B%AE%E8%A1%A8%E8%87%AA%E5%AE%9A%E4%B9%89%E5%AD%97%E6%AE%B5%E5%8C%B9%E9%85%8D%E8%AE%BE%E7%BD%AE

* **功能概述**

实际业务中，有些客户组织间结算价格需要根据跨组织业务单据上的客户、仓库或者其他字段进行定价。组织间结算价目表现可支持按自定义字段进行取价，可满足不同客户按不同维度进行取价的需求



  * **功能路径**

【供应链】－>【组织间结算】－>【价格资料】－>【结算价目表自定义字段匹配设置】


  * **字段说明**

|**字段**||**说明**|
|组织间价目表的字段标识||设置结算价目表中要进行取价匹配的自定义字段，可选组织间结算价目表上增加的自定义字段|
|价目表字段名称||根据已选的组织间价目表字段标识自动带出自定义字段的名称|
|结算清单上的字段标识||设置结算清单中要进行取价匹配的自定义字段，可选结算清单中增加的自定义字段|
|结算清单字段名称||根据已选的结算清单中的字段标识自动带出自定义字段的名称|
|基础资料字段匹配模式||是指当自定义字段是基础资料时，是按基础资料的ID匹配还是按基础资料编码匹配。 \\ 根据基础资料的字段值匹配:表示按基础资料的ID匹配,如客户ID \\ 根据基础资料的编码匹配:表示按基础资料的编码来匹配，比如客户编码。 \\ 若基础资料从A组织分配到B组织，在A组织的ID和B组织的ID是不一样的，按字段值匹配就匹配不上，按编码匹配就可以匹配上。|


 
  * **操作说明**

按以下步骤进行组织间结算价目表自定义字段匹配设置：

一、在结算清单上新增自定义字段。
参考以下链接文档配置自定义字段的数据取值https://vip.kingdee.com/article/45278

二、在Boside--结算价目表中新增自定义字段。
 
如新增的自定义字段是基础资料，需指定基础资料类型。
 
如第四步保存结算价目表时提示分录不唯一，可以在操作列表--保存和提交操作中，取消掉唯一性校验插件，目的是在做结算价目表时，允许设置相同物料不同的自定义字段有不同价格；

三、在“结组织间结算价目表自定义字段匹配设置”中建立结算清单和结算价目表的匹配关系，如果在主控台上没有看到菜单，请给用户授权。
  
四、新建结算价目表，设置“物料+自定义字段”的价格，然后结算关系中选择这张结算价目表；

五、创建结算清单，当取价来源为结算价目表时，系统就会自动按设置的自定义字段匹配关系进行匹配对应的价目表明细获取价格

具体配置操作可参考以下链接文档：https://vip.kingdee.com/article/173069576052389376

## 【页面】规格要求
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%A7%84%E6%A0%BC%E8%A6%81%E6%B1%82

用于设置食品规格要求的成本卡用料比例，是一种‘弹性’的食品成本用料比例，确定每一规格要求所需要的原材料及其数量。对食品规格要求成本管理不太重视的企业可以不设置。

**使用前提**

必须先设置好口味要求中规格成本比例等基础资料。

**功能路径**

【门店经营】->【门店数据管理】->【食品管理】->【口味及要求】->【要求】->规格成本比例

**操作说明**

维护规格要求时设置规格成本比例，设置完毕后审核才生效。

**业务说明**

规格要求的成本管理在快餐中比较普遍，主要运用于同一食品有多种规格要求，如大份和小份，且不同规格要求需要的原材料所占食品成本比重较大的情况。在食品成本核算时，与食品成本卡生成一个新的成本卡进行核算

**举例说明**

规格要求中设置‘大份’，且规格成本比例为：1.5

*小炒牛肉的标准成本卡为：*                                                                       

芹菜：200克                                                                                   
                           
牛肉：500克                                                                                   
                           
姜  ：30克
                           
黄酒：60克


*则：销售一份要求为‘大份’的小炒牛肉新成本卡标准用量为：*

芹菜：300克

牛肉：750克

姜  ：150克

黄酒：90克

## 【页面】订单准时率分析
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%AE%A2%E5%8D%95%E5%87%86%E6%97%B6%E7%8E%87%E5%88%86%E6%9E%90

===== 1 订单准时率分析 ===== 


 
===== 2 数据说明 =====

  - 数据来源为：销售订单、销售出货单。
  - 日期设置：设置到年、月，可指定某年月至某年月。
  - 金额单位：元/万元，默认万元。
  - 公式说明：
            * 到货时间 < 订单交货时间、出货时间
            * 当同一个订单的出货次数大于1次时，以最后一次到货时间为准，若最后一次到货时间>订单交货时间，则此订单为不准时，准时次数为0；若最后一次到货时间 < = 订单交货时间，则准时次数记为1。
            * 订单准时率 = 准时次数 / 总订单数

===== 3 图表说明 =====

  * 客户发货及时率后十名：采用条形图展示客户发货率，默认按准时率从低到高排列，突出显示发货及时率差的客户。
  * 产品发货及时率后十名：采用条形图展示产品发货率，默认按准时率从低到高排列，突出显示发货及时率差的产品。
  * 发货及时率月度趋势：采用折线图，将本期和同期的发货及时率作对比，直观展示不同年份的月度趋势。
  * 销售到货及时率明细：采用交叉表，展示整体的销售到货情况，包含销售部门、销售员、客户、物料、订单次数、发货及时率等信息，对发货及时率低的项用颜色标示。

===== 4 功能与价值 =====

  * 主要功能：展现客户交货准时率、订单金额及数量、发货金额及数量、开票金额及数量、订单金额占比等常用分析指标。
  * 业务价值：对交货及时率的分析，将有助于企业持续改进内部流程，提高客户满意度和信任感，增进客户关系。

## 【页面】退货管理

**功能概述**

退货管理用于用户已经收货后的退货以及历史退货记录查询。

**使用前提**

存在收货记录。

**功能路径**

B2B电商门户-【订单管理】-【退货管理】

**功能说明**

  * 退货也是针对销售出库单（调拨单）进行的操作，系统提供按销售出库单（调拨单）状态、商品以及单据时间来过滤销售出库单（调拨单） 
  * 退货界面会一并展示发货单的已退货数量、可退数量供用户参考 
  * 用户的退货，会在内部系统里面自动生成暂存的退货单 
  * 退货管理里还支持历史退货信息的查询 

**内外部协同**

  * 申请退货数量即为内部自动生成退货单的退货数量 
  * 是否补货决定了内部退货单的退货类型，当补货时，退货类型为退货补货，不补货时，退货类型为退货

只有在【基础资料控制策略】中分配给了相关的业务组织后，业务组织才能够使用。目标组织可依据权限设置对分配过来的选项配置进行修改操作。
 
用户可对已经分配的选项配置取消分配，前提是目标组织中的选项配置没有提交审核。 

用户可以先设置好某一组织的选项配置，之后对相同类型的组织进行分配。

成本核算是将“核算体系+核算组织+会计政策”作为总的核算维度，三者之间的联系及应用通过如下案例来说明：

接上面那个案例，在华美资企业在深圳有三家销售中心，都是利润中心，企业财务要求每月按法人整体出具符合中国会计准则及美国会计准则的两套财务账，同时还要一套符合中国会计准则的按利润中心考核的内部管理账。案例中三家销售中心是三个业务组织，同属于美资企业这家法人，按财务的要求，建立两个核算体系：法人体系及责任中心体系。法人体系下，三家销售中心归属于同一核算组织，按中美两套会计政策核算，即“法人体系+核算组织+会计政策（中）”及“法人体系+核算组织+会计政策（美）”；责任中心体系下，三家销售中心各为核算组织，按中国会计政策核算，即“责任中心体系+核算组织（销售中心A）+会计政策（中）”、“责任中心体系+核算组织（销售中心B）+会计政策（中）”及“责任中心体系+核算组织（销售中心C）+会计政策（中）”。

## 【页面】食品配送与加工
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%A3%9F%E5%93%81%E9%85%8D%E9%80%81%E4%B8%8E%E5%8A%A0%E5%B7%A5

====== 1. 中央配送管理概述 ======





===== 1.1 关于本系统 =====

 
餐饮业的行业特点决定了餐饮企业发展速度很快，经常能看到一些成功的餐饮企业在短时间内就会在各个城市建立大量分店。为了减少成本，大多数餐饮连锁企业都会建立地区性的中央配送与中央厨房。对于有大量门店的餐饮连锁企业来说，关键原材料的物流配送是保证门店正常营业的关键业务。因此餐饮连锁企业需要对集团内大量的门店进行物流配送的合理规划与执行。
餐饮企业的物流配送需要保障原料按时、按量、按质地送达门店，从而保证门店营业的正常进行。

===== 1.2 系统特性 =====
 


K/3Cloud中央配送管理系统，是通过门店要货申请、申请汇总、总部配送出库、门店收货、配送异常处理、门店退货流程、配送价格管理等功能综合运用的管理系统，对配送物流和资金流的全过程进行有效的双向控制和跟踪，实现完善的企业物资供应信息管理。该系统可以独立执行配送操作，或与供应链其他子系统、应付款管理系统等其他系统结合运用，将能提供更完整、全面的企业物流业务流程管理和财务管理信息。
其主要功能包括：门店要货处理、门店收货处理、门店退货处理、配送异常处理、总部配送出货处理、总部配送退货处理、配送价格管理。
配送系统支持以下业务：直拨配送业务、统配配送业务、配送退货业务。



======  2. 配送业务及应用 ======

 

===== 2.1 直拨配送业务 =====
 


直拨配送满足餐饮连锁企业业务分离的要求，餐饮门店只负责提出要货申请，配送中心负责进行采购、加工、物流配送。
直拨配送是指货品从供应商处直接运抵到无采购权的门店仓库或门店客户的采购形式。
货品不由总部的仓库发出，不影响总部仓库库存，但由总部形成对供应商的应付账款；分部只增加库存账或应收账款，由于没有采购权，所以不形成对供应商的应付账款。
 

[图:直拨统配流程图.png]

图2.1-1 直拨配送流程图
===== 2.2 统配配送业务 =====

统配配送是指集中采购的物料或加工品，统一进入本地仓库（通常是总部仓库），然后通过物流统一配送到各门店。
统配配送有原材料统配和加工品统配，原材料通过总部统一采购后，货品入总部仓库，由总部形成对供应商的应付账款。中央厨房加工品入总仓，配送中心对入总仓的货品进行统一配送。

图2.2-1 统配流程图
===== 2.3 配送退货业务 =====

配送中心配送物料到各个门店，门店收货处理，对于在途损耗、损毁或货单不符的物料，门店可进行配送异常处理。
配送退货是指由于配送中心供货质量问题、运输损坏、发运错误等原因从而需要将配送中心的货物退回的一种业务。退料一般包括退货申请、退料出库业务环节。

===== 3.1 过滤界面概述 =====

金蝶AI星空食神餐饮中央配送系统中所有单据列表的过滤界面都大同小异，因此本章着重讲解过滤界面的公共部分，后期如果个别表有差异的话，在相应表的介绍时会详细说明，过滤界面通常用于列表中，用户可以根据自己的需要对单据列表的数据进行筛选，符合条件的数据将会显示，这样有利于用户查看数据。本章节以食品成本卡列表的过滤界面为例进行讲解，大家在后面单据列表使用过滤功能时可以参考本章进行学习和查看。
==== 3.1.1 功能概述 ====

过滤界面主要包括方案的创建，条件过滤设置，高级过滤设置，排序设置，显示隐藏列五个部分。下面会对每个部分进行详细得讲解。


**一、方案的创建界面**


方案的创建界面在整个过滤界面的左边，通常每一个过滤界面都会有一个缺省方案，该方案是系统默认的，用户也可以自己设置方案，点击另存或者复制按钮即可设置自己想要的方案。在另存方案界面，用户需要设置方案名称以及共享设置，如果设置了共享所有用户，那么设置的方案其他用户登录系统的时候也能看到，如果另存的方案不设置共享，那么该方案只有当前用户可见。
在方案创建界面的最下方，有一个下次以此方案自动进入的选择框，默认不勾选，如果用户勾选的话，下次打开单据列表时会自动根据设置的方案查询数据而不会显示过滤界面。

[图:1.png]


[图:1.2.png]
 
**二、条件过滤设置界面**


条件过滤设置界面用户可以设置过滤的组织，默认会当前组织。在条件过滤中中间有个新增行，删除行等按钮，用户可以根据自己的需要选择某个字段过滤，里面有版本号，创建组织，使用组织，创建人，修改人，创建日期等列表中所有的字段。
条件过滤设置界面有数据状态和禁用状态设置，数据状态包括全部，暂存，创建，审核中，已审核，重新审核六中状态，用户可以设置不同的数据状态过滤符合条件的数据；禁用状态包括全部，是，否三种。
   
[图:2.1.png]
 
** 三、高级设置**


高级设置界面跟条件设置过滤界面的一致，用户可以设置列表中的每个字段进行过滤想要的数据。

[图:3.1.png]

**四、排列设置**


过滤界面排列设置是用来设置不同单据的显示顺序的，列表中的每个字段都可以设置排序方式，升序或者降序。

[图:4.1.png]
 
**五、显示隐藏列**


由于列表中字段比较多，所以不能所有的字段都显示出来，客户可以设置自己想要显示的字段以便更直观的查看数据。

[图:5.1.png]

## 【页面】首检
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%A6%96%E6%A3%80

**功能路径**

【HMI主控台】－>【首检】

**功能说明**

待检验列表：

1、检验单（报工自动下推生成），用户具有车间调度汇报权限；

2、条码扫描：工序计划单编号-序列号-行号，支持模糊查询；

3、支持调用移动平板摄像头扫描；

4、开始检验：审核检验单，将检验状态置为“质检开始”；

[图:mfg_移动质检首检待检验列表.png]

首检录入：

1、单据头区域：工单、工序、产品信息；作业指导书、图片上传；

2、单据体区域：

（1）抽样序号，前一、后一跳转；

（2）检验项目、目标值、检测值录入、检验项目的检测结果判定、当前检测品检测结果判定；

3、数量区域：

（1）抽样检测结果，默认抽样1份，可修改；

（2）整体送检结果，默认完工数量全部送检，根据抽样品的检测结果，自动计算整体送检结果数量；

[图:mfg_移动质检首检编辑.png]

作业指导书：质检方案的作业指导书和技术文档，点击显示；

点击蓝色字体“检验项目”，弹出检验方法，自动高亮显示定位行，用户查看检验项目相关的检验方法、质量标准、检验依据、检验仪器相关资料；

[图:mfg_移动质检首检检验方法.png]

图片处理：

1、点击“+”，提示调用拍照或相册，拍照或选择照片后上传；

2、图片（数字）：显示已上传的图片数量；

3、点击蓝色字体“图片（N）”，打开图片列表界面；

4、图片查看：缩略图显示，可删除图片；

5、图片保存到PC端检验单附件中；

[图:mfg_移动质检首检图片.png]

检测值：

（1）定性分析：默认携带“检测项目对应检测值”中设置的默认值，F8列表，可修改，根据质检方案设置的目标值，自动判定检测结果“合格”或“不合格”；

（2）定量分析：用户输入检测值，根据质检方案设置的目标值，自动判定检测结果“合格”或“不合格”；

不合格项提示：当检验项目中出现不合格项时，显示不合格项数量，提示用户；

[图:mfg_移动质检首检检测值.png]

抽样序号：

1、默认1，当抽样数量变化时，抽样序号随之改变；

2、抽样判定：当前样本序号，默认判定“接收”，即“合格”；

3、前一、后一翻转序号，当判定当前抽样品为“返修”时，抽样检验结果的返修数量自动+1，接收数量自动-1，整体送检结果的返修数量自动+1，接收数量自动-1；当产品计量单位与工序单位不同时，数据不联动；

4、界面数据实时保存，无需用户点击保存按钮；

5、点击“质检完成”按钮，检验单置为质检完成状态；

检测结果查询：

1、展示质检开始和质检完成的数据；

2、参数设置：显示所有检验单，列表默认显示当前用户处理的检验单，勾选参数，显示用户有车间调度汇报权限的所有检验单；

3、查看/修改按钮：质检状态=质检开始，打开检验单可编辑；质检状态=质检完成，打开检验单查看界面；

4、质检完成按钮：质检状态=质检开始，按钮可用；质检状态=质检完成，按钮锁定；

## 【页面】高级选项_页签
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%AB%98%E7%BA%A7%E9%80%89%E9%A1%B9_%E9%A1%B5%E7%AD%BE

====== 【高级选项】页签 ======
选项说明：

允许转交： 
  * 勾选：则在信息中心处理此审批动作对应的待处理任务时，可以将此任务转发给其他用户； 
  * 不勾选：则在信息中心的待处理任务不支持转发功能，点击转交提示：审批动作设置为不允许转发。 

允许加签：

  * 勾选：则在信息中心处理此审批动作对于的待办任务时，点加签按钮，可以临时添加用户作为该节点的处理人；
         前加签：在信息中心处理待办任务前，临时添加处理人
  * 不勾选：则在信息中心处理此审批动作对于的待办任务时。点加签按钮，提示不允许加签；
允许传阅：
  * 勾选，则在信息中心此审批动作对应的待处理任务、已处理任务允许传阅给他人 
  * 不勾选，控制不允许传阅
 
批量处理：
  * 勾选，支持对相同流程版本、相同流程节点产生的任务进行批量处理； 
  * 不勾选，则不支持批量处理待办任务； 
 
指定下一步处理人： 控制审批流运行时，是否可以指定下一步处理人； 
勾选，则可以指定下一步处理人，包括流程正向运行和逆向运行； 
不勾选，则流程运行时不能选择下一步处理人，默认为下一步节点的所有参与人； 
注意：【支持会签】选项和【指定下一步处理人】选项不能同时勾选。 
 
允许追加参与人： 前置属性：允许指定下一步处理人
勾选后，当前节点可以追加参与人，反之则不能追加。
 
选择驳回节点： 控制审批流驳回时是否可以选择驳回节点；
勾选，流程驳回时，可以选择审批流已经运行过的上游节点进行驳回处理； 
不勾选，流程默认驳回至当前节点的直接上游节点，且默认任务接收人为驳回节点所有参与人； 
注意：【支持会签】选项和【选择驳回节点】选项不能同时勾选。 
 
未解析出处理人，自动跳过 此选项运行时起作用，即当前节点的参与人为空时，流程运行时跳过当前节点，流程直接流转到下游节点。
 
允许上一步处理人，选择跳过本节点 控制当前节点是否允许其上游节点在指定下游节点时被选择到，不勾选，则在指定下一节点跳转时，选择不到此节点。 
启用超时处理 勾选，可以设置后面的超时时长，以小时为单位；且可以设置下面的超时策略； 
不勾选，节点不会超时自动处理，需要节点任务的处理人自己完成任务处理； 
会签节点不支持超时处理。
 
超时策略 【自动执行审批项】：可以选择当前节点的审批项在超时后自动执行；若当前节点有多个处理人，则超时后自动执行审批项的处理人为其中一个用户； 
【指定处理人】：可弹出用户列表选择超时处理人，超时后自动将任务转发给指定处理人，指定处理人收到任务后，没有处理时长的限制。
 
通知方式  超过**小时发邮件：收到待办任务后**小时发送邮件通知
     前提：设置邮件服务器地址，路径：administrator登录后，【基础管理】-【公共设置】-【邮件设置】-【邮件服务设置】，系统管理员设置发送邮件的服务器地址，设置成功后，普通用户设置邮箱地址时，会自动带出缺省邮箱地址，此步骤也可以跳过，邮箱地址由用户自行设置； 
     用户设置邮箱地址：路径：用户登录后，打开个人信息页面，点击【邮件设置】进行相关设置，也可测试邮件发送。PS：发送邮件时，取【邮件设置】中的邮件地址信息。
超过**小时发短信：收到待办任务后**小时发送短信通知
     前提：
配置短信服务，路径：administrator登录管理中心后，【数据中心管理】-【数据中心】-【移动应用管理】-【短信服务配置】，设置短信平台的企业用户帐号； 
设置接收人手机号，路径：用户登录后，打开个人信息页面，，录入手机号即可；或者系统管理员，在【用户】基础资料中维护手机号。
超过**小时发云之家消息：收到待办任务后**小时发送云之家消息。
