====== 1 中央配送概述 ======

===== 1.1 中央配送概述 =====

餐饮业的行业特点决定了餐饮企业发展速度很快，经常能看到一些成功的餐饮企业在短时间内就会在各个城市建立大量分店。为了减少成本，大多数餐饮连锁企业都会建立地区性的中央配送与中央厨房。对于有大量门店的餐饮连锁企业来说，关键原材料的物流配送是保证门店正常营业的关键业务。因此餐饮连锁企业需要对集团内大量的门店进行物流配送的合理规划与执行。

餐饮企业的物流配送需要保障原料按时、按量、按质地送达门店，从而保证门店营业的正常进行。


===== 1.2 中央配送总体流程图 =====





===== 1.3 系统特性=====

金蝶云食神餐饮中央配送管理系统，是通过门店要货申请、申请汇总、总部配送出库、门店收货、配送异常处理、门店退货流程、配送价格管理等功能综合运用的管理系统，对配送物流和资金流的全过程进行有效的双向控制和跟踪，实现完善的企业物资供应信息管理。该系统可以独立执行配送操作，或与供应链其他子系统、应付款管理系统等其他系统结合运用，将能提供更完整、全面的企业物流业务流程管理和财务管理信息。



====== 2 业务类型及应用 ======

===== 2.1 直拨配送业务 =====

满足餐饮连锁企业业务分离的要求，餐饮门店只负责提出要货申请，配送中心负责进行采购、加工、物流配送。
直拨配送是指货品从供应商处直接运抵到无采购权的门店仓库或门店客户的采购形式。
货品不由总部的仓库发出，不影响总部仓库库存，但由总部形成对供应商的应付账款；分部只增加库存账或应收账款，由于没有采购权，所以不形成对供应商的应付账款。

直拨配送业务流程
 

===== 2.2 统配配送业务 ===== 
统配是指集中采购的物料或加工品，统一进入本地仓库（通常是总部仓库），然后通过物流统一配送到各门店。
统配有原材料统配和加工品统配，原材料通过总部统一采购后，货品入总部仓库，由总部形成对供应商的应付账款。中央厨房加工品入总仓，配送中心对入总仓的货品进行统一配送。


===== 2.3 配送退货业务===== 
配送中心配送物料到各个门店，门店收货处理，对于在途损耗、损毁或货单不符的物料，门店可进行配送异常处理。
配送退货是指由于配送中心供货质量问题、运输损坏、发运错误等原因从而需要将配送中心的货物退回的一种业务。退料一般包括退货申请、退料出库业务环节。

==== 4.4.1历史物料用量要货 ====
根据历史同期时间范围内：最近一天要货、上周同期、上月同期、上年同期、固定日期等要素计算门店的要货需求。

[[历史物料用量要货]]

==== 4.4.2历史食品销量要货 ====
根据历史营业销售数据，统计出历史平均营业总额，计算出各菜品的平均销售份数，平均日销售金额，可手工输入预估营业总额，根据各菜品的预估营业额与平均营业额的比值，算出各菜品的预估销售数量及预估销售金额。根据算出的预估销售数量和销售金额，通过食品成本卡计算物料的需求。

[[历史食品销量要货]]

==== 4.4.3物料预估要货单 ====


[[物料预估要货单]]

==== 4.4.4门店要货申请单 ====
门店要货申请单是门店用来提交要货需求的申请，然后，总部根据要货需求及库存情况进行配送处理。作为门店货品来源的依据之一，是门店各业务部门或计划部门根据门店食品消耗计划、食品需求等实际情况，向总部提出食品申请的单据；申请单经过各方面的审核后，才能进行配送。

[[门店要货申请单]]

==== 4.4.5门店要货申请单汇总单 ====
门店要货申请汇总单记录了企业配送货物的规格说明，交货条件，以及其它要求，配送组织依据门店要货申请汇总单进行产品的配送、采购、加工，并按时按质交付产品。 

[[门店要货申请汇总单]]

==== 4.4.6配送出库单 ====
门店通过要货申请发出要货指令，总部配送中心接到要货需求后，根据总仓库存的物料库存情况，对于有货的物料，进行配送出库。 

[[配送出库单]]

==== 4.4.7配送退货单 ====
配送退货单是处理由于质量不合格、价格不正确等因素、或与门店要货的相关条款不相符等原因，配货单位将货物退回的业务单据。 

[[配送退货单]]

===== 3.1 过滤界面概述 =====

金蝶AI星空食神餐饮中央配送系统中所有单据列表的过滤界面都大同小异，因此本章着重讲解过滤界面的公共部分，后期如果个别表有差异的话，在相应表的介绍时会详细说明，过滤界面通常用于列表中，用户可以根据自己的需要对单据列表的数据进行筛选，符合条件的数据将会显示，这样有利于用户查看数据。本章节以食品成本卡列表的过滤界面为例进行讲解，大家在后面单据列表使用过滤功能时可以参考本章进行学习和查看。
==== 3.1.1 功能概述 ====

过滤界面主要包括方案的创建，条件过滤设置，高级过滤设置，排序设置，显示隐藏列五个部分。下面会对每个部分进行详细得讲解。


**一、方案的创建界面**


方案的创建界面在整个过滤界面的左边，通常每一个过滤界面都会有一个缺省方案，该方案是系统默认的，用户也可以自己设置方案，点击另存或者复制按钮即可设置自己想要的方案。在另存方案界面，用户需要设置方案名称以及共享设置，如果设置了共享所有用户，那么设置的方案其他用户登录系统的时候也能看到，如果另存的方案不设置共享，那么该方案只有当前用户可见。
在方案创建界面的最下方，有一个下次以此方案自动进入的选择框，默认不勾选，如果用户勾选的话，下次打开单据列表时会自动根据设置的方案查询数据而不会显示过滤界面。


 
**二、条件过滤设置界面**


条件过滤设置界面用户可以设置过滤的组织，默认会当前组织。在条件过滤中中间有个新增行，删除行等按钮，用户可以根据自己的需要选择某个字段过滤，里面有版本号，创建组织，使用组织，创建人，修改人，创建日期等列表中所有的字段。
条件过滤设置界面有数据状态和禁用状态设置，数据状态包括全部，暂存，创建，审核中，已审核，重新审核六中状态，用户可以设置不同的数据状态过滤符合条件的数据；禁用状态包括全部，是，否三种。
   

 
** 三、高级设置**


高级设置界面跟条件设置过滤界面的一致，用户可以设置列表中的每个字段进行过滤想要的数据。



**四、排列设置**


过滤界面排列设置是用来设置不同单据的显示顺序的，列表中的每个字段都可以设置排序方式，升序或者降序。


 
**五、显示隐藏列**


由于列表中字段比较多，所以不能所有的字段都显示出来，客户可以设置自己想要显示的字段以便更直观的查看数据。

====== 1.备料计算 ======
===== 1.1 功能概述 =====

备料计算是根据历史的门店要货申请单/门店要货申请汇总单/加工计划单/物料清单预估生成采购订单，加工计划单，门店要货申请单的过程。
===== 1.2  业务说明 =====

  * 采购物料的门店要货申请单/门店要货申请汇总单可以生成采购申请单或者采购订单
  * 加工物料的门店要货申请单/门店要货申请汇总单可以生成加工计划单或者加工订单
  * 自制物料的加工计划单/物料清单可以生成门店要货申请单/采购申请单（在配送管理参数设置界面进行设置）

===== 1.3 关键字段 =====

| 字段名称         | 字段说明                                                                                                                 |
| 选单           | 支持门店要货申请单/门店要货申请汇总单/加工计划单/物料清单                                                                                       |
| 库存组织         | 门店要货申请单/门店要货申请汇总单中的配送组织，加工计划单的加工组织，物料清单的使用组织                                                                         |
| 考虑安全库存与可用库存  | 如果勾选的话，如果可用库存数-安全库存数-毛需求小于0时才会生成相应的单据，且净需求 =（可用库存数-安全库存数-毛需求）的相反数\\ 只展示净需求大于0的结果	如果勾选的话，则计算出的物料只显示大于0的结果，小于0的物料不会显示  |
| 辅助属性         | 如果勾选则会把不同的辅助属性求和进行后续的计算，如果不勾选，则会把不同的辅助属性当做不同的物料进行计算                                                                  |
| 汇总自制件        | 勾选的话只会汇总物料属性是自制的物料                                                                                                   |
| 汇总采购件        | 勾选的话只会汇总物料属性是采购的物料                                                                                                   |
| 汇总所有物料       | 会汇总所有（自制与采购）的物料                                                                                                      |

====== 1.配送价格管理 ======

===== 1.1 配送价格管理应用场景 =====

配送业务是连锁餐饮企业最核心的业务之一，价格管理又是配送管理的一个关键，只有合理的价格，才能保证配送行为持续的支撑企业的运转。通过价格控制可以保证企业配送政策的有效执行。

配送价格管理是企业一种重要的配送政策，通过价格控制可以保证企业配送政策的有效执行。 

配送价来源于两个方面：配送价目表、入库价

配送价目表：

配送价目表支持由上级组织统一定价，即上级组织确定企业配送价目表后，分发给其他配送组织使用；也支持由各配送组织分别制定价目表并应用。价格调制时，支持通过调价单严格流程调制；或直接在价目表上通过行反审核简易、快速处理 价格变动。

入库价：

配送出库时取物料的入库价。


===== 1.2 配送价目表价格应用 =====


==== 1.2.1 取价规则 ====

 
在配送出库单上录入价目表后，系统会按照配送出库单分录行依次进行自动取价，取价依据要素有以下几个，系统会按顺序进行匹配对应：

价格对象，如果价格对象是物料，则系统会自动找到对应的物料辅助属性，如果物料启用了辅助属性，且辅助属性影响价格时，系统会找到与配送出库单分录匹配的价目表分录单位，配送出库单上的单位必须与价目表单位相同或者物料的计价单位与价目表的单位相同，两者之一能够匹配后价目表上的价格会按照单位换算后再回填到配送出库单上计价数量，当价目表有计价数量段时，系统会找到符合计价数量段的配送出库单分录，与对应的价目分录表对应；如果价目表没有计价数量段时，则系统不考虑计价数量有效期，系统会按照配送出库单设置的定价时点来匹配有效期，定价时点时间必须在价目表分录的有效期内进行了上述四个匹配环节后，系统能找到唯一的价目表匹配价格或者找不到对应的价目表价格。

==== 1.2.2 价格携带 ====


配送价来源勾选配送价目表：

取价过程完成了之后，系统会将取到的价格相关字段携带到配送出库单对应字段上：

如果配送出库单上是否含税价打勾，则将价目表的净价分别携带到表体【含税单价】和【系统定价】。 
如果配送出库单上是否含税价没打勾，即价格不含税，则将价目表的净价分别携带到表体【单价】和【系统定价】 。
如果没有符合的价目表分录价格，则不携带任何字段。

配送价来源勾选入库价：
系统会将即时库存中物料的入库加权平均价携带到配送出库单对应字段上。

==== 1.2.3  配送价目表与配送调价表的单据转换 ====


可以由价目表下推配送调价表，也可以在配送调价表上选单价目表来生成配送调价表，两者之间转换的规则如下：

  * 只有已审核、未失效、未业务失效的价目表才能够下推配送调价表 
  * 选单时，只有符合条件的价目表才会过滤出来 
  * 选择多张价目表合并生成配送调价表时，【配送组织】和【价目表对象】必须相同 
  * 调价表审核时更新对应的价目表信息，包括【调后单价】、【价格上限】、【价格下限】，【生效日期】，【失效日期】字段 
  * 调整后的【生效日期】，【失效日期】不能超过价目表表头的【生效日期】，【失效日期】

===== 1.3 门店要货申请单 =====

在要货申请单上录入价目表后，系统会按照要货申单分录行依次进行自动取价，取价依据要素有以下几个，系统会按顺序进行匹配对应：

**一、价格对象**

如果价格对象是物料，则系统会自动找到对应的物料。
**二、辅助属性**

如果物料启用了辅助属性，且辅助属性影响价格时，系统会找到与要货申请分录匹配的价目表分录。

**三、单位**
要货申请单上的单位必须与价目表单位相同或者物料的计价单位与价目表的单位相同，两者之一能够匹配后价目表上的价格会按照单位换算后再回填到要货申请单上。

**四、计价数量**
当价目表有计价数量段时，系统会找到符合计价数量段的要货申请单分录，与对应的价目分录表对应；如果价目表没有计价数量段时，则系统不考虑计价数量。

**五、有效期**
系统会按照订单设置的定价时点来匹配有效期，定价时点时间必须在价目表分录的有效期内。

进行了上述匹配环节后，系统能找到唯一的价目表匹配价格或者找不到对应的价目表价格。

====== 1.4 配送出库单 ======

====== 1.4.1 功能概述 ======

 在配送出库单上录入价目表后，系统会按照配送出库单分录行依次进行自动取价，取价依据要素有以下几个，系统会按顺序进行匹配对应：

**一、价格对象**
如果价格对象是物料，则系统会自动找到对应的物料。

**二、辅助属性**
如果物料启用了辅助属性，且辅助属性影响价格时，系统会找到与配送出库单分录匹配的价目表分录。

**三、单位**
配送出库单上的单位必须与价目表单位相同或者物料的计价单位与价目表的单位相同，两者之一能够匹配后价目表上的价格会按照单位换算后再回填到配送出库单上。

**四、计价数量**
当价目表有计价数量段时，系统会找到符合计价数量段的配送出库单分录，与对应的价目分录表对应；如果价目表没有计价数量段时，则系统不考虑计价数量。

**五、有效期**
系统会按照配送出库单设置的定价时点来匹配有效期，定价时点时间必须在价目表分录的有效期内。
进行了上述四个匹配环节后，系统能找到唯一的价目表匹配价格或者找不到对应的价目表价格。


===== 1.4.2 价格携带 =====

配送管理系统参数设置了配送价来源：配送价目表和入库成本价，两个来源。

一、配送价来源勾选配送价目表
取价过程完成了之后，系统会将取到的价格相关字段携带到配送出库单对应字段上：

（一）如果配送出库单上是否含税价打勾，则将价目表的净价分别携带到表体【含税单价】和【系统定价】 

（二）如果配送出库单上是否含税价没打勾，即价格不含税，则将价目表的净价分别携带到表体【单价】和【系统定价】 

（三）如果没有符合的价目表分录价格，则不携带任何字段

二、配送价来源勾选入库成本价

（一）物料入库后，根据入库成本核算，核算物料批号对应的入库成本，配送出库时，根据批号对应的入库成本，配送出库价自动取入库成本价。


==== 1.4.3 价格条件修改 ====

若系统取价过程已经完成后修改单据与价格相关的字段，会对单据的价格产生一定影响：

一、如果表头变更了结算币别，且价目表的币别和结算币别不一致，则会清空价目表。

二、如果表体变更了数量，则根据价目表重新取价。


==== 1.4.4 价格控制 ====

配送价格控制只控制配送出库时的价格。配送参数【配送限价控制强度】控制配送价格不在【价格下限】【价格上限】之间的处理方式，分为以下三种：
一、“禁止交易”时，则单据无法保存。

二、“预警提示”时，则出现确认框供用户确认，确认后单据保存。

三、“不予控制”时，则不进行限价控制。

配送价目表与配送调价表的单据转换

===== 1.5 配送价目表与配送调价表的单据转换 =====

==== 1.5.1 配送价目表调价 ====
 
可以由价目表下推配送调价表，也可以在配送调价表上选单价目表来生成配送调价表，两者之间转换的规则如下：

二、选单时，只有符合条件的价目表才会过滤出来。

三、选择多张价目表合并生成配送调价表时，【配送组织】和【价目表对象】必须相同。

四、调价表审核时更新对应的价目表信息，包括【调后单价】、【价格上限】、【价格下限】，【生效日期】，【失效日期】字段。

五、调整后的【生效日期】，【失效日期】不能超过价目表表头的【生效日期】，【失效日期】。

====== 1.配送拣货单 ======

===== 1.1 功能概述 =====
配送拣货单主要用于统计各个门店要货申请汇总的情况，结合配送路线来查看各个门店的配送物料情况的单据。对于多个要货组织生成的门店要货申请汇总单，配送拣货单会按照配送路线表的顺序倒叙排列。

===== 1.2 关键字段 =====
| 字段名称     | 字段说明                             |
| 配送路线     | 选择配送路线后会自动过滤配送路线下的要货组织           |
| 导出单据体    | 配送拣货单只统计要货申请汇总单的所有数据             |
| 保存       | 可以修改拣货数量                         |
| 拣货完成     | 点击拣货完成会反写到对应门店要货申请汇总的已拣货字段       |
| 生成配送出库单  | 点击生成配送出库单会把拣货的数量自动下推到暂存状态的配送出库单  |


===== 1.3 业务说明 =====

  * 配送拣货单过滤框中，去掉“报表展示”、“数据来源”及单据状态                     
  * 配送拣货单的数据来源为“已审核的门店要货汇总单”；且过滤掉物料类型为允许直拨的物料；
  * 配送拣货单页面去掉“改写源单”、“改写源单并审核”，将当前页数移至尾页后面                         
  * 在配送拣货单页面工具栏上增加四个功能按钮：保存、拣货完成、打印、生成配送出单；保存---保存当前条件生成并更新过的配送拣货单；拣货完成---全部录入完拣货数量后，点击拣货完成，结束拣货的业务操作，并将拣货数量反写至门店要货申请汇总单的已拣货数量；打印---点击打印时，可支持在线打印当前拣货单；生成配送出库单按钮---默认灰色显示，当点击了拣货完成时，该按钮则亮色显示且可点击。点击后，以当前拣货数量生成配送出库单。
  * 在未点击拣货完成时，关掉配送拣货单，提示用户是否需要保存，用户点击保存时，返回提示：已保存成功，下次打开配送拣货单时会直接进入本次保存页面！用户在关掉配送拣货单之前，先点击保存，当页面未发生变化时，关掉配送拣货单时，不需要再次提示是否需要保存，可直接关掉。下次打开配送出库单时，可直进入最后一次保存的拣货单页面
  * 配送拣货单的物料数量等于批准数量-已发货数量；
  * 配送拣货单完成后生成保存状态的配送出库单
  * 首先应该给配送组织下的物料设置默认仓库

====== 1.配送调价方案 ======

===== 1.1 功能概述 =====

配送单价是配送业务管理的核心要素之一，餐饮供应的原材料导致配送单价上下波动是非常常见的现象。配送调价表就是用来处理配送单价变更业务的功能。

===== 1.2 使用前提 =====


定义配送组织、物料、价目表等。

===== 1.3 功能路径 =====


【餐饮配送与加工】－>【总部配送管理】－>【配送价格管理】－>【配送调价表】

===== 1.4 字段说明 =====

==== 1.4.1 表头基本字段 ====

|**字段**||**说明**|
|配送组织||配送调价表对应的配送组织，从拥有库存职能的组织基础资料中选择|
|单据编码||配送调价表对应的编码，编码必须具有唯一性|
|名称||配送调价表的名称|
|调价原因||调价原因，从调价原因辅助资料中选择|
|日期||配送调价的日期|
|状态||配送调价表的状态|
|描述||配送调价表的说明|

==== 1.4.2 表头其他字段 ====

|**字段**||**说明**|
|创建人||指创建配送调价表的用户|
|创建日期||指创建配送调价表的日期|
|修改人||指最后修改配送调价表的用户|
|修改日期||指最后修改配送调价表的日期|
|审核人||指审核配送调价表的用户|
|审核日期||指审核配送调价表的日期|
|生效状态||调价表是否生效|
|生效人||调价表的生效人|
|生效日期||调价表的生效日期|

==== 1.4.3 表体调价明细字段 ====

|**字段**||**说明**|
|序号||配送调价表的分录行号|
|价目表||配送调价表对应的价目表|
|调价对象||配送调价单的调价对象|
|币别||配送调价表对应价目表的币别|
|物料编码||物料编码，从物料基础资料中选择，调价对象为“物料”时才允许编辑|
|物料名称||指物料的名称，根据物料编码携带，表头调价对象为“物料类别”时锁定不可编辑|
|规格型号||指物料的规格型号，根据物料编码携带，表头调剂对象为“物料类别”时锁定不可编辑|
|至||按计价单位计量的数量区间值，用以定义调价价格区间|
|调前单价||调价前的单价，与价目表关联时携带价目表价格，新增价格分录时允许为空|
|调后单价||调价后的单价，调后单价=调前单价*调价幅度|
|调价幅度||调价的幅度，调价幅度=(调后单价-调前单价)/调前单价|
|价格上限||指调价后物料对应的价格上限|
|价格下限||指调价后物料对应的价格下限|
|生效日期||指调价的生效时间，调价表生效日期必须不小于对应价目表头生效日期|
|失效日期||指调价的失效时间，调价表生效日期必须不大于价目表表头失效日期|

===== 1.5 业务说明 =====


调价表生效必须依次遵循以下规则：

  -对应价目表中（物料+单位+辅助属性+数量区间）不存在则携带调价表数据在该价目表中插入新纪录 
  -对应价目表中（物料+单位+辅助属性+数量区间）存在，则有如下几种情况
  -分录有效期相同则直接更新价格和价格上下限 
  -有效期不同且新记录的生效日小于或等于原记录的生效日，则提示用户，更新不成功 
  -有效期不同且新记录的生效日介于原记录的生效日和失效日之间，则携带调价表数据在该价目表中插入新纪录，同时用新生效日更新原记录的失效日 
  -如果有效期不同且新记录的生效日大于或等于原记录的失效日，则携带调价表数据在该价目表中插入新纪录

====== 1.门店要货申请汇总 ======


====== 1功能概述 ======
 门店要货申请汇总单记录了企业配送货物的规格说明，交货条件，以及其它要求，配送组织依据门店要货申请汇总单进行产品的配送、采购、加工，并按时按质交付产品。
 
====== 2系统应用 ======
汇总各个门店的物料要货需求，查看库存情况，确定物料是否需要采购、加工及配送业务。
   
====== 3使用前提 ======

  -定义门店要货申请汇总单的单据类型、配送组织、配送部门、需求组织、物料、单位等基础资料。
  -按实际配送业务流程设置配送参数。 

====== 4功能路径 ======
【餐饮配送与加工】－>【总部配送管理】－>【门店要货处理】－>【门店要货申请汇总】

====== 6操作说明 ======

===== 6.1门店要货申请汇总单指定供应商业务 =====

   在门店要货申请汇总单列表中可以指定供应商操作，指定供应商操作的规则如下：

  -物料存在采购价目表，该价目表为默认价目表。
  -当价目表上的门店不为空时，优先取不为空的默认价目表上的供应商；否则，取门店为空的默认价目表上的供应商。 
  -物料且对应申请门店不存在价目表则指定供应商为空。 

===== 6.2门店要货申请汇总单单据转换规则  =====

**(一)门店要货申请汇总单与采购申请单关联转换业务** 

“直拨要货汇总”单据类型门店要货申请单与采购申请单的业务关联，即可手工下推，也可系统自动生成。

手工下推：门店要货申请汇总单可以下推采购申请单，也可以在采购申请单界面选单门店要货申请汇总单生成，实现关联业务的转化，门店要货申请汇总单与采购申请单转化的规则如下：

  * 单据状态为“已审核”，且关闭状态为“未关闭”，且业务状态为 “正常”的门店要货申请汇总单才能转换为采购申请单 

  * 系统参数要货汇总采购物料自动生成采购申请打勾或者要货汇总采购物料自动生成采购订单打 勾，“直拨要货汇总”单据类型的门店要货申请汇总单，“需采购数量”默认等于批准数量，如果汇总单单据表体“供应商”为空或者物料属性是“需申购”的物料，单据审核时，该类物料自动生成采购申请单。如果汇总单单据表体“供应商”不为空或者物料属性不是“需申购”的物料，系统参数自动生成采购申请打勾，则单据审核时自动生成采购申请；如果系统参数数自动生成采购订单打勾，则单据审核时不自动生成采购申请。


  * 门店要货申请汇总单申请/采购关联数量大于等于申请数量时，门店要货申请汇总单无法下推采购申请单


  * 在采购申请单界面选单时，可选择的门店要货申请汇总单列表界面默认只过滤出符合上面条件的门店要货申请汇总单 


  * 选择多张门店要货申请汇总单合并生成采购申请单时，供应商、收货组织、配送组织、需求组织、结算组织和结算币别相同的分录才能合并到一张采购申请单上


  * 门店要货申请汇总单下推采购申请单时，门店要货申请汇总单的字段关联携带到采购申请单上 


  * 采购申请单审核时，将采购申请单数量累加至门店要货申请汇总单【申请/采购数量】字段上，采购申请单反审核时，需要扣减数量  

 


**（二）门店要货申请汇总单与采购订单关联转换业务** 

 

转换规则 
“直拨要货汇总”单据类型门店要货申请单与采购订单的业务关联，即可手工下推，也可系统自动生成。

手工下推：门店要货申请汇总单可以下推采购订单，也可以在采购订单界面选单门店要货申请汇总单生成，实现关联业务的转化，门店要货申请汇总单与采购订单转化的规则如下：

 

1.    单据状态为“已审核”，且关闭状态为“未关闭”，且业务状态为 “正常”的门店要货申请汇总单才能转换为采购订单 

2.    系统参数要货汇总采购物料自动生成采购申请打勾或者要货汇总采购物料自动生成采购订单打勾，“直拨要货汇总”单据类型的门店要货申请汇总单，“需采购数量”默认等于批准数量，如果汇总单单据表体“供应商”为空或者物料属性是“需申购”的物料，单据审核时，该类物料不自动生成采购订单单。

如果汇总单单据表体“供应商”不为空或者物料属性不是“需申购”的物料，系统参数自动生成采购订单打勾，则单据审核时自动生成采购订单；如果系统参数数自动生成采购申请打勾，则单据审核时不自动生成采购订单。

 

3.    门店要货申请汇总单关联数量大于等于订单数量时，门店要货申请汇总单无法下推采购订单 

4.    在采购订单界面选单时，可选择的门店要货申请汇总单列表界面默认只过滤出符合上面条件的门店要货申请汇总单 

5.    选择多张门店要货申请汇总单合并生成采购订单时，供应商、收货组织、配送组织、需求组织、结算组织、结算币别相同的分录才能合并到一张采购订单上  

6.    门店要货申请汇总单下推采购订单时，门店要货申请汇总单的字段关联携带到采购订单上 

7.    采购订单审核时，将采购订单数量累加至门店要货申请汇总单【申请/采购数量】字段上，采购订单反审核时，需要扣减数量  


 


**（三）门店要货申请汇总单与加工计划单关联转换业务** 

“加工品统配要货汇总”单据类型的要货申请汇总单与加工计划单的业务关联，即可手工下推，也可系统自动生成。

手工下推：门店要货申请汇总单可以下推加工计划单，也可以在加工计划单界面选单门店要货申请汇总单生成，实现关联业务的转化，门店要货申请汇总单与加工计划单转化的规则如下：

转换规则 
“加工品统配要货汇总”单据类型的要货申请汇总单，“需加工数量”默认等于批准数量，系统参数自动生成配送出库单勾选，单据审核时，根据批准数量自动生成配送出库单，再根据系统参数“要货汇总加工物料自动生成”勾选加工计划单，根据需加工数量自动生成加工计划单。

单据状态为“已审核”，且关闭状态为“未关闭”，且业务状态为 “正常”的门店要货申请汇总单才能生成加工计划单 
在加工计划单界面选单时，可选择的门店要货申请汇总单列表界面默认只过滤出符合上面条件的门店要货申请汇总单 
选择多张门店要货申请汇总单合并生成加工计划单时，计划组织相同的分录才能合并到一张加工计划单上

====== 1功能概述 ======
 门店要货申请汇总单记录了企业配送货物的规格说明，交货条件，以及其它要求，配送组织依据门店要货申请汇总单进行产品的配送、采购、加工，并按时按质交付产品。
 
====== 2系统应用 ======
汇总各个门店的物料要货需求，查看库存情况，确定物料是否需要采购、加工及配送业务。
   
====== 3使用前提 ======

  -定义门店要货申请汇总单的单据类型、配送组织、配送部门、需求组织、物料、单位等基础资料。
  -按实际配送业务流程设置配送参数。 

====== 4功能路径 ======
【中央配送】－>【门店要货】－>【门店要货处理】－>【门店要货申请汇总】

====== 6操作说明 ======

===== 6.1门店要货申请汇总单指定供应商业务 =====

   在门店要货申请汇总单列表中可以指定供应商操作，指定供应商操作的规则如下：

  -物料存在采购价目表，该价目表为默认价目表。

===== 6.2门店要货申请汇总单单据转换规则  =====
门店要货申请汇总单与采购申请单关联转换业务
