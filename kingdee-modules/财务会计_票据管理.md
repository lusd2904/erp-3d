## 【页面】应付到期付款
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E4%BB%98%E5%88%B0%E6%9C%9F%E4%BB%98%E6%AC%BE

====== 应付票据到期付款 ======
1、企业签发的应付票据到期，正常进行付款，在系统中进行到期付款处理，功能路径：【财务会计】—>【出纳管理】—>【日常处理】—>【应付票据】—>【业务操作】—>【到期付款】。

2、应付票据到期付款操作条件：应付票据已审核且结算状态字段为空时，允许进行付款操作。

3、对应付票据执行到期付款，系统弹出对话框，用户录入到期付款相关信息：

|**字段**||**说明**|
|币别||系统自动携带票据的币别信息。|
|付款日期||录入进行付款时的日期。|
|付款银行||企业付款银行账号对应的开户银行。|
|付款银行账号||企业付款的银行账号。|
|付款账户名称||企业付款银行账号的名称。|
|票面金额||系统自动带出票据的票面金额。|
|实付金额||系统自动计算企业实际要支付的金额。|
|利息||录入带息票据的利息金额。|
|费用||录入付款时发生的费用。|
|结算号||录入银行付款处理回单的结算号。|

4、用户录入完整的付款信息后，点确定，应付票据到期付款动作完成。

5、应付票据到期付款后系统处理结果：

1）系统自动置应付票据结算状态为“付款”。

2）系统自动产生应付票据结算单，单据类型为应付票据到期付款，记录应付票据到期付款业务，并支持生成应付票据到期付款记账凭证。

====== 应付票据======
=====1 功能说明 =====

管理企业签发的应付票据。

已经审核的应付票据可以被相应的付款单引用，确认以应付票据的方式付款。

支持应付票据后续的票据结算业务处理，包括应付票据的到期付款以及退票等。

=====2 操作前提 =====

1、定义了付款组织、供应商、币别等基础数据。

3、如果是通过票据类结算方式付款，则还需要先维护了应付票据数据。

=====3 功能路径 =====

【财务会计】—>【出纳管理】—>【票据处理】—>【应付票据】

【财务会计】—>【票据管理】—>【票据处理】—>【应付票据】

=====5 操作说明 =====

====5.1 付款单引用应付票据  ====

企业签发应付票据，应该进行确认付款处理。用户需要在系统中维护了所签发的应付票据后，新增引用该应付票据的付款单，完成确认付款的动作。

新增付款单，并在付款单表体的应付票据页签，录入或者选择相应的应付票据流水号，即完成付款单对应付票据的引用，确认付款。

==== 5.4 应付票据取消处理 =====
1、应付票据如果发生了到期付款、退票等等的结算误操作，系统支持进行取消处理，功能路径：【财务会计】—>【出纳管理】/【票据管理】—>【票据处理】—>【应付票据】—>【业务操作】—>【取消处理】。

2、应付票据已经发生过结算业务，也就是结算状态字段不为空时，允许进行取消处理操作。

3、用户每点击一次取消处理功能按钮，系统进行取消处理一次，也就是对距离取消处理时点最近的一次结算业务操作进行取消处理，恢复为最近一次结算业务操作之前的系统状态。

==== 5.5 应付票据关联查询 === 
1、【财务会计】—>【出纳管理】/【票据管理】—>【日常处理】—>【应付票据】—>【关联查询】—>【结算单】，支持关联查询当前应付票据所有相关的应付票据结算单。

2、【财务会计】—>【出纳管理】/【票据管理】—>【日常处理】—>【应付票据】—>【关联查询】—>【付款单】，支持关联查询所有引用了当前应付票据的付款单。

应付票据结算单均由结算业务操作自动产生，不支持手工新增，只提供查询功能。

## 【页面】应付退票
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E4%BB%98%E9%80%80%E7%A5%A8

====== 应付票据退票 ======
1、企业签发的应付票据被退票时，在系统中进行退票处理，功能路径：【财务会计】—>【出纳管理】—>【日常处理】—>【应付票据】—>【业务操作】—>【退票】。

2、应付票据退票操作条件：应付票据已审核且结算状态字段为空，同时应付票据已经完全被付款单引用时，允许进行退票操作。

3、对应付票据执行退票，系统弹出对话框，用户录入退票相关信息：

| **字段**     || **说明**                             |
| 币别         || 系统自动携带票据的币别信息。                     |
| 退票日期       || 录入发生退票时的日期。                        |
| 供应商        || 系统自动带出票据的供应商信息。                    |
| 退票金额       || 系统自动带出票据的票面金额。                     |
| 单据类型       || 用户选择应付票据退票时产生的单据类型，可选其他应付单和付款退款单。  |
| 本位币        || 结算组织对应的默认核算体系的核算组织默认会计政策的本位币。      |
| 汇率类型       || 结算组织对应的默认核算体系的核算组织默认会计政策的汇率类型。     |
| 汇率         || 原币到本位币的汇率。                         |

4、用户录入完整的退票信息后，点确定，应付票据退票动作完成。

1）系统自动置应付票据结算状态为“退票”。

===== 应收票据贴现 ======
1、企业将持有的应收票据到银行贴现，在系统中进行贴现处理，功能路径：【财务会计】—>【出纳管理】—>【日常处理】—>【应收票据】—>【业务操作】—>【贴现】。

2、应收票据贴现操作条件：应收票据已审核且结算状态字段为空或者为背书退回时，允许进行贴现操作。

3、对应收票据执行贴现，系统弹出对话框，用户录入贴现相关信息：
|**字段**||**说明**|
|币别||系统自动携带票据的币别信息。|
|贴现日期||录入进行贴现时的日期。|
|收款银行||企业收款银行账号对应的开户银行。|
|收款银行账号||企业收款的银行账号。|
|收款账户名称||企业收款银行账号的名称。|
|贴现银行||录入进行票据贴现的银行。|
|贴现率%||录入本次贴现的贴现率。|
|实收金额||系统自动计算企业实际收到的金额。|
|贴现息||录入应收票据贴现息。|
|费用||录入贴现时发生的费用。|
|结算号||录入银行付款处理回单的结算号。|
4、用户录入完整的贴现信息后，点确定，应收票据贴现动作完成。

5、应收票据贴现后系统处理结果：

1）系统自动置应收票据结算状态为“贴现”。

2）系统自动产生应收票据结算单，单据类型为应收票据贴现，记录应收票据贴现业务，并支持生成应收票据贴现记账凭证。

======应收票据退票======
1、企业持有的应收票据需要退票时，在系统中进行退票处理，功能路径：【财务会计】—>【出纳管理】—>【日常处理】—>【应收票据】—>【业务操作】—>【退票】。

2、应收票据退票操作条件：应收票据已审核且结算状态字段为空或者为背书退回，同时应收票据已经完全被收款单引用时，允许进行退票操作。

3、对应收票据执行退票，系统弹出对话框，用户录入退票相关信息：

| **字段**     || **说明**                             |
| 币别         || 系统自动携带票据的币别信息。                     |
| 退票日期       || 录入发生退票时的日期。                        |
| 客户         || 系统自动带出票据的客户信息。                     |
| 退票金额       || 系统自动带出企业收到票据的交易金额。                 |
| 单据类型       || 用户选择应收票据退票时产生的单据类型，可选其他应收单和收款退款单。  |
| 本位币        || 结算组织对应的默认核算体系的核算组织默认会计政策的本位币。      |
| 汇率类型       || 结算组织对应的默认核算体系的核算组织默认会计政策的汇率类型。     |
| 汇率         || 原币到本位币的汇率。                         |
4、用户录入完整的退票信息后，点确定，应收票据退票动作完成。

5、应收票据退票后系统处理结果：

1）系统自动置应收票据结算状态为“退票”。

2）系统自动产生应收票据结算单，单据类型为应收票据退票，记录应收票据退票业务，并支持生成应收票据退票记账凭证。

3）应收票据发生退票后，企业还需要恢复原有的应收账款金额，退票单据类型选择其他应收单，系统将自动产生一张其他应收单，恢复应收账款的余额；选择收款退款单，系统将自动生成一张收款单退款单。


注意：应收票据退票的记账凭证通过应收票据结算单生成，因此退票产生的其他应收单不需要生成记账凭证。

=====4 业务操作=====

====4.1 领用 ====
从支票卷进行领用，出纳对领用人信息进行登记、填写使用限额、预计报销日期等。领用确定后，系统自动生成支票管理单据，一个支票号对应生成1张单据。

支持领用1张或者多张支票。领用多张时，支票号码注意按要求界面要求填写

出纳直接签发支票，填写收款人信息、金额等，领用部门、领用人可填写出纳及所在部门，预计报销日期、领用日期、签发日期可写同一天。

其他领用人领用空白支票的，按实际领用人及部门填写。日后在限额内签发支票，签发后及时报销。
====4.2 核销====
对支票进行支付后，进行核销操作。核销后，持票人不再有支票相关权利。

====4.3 作废与反作废====
在实际业务中，如果填开支票出现错误等各种原因，会对发票进行作废。

对真实支票作废时，在系统进行作废操作。反作废，处理系统作废误操作后，取消作废。

## 【页面】票据管理
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%A5%A8%E6%8D%AE%E7%AE%A1%E7%90%86

======= 票据管理 =======

=====1 票据管理概述 =====

==== 1.1 票据管理概述 ====

金蝶AI星空票据管理系统为企业提供票据的收发、背书、贴现、到期收付、质押、托管等业务的集中处理平台。旨在帮企业实现票据的全生命周期管理。主要应用特色：
  - 票据管理平台：票据管理人员可在票据管理模块完成票据的收发、背书、贴现等日常业务处理。 
  - 支持事业部下的票据池管理：结算中心代事业部成员单位收发票据。收付组织为结算中心，结算组织为事业部。
  - 与资金管理联用，支持结算中心下拨票据额度：勾选资金管理参数“资金下拨单以票据方式下拨时只下拨票据可用额度，并按照下拨额度控制应收票据的使用”，结算中心可对成员单位应收票据使用额度进行控制。
  - 与网上银行联用，支持电子票据的签收、开票、背书、贴现等功能。
 





==== 1.2 票据管理蓝图 ====

[图:票据管理3.png]

===== 2 主要功能及应用 =====

===2.1 期初票据===
 
期初应收票据勾选“期初”标识。勾选期初后，不能也无需被收款类单据关联。

期初应付票据勾选“期初”标识。勾选期初后，不能也无需被付款类单据关联。

===2.2 应收票据===

管理和维护企业接收的应收票据，包括银行承兑汇票和商业承兑汇票。

应收票据的接收

企业通过票据类结算方式进行收款时，会收到对方签发或者背书过来的应收票据，包括银行承兑汇票和商业承兑汇票。企业需要在系统中维护所接收到的应收票据，同时进行收款处理。

系统支持存在票据类结算方式的收款单，引用相应的应收票据进行收款处理，并支持多笔收款业务合并签发一笔应收票据进行结算的应用场景。

应收票据的结算

系统支持企业进行应收票据的贴现、背书、背书退回、到期收款以及退票等后续结算业务处理。应收票据的每一次结算业务处理，均由系统自动产生一张应收票据结算单与之对应，并据此应收票据结算单进行应收票据结算业务的账务处理。
===2.3 应付票据===


管理和维护企业接收的应收票据，包括银行承兑汇票和商业承兑汇票。

应付票据的签发

企业通过签发应付票据进行付款时，需要在系统中维护所签发的应付票据，同时进行付款处理。

系统支持存在票据类结算方式的付款单，引用相应的应付票据进行付款处理，并支持多笔付款业务合并签发一笔应付票据进行结算的应用场景。

应付票据的结算

系统支持企业进行应付票据的到期付款以及退票等后续结算业务处理。应付票据的每一次结算业务处理，均由系统自动产生一张应付票据结算单与之对应，并据此应付票据结算单进行应付票据结算业务的账务处理。
===2.4 支票===
支票购置

系统支持企业购买空白支票卷的业务。

支票管理

系统支持企业进行支票管理，进行支票领用、支票开具、核销等操作。

===2.5 票据报表===

应收票据使用流水：系统提供应收票据使用流水功能，用户可查询某时间范围内应收票据的收款组织、币别、票据号、增加金额、已用金额、可用金额等项目的数据。

应收票据余额表：系统提供应收票据余额表，用户可查询某时间范围内应收票据，按往来单位汇总显示期初金额、本期实收金额、背书金额、退票金额、背书退回、退票等项目的数据。

应收票据执行明细：系统提供应收票据执行明细功能，用户可查询某时间范围内应收票据的收款组织、往来单位、票据号、票据金额、结算状态、实收金额、背书金额、退票金额等项目的数据。

应收票据收发存明细：系统提供应收票据收发存明细表，用户可查询某时间范围内应收票据期初余额、本期收到多少票据、本期支出多少票据、期末余额是多少，并显示查询期间每张票据的票据金额、结算状态、实收金额、背书金额、退票金额等项目的数据。

应付票据余额明细表：系统提供应付票据余额明细表，用户可查询某时间范围内应付票据期初余额、本期增加到多少票据、本期支出多少票据、期末余额是多少，并显示查询期间每张票据的票据金额、结算状态、到期付金额、退票金额等项目的数据。

=====5 业务操作=====

====5.1 提交银行 ====

贴现申请单提交、审核后，可以进行提交银行，提交银行会将贴现申请指令，通过银企互联，提交到网银。
提交银行，系统会自动生成电子票据贴现单，记录贴现操作。
====5.2 同步银行状态 ====
通过同步银行状态，获取银行对电子票据贴现请求的处理状态。
如果交易成功，系统会自动生成应收票据贴现结算单，并更新票据结算状态为贴现。

====5.3 撤销提交银行 ====
如果银行处理状态为交易失败，则可以进行撤销提交银行操作，更新提交银行状态字段。
撤销提交银行后，可以对单据反审核进行修改，再次提交银企。
