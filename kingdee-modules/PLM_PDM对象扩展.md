====== PDM对象扩展-定制业务类型 ======
===== 一、背景 =====
  - 基于PLM面对的是多个行业的客户，客户的需求呈多样化，难以通过标准功能统一满足；
  - 并且目前二开增加业务对象比较麻烦、困难度较大；
  - 为了让标准产品聚焦核心业务，项目又能满足不同行业客户的需求、增加业务覆盖度，PDM对象拓展功能可以新建一个全新的业务类型。
===== 二、说明  =====
  - 标准版不支持该功能；
  - 可以新建一个全新业务类型，交互式新增中可以设置业务类型的编码、和名称，图标；
  - 新增的业务类型包含以下几个一级页签：基本信息、反查、相关过程、相关对象、历史记录可支持创建子业务类型；
  - 支持业务对象单据预置字段和增加自定义字段，并提供按页签分组功能，页签分组可以实现和流程结合，按不同的流程节点设置权限功能；
  - 绑定流程，配置流程中的状态转换；
  - 支持通过系统配置操作；
  - 支持与系统中其他基础对象相互关联。
===== 三、操作步骤 ===== 
==== 1. Administrator登录系统（或拥有administrator角色的用户） ====
   路径：【系统管理】→【PLM初始化】→【业务类型初始化】
[图:1.1定制入口.png]
==== 2. 开始创建业务类型 ====
   找到定制PDM对象的入口：【定制业务类型】→【创建】
   说明：一共可以定制40个业务类型
[图:1.2定制业务类型-创建.png]
==== 3. 使用说明中勾选同意接受相关规定 ====
[图:1.3勾选同意接受相关规定.png]
==== 4. 维护业务类型的编码、名称、编码规则、版本序列号等 ====
   说明：
   可以选择已有的编码规则，也可新增编码规则；
   点击编码规则放大镜，在弹出的编码规则列表中点【新增】按钮，即可创建新的编码规则
[图:1.4维护业务类型编码规则.png]
==== 5. 是否定义相关性 ====
[图:1.5.1是否定义相关性.png]
   说明：
   关系类型指将两个业务类型的对象相关联，两个对象之间形成隶属关系，第一次创建关系类型只能选择系统中原有的PDM业务类型
[图:1.5.2关系业务类型说明.png]
   关系业务类型最终效果展示
[图:1.5.3关系业务类型最终效果展示.png]
==== 6. 配置业务类型的生命周期模板和图标 ====
   说明：
   可以选择系统中已有的生命周期模板，也可新增生命周期模板
   点击生命周期模板放大镜，在弹出的生命周期模板列表中点【新增】按钮，即可创建新的生命周期模板
   图标必填，支持.jpg、.png格式，图片大小24*24且图片大小不能超过20.0KB
[图:1.6配置业务类型的生命周期模板.png]
==== 7. 规则配置、属性配置、唯一性检查规则 ====
   说明：
   规则配置：
   属性配置：界面布局配置，包括字段的显示、只读、必填、列表显示、默认值等，支持新增自定义字段、调整字段顺序
   唯一性检查规则：
[图:1.7规则配置_属性配置.png]
==== 8. 业务类型授权 ====
   注意：
   先点【授权】，再点【下一步】
[图:1.8业务类型授权.png]
==== 9. 发布菜单 ====
   说明：发布维护菜单、列表菜单至子系统、子功能，勾选发布至桌面端或浏览器
[图:1.9.1发布菜单.png]
   说明：
   维护菜单：新增对象界面
   列表菜单：对象列表界面（对象库）
   子系统、子功能均可选择系统已有的，也可提前在BOSIDE中创建
   子系统：归属于PLM领域下的系统，与文档管理、研发物料管理等模块同级，若需要发布至新的子系统，需要提前在BOSIDE中创建
   子功能：归属于子系统下的功能菜单，若需要发布至新的子功能，需要提前在BOSIDE中创建

   创建子系统
   路径：开始→业务领域选择PLM-右边子系统栏中点【新增】按钮，维护子系统编码、名称等信息并保存
[图:1.9.2子系统.png]
   创建子功能
   路径：【发布】→【发布至主控台】→PLM领域下选择子系统-新增子功能，维护子功能编码、名称等信息并保存
[图:1.9.3子功能.png]
==== 10. 功能菜单授权 ====
   说明：
   先点【授权】，再点【下一步】，菜单发布与授权后，需要清除缓存
[图:1.10功能菜单授权.png]
==== 11. 完成业务类型定制 ====
[图:1.11完成业务类型定制.png]
==== 12. 清除缓存 ====
   说明：
   用Administrator(或拥有Administrator角色的用户)清除缓存
[图:1.12清除缓存.png]
==== 13. 创建完成后续维护 ====
   说明：
   用户登录系统维护
   路径：【PLM】→【系统建模】→【业务类型配置】→【设置向导】中重新维护图标、规则或重新发布菜单
[图:1.13创建完成后续维护.png]
