## 【页面】webapi日志
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=webapi%E6%97%A5%E5%BF%97

====== 1 功能概述 ======

记录Web API的执行情况，输出执行耗时、执行明细情况等各类信息，同时还提供了自动清理，减少日志记录的表空间占用。

**功能路径**

Administrator用户登录数据中心，打开日志管理。

**启用步骤**

金蝶AI星空V7.1以上版本已提供为业务数据中心单独创建日志库的功能，将业务数据中心与日志的存储分离。日志库创建与注册可以参考[[数据中心|数据中心]]管理的介绍。
  - 登录管理中心→进入数据中心列表→选择业务数据中心，创建或注册日志库（根据是否创建过日志库选择对应方式）
  - administrator用户登录业务数据中心，进入【基础管理-公共设置-参数设置】，日志管理节点开启对应日志的记录。

====== 2 字段说明 ======
  - 创建人：日志产生的当前操作人。
  - 创建人编码：日志产生的当前操作人对应编码。
  - 业务对象编码：WebAPI对应业务对象的编码。
  - 业务对象名称：WebAPI对应业务对象的名称。
  - 操作名称：WebAPI调用涉及的操作名称。
  - 开始执行时间：开始执行的时间点。
  - 结束执行时间：结束执行的时间点。
  - 总耗时间：本此操作调用的耗时。
  - 执行状态：分为正常和异常。
  - 日志类型：分为错误日志、业务日志、调试日志。
  - 日志内容：记录本次执行的详细情况。

====== 3 功能说明 ======

**过滤**
  - 显示所有组织的操作日志记录；
  - 操作日志按照开始执行时间的降序显示；
  - 系统预置了“今天”和“本月”的查询方案，以便用户直接使用。

**删除**

  - 删除执行计划日志记录。

**日志启用**
  - 【公共设置-参数设置-日志管理】，可以设置日志启用及记录范围。
  - 记录类型：错误日志强制记录，业务日志与调试日志允许用户选择。
  - 记录范围：默认选择业务对象，由用户在下方列表设置对哪些业务对象进行监控。

**自动清理**
  - 【公共设置-参数设置-日志管理】，可以设置日志自动清理规则。
  - 通过设置日志保留天数及保留类型，对于保留范围之外的日志进行自动清理。

## 【页面】上机操作日志
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8A%E6%9C%BA%E6%93%8D%E4%BD%9C%E6%97%A5%E5%BF%97

====== 1 功能描述 ====== 
上机操作日志用来记录用户操作金蝶云系统的情况，以备系统管理员查看，同时还提供了归档或者情况处理，以减少日志记录日渐增长对系统性能造成影响。

**功能路径**
  - 管理中心：【数据中心管理】→【数据中心】→【日志管理】 
  - 数据中心：【系统管理】→【系统管理】→【日志管理】 

 ====== 2 字段说明 ======
  - 操作用户:显示当前登录用户权限查看的用户名称；
  - 操作时间:显示业务操作时的数据库服务器时间，长日期格式；
  - 当前组织:显示当前登录组织；
  - 子系统: 业务对象对应的子系统名称；
  - 业务对象: 操作业务对象的名称，涉及内容：业务单据、基础资料、报表、凭证等；
  - 操作场景: 执行操作的应用场景，比如：登录（登出）系统、进入业务对象、业务操作；
  - 操作名称: 执行的操作名称，比如：保存、提交、审核、删除等；
  - 操作描述: 执行操作的详细描述，例如：编码为“GW00005”的岗位信息，保存成功！
  - IP地址: Web端/GUI客户端所属机器对应的IP地址；
  - 机器名称: Web端/GUI客户端所属机器对应的IP地址；
  - 对象内码：对象内码信息；
  - 单据编码：显示单据编码，方便用户根据单据编码快速查询日志；
  - 业务组织：显示操作数据记录的业务组织字段信息，方便用户区分操作的这条记录是属于哪个业务组织的；

 ====== 3 功能操作 ======
=====3.1 过滤=====
  - 默认显示当前登录组织的操作日志记录；
  - 允许勾选当前用户有权限的组织范围，显示对应的操作日志；
  - 操作日志按照操作时间的降序显示；
  - 系统预置了“今天”和“本月”的查询方案，以便用户直接使用。

=====3.2 归档规则 =====
**日志超过（5）万条执行自动归档**
  - 主要是进行后台数据库表的转移，以减少操作日志查询的数据量；
  - 归档执行都是后台执行，无需人工干预。

**启用日志定时清理**
  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志定时清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 定时清理：预置默认清理时间，每月3号02:00执行日志清理，可以修改；
  - 支持设置清理规则，支持把上机操作日志清理到应用服务器指定目录，或已部署配置文件服务器，清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，并且当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容，且每月一个备份文件。
  - 定时清理是系统后台按照清理周期定时执行，无需人工干预；
  - 注意：启用定时清理后，不能回滚，且启用归档到日志库不可使用。
      
=====3.3 归档查询 =====
针对已经归档到归档表或日志库的历史较为久远的上机操作日志进行查询。

 ====== 4 业务说明 ======
  - 数据中心的上机操作日志只有Administrator和具有系统管理员角色的用户才可以查看；且非Administrator用户只能查看自己组织范围内的内容；
  - 管理中心的上机操作日志只有Administrator可以查看。

## 【页面】上机操作日志备份文件列表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8A%E6%9C%BA%E6%93%8D%E4%BD%9C%E6%97%A5%E5%BF%97%E5%A4%87%E4%BB%BD%E6%96%87%E4%BB%B6%E5%88%97%E8%A1%A8

====== 1 功能描述 ====== 
上机操作日志清理完成，会在上机操作日志备份文件列表生成记录，方便系统管理员查看和下载已清理的历史久远的上机操作日志。

**功能路径**
  - 系统管理员登录主控台【系统管理】→【日志管理】→【上机操作日志备份文件列表】； 

====== 2 字段说明 ======
  - 文件名：清理生成文件的名称，一般规则是：logBackup+YYYYMM(日志产生年月)+(日期清理年月日时分秒)+(数据中心名称)+序号。
  - 大小（KB）：日志清理后生成的Excel文件的大小，单位是KB。
  - 说明：文字描述文件里面存储的上机操作日志，是从什么时间开始，到什么时间截止的日志，方便后续按时间查找。例如：从2018-02-08至2018-03-01的上机操作日志备份文件。
  - 存储位置：清理出的文件，存储的位置。
  - 创建人：清理执行的用户，一般是默认Administrator。
  - 创建时间：清理文件的生成时间。

====== 3 功能说明 ======

**过滤**
  - 显示上机操作日志备份文件列表记录；
  - 列表记录按日志产生的时间进行升序显示；

**下载**

  - 选择文件，点击下载，可下载上机操作日志备份文件。

## 【页面】业务对象功能授权
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E5%8A%9F%E8%83%BD%E6%8E%88%E6%9D%83

====== 1 功能描述 ====== 
业务对象功能授权是角色按照【业务对象+权限】的组合模式进行授权，适用于精细型管理的企业。授权后可以查看权限的内容以及影响的用户。

**使用前提** 维护好角色。

**功能路径**
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】

 ====== 2 字段说明 ======

=====2.1 权限状态 =====
  - 按权限组的权限状态分为三类：有权、无权和禁止；
  - 禁止是一种特殊模式的无权，主要应用于多个角色集于一个用户时，由于权限的并集处理，造成该用户具有业务同时具有业务制度上要求不能同时拥有的两个及以上的冲突权限；
  - 权限优先顺序：禁止→有权→无权。

    举例：财务制度要求，出纳和会计的权限不能在一个人上
    用户张三分配了角色A和角色B，角色A中现金日记账有权，凭证处理无权，角色B中凭证处理有权，但是由于同时分配到张三，基于权限的并集处理，张三既可以做现金日记账又可以做现金业务的凭证处理，就不符合财务制度要求，
    相应处理是：角色A中凭证处理设置为禁止，这样按照权限状态的优先顺序，张三是没有凭证处理的权限。

=====2.2 授予角色 =====
  - 支持F8选择；
  - 当前用户=Administrator，则F8显示全部的角色；
  - 当前用户=非Administrator，则F8显示当前用户有权限范围组织内的私有角色。

=====2.3 显示全部子系统 =====
  - 默认不勾选；则只显示所选角色已经授权的业务对象；
  - 勾选后，显示全部的业务对象。

 ====== 3 功能操作 ======
  - 授权：对业务对象不同权限项勾选不同的权限状态，点击【授权】，这样权限设置才会生效；
  - 子系统功能授权：可以在调用子系统功能授权对当前角色进行授权；
  - 字段权限：可以在调用字段权限对当前角色进行字段授权；
  - 查询权限：业务对象授权后，可以通过【查询权限】调出角色业务对象权限报表，查看当前角色对应的业务对象的权限情况
  - 查询用户：业务对象授权后，可以通过【查询用户】查看当前角色影响的用户列表。
 
====== 4 业务说明 ======
1、对于同一业务对象，查看是其余权限的前置权限，即其余权限以查看为前置权限（特殊业务操作不以查看权限为前置权限的除外），具体控制为：
     1）当查看设置为有权，则允许其余权限设置为有权、无权和禁止；
     2）当查看设置为无权，则允许其余权限设置为无权或禁止，但不能设置为有权；
         例如：对角色“财务会计”设置“凭证”查看无权，
                  新增权限选择有权，进行授权后，新增权限自动无权；
                  新增权限选择禁止，进行授权后，新增权限仍然为禁止；
    3）当查看设置为禁止，则其余权限只能为禁止；
        沿用上例：新增权限选择有权、无权或禁止，进行授权后，新增自动设置为禁止；
    4）此外，新增、修改等权限组组合之间的设置顺序没有限制。选择或清除任意一个，剩下的权限组合状态不受影响；
2、若用户具有多个角色的，权限是多个角色的并集，但是禁止权限优先，见权限状态中举例。

## 【页面】业务对象批量授权
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E6%89%B9%E9%87%8F%E6%8E%88%E6%9D%83

====== 1 功能描述 ====== 
业务对象批量授权是针对系统全部功能按照所选业务对象、业务对象权限组、业务对象单个权限进行批量授权的处理。适用于授予业务对象某个权限的场景，例如：为某个角色授予采购订单的查询权。

**使用前提**  维护好角色的内容。

**功能路径**
【系统管理】→【系统管理】→【批量授权】→【业务对象批量授权】

 ====== 2 字段说明 ======
  - 授予角色：支持F8选择；支持选择多个角色；
  - 清空：清除所选的角色内容；
  - 授权模式：业务对象、权限组（默认）、权限项；可以选择不同模式进行授权操作；
  - 权限内容：以业务对象为对象，根据授权模式显示对应的内容，进行快速授权操作。

 ====== 3 功能操作 ======
  - 授权：选择授权模式+权限内容后，点击【授权】权限设置才生效；系统以追加模式将权限明细内容进行后台对应处理；
  - 查询权限：调出“角色业务对象权限报表”查看所选角色的权限内容；
  - 查询用户：调出所选角色所影响的用户。

## 【页面】业务数据日志明细表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%95%B0%E6%8D%AE%E6%97%A5%E5%BF%97%E6%98%8E%E7%BB%86%E8%A1%A8

====== 1 功能概述 ======

通过查看明细、对比差异操作，打开“业务数据日志”等方式，都会打开数据日志的明细界面，按照不同方式传入的条件，展示对应的修改记录。

====== 2 操作说明 ======

字段：显示"单据实体名称.字段名称”的格式。

旧值：显示本次修改之前的旧值。

变更值：显示本次修改的变更值。

实体序号：依据修改日志中的分录内码ID，动态匹配该分录在当前最新数据中对应的分录序号。如果分录未开启序号或者单据头实体字段，则实体序号列显示 /，表示无法获取其分录序号。

注意：
  * 业务数据日志明细表因为可以批量查询多个单据多笔修改记录，因此会等待异步服务进行差异分析计算的结果（计算会有延时，测试时立即查看会出现旧值不显示）
  * 变通办法是使用业务数据日志汇总表或单据上配置“查看业务数据日志”操作，这2种方式因为只能查询一张单据的2笔数据的差异，系统发现异步服务未计算完成会自动转为实时方式分析差异数据。
  * 对于基础资料、辅助资料字段会采用显示编码或名称、下拉列表显示枚举名称的方式，便于用户阅读。
  * 系统还提供了旧值内码、变更值内码字段，默认是隐藏，可以通过选项配置显示。如果基础数据在使用过程中发生了名称修改，可以通过内码确定后台存储的真正数据值变化情况。

## 【页面】业务数据日志汇总表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%95%B0%E6%8D%AE%E6%97%A5%E5%BF%97%E6%B1%87%E6%80%BB%E8%A1%A8

====== 1 功能概述 ======

业务数据日志汇总表查询修改记录。系统支持同时查询多个业务对象的修改记录，左侧会按业务对象分类展示修改记录。

====== 2 操作说明 ======

  * 查看明细：可以查看本次修改操作中发生数据变化的字段内容。
  * 对比差异：可以选择同一个单据的两个修改版本，进行跨版本差异对比。
  * 记录号：每一次修改保存产生一个记录号，记录号里面会包括多个字段的修改记录。
  * 内码：每一个单据创建的后台内码ID。
  * 操作类型：代表单据的新增、修改、删除行为。
注意，由于单据可能发生补号，单据删除再重建，系统会视作2个单据，可以通过内码字段识别。

## 【页面】业务数据日志设置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E6%95%B0%E6%8D%AE%E6%97%A5%E5%BF%97%E8%AE%BE%E7%BD%AE

====== 1 功能概述 ======

在系统使用过程中，单据可能多人具备修改权限，当关键数据出现被人修改的异常时，通过上机操作日志记录仅能知道多人对此单据都有过修改操作，无法准确的追溯问题。 通过业务数据日志功能，可以指定需要进行数据修改监管的单据对象及其具体字段，查询数据修改变化。

====== 2 操作步骤 ======

  - Administrator用户登录系统，在基础管理-系统管理中，打开“业务数据日志设置”，自建单据模版，指定单据对象及监控字段。
  - 将自建的模版启用后，状态=启用的单据表示开始进行监控，会记录业务数据日志。
  - 管理员可以通过业务数据日志汇总表、业务数据日志明细表查询数据修改变化。

====== 3 操作说明 ======

  * 打开“业务数据日志设置”，自建需要监控的单据及字段，并启用。
  * 支持对象类型：基础资料、单据。
  * 监控全部字段：表示不需要逐个配置监控字段，该单据上所有字段都进行监控。建议一般不要开启，全量监控所占用的日志空间会非常大。
  * 记录新增/删除详细日志：建议视用户需求开启，会增加日志空间占用。开启后，在查询业务数据日志时，每个单据会记录首次保存的所有监控字段数据，后续的修改记录是采用差量化方式记录的，仅记录发生变化的字段内容。
如果不开启该选项，可以显著减少日志空间占用，适用于用户仅关注修改变化的变更值场景。
不启用时，由于首次保存的全量不记录，则第一次修改单据上某字段时，查看修改记录中的原值会显示为空；后续多次修改这个字段，则原值、变更值都可以查看到。

## 【页面】云瘦身
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BA%91%E7%98%A6%E8%BA%AB

======1 数据瘦身概述 ======

===== 1.1 数据瘦身概述 =====
 
金蝶云系统运行一段时间后，数据库日渐庞大，金蝶云推出数据瘦身服务，通过订阅实现数据库优化、临时表和日志的清理，缩小数据库的容量。

===== 1.2 系统特性 =====
 
本系统主要包含以下应用：

  - 金蝶云自动计算数据的冗余情况，达到预警状态，则推送数据瘦身服务及预警消息；
  - 数据瘦身服务订阅后可以使用；
  - 支持数据库临时表、操作日志、监控消息等清理；
  - 提供数据瘦身报告；
  - 定期瘦身可以减少过时的数据，提升系统运行速度。
 
====== 2 数据瘦身操作手册 ======

===== 2.1 金蝶云推送数据清理服务 =====

系统运行一段时间后，若不进行定期的清理，会产生太多的冗余数据，数据库会越来越大，影响系统运行。

金蝶云系统会自动智能判断客户系统当前系统的冗余情况，当冗余数据达到预警状态，则推送【数据清理】预警消息。


===== 2.2 订阅数据瘦身服务 =====

当前系统达到预警状态，右下角显示金蝶云消息：

金蝶云检查到当前数据中心数据量已超（*）GB，赶快订阅数据瘦身服务，给数据中心来一次全面瘦身，让数据中心轻盈灵动。点击【了解更多】则可以进入数据瘦身向导界面。

在数据瘦身向导界面，点击【我要订阅】后就可以启用并使用数据瘦身服务了。


【温馨提示】

若管理员已订阅数据瘦身服务，当前系统达到预警状态，右下角显示金蝶云消息：

金蝶云检查到当前数据中心数据量已超（*）GB，建议进行数据瘦身，降低数据中心的容量， 点击【启动数据瘦身】，则可以进入数据瘦身向导界面开始清理。


===== 2.3 数据清理过程 =====


==== 2.3.1 备份数据库 ====

数据清理前，需要备份好待清理的数据库。

==== 2.3.2 定制清理规则 ====

定制清理规则确保能保留最近多少个月的数据备查，历史记录将全部清理。

Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

==== 2.3.3 使用清理向导 ====

使用清理向导，定制清理服务，选择清理项，执行时间和时长限制，勾选清理高级选项，以确保清理过程少产生日志。

进入清理向导，首先看到的是清理前的温馨提醒信息，并可以查看设置[[云瘦身#数据清理过程|清理瘦身规则]]，接着按向导步骤及流程执行。

第一步：

  - 系统会自动计算当前数据中心的的空间占用情况，并预估可清理空间大小；
  - 确定清理方案名称；
  - 根据需要选择清理项目，包括上机操作日志清理、监控执行情况清理、分配执行情况清理、临时表清理、批改日志清理
  - 注意：确保所有清理项目已经设置好[[云瘦身#数据清理过程|清理瘦身规则]]，特别是上机操作日志备份路径不能为空。另外所选清理项中至少有一个选项的清理空间大于0，否则不能建立清理计划。

第二步：

  - 确定清理时间和清理时长，可以选择立即执行，但是数据清理尽量选择在业务空闲期间执行；
  - 勾选选项【清理任务执行时，恢复模式修改为简单】，这样可以大大减少日志产生，避免日志文件过度膨胀；
  - 勾选选项【数据后，收缩数据库】，，以便回收数据文件占用空间，注意此过程耗时较长；
  - 点击下一步，进行瘦身清理计划确认。

第三步：

  - 清理参数确认，包括清理时间、清理时长限制等；
  - 已选清理项确认；
  - 点击下一步，确认保存瘦身清理计划，可打开瘦身服务清理执行情况查看结果。


==== 2.3.4 查看执行情况 ====

查看清理执行情况，查看清理后，各个清理项数据量和清理存储空间的释放情况、完成时间、状态以及相关描述。

查看路径：

1、数据瘦身向导执行完后，在最后一步可以点击【查看执行结果】查看；

2、可以通过路径打开：【系统管理】→【系统管理】→【数据瘦身】→【数据瘦身执行情况】 。


===== 2.4 相关说明 =====

用户订阅后，HTML5的更多服务卡片中会自动增加【数据瘦身】入口，方便操作；

若编辑卡片时，删除【数据瘦身】，将会停用瘦身清理服务。

## 【页面】子系统功能授权
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%AD%90%E7%B3%BB%E7%BB%9F%E5%8A%9F%E8%83%BD%E6%8E%88%E6%9D%83

====== 1 功能描述 ====== 
子系统功能授权是角色按照【子系统+权限组】的组合模式进行授权，适用于粗放型管理的企业。授权后可以查看权限的内容以及影响的用户。

**使用前提**  维护好角色。

**功能路径**
【系统管理】→【系统管理】→【授权】→【子系统功能授权】

 ====== 2 字段说明 ======
=====2.1 权限组名称=====
权限组分五类：查询、编辑、审核、其他、业务操作，具体包含的权限项内容如下：
  - 查询：查看
  - 编辑：新增、修改、批改、删除、提交
  - 审核：审核、反审核
  - 其他：引入、引出、打印、附件
  - 业务操作：除上述四类权限组不包含的权限，例如：禁用、分配、冻结、即时库存查询等业务权限。 

=====2.2 权限状态 =====
  - 按权限组的权限状态分为三类：有权、无权和禁止；
  - 禁止是一种特殊模式的无权，主要应用于多个角色集于一个用户时，由于权限的并集处理，造成该用户具有业务同时具有业务制度上要求不能同时拥有的两个及以上的冲突权限；
  - 权限优先顺序：禁止→有权→无权。 

    举例：财务制度要求，出纳和会计的权限不能在一个人上；  
    用户张三分配了角色A和角色B，角色A中出纳系统有权总账系统无权，角色B中总账系统有权，但是由于同时分配到张三，基于权限的并集处理，总账和出纳系统均有权，就不符合财务制度要求；
    相应处理是：角色A中总账系统设置为禁止，这样按照权限状态的优先顺序，张三是没有总账的权限。

=====2.3 授予角色 =====
  - 支持F8选择；
  - 当前用户=Administrator，则F8显示全部的角色；
  - 当前用户=非Administrator，则F8显示当前用户有权限范围组织内的私有角色。

=====2.4 显示全部子系统 =====
  - 默认不勾选；则只显示所选角色已经授权的子系统；
  - 勾选后，显示全部的子系统。

 ====== 3 功能操作 ======
=====3.1 授权 =====

  - 对子系统的不同权限组勾选不同的权限状态后，点击【授权】，这样权限设置才会生效；
  - 子系统授权后，系统会根据子系统与业务对象的隶属关系，权限组与权限项的对应关系，自动更新业务对象的权限情况。

=====3.2 业务对象功能授权 =====
进行子系统授权后，如果想再进行细化的权限设置，可以点击【业务对象功能授权】，系统对当前角色进行业务对象授权界面。

=====3.3 其他操作 =====
  - 查询权限：子系统授权后，可以通过【查询权限】调出角色子系统权限报表，查看当前角色对应的子系统的权限情况；
  - 查询用户：子系统授权后，可以通过【查询用户】查看当前角色影响的用户列表。
 
====== 4 业务说明 ======
1、对于同一子系统，查询是其他权限组的前置权限组，即其他权限必须以查看为前置权限（特殊业务操作不以查看权限为前置权限的除外），具体控制为：
     1）当查询设置为有权，则允许编辑、审核等权限组设置为有权、无权和禁止；
     2）当查询设置为无权，则允许编辑、审核等权限组设置为无权或禁止，但不能设置为有权；
  例如：对角色“财务会计”设置“总账”查询无权
         编辑、审核等权限组选择有权，进行授权后，编辑、审核等其余权限组自动设置为无权
         编辑、审核等权限组选择禁止，进行授权后，编辑、审核等其余权限组仍然为禁止
     3）当查询设置为禁止，则编辑、审核等其余权限组只能为禁止；
          沿用上例：编辑、审核等其余权限组选择有权、无权或禁止，进行授权后权限组编辑、审核、其他、业务操作自动设置为禁止
     4）此外，编辑、审核等其余权限组组合之间的设置顺序没有限制。选择或清除任意一个，剩下的权限组合状态不受影响。
2、若用户具有多个角色的，权限是多个角色的并集，但是禁止权限优先；

3、子系统授权后，每个子系统对应全部业务对象也同步授权，并且授权权限组与功能授权的权限也同步。

  - 查询权限：调出“角色业务对象权限报表”查看所选角色的权限内容；

## 【页面】子系统管理员功能授权模式
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%AD%90%E7%B3%BB%E7%BB%9F%E7%AE%A1%E7%90%86%E5%91%98%E5%8A%9F%E8%83%BD%E6%8E%88%E6%9D%83%E6%A8%A1%E5%BC%8F

====== 1 功能描述 ====== 
企业信息化系统中的管理员权限由一人承担，对企业信息安全存在很大的安全隐患，为了避免系统管理员拥有过度集中的权利带来高风险，金蝶AI星空提供了“子系统管理员授权模式”，可以将系统管理员的权限进行细分，子系统管理员只能负责自己的管理范畴，满足企业精细化管理的同时，系统管理员无法越权处理，可以有效满足ERP信息安全管理需要。

**系统特性**
  - 有效规避系统管理员拥有过大权利带来高风险，提升安全管理；
  - 支持子系统管理员按权限设置进行系统管理，满足企业精细化管理需要；
  - 预置两个系统管理员类型角色（安全保密员和安全审计员）及权限，方便企业参考快速应用； 
  - 支持业务对象的组织隔离应用
  - 支持停用子系统管理员授权设置，停用后可以还原为原有授权模式

**功能路径**

【系统管理】—>【权限基础设置】—>【子系统管理员授权模式】。

====== 2 操作流程 ======

===== 2.1启用子系统管理员功能授权 =====
  - 登录数据中心，进入【系统管理】—>【权限基础设置】—>【子系统管理员授权模式】打开子系统管理员授权模式界面，勾选“启用子系统管理员授权模式”保存后即可生效；
  - 启用后，可以对子系统管理员角色进行功能授权。 
  - 授权后，子系统管理员按权限设置进行精细管理。
比如：对“日志维护管理员”角色授予上机操作日志的查看权限，那么分配了“日志维护管理员”角色的用户登录系统，只能看到上机操作日志菜单，看不到其他业务菜单。

===== 2.2 预置角色=====
  - 启用子系统管理员功能授权后，系统自动预置两个系统管理员类型角色（安全保密员和安全审计员）及权限，方便企业应用；
  - 对于原有预置的administrator角色及权限保留，若认为分配了administrator角色的用户权限太大，建议取消或调整；
  - 注意：启用后原有子系统管理角色的系统管理权限不再保留，需根据实际应用重新定义；

===== 2.3停用子系统管理员功能授权 =====
  - 停用子系统管理员功能授权，将还原为原有授权模式
  - 停用后，预置角色和自定义子系统管理角色的系统管理权限将全部还原，且将不再允许对子系统管理员角色进行功能授权

===== 2.4多组织隔离应用 =====

支持多组织隔离应用，比如：负责A组织和B组织的安全审计员，只允许查看A组织和B组织的上机操作日志，不能查看C组织的上机操作日志。

具体是否受组织控制取决于业务对象本身是否支持组织隔离，具体规则如下：

   - 支持组织隔离的业务对象（比如：上机操作日志），管理员的操作按组织及权限控制和隔离；
   - 不支持组织隔离的业务对象（比如：权限相关），管理员操作不受组织控制，只要有其中一个组织的权限，就能做相关操作。

## 【页面】字段授权
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%AD%97%E6%AE%B5%E6%8E%88%E6%9D%83

====== 1 功能描述 ====== 
字段权限是指对业务对象的字段操作权限。提供了查看和编辑两个分组，每个分组都支持有权、无权和禁止的设置。

**使用前提**  维护好角色。

**功能路径**
【系统管理】→【系统管理】→【授权】→【字段权限】

 ====== 2 字段说明 ======
=====2.1 权限状态 =====
  - 按权限组的权限状态分为三类：有权、无权和禁止；
  - 禁止是一种特殊模式的无权，主要应用于多个角色集于一个用户时，由于权限的并集处理，造成该用户具有业务同时具有业务制度上要求不能同时拥有的两个及以上的冲突权限；
  - 权限优先顺序：禁止→有权→无权。
    
=====2.2 授予角色 =====
  - 支持F8选择；
  - 当前用户=Administrator，则F8显示全部的角色；
  - 当前用户=非Administrator，则F8显示当前用户有权限范围组织内的私有角色。

=====2.3 显示全部子系统 =====
  - 默认不勾选；则只显示所选角色已经设置字段权限的业务对象；
  - 勾选后，显示全部的业务对象。

 ====== 3 功能操作 ======
  - 授权：对业务对象的字段勾选不同的权限状态，点击【授权】，这样权限设置才会生效；
  - 业务对象功能授权：可以点击【业务对象功能授权】，系统对当前角色进行业务对象授权界面。
  - 查询权限：业务对象授权后，可以通过【查询权限】调出角色字段权限报表，查看当前角色对应的业务对象的权限情况
  - 查询用户：业务对象授权后，可以通过【查询用户】查看当前角色影响的用户列表。
  - 字段批量授权：需要对批量授权字段进行字段批量授权，可以通过【字段批量授权】页面进行设置。
  - 设置批量授权字段：进入【设置批量授权字段】页面，设置需要授权的字段的状态为有权或无权。
  - 应用批量授权字段：设置完批量授权字段后，选择需要授权的业务对象，点击【应用批量授权字段】后，该业务对象相应类型字段按照设置的字段进行授权。

====== 4 业务说明 ======
1、对同一业务对象，每个字段查看权是编辑权的前置权限，具体控制为：
     1）当查看设置为有权，则允许编辑权设置为有权、无权和禁止；
     2）当查看设置为无权，则允许编辑权设置为无权或禁止，但不能设置为有权；
          例如：对角色“财务会计”设置“凭证”的“期间”字段查看无权
                   编辑选择有权，进行授权后，编辑自动无权
                   编辑选择禁止，进行授权后，编辑权仍然为禁止
     3）当查看设置为禁止，则编辑权只能为禁止；
          沿用上例：编辑权选择有权、无权或禁止，进行授权后，编辑自动设置为禁止
          
2、业务对象的字段只涉及查看权和编辑权。

3、字段权限默认是有权，若有角色授权了业务对象的功能权限，则该角色在未进行字段授权前，默认有对应业务对象的所有字段权限（查看有权/编辑有权），可以设置某个字段权限为查看或者编辑为无权或禁止。

## 【页面】岗位体系数据规则
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%B2%97%E4%BD%8D%E4%BD%93%E7%B3%BB%E6%95%B0%E6%8D%AE%E8%A7%84%E5%88%99

====== 1 功能描述 ====== 
岗位体系数据规则是指按照岗位汇报关系的上下级关系，通过向下钻取的方式实现查询数据的隔离。

**使用前提**  
  - 维护岗位及其在不同汇报类型的上级汇报关系。
  - 维护员工的任岗情况，支持多岗位。
  - 维护用户及其角色。
  - 维护用户的联系对象=员工。

**功能路径**
【系统管理】→【系统管理】→【岗位体系数据规则】→【岗位汇报体系】

====== 2 字段说明 ======
 =====2.1 授予角色 =====
  -支持F8选择角色，只能选择一个；
  -F8显示的是当前用户有权限使用的公有角色以及当前登录组织的私有角色。
    
 =====2.2 汇报类型 =====
  -支持F8选择辅助资料的汇报类型；
  -只能选择一个。


 =====2.3 业务对象 =====
  -支持F8选择岗位规则业务对象；
  -业务对象支持多选。

 =====2.4 直接下属 =====
 
取数规则：以当前登录用户对应的员工的主任岗位在岗位汇报体系中的节点，向下获取直接下级节点岗位的全部员工所对应的业务员，以该业务员的范围过滤当前业务对象的数据。

**举例**  
    - 李四的岗位是南山片区经理，其直接下级岗位是南山片区销售代表（对应业务员：王一、王二、王六）；张三的岗位是龙华片区经理，其下级岗位是龙华片区销售代表（对应业务员：张一、张二、张六）；
    - 对用户李四和王五都授予销售主管的角色（功能权限=销售订单查看）；
    - 对销售订单进行岗位体系数据规则授权，勾选【直接下属】选项；
    - 则：李四可以看到销售员=王一、王二、王六的销售订单；张三可以看到销售员=张一、张二、张六的销售订单。

 =====2.5 所有下属 =====
取数规则：以当前登录用户对应的员工的主任岗位在岗位汇报体系中的节点，向下获取所有下级节点岗位的全部员工所对应的业务员，以该业务员的范围过滤当前业务对象的数据。

**举例**  
  - 陈三的岗位是深圳区销售经理，其直接下级岗位是南山片区经理和龙华片区经理，而南山片区经理的下级岗位是南山片区销售代表（对应业务员：王一、王二、王六），龙华片区经理下级岗位是龙华片区销售代表（对应业务员：张一、张二、张六）；
  - 对用户陈三授予销售主管的角色（功能权限=销售订单查看）；
  - 对销售订单进行岗位体系数据规则授权，勾选【所有下属】选项； 
  - 则：陈三可以看到销售员=王一、王二、王六和张一、张二、张六的销售订单。

 =====2.6 其他业务员 =====
  - 支持选择指定的业务员；支持多选；
  - 使用场景：为不在岗位体系节点往下范围内的，例外需要指定的业务员；

**举例**  使用上例，其他业务员选择了：刘义；则：陈三可以看到销售员=王一、王二、王六和张一、张二、张六，还有刘义的销售订单。

 =====2.7 本部部门 =====
取数规则：业务单据的部门=当前登录用户对应的员工的主任岗位的所属部门 的数据。

**举例**  
  - 王五的主任岗位是一部销售经理，岗位的所属部门是销售一部；
  - 对用户王五授予部门主管的角色（功能权限=销售订单查看）；
  - 对销售订单进行岗位体系数据规则授权，勾选【本部部门】选项；
  - 则：王五可以看到销售部门=销售一部的销售订单。

 =====2.8 直属部门 =====
取数规则：业务单据的部门=当前登录用户对应的员工的主任岗位的直接下级岗位的所属部门  的数据 。

**举例**  
  - 肖三的主任岗位是国内销售经理，岗位的所属部门是国内销售部（直接下属部门：销售一部和销售二部）；
  - 对用户肖三授予部门主管的角色（功能权限=销售订单查看）；
  - 对销售订单进行岗位体系数据规则授权，勾选【直属部门】选项；
  - 则：肖三可以看到销售部门=销售一部和销售二部的销售订单。

 =====2.9 所有下级部门 =====
取数规则：业务单据的部门=当前登录用户对应的员工的主任岗位的全部下级岗位的所属部门  的数据 。

**举例**  
  - 黄六的主任岗位是销售总监，岗位的所属部门是销售部（直接下属部门：国内销售部和出口部，国内销售部的直接下属部门：销售一部和销售二部）；
  - 对用户黄六授予部门主管的角色（功能权限=销售订单查看）；
  - 对销售订单进行岗位体系数据规则授权，勾选【所有下级部门】选项；
  - 则：黄六可以看到销售部门=销售一部、销售二部和出口部的销售订单。


 =====2.10 其他部门 =====
  - 支持选择指定的部门；支持多选；
  - 使用场景：为不在岗位体系节点范围内的，例外需要指定的部门；

**举例**  使用上例，其他部门选择了：维修部；则：黄六可以看到销售部门=销售一部、销售二部、出口部和维修部的销售订单。

 =====2.11 数据范围 =====
就是针对所选业务对象设置的数据范围，例如：销售订单的查看，数据范围：单据类型=标准订单。


====== 3 功能操作 ======
保存：要求一个角色只有一个岗位汇报体系数据规则；如果不同汇报类型需要不同的岗位体系数据规则，则需要建立多个角色与之对应。


====== 3 业务说明 ======  
岗位汇报体系数据规则只对业务单据的查看权限有效；
岗位汇报体系数据规则与业务单据功能授权的数据范围，按照启用岗位体系规则选项中选择的选项进行并集或者交集取数；

## 【页面】岗位体系数据规则概述
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%B2%97%E4%BD%8D%E4%BD%93%E7%B3%BB%E6%95%B0%E6%8D%AE%E8%A7%84%E5%88%99%E6%A6%82%E8%BF%B0

====== 1 功能描述 ====== 

岗位体系数据规则是指按照岗位汇报关系的上下级关系，通过向下钻取的方式实现查询数据的隔离。

**使用前提**  
  - 用户维护联系对象类型=员工，选择对应的员工；
  - 岗位维护上级汇报关系，如果有多个汇报类型则需要先维护汇报类型辅助资料；
  - 员工选择一个或者多个岗位；
  - 维护业务员，选择有员工任岗的员工；
  - 维护角色；

**功能路径**
【系统管理】→【系统管理】→【岗位体系数据规则】

## 【页面】岗位汇报体系
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%B2%97%E4%BD%8D%E6%B1%87%E6%8A%A5%E4%BD%93%E7%B3%BB

====== 1 功能描述 ======= 
根据汇报类型下岗位的上下级关系组合而成，可以展示每个汇报类型的岗位整体关系。

**使用前提**  
  - 维护岗位及其上下级关系。
  - 维护员工的任岗情况。

**功能路径**
【系统管理】→【系统管理】→【岗位体系数据规则】→【岗位汇报体系】

====== 2 字段说明 ======
 =====2.1 汇报类型 =====
  - 默认显示预置的行政汇报类型；
  - 支持F8选择辅助资料汇报类型；
  - 可以显示不同的汇报类型下的岗位汇报体系。
    
 =====2.2 岗位 =====
  - 默认为空；
  - 支持F8选择，查看岗位信息的情况；


====== 3 功能操作 ======
=====3.1 添加岗位 =====
  - 调出新增岗位界面；
  - 可以在当前汇报类型下，以及所选的岗位节点下新增岗位；
  - 岗位的上级编码和上级名称不可编辑，回填所选的岗位节点信息；
  - 支持增加多个岗位；
  - 岗位的创建组织=当前登录组织；如果是跨组织创建岗位，需要切换登录组织后，再添加岗位；
  - 岗位的使用组织=当前登录组织，支持手工调整；

=====3.2 删除岗位 =====
  - 删除选中的岗位；
  - 删除后刷新岗位汇报体系；

=====3.3 引入下级 =====
  - 可以在当前岗位节点直接从岗位信息列表中引入下级，不用在岗位中调整上级关系；
  - 支持引入多个下级岗位；


=====3.4 调整汇报关系 =====
  - 通过调整汇报关系可以直接调整选中岗位的上级岗位，不用再到岗位中调整；
  - 调整汇报关系后，刷新岗位汇报体系； 

=====3.5 添加任岗信息 =====
  - 通过添加任岗信息，可以直接新增员工，并选择岗位信息；
  - 添加后可以在对应的岗位节点看到所属的员工；

## 【页面】应用性能监控日志
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E7%94%A8%E6%80%A7%E8%83%BD%E7%9B%91%E6%8E%A7%E6%97%A5%E5%BF%97

====== 1 功能概述 ======

企业的信息化系统在日常使用过程中，难免会碰到性能变慢的情况发生。分析此类问题时，需要考虑客户端、服务端、数据库、网络环境等多方面的可能性，分析过程往往耗时非常长，投入的人力、物力也较大。
通过实时性能监控，可以快速的拆解业务操作的后台调用情况，准确定位性能瓶颈点，有助于高效分析性能问题。

====== 2 操作步骤 ======

  - 选择具有性能问题的入口单据页签，同时按住Ctrl+Alt+Shift+M（4个键）开启性能监控工具栏。
  - 点击“开启监控”后，当前页面及该页面中所有操作打开的相关页面都会纳入监控范围。
  - 操作过程中随时可以点击查看报告，查看实时性能监控所记录到的每一次交互下的服务端方法调用情况。
  - 操作完毕点击“停止”，避免产生不必要的日志记录。退出、注销、超时等情况系统会自动停止监控。
  - 如果有其他不具有相关的页面需要开启监控，可以从搜索、全部功能等方式打开对应单据，再次通过快捷键唤起性能监控工具栏，开启监控。

====== 3 操作说明 ======
按住Ctrl+Alt+Shift+M（4个键）开启性能监控工具栏，注意，如果出现查看不到监控报告，可检查：

1、列表监控时，可以先打开列表界面，点击列表上的行或字段标题（获取一个焦点），然后再按住Ctrl+Alt+Shift+M（4个键），可以开启对列表的监控（包括列表上做操作弹出界面都会进行监控）。
如果您看到的监控界面标题是主控台的，说明这个已经打开的列表界面不在监控范围内，系统是识别到主控台开启监控，需要重新打开新窗口。

[图:性能监控面板.png]

2、需要检查计算服务站点是否已启用。

[图:计算站点.png]

3、检查计算站点的配置，可以在common配置文件中查看（有时可能是common配置设置了不正确的地址）。

[图:common计算站点配置.png]

4、开启监控后，录制单据操作，查看性能监控报告。（耗时达到1秒以上的方法会逐级加深红色标识）

## 【页面】执行计划日志
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%89%A7%E8%A1%8C%E8%AE%A1%E5%88%92%E6%97%A5%E5%BF%97

====== 1 功能概述 ======

记录执行计划过程中各项服务的执行情况，以备系统管理员查看，同时还提供了自动清理，减少日志记录的表空间占用。

**功能路径**

Administrator用户登录数据中心，打开日志管理。

**启用步骤**

金蝶AI星空V7.1以上版本已提供为业务数据中心单独创建日志库的功能，将业务数据中心与日志的存储分离。日志库创建与注册可以参考[[数据中心|数据中心]]管理的介绍。
  - 登录管理中心→进入数据中心列表→选择业务数据中心，创建或注册日志库（根据是否创建过日志库选择对应方式）
  - administrator用户登录业务数据中心，进入【基础管理-公共设置-参数设置】，日志管理节点开启对应日志的记录。

====== 2 字段说明 ======
  - 创建人：日志产生的当前操作人。
  - 创建人编码：日志产生的当前操作人对应编码。
  - 任务编号：后台记录的执行计划任务编号。
  - 任务名称：执行计划名称。
  - 开始执行时间：开始执行的时间点。
  - 结束执行时间：结束执行的时间点。
  - 总耗时间：执行的耗时。
  - 执行状态：分为正常和异常。
  - 日志类型：分为错误日志、业务日志、调试日志。
  - 跟踪码：后台生成的跟踪码。
  - 日志内容：记录本次执行的详细情况。

====== 3 功能说明 ======

**过滤**
  - 显示所有组织的操作日志记录；
  - 操作日志按照开始执行时间的降序显示；
  - 系统预置了“今天”和“本月”的查询方案，以便用户直接使用。

**删除**

  - 删除执行计划日志记录。

**日志启用**
  - 【公共设置-参数设置-日志管理】，可以设置日志启用及记录范围。
  - 记录类型：错误日志强制记录，业务日志与调试日志允许用户选择。
  - 记录范围：默认选择执行计划，由用户在下方列表设置对哪些执行计划进行监控。

**自动清理**
  - 【公共设置-参数设置-日志管理】，可以设置日志自动清理规则。
  - 通过设置日志保留天数及保留类型，对于保留范围之外的日志进行自动清理。

## 【页面】数据归档任务
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E5%BD%92%E6%A1%A3%E4%BB%BB%E5%8A%A1

====== 1 概述 ======

部分企业的业务单据流水特别大，单表数据量超过千万级，因数据量过大影响到正常业务操作性能。而且，业务已经结束，仅有读的需求，没有写数据的需求。此时，暂不希望进行账套结转处理，想要进行分离存储，特殊必要时进行反向恢复。

====== 2 系统特性 ======

入口：【系统管理】-【数据归档】。

相关特性如下：

  * 向导方式创建归档任务；

  * 采用分表方式归档数据；

  * 提供归档任务跟踪与日志记录；

  * 预置两张标准产品单据：销售出库单、应付单，包含相关后台表的数据同步归档。

====== 3 功能说明 ======

===== 3.1 风险须知 =====
数据归档功能，主要用于将业务上已经完结的历史数据迁移到单独的归档表，减轻正式表的数据量，改善业务性能。 关于数据归档功能及迁移后的影响说明，如下： 

  - 列表查询将不显示已归档迁移的数据。 
  - 报表查询将不显示已归档迁移的数据，标准报表将在查询到已归档的数据时进行提醒，告知操作人员查询的范围内存在已归档的数据，不会被报表统计查询。  
  - 上查、下查、全流程跟踪、业务流程图的流程数据不会进行归档迁移，因此，如果联查到已迁移的历史数据，关联节点会显示但实际打开列表不会显示已归档数据。  
  - 归档单据的编码规则若开启手动补号、自动补号功能时，补号运算不会读取归档表的数据。建议编码规则考虑使用日期字段作为编码依据，避免已归档数据未纳入范围而影响补号计算结果。 
  - 数据归档操作不可逆，不允许反归档，请仔细阅读说明，确认业务需求后再实行。 
  - 如果存在按组织拆分、数据清理、数据结转的业务需求，不属于本功能覆盖范畴。可考虑购买金蝶专项服务，通过其他的服务工具配合专人服务方式实现。【参见[[https://www.kingdee.com/services/concentrate|金选成功服务]]】

应收单业务说明：

  - 归档操作：是针对指定日期及其之前所有期间的所有组织的业务单据发起归档； 
  - 归档成功后，已归档期间的业务单据不再支持直接在单据列表查询显示； 
  - 归档成功后，已归档期间的报表查询结果可能受影响，如：不支持查询归档期间数据； 
  - 归档成功后，不允许再反结账、反初始化等操作；

销售出库单业务说明：

  - 启用库存的库存组织最后关账日期需要大于等于归档截止日期；启用存货核算的核算组织最后关账日期需要大于等于归档截止日期； 
  - 标准销售业务按销售出库单业务日期归档，且已生成凭证并完全应收，应收单收款核销状态=完全； 
  - 包含有套件父项或套件子项的销售出库单不归档，直运销售出库单、寄售销售出库单不进行归档，VMI销售出库单需要进行VMI消耗结算后才能归档； 
  - 归档后出库单数据移至归档表，原出库单列表不再显示归档的出库单，在查询销售报表时，将查询不到已被归档的销售出库单相关数据； 
  - 归档后库存报表可查询范围将受到限制，查询条件的起始日期小于等于归档日期则查询结果缺少被归档的销售出库单，涉及计算期初数量的库存报表要求查询条件的起始日期大于归档日期后的最近一次库存关账日期； 
  - 归档后库龄计算统计年限将受到限制，库龄计算要求执行日期减去统计年限的日期大于归档日期；库存账龄分析表要求查询日期大于归档日期后的最近一次库存关账日期； 
  - 归档后库存反关账不允许反关账后的最后关账日期小于归档日期； 
  - 归档后批号/序列号主档追踪信息将无法联查已被归档的销售出库单； 
  - 归档后，信用重算起始日期不能早于归档日期。

===== 3.2 操作步骤 =====
1 选择业务对象。
目前预置2张标准产品单据：应收单、销售出库单；

2 设置归档期间。
  * 每个一个业务对象会在后台绑定一个归档规则设置，归档规则中会定义归档日期字段在每个业务对象上的映射字段，通常是绑定业务日期字段。
  * 选择会计日历及会计期间，表示取该会计期间的截止日期作为归档日期，将小于等于归档截止日期的数据全部归档。
  * 确定截止日期后，点击执行检测，系统会对业务对象的已有数据状况进行检查。必须满足系统检查要求，全部显示检查通过的业务对象才允许继续进行归档。

3 设置执行时间。
由于归档的数据量可能非常庞大，短时间内可能无法归档完毕。因此，系统采用定时执行方式，利用系统闲置时间段处理大量归档数据，并采用分批取数：
  * 每次取一批数据，按日期升序取数，先取早期数据归档。
  * 处理完一批再获取下一批，如果中间因环境因素（重启、断电等）导致执行异常，需等待若干小时通过异常恢复方式进行调用。

4 数据归档任务列表。
任务创建成功后，可以打开任务详情查看执行情况。打开任务详情界面查看，了解任务的运行情况：
  * 启用：启用的任务是准备状态。
  * 暂停：启用的任务可以暂停不执行。暂停任务可点击【启用】操作。
  * 终止：误配置的任务，可以终止不执行。终止任务不可以【启用】。
  * 注意：创建新的归档任务时，必须对应的业务对象归档任务已完成或终止，避免同一个业务对象启动多个归档任务造成异常。

## 【页面】数据权限
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E6%9D%83%E9%99%90

====== 1 功能描述 ====== 
数据权限是基于有功能权限内容的进一步数据范围控制，以缩小关键数据范围，从而保证敏感数据的安全性。

**使用前提**
具备当前业务对象的功能权限。例如：查看、新增等。

**功能路径**
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→数据范围
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→基础资料权限

 ====== 2 字段说明 ======
=====2.1 数据范围 =====

  - 数据范围支持的权限项：查看、修改、删除、审核。
  - 调出数据规则列表进行选择；也可以选择当前业务对象的单据头字段设置新的数据规则；
  - 在设置数据规则时，可以利用业务对象提供的变量，以减少数据规则方案的数量；目前提供的变量有：当前组织（组织属性字段）、当前用户（用户属性字段）、当前用户对应的部门、当前用户对应的业务组、当前用户对应的业务员；
  - 数据范围应用只对单一对象有效，不支持联动控制机制；例如：销售订单的查看时，不会调用销售订单所引用客户基础资料设置的查看数据规则（查看华南区客户）进行筛选，而是使用销售订单查看权限设置的客户查看数据规则（查看珠三角客户）进行处理；
  - 数据规则默认不支持单据体字段的设置，例如：物料、仓库等；
  - V7.6新增参数“单据列表启用单据明细数据权限控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后在数据规则设置时可以选择到单据体字段（只支持单个单据体），单据列表只显示有权限的单据明细行，查看、编辑单据明细数据不做控制。
  - V7.7新增参数“存在无权单据明细不能打开单据”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置哪些单据需要控制，则打开单据时会校验只要存在一行明细没有权限则不允许打开单据。
  - V7.7新增参数“基础资料数据范围联动应用到业务对象”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置基础资料对应哪些业务单据的哪个字段受控，则设置基础资料数据范围后，关联受控的业务单据只能看到有权限的基础资料对应单据。可同时控制单据头和单据体。
  - V7.7新增参数“报表的基础资料数据权限由报表本身的基础资料数据范围控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后报表数据权限完全按照报表的基础资料数据范围控制。
  - V8.2新增“基础资料数据直接授权”，直接选择需要授权的基础资料数据，授权给相关员工及关联的用户，来实现基础资料快速灵活的授权。目前支持直接授权的基础资料包括：物料、供应商、客户、仓库。功能路径：【基础资料列表】→【业务操作】→【数据直接授权】。

  
=====2.2 基础资料权限=====
  - 此处设置的数据范围，只对当前业务对象新增时有效，且影响该基础资料F8界面展示的数据行数；
  - 显示当前业务对象引用的基础资料列表；
  - 支持单据类型的数据范围，数据规则配置时先要确定单据类型的单据，再选择具体的单据类型；
  - 支持选单的数据范围，影响业务单据新增时，选单的范围；
  - 在数据规则选项勾选了【联动应用基础资料本身的查看数据范围】，则业务单据新增时，基础资料的F8界面优先取基础资料权限设置的数据范围，如没有设置则取该基础资料本身的查看数据范围。
  - V7.7新增在数据规则选项勾选了【基础资料数据范围联动应用到业务对象】，设置基础资料关联业务对象的受控字段，则只能查看有权限的基础资料业务单据。
=====2.3 分组数据权限=====
  - 支持对业务对象新增“分组”权限项，可针对分组设置分组权限数据规则；
  - 分组权限默认只对分组树查看范围有效，如勾选了【分组数据应用到列表数据范围】，则对数据查看范围也有效；
  - 分组也可应用到F8选择，应用规则和列表数据的应用规则一致；
  - 分组可从不同维度设置分组数据规则，多个分组维度同时设置，则数据取交集。
 ====== 3 功能操作 ======
=====3.1 批量应用数据规则 =====
  - 主要便于该数据规则的快速应用，减少多次选择；
  - 在权限项，例如：销售订单的查看，选择数据规则（华南区客户）后，如果其他权限项以及其他角色都是使用该数据的，则可以在当前行点击【批量应用数据规则】，系统调出批量应用的界面，支持选择其他角色，以及当前角色的其他权限项；
  - 执行批量应用，系统自动将数据规则回填所选用户的所选权限项。

====== 4 业务说明 ======
=====4.1数据规则应用 =====
**单据新增**     单据新增时，单据上的基础资料F8范围优先取该单据基础资料权限设置的数据范围，如没有设置则取基础资料本身的查看范围；
     例如：新增采购订单时，单据上部门的F8选择范围，优先取采购订单基础资料权限设置的部门查看范围，若没有设置则取部门基础资料本身的查看范围。

**单据操作**   单据查询、修改、删除、审核应用对应权限对应的数据范围进行显示。    
    例如：一部采购员只能查看一部门的采购订单，在采购订单查看权限的数据范围中设置【部门名称=“一部门”】的数据规则即可。

**变量应用**   需要根据用户的一些身份或者其他一些条件隔离，例如：我的业务单据，我所属部门的业务单据，我所在业务组的业务单据
   设置方案：
   1）可以使用业务单据的字段对应的变量进行设置，例如：我的销售订单（业务单据=销售订单，字段=创建人，比较=当前用户）
   2）供应链提供业务员和业务组隔离的选项设置，选择后系统按照用户对应职员所属的业务员或者业务组进行隔离处理，无需通过数据规则处理（前提：用户必须设置对应的职员信息）。

## 【页面】数据瘦身
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E7%98%A6%E8%BA%AB

======1 数据瘦身概述 ======

===== 1.1 数据瘦身概述 =====
 
金蝶云系统运行一段时间后，数据库日渐庞大，金蝶云推出数据瘦身服务，通过订阅实现数据库优化、临时表和日志的清理，缩小数据库的容量。

===== 1.2 系统特性 =====
 
本系统主要包含以下应用：

  - 金蝶云自动计算数据的冗余情况，达到预警状态，则推送数据瘦身服务及预警消息；
  - 数据瘦身服务订阅后可以使用；
  - 支持数据库临时表、操作日志、监控消息等清理；
  - 提供数据瘦身报告；
  - 定期瘦身可以减少过时的数据，提升系统运行速度。
 
====== 2 数据瘦身操作手册 ======

===== 2.1 金蝶云推送数据清理服务 =====

系统运行一段时间后，若不进行定期的清理，会产生太多的冗余数据，数据库会越来越大，影响系统运行。

金蝶云系统会自动智能判断客户系统当前系统的冗余情况，当冗余数据达到预警状态，则推送【数据清理】预警消息。


===== 2.2 订阅数据瘦身服务 =====

当前系统达到预警状态，右下角显示金蝶云消息：

金蝶云检查到当前数据中心数据量已超（*）GB，赶快订阅数据瘦身服务，给数据中心来一次全面瘦身，让数据中心轻盈灵动。点击【了解更多】则可以进入数据瘦身向导界面。

在数据瘦身向导界面，点击【我要订阅】后就可以启用并使用数据瘦身服务了。


【温馨提示】

若管理员已订阅数据瘦身服务，当前系统达到预警状态，右下角显示金蝶云消息：

金蝶云检查到当前数据中心数据量已超（*）GB，建议进行数据瘦身，降低数据中心的容量， 点击【启动数据瘦身】，则可以进入数据瘦身向导界面开始清理。


===== 2.3 数据清理过程 =====


==== 2.3.1 备份数据库 ====

数据清理前，需要备份好待清理的数据库。

==== 2.3.2 定制清理规则 ====

定制清理规则确保能保留最近多少个月的数据备查，历史记录将全部清理。

Administrator登录后，可以通过路径打开：【系统管理】->【系统管理】->【数据瘦身】->【瘦身规则】

数据清理规则目前包括上机操作日志、监控执行情况、分配执行情况、临时表、批改日志设置。

**上机操作日志清理规则**

  - 业务背景：主要是操作日志随着数据中心的长期使用，数据量不断增长，造成金蝶云数据库膨胀，对使用性能有很大的影响。
  - 功能描述：通过日志清理，将操作日志移出金蝶云数据库，缩小占用空间，并将其用EXCEL形式备份到指定路径下，以便进行备查；
  - 支持设置清理规则，把上机操作日志清理到文件服务器（要求已做文件服务器配置）；
  - 备份文件路径：指定应用服务器所在的文件路径，要求当前操作系统用户对该文件夹有读写的权限；
  - 备份文件格式：以EXCEL格式备份，要求应用服务器必须安装EXCEL才可以打开；
  - 备份文件名称：后缀标明yyyymm内容；
  - 清理日志范围：清理时保留最近（1-24）个月的上机操作日志，清理其余相关日志；
  - 注意：此处清理是人工干预的清理，按约定保留时间范围的内容先备份再清理，系统不会定期执行。


**监控执行情况清理规则**

  - 业务背景：清理监控执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过监控执行情况清理，可以按设置的时间维度规则，清理监控执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：监控执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

**分配执行情况清理规则**

  - 业务背景：清理分配执行情况相关日志，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过分配执行情况清理，可以按设置的时间维度规则，清理分配执行情况列表和监控执行情况历史记录列表相关数据；
  - 清理日志范围：清理时保留最近（1-24）个月的业务监控日志，清理其余相关日志；
  - 注意：分配执行情况的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。


**临时表清理规则**

  - 业务背景：业务运行过程中产生的临时表，用完后标识未可删除状态，这部分临时表可以直接删除，减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过临时表清理，可以按设置的时间维度规则，清理已标记为可删除的临时表相关数据；
  - 清理日志范围：清理时（4-24）小时前生成的临时表；
  - 注意：临时表的清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询，一般情况下，临时表生成超过4个小时，可以做删除，不建议设置成更小的值，避免还在使用的临时表被删除。


**批改日志清理规则**

  - 业务背景：业务进行批改时记录日志数据，对历史比较久远的日志可以进行清除，以减少数据中心的数据量，避免过多无用的历史日志占用服务器空间资源。
  - 功能描述：通过批改日志清理，可以清除历史久远的批改日志数据；
  - 注意：批改日志清理是直接清理，不生成备份文件，清理后满足清理规则的历史日志将无法查询。

==== 2.3.3 使用清理向导 ====

使用清理向导，定制清理服务，选择清理项，执行时间和时长限制，勾选清理高级选项，以确保清理过程少产生日志。

进入清理向导，首先看到的是清理前的温馨提醒信息，并可以查看设置[[云瘦身#数据清理过程|清理瘦身规则]]，接着按向导步骤及流程执行。

第一步：

  - 系统会自动计算当前数据中心的的空间占用情况，并预估可清理空间大小；
  - 确定清理方案名称；
  - 根据需要选择清理项目，包括上机操作日志清理、监控执行情况清理、分配执行情况清理、临时表清理、批改日志清理
  - 注意：确保所有清理项目已经设置好[[云瘦身#数据清理过程|清理瘦身规则]]，特别是上机操作日志备份路径不能为空。另外所选清理项中至少有一个选项的清理空间大于0，否则不能建立清理计划。

第二步：

  - 确定清理时间和清理时长，可以选择立即执行，但是数据清理尽量选择在业务空闲期间执行；
  - 勾选选项【清理任务执行时，恢复模式修改为简单】，这样可以大大减少日志产生，避免日志文件过度膨胀；
  - 勾选选项【数据后，收缩数据库】，，以便回收数据文件占用空间，注意此过程耗时较长；
  - 点击下一步，进行瘦身清理计划确认。

第三步：

  - 清理参数确认，包括清理时间、清理时长限制等；
  - 已选清理项确认；
  - 点击下一步，确认保存瘦身清理计划，可打开瘦身服务清理执行情况查看结果。


==== 2.3.4 查看执行情况 ====

查看清理执行情况，查看清理后，各个清理项数据量和清理存储空间的释放情况、完成时间、状态以及相关描述。

查看路径：

1、数据瘦身向导执行完后，在最后一步可以点击【查看执行结果】查看；

2、可以通过路径打开：【系统管理】→【系统管理】→【数据瘦身】→【数据瘦身执行情况】 。


===== 2.4 相关说明 =====

用户订阅后，HTML5的更多服务卡片中会自动增加【数据瘦身】入口，方便操作；

若编辑卡片时，删除【数据瘦身】，将会停用瘦身清理服务。

## 【页面】数据规则选项
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E8%A7%84%E5%88%99%E9%80%89%E9%A1%B9

数据权限是基于有功能权限内容的进一步数据范围控制，以缩小关键数据范围，从而保证敏感数据的安全性。

**使用前提**
具备当前业务对象的功能权限。例如：查看、新增等。

**功能路径**
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→数据范围
【系统管理】→【系统管理】→【授权】→【业务对象功能授权】→基础资料权限

 ====== 2 字段说明 ======
=====2.1 数据范围 =====

  - 数据范围支持的权限项：查看、修改、删除、审核。
  - 调出数据规则列表进行选择；也可以选择当前业务对象的单据头字段设置新的数据规则；

  - 数据范围应用只对单一对象有效，不支持联动控制机制；例如：销售订单的查看时，不会调用销售订单所引用客户基础资料设置的查看数据规则（查看华南区客户）进行筛选，而是使用销售订单查看权限设置的客户查看数据规则（查看珠三角客户）进行处理；
  - 数据规则默认不支持单据体字段的设置，例如：物料、仓库等；
  - V7.6新增参数“单据列表启用单据明细数据权限控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后在数据规则设置时可以选择到单据体字段（只支持单个单据体），单据列表只显示有权限的单据明细行，查看、编辑单据明细数据不做控制。
  - V7.7新增参数“存在无权单据明细不能打开单据”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置哪些单据需要控制，则打开单据时会校验只要存在一行明细没有权限则不允许打开单据。
  - V7.7新增参数“基础资料数据范围联动应用到业务对象”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选参数并且设置基础资料对应哪些业务单据的哪个字段受控，则设置基础资料数据范围后，关联受控的业务单据只能看到有权限的基础资料对应单据。可同时控制单据头和单据体。
  - V7.7新增参数“报表的基础资料数据权限由报表本身的基础资料数据范围控制”，参数路径：【系统管理】→【权限基础设置】→【数据规则选项】。勾选后报表数据权限完全按照报表的基础资料数据范围控制。
  
=====2.2 基础资料权限=====
  - 此处设置的数据范围，只对当前业务对象新增时有效，且影响该基础资料F8界面展示的数据行数；
  - 显示当前业务对象引用的基础资料列表；
  - 支持单据类型的数据范围，数据规则配置时先要确定单据类型的单据，再选择具体的单据类型；
  - 支持选单的数据范围，影响业务单据新增时，选单的范围；
  - 在数据规则选项勾选了【联动应用基础资料本身的查看数据范围】，则业务单据新增时，基础资料的F8界面优先取基础资料权限设置的数据范围，如没有设置则取该基础资料本身的查看数据范围。
  - V7.7新增在数据规则选项勾选了【基础资料数据范围联动应用到业务对象】，设置基础资料关联业务对象的受控字段，则只能查看有权限的基础资料业务单据。
=====2.3 分组数据权限=====
  - 支持对业务对象新增“分组”权限项，可针对分组设置分组权限数据规则；
  - 分组权限默认只对分组树查看范围有效，如勾选了【分组数据应用到列表数据范围】，则对数据查看范围也有效；
  - 分组也可应用到F8选择，应用规则和列表数据的应用规则一致；
  - 分组可从不同维度设置分组数据规则，多个分组维度同时设置，则数据取交集。
 ====== 3 功能操作 ======
=====3.1 批量应用数据规则 =====
  - 主要便于该数据规则的快速应用，减少多次选择；
  - 在权限项，例如：销售订单的查看，选择数据规则（华南区客户）后，如果其他权限项以及其他角色都是使用该数据的，则可以在当前行点击【批量应用数据规则】，系统调出批量应用的界面，支持选择其他角色，以及当前角色的其他权限项；
  - 执行批量应用，系统自动将数据规则回填所选用户的所选权限项。

====== 4 业务说明 ======
=====4.1数据规则应用 =====
**单据新增**     单据新增时，单据上的基础资料F8范围优先取该单据基础资料权限设置的数据范围，如没有设置则取基础资料本身的查看范围；
     例如：新增采购订单时，单据上部门的F8选择范围，优先取采购订单基础资料权限设置的部门查看范围，若没有设置则取部门基础资料本身的查看范围。

**单据操作**   单据查询、修改、删除、审核应用对应权限对应的数据范围进行显示。    
    例如：一部采购员只能查看一部门的采购订单，在采购订单查看权限的数据范围中设置【部门名称=“一部门”】的数据规则即可。

**变量应用**   需要根据用户的一些身份或者其他一些条件隔离，例如：我的业务单据，我所属部门的业务单据，我所在业务组的业务单据
   设置方案：
   1）可以使用业务单据的字段对应的变量进行设置，例如：我的销售订单（业务单据=销售订单，字段=创建人，比较=当前用户）
   2）供应链提供业务员和业务组隔离的选项设置，选择后系统按照用户对应职员所属的业务员或者业务组进行隔离处理，无需通过数据规则处理（前提：用户必须设置对应的职员信息）。

## 【页面】新增单据防重配置
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%96%B0%E5%A2%9E%E5%8D%95%E6%8D%AE%E9%98%B2%E9%87%8D%E9%85%8D%E7%BD%AE

﻿
====== 1 概述 ======

异构系统接入星空业务单据涉及支付需要设置唯一索引，通过“新增单据防重配置”实现指定字段的唯一索引管控。

====== 2 操作入口 ======

入口：系统管理-其他，打开【新增单据防重配置】。

====== 3 功能说明 ======

  - 仅允许选择【单据】对象。
  - 一个业务对象最多允许创建2条防重管控配置（即 最多2个字段进行唯一性管控），创建后是分开各自校验唯一性，不是多个字段组合唯一性管控。
  - 同一个业务对象不允许重复使用相同的校验字段。同一个业务对象最多设置2个不同的校验字段。
  - 内置执行计划“新增单据防重复表的历史数据清理”，将自动清理1年（365天）之前的防重表记录，避免大量历史记录占用存储空间或影响系统性能。
  - 详细功能说明，见下面表格。

| 检验字段            || 1、仅允许选择单据头的“文本”类型字段，表示该字段作为唯一性判断的校验字段。2、配置保存后，将依据 【单据+检验字段】生成对应防重管控记录表。3、新增单据保存时，将“检验字段”纳入唯一性管控，避免并发新增时重复生成。4、注意：谨慎使用单据编号字段作为校验字段，如果作为校验字段，建议配合勾选“WebAPI必录”使用，由第三方系统传入单据编号。必须避免通过星空系统编码规则自动生成单据编号，因自增长流水号生成多个不同编码的单据（实际属于第三方的同一笔业务），达不到防止并发重复创建的管控目的。  |
| 为空不校验           || 1、默认表示为空是校验的，包括1个或多个空格也视作空值。例如，传入2个单据的校验字段都是空值，则视作不满足唯一性，第2张单据新增保存失败。2、若勾选“为空不校验”，则校验字段的值为空时，忽略不校验（即 不记录空值到防重管控表）。                                                                                                                                     |
| WebAPI必录        || 默认勾选，表示有防重管控要求的校验字段，建议在WebAPI接口必录，需传入第三方业务的唯一号。                                                                                                                                                                                                        |
| 附加说明            || 1、异构系统接入星空业务单据涉及支付必须设置唯一索引，以防并发导致数据重复。2、仅对新建配置之后的新增单据数据进行管控，历史已保存数据不进行管控。更换校验字段，需要创建新配置。3、系统预置的单据防重配置不允许删除，企业自建的单据防重配置允许删除。4、单据删除、作废操作，将按检验字段值移除防重表记录。5、新增单据保存、修改校验字段值保存单据、反作废操作，将同步更新防重表记录。                                                           |

## 【页面】用户子系统权限报表过滤
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%94%A8%E6%88%B7%E5%AD%90%E7%B3%BB%E7%BB%9F%E6%9D%83%E9%99%90%E6%8A%A5%E8%A1%A8%E8%BF%87%E6%BB%A4

====== 1 功能描述 ====== 
用户子系统权限报表主要从用户和子系统维度来查询用户的组织+子系统+权限组+角色的情况，即展示用户具有哪些子系统的哪些权限，是由哪个组织下的哪个角色带来的，便于管理员对用户的功能权限进行有效管控和综合分析。

**功能路径**
【系统管理】→【系统管理】→【权限报表】→【用户子系统权限报表】

 ====== 2 字段说明 ======
  - 用户：符合查询条件的用户名称；以名称升序展示；
  - 业务领域：子系统所属的业务领域
  - 子系统：符合查询条件的子系统名称
  - 权限项组：子系统授权的权限组名称；
  - 权限状态：权限项组的状态，分为：有权、无权、禁止；默认查询有权状态；
  - 角色：显示当前子系统权限是由哪个角色所带来的；
  - 组织编码/组织名称：显示子系统权限是由哪个组织带来的。

 ====== 3 功能操作 ======
===== 3.1 查询 =====
  - Administrator用户查看全部用户数据，非Administrator默认显示当前组织下的用户子系统权限数据；
  - 同一个权限组有多行数据，是因为用户的多个角色都有相同权限组的情况；
  - 建议查询时，尽量设置过滤条件，以减少查询数据，避免对服务器的性能带来影响；
  - 预置了【按权限组】的查询方案，可以直接按照选择的权限组名称查看用户的子系统权限情况。
	
===== 3.1 子系统功能授权 =====
通过用户的子系统权限报表，发现某个角色的子系统权限有问题，可以直接对报表选中行次的角色进行子系统功能授权，减少重复选择主控台菜单的操作。

====== 1 系统管理概述 ======
===== 1.1 概述 =====
系统管理既是系统运行的基础，又是支撑业务运作的基石。主要功能有：用户管理、角色管理、权限管理、上机操作日志等。

===== 1.2 系统特性 =====
本系统主要包含以下特性：

  - 多角度权限控制，搭建立体权限体系：对角色的授权设置，结合用户和组织的权限控制，提供从功能、数据以及字段上的权限控制，加上多维度的批量处理，并辅以管理报表的查询，搭建多角度的立体权限体系，且关注权限的分布以及合理性。
  - 角色驱动的业务应用：用户根据授予角色权限展示主控台界面、菜单以及业务应用，用户可方便快捷的开展业务。
  - 用户灵活创建，全面支持：支持追加模式批量分配角色；提供密码策略对用户密码统一控制；关注用户与职员之间的关系、用户的综合情况以及操作系统的情况。

## 【页面】系统管理使用流程
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%B3%BB%E7%BB%9F%E7%AE%A1%E7%90%86%E4%BD%BF%E7%94%A8%E6%B5%81%E7%A8%8B

系统管理操作流程：

====== 第一步 登录数据中心 ======
数据中心创建后，默认系统管理员用户，用户名：Administrator（SQL Server下Administrator不区分大小写，Oracle下必须是Administrator，区分大小写且要求首字母大写）。

====== 第二步 建立组织体系 ======
数据中心创建后默认单体组织应用模式，若企业需支持多组织业务，要先启用多组织，然后再创建业务组织体系。

  - 业务组织体系是多组织应用的基础，主要包括组织机构、隶属关系、业务关系等。
  - 进入【系统管理】→【系统管理】→【组织机构】，可以建立组织相关内容，详见组织机构介绍。

====== 第三步 建立角色体系 ======
建立角色体系
  - 系统中已经根据岗位预置了角色，且赋予对应权限，可直接使用。
  - 角色属性分为公有和私有两种，公有角色可以用于所有组织，私有角色只能用于某个指定的组织，只有Administrator可以建立公共角色。
  - 角色类型分为系统管理员和普通角色两类，管理员可建立普通角色并对普通角色授予功能权限，也可以建立系统管理员角色并对系统管理员角色设置授权范围，以便于约束系统管理员的管理权限。
  - 进入【系统管理】→【系统管理】→【角色管理】，可以建立角色相关内容，详见角色管理介绍。
  - 
====== 第四步 建立用户体系 ======
建立用户体系
  - 用户是金蝶云的操作人员;
  - 建立用户后，首先要指定组织，再分配角色，支持批量操作。
  - 进入【系统管理】→【系统管理】→【用户管理】，可以建立角色相关内容，详见用户管理介绍。

====== 第五步 建立权限体系 ======
  - 根据角色进行授权，提供了功能授权、批量功能授权、字段授权等多种授权方式，以满足不同组织机构对用户的不同要求。
  - 多个维度提供了权限报表，方便管理员查询和分析。
  - 进入【系统管理】→【系统管理】→【授权】，可以进行功能授权，详见授权介绍。
  - 进入【系统管理】→【系统管理】→【批量授权】，还可以进行批量功能授权，详见批量授权介绍。
  - 进入【系统管理】→【系统管理】→【授权】→【字段授权】，还可以进行字段授权，详见字段授权介绍。
  - 进入【系统管理】→【系统管理】→【权限报表】，还可以查询权限报表，详见权限报表介绍。

金蝶云的角色既是用户的职责体现，同时也是权限的载体，起到很重要的桥梁作用。

功能路径：【系统管理】→【系统管理】→【角色管理】 

 ====== 2 字段说明 ======
=====2.1 角色类型 =====
角色属性分为：普通角色（默认）、系统管理员

**角色类型=普通角色**
  - 可以进行授权管理，点击工具栏【业务对象功能授权】进行授权。详见业务对象功能授权。
  - 可以查询权限，点击工具栏【查询权限】，则打开“角色业务对象权限报表”查看该角色的功能权限。详见角色业务对象权限报表。
    
**角色类型=系统管理员**
  - 也就是子管理员，不需要进行授权管理，自动具有系统管理的功能；
  - 可以设置授权范围，点击工具栏【设置授权范围】进行设置；
  - 设置了授权范围后，具有该角色的用户在给角色授权时不能超出授权范围。

=====2.2 角色属性 =====
  - 在启用多组织后才显示；
  - 角色属性分为：公有、私有
  - 属性=公有 1）则该角色在全部组织（包括新增组织）均可使用；  2）具有系统管理员角色类型的用户均可使用；3）只有Administrator用户才可以创建和维护
  - 属性=私有 1）选择私有属性，则必须指定组织，且该角色只能在指定组织下使用； 2）只有指定组织下的系统管理员用户才可以使用；3）Administrator和具有系统管理员角色的用户均可创建，Administrator和在指定组织下的具有系统管理员角色的用户均可维护；
  - 角色属性在角色保存后不可修改。

=====2.3 所属组织 =====
  - 在启用多组织后，且角色属性=私有才激活；
  - 默认携带当前登录组织，可以选择当前登录用户的组织范围内的组织；
  - 只能选择一个组织。

=====2.4 其他字段 =====
  - 编码、名称：为必录；均控制唯一性；
  - 用户列表：用户选择角色后回填的信息，可以查看当前角色有哪些用户使用。支持删除用户。

====== 3 功能操作 ======
=====3.1 复制=====
  - 复制角色的内容，但是编码、名称、用户信息除外；
  - 复制时，同时复制该角色具有的权限。

=====3.2 修改=====
  - 除角色类型、角色属性和用户信息外，其他内容均可修改；
  - Administrator可以修改任一角色；
  - 具有系统管理员的用户只能修改角色属性=私有且所属组织在自己组织范围内的角色。

=====3.3 禁用 =====
  - 角色禁用后，已经分配该角色的用户不可应用其具有的权限；
  - 反禁用后则恢复该权限；
  - 禁用后的角色可以修改、复制和删除。

=====3.4 其他操作 =====
  - 查询: 角色列表默认显示当前用户在当前登录组织下的私有属性角色以及全部的公有属性角色；
  - 新增: 当前用户不是Administrator时，只能新增私有属性的角色；
  - 删除: 角色处于被授权时，也不允许删除；
  - 业务对象功能授权: 可以查看当前角色的功能权限；也可以在此处进行授权，前提是当前用户可以对其进行授权；
  - 查询权限: 调出角色权限列表，可以直观查看角色的功能权限；
  - 引入/引出: 角色支持引入引出，以实现快速录入数据；
  - 网络控制：系统中对角色做了网络控制，不能对同一角色同时进行修改和删除操作。

 ====== 4 业务说明 ======
==== 4.1 预置角色 ====
  - 系统提供了预设角色，同时设置了对应的权限，可以直接使用；
  - 预设角色均是公有角色，只有Administrator才可以修改；
  - 预设角色不可删除，但可以修改；
  - 预置角色在出厂时有权限调整，只会影响新建的数据中心。
  - V7.5新增预置“全功能角色”，包含所有业务功能权限，方便用户查询、体验新功能。
  - V7.5新增预置“全员角色”，功能权限和数据权限为空，勾选参数“自动新增全员角色”后，每次新增用户都会自动加上全员角色。参数路径：【查询角色】→双击进入角色→【选项】

## 【页面】角色业务对象字段权限报表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%A7%92%E8%89%B2%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E5%AD%97%E6%AE%B5%E6%9D%83%E9%99%90%E6%8A%A5%E8%A1%A8

====== 1 功能描述 ====== 
角色和业务对象角度，进行字段权限的审计和查询，查询业务对象所有字段的有权和无权。

**功能路径**
【系统管理】→【系统管理】→【权限报表】→【角色业务对象字段权限报表】

 ====== 2 字段说明 ======
  - 角色名称：符合查询条件的角色名称；以角色升序展示；
  - 业务领域：符合查询条件的业务领域；
  - 子系统：符合查询条件的子系统名称；
  - 业务对象：符合查询条件的业务对象名称；
  - 字段名称：业务对象全部字段名称；
  - 查看权限状态：最终的权限的状态，分为：有权、无权；
  - 编辑权限状态：最终的权限的状态，分为：有权、无权；

 ====== 3 功能操作 ======
===== 3.1 查询 =====
  - 通过多个角色和业务对象和组织机构，快捷过滤字段权限报表；
  - 支持显示有权和无权字段。

## 【页面】角色业务对象权限报表过滤
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%A7%92%E8%89%B2%E4%B8%9A%E5%8A%A1%E5%AF%B9%E8%B1%A1%E6%9D%83%E9%99%90%E6%8A%A5%E8%A1%A8%E8%BF%87%E6%BB%A4

====== 1 功能描述 ====== 
角色业务对象权限报表主要从角色和业务对象的维度来查询角色的业务对象+权限项的情况，即展示角色具有哪些业务对象的哪些权限，便于管理员对角色的具体业务功能权限进行有效管控和综合分析。

**功能路径**
【系统管理】→【系统管理】→【权限报表】→【角色业务对象权限报表】

 ====== 2 字段说明 ======
  - 角色：符合查询条件的角色名称；以名称升序展示；
  - 业务领域：业务对象所属的业务领域
  - 子系统名称：业务对象所属的子系统；
  - 业务对象：符合查询条件的业务对象名称；
  - 权限项：业务对象的权限项名称；
  - 权限状态：权限项组的状态，分为：有权、无权、禁止；默认查询有权和禁止状态。

 ====== 3 功能操作 ======
====== 3.1 查询 ======
  - Administrator用户查看全部角色数据，非Administrator默认显示当前组织下的角色业务对象权限数据；
  - 建议查询时，尽量设置过滤条件，以减少查询数据，避免对服务器的性能带来影响；
  - 预置了【按权限名称】的查询方案，可以直接按照选择的权限项名称查看角色的业务对象权限情况。

====== 3.2 业务对象功能授权 ======
通过角色的业务对象权限报表，发现某个角色的业务对象权限有问题，可以直接对报表选中行次的角色进行业务对象功能授权，减少重复选择主控台菜单的操作。

## 【页面】设置批量授权字段
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%AE%BE%E7%BD%AE%E6%89%B9%E9%87%8F%E6%8E%88%E6%9D%83%E5%AD%97%E6%AE%B5

====== 1 功能概述 ======
管理员可以提前设置常用的批量授权字段有权或者无权，包含：单价、金额、数量、折扣率、折扣额。字段授权的时候，只需要点击【应用批量授权字段】，就可以按照提前设置的批量授权字段的权限状态，更新这个业务对象的字段权限。

**功能路径**
【系统管理】→【系统管理】→【权限基础设置】→【设置批量授权字段】

====== 2 功能说明 ======
字段设置为无权/禁止，则字段授权时该类型字段默认为无权/禁止；

查看设置为无权/禁止，编辑会联动设置为无权或禁止；

基础资料设置为无权/禁止，则字段授权时关联该基础资料的所有业务单据的该字段默认为无权/禁止；

遵循禁止权优先的原则，禁止则无权；

设置完批量授权字段的状态，仅作为设置进行保存，需到字段授权页面，点击应用批量授权字段，字段状态则按照设置的勾选，最终需点击授权才生效；

## 【页面】限流配置情况
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E9%99%90%E6%B5%81%E9%85%8D%E7%BD%AE%E6%83%85%E5%86%B5

====== 功能概述 ======

为确保系统稳定运行，系统针对大数据量操作设有限流管控机制，以平衡资源负载并保障核心业务的高可用性。本页面用于展示当前系统限流配置信息。对于私有化部署和公有云专属租户，可以在系统参数配置页面，结合自身环境的硬件资源条件对默认的限流参数值进行调整。
