====== 付款条件 ======

付款条件主要是用来设置预付比例、到期日计算日期、付款方式及到期日确认方式。

  * 到期日计算日期系统预设为订单日期、入库日期、收料日期和应付单业务日期。用户可以根据企业的实际业务增加单据上的其它日期为到期日计算日期。
  * 付款方式包括：按到期日付款、按订单付款、按物料明细付款三种。
  * 到期日计算需要设定设置标准和确认方式。设置标准可以是比例或者金额；确认方式包括交易日、月结、X天后和固定日四种。
可参考：
     四种到期日确定方式解析说明之一 : 交易日	https://vip.kingdee.com/article/13938
	
    四种到期日确定方式解析说明之二 : X天后	https://vip.kingdee.com/article/13939
		
    四种到期日确定方式解析说明之三 : 月结         https://vip.kingdee.com/article/13941
	
    四种到期日确定方式解析说明之四: 固定日	https://vip.kingdee.com/article/13942


  * 系统预设四种付款条件：货到付款、30天后付款、月结30天和多到期日（按金额）。用户可以根据实际需要，参照系统预设的付款条件进行设置。

====== 价格维护表 ======



====== 1 功能说明 ======


入库单下推应付单时，如果上游单据没有单价，应付单上的物料则也无法携带到单价，可以使用价格维护表预先对物料设置好单价再批量引入到应付单中。

====== 2 操作步骤 ======

  - 新增价格维护表，录入物料价格
  - 选择单据后，点击价格维护，系统将暂存单据中没有价格信息的物料与价格维护表中的数据进行匹配，更新应付单的价格
  - 更新价格后，必录字段完整的单据状态变为创建
  - 更新结束后会提示更新结果

## 【页面】供应商对账单
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%BE%9B%E5%BA%94%E5%95%86%E5%AF%B9%E8%B4%A6%E5%8D%95

====== 1 报表功能 ======

供应商对账单提供应付的原始金额、已付款金额、未付款金额和对应的账龄分析，主要用来传递给供应商进行对账。

====== 2 操作说明 ======

===== 2.1 核销 =====

因为核销会影响报表数据的准确性，因此系统在报表展示界面提供了调用核销的功能。

===== 2.2 账龄分组设置 =====

系统提供用户自定义账龄分组功能。通过该功能用户可以自由定义自己需要报表显示的账龄区间。

===== 2.3 账龄计算标准 =====

账龄计算标准分为按照业务日期计算和按照到期日计算。


===== 2.4 显示选项 =====

报表显示选项包括：

  * 包括未审核单据，默认不勾选
  * 按供应商分页显示，默认勾选
  * 按物料明细显示，默认不勾选


以上选项用户可以根据自己的应用选择。

====== 内部应付清理 ======

====== 1 功能说明 ======


对于组织间交易产生的内部往来，有时候不需要实际的现金支付或者开具发票，年末或者年中统一清理掉。所以应付款管理模块提供了内部应付清理功能，清理后生成相应[[内部应付清理单]]和[[内部应付清理记录]]。

内部应付清理包括无需付款清理和无需开票清理。通过“内部应付清理”可以进入“无需付款清理”界面，在该界面上通过“无需开票清理”按钮进行切换。

===== 1.1 无需付款清理 =====


无需付款清理是指该内部应付单不需要实际的现金支付，用户可以用该功能清理掉，清理时还可以指定应付清理单的业务日期。

清理后可以通过内部应付清理记录查询清理情况，选择清理记录还可以进行反清理。

===== 1.2 无需开票清理 =====


无需开票清理是指该内部应付单不需要实际的开具发票，用户可以用该功能清理掉。

清理后可以通过内部应付清理记录查询清理情况，选择清理记录还可以进行反清理。

====== 应付付款手工核销 ======

## 【页面】应付付款核销

====== 应付付款核销 ======

====== 1 功能说明 ======


应付付款核销包括关联关系核销、匹配条件核销和手工核销。

一般情况下通过关联关系核销、匹配条件核销可以将用户多数的单据核销完毕。手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何的单据核销，但是建议用户仅在需要对单据尾数冲销或者不同往来单位的应付单与付款单、付款退款单核销时才使用。

====== 2 操作说明 ======

===== 2.1 关联关系核销 =====


关联关系是指通过单据转换功能，通过上游单据生成下游单据，在下游单据审核时，系统会自动执行核销。例如通过应付单生成付款单，在付款单审核时，系统会自动对应付单和付款单进行应付付款核销。
关联关系核销是优先级最高的核销，如果单据间有关联关系，则系统一定执行关联关系核销。

由于关联关系核销是在下游单据审核时系统自动执行，所以没有单独的菜单。

===== 2.2 匹配条件核销 =====


匹配条件核销是指系统根据用户选择的核销方案，对系统单据进行批量的核销。在系统中，应付付款的匹配条件核销通过菜单【应付付款核销】进行。

该功能为向导式功能，用户首先需要在向导界面中选择核销方案，有关核销方案的说明请参见[[应付付款核销方案|应付付款核销方案]]。用户同时可以选择多个核销方案，系统会按照核销方案的优先级，自动执行多次匹配条件的核销。

在向导界面中还可以设置参与核销的单据范围和核销过程中产生的[[应付核销单|应付核销单]]的业务日期。

在单据间没有关联关系的情况下，匹配条件核销为用户的最主要核销方式。通过匹配条件核销，应该可以对用户大多数的单据核销完毕。

===== 2.3 手工核销 =====

在系统中，应付付款手工核销提供【手工核销】及【特殊核销】功能。 

手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何单据进行核销，但是建议仅在需要对单据尾数冲销或者不同往来单位的应付单和付款单、付款退款单核销时才使用该功能。

详细描述请见：[[应付付款手工核销]]


====== 2.4 应付付款定时核销方案 ======


在系统中，应付付款核销提供【定时核销】功能。 

系统可以根据用户的设定，按用户设定的频率自动进行核销，来提高工作效率。。 

详细描述请见：[[应付定时核销]]



===== 2.5 反核销 =====


在【[[应付付款核销记录]]】界面，系统提供了反核销功能，选择一组或多组核销记录，点击【反核销】按钮，系统将自动反核销。

来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E4%BB%98%E4%BB%98%E6%AC%BE%E6%A0%B8%E9%94%80%E6%96%B9%E6%A1%88

[[应付款管理#基础资料|<<返回应付款管理界面]]




====== 1 应付付款核销方案 ======


应付付款核销方案主要是为匹配条件核销设置核销关系、核销匹配条件和核销顺序。系统预设了一个核销方案，用户可以根据实际应用增加。

在匹配条件核销向导界面，用户可以选择多个核销方案，并设置优先级，系统会根据用户的设置多次执行匹配条件核销。

===== 1.1 核销关系 =====


系统现支持如下核销关系：

  * 应付单VS付款单/付款退款单
  * 应付单(正)VS应付单(负)
  * 付款单VS付款退款单 
  * 应收单VS应付单
  * 应付单VS付款单（预付）
  * 其他应付单VS付款单/付款退款单
  * 其他应付单(正)VS其他应付单(负)
  * 其他应收单VS其他应付单

===== 1.2 核销顺序 =====

核销顺序指应付付款核销中，当参与核销的单据为应付单、应收单、其他应付单或者其他应收单时，单据的优先顺序。系统支持如下核销顺序：

  * 按到期日从前往后核销
  * 按业务日期从前往后核销
说明：付款单、付款退款单因为只有业务日期，所以核销顺序均为按业务日期从前往后核销。

====== 应付单 ======

====== 1 功能说明 ======


应付单是对采购产生的应付的管理。

====== 2 字段说明 ======


^ 字段名        ^ 说明                                                                             ^ 备注  ^

====== 3 操作说明 ======


===== 3.1 自动生成 =====


  - 如果勾选“入库单审核时自动生成应付单”，则在入库单审核时，会自动生成应付单，生成的应付单如果必录字段完整，则为创建状态，如果必录字段不完整，则为暂存状态。
  - 如果勾选“应付单审核时自动生成采购发票”，则在应付单审核时，系统会根据供应商基础资料中的发票类型自动生成增值税专用发票或者普通发票。

===== 3.2 快速新增 =====


通过点击【应付单快速新增】菜单可以实现应付单的快速新增。在该功能下，系统分类展示出所有还未生成应付单的采购入库单、采购退料单、收料单和采购订单，使用户集中、快速的生成应付单。

====== 4 业务说明 ======


===== 4.1 多日期管理 =====


通过应付单的付款计划页签，系统支持一张应付单多到期日的管理，用户可以根据自己的管理需求，针对应付单设置不同的到期日及不同到期日的应付金额。

===== 4.2 供应商的多方交易 =====


系统支持供应商多方交易的场景，即供应商的结算费、订货方、供货方和收款方可以不同。

===== 4.3 内部结算 =====


内部结算的应付单必须通过供应链的组织间结算清单下推生成，而不能手工新增。内部结算的应付单表头的会计核算体系字段不为空，而一般的应付单该字段为空。

应付单上的会计核算体系字段默认隐藏，如果用户有内部结算的业务，可以通过单据类型将该字段放开。

====== 应付开票核销 ======

====== 1 功能说明 ======


应付开票核销包括关联关系核销、匹配条件核销和手工核销、定时核销。

一般情况下通过关联关系核销、匹配条件核销可以将用户多数的单据核销完毕。手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何的单据核销，但是建议用户仅在需要对单据尾数冲销或者不同往来单位的应付单与发票核销时才使用。

====== 2 操作说明 ======


有关联关系的应付单和发票已经自动核销了，本功能主要是提供没有关联关系的应付单和采购发票的核销。

===== 2.1 关联关系核销 =====


关联关系是指通过单据转换功能，通过上游单据生成下游单据，在下游单据审核时，系统会自动执行核销。例如通过应付单生成采购增值税专用发票，在采购增值税专用发票审核时，系统会自动对应付单和采购增值税专用发票进行应付开票核销。
关联关系核销是优先级最高的核销，如果单据间有关联关系，则系统一定执行关联关系核销。

由于关联关系核销是在下游单据审核时系统自动执行，所以没有单独的菜单。

===== 2.2 匹配条件核销 =====


匹配条件核销是指系统根据用户选择的核销方案，对系统单据进行批量的核销。在系统中，应付开票的匹配条件核销通过菜单【应付开票核销】进行。

该功能为向导式功能，用户首先需要在向导界面中选择核销方案，有关核销方案的说明请参见[[应付开票核销方案|应付开票核销方案]]。用户同时可以选择多个核销方案，系统会按照核销方案的优先级，自动执行多次匹配条件的核销。

在向导界面中还可以设置参与核销的单据范围和核销过程中产生的应付单的业务日期。

在单据间没有关联关系的情况下，匹配条件核销为用户的最主要核销方式。通过匹配条件核销，应该可以对用户大多数的单据核销完毕。

===== 2.3 手工核销 =====


在系统中，应付开票手工核销提供【手工核销】及【特殊核销】功能。 

手工核销可以选择满足核销方案的单据进行核销；特殊业务核销可以对任何单据进行核销，但是建议仅在需要对单据尾数冲销或者不同往来单位的应付单和发票核销时才使用该功能。

详细描述请见：[[应付开票手工核销]]

===== 2.4 反核销 =====


在【[[应付开票核销记录]]】界面，系统提供了反核销功能，选择一组或多组核销记录，点击【反核销】按钮，系统将自动反核销。

===== 1.1 应付款管理概述  =====


系统将应付款管理分为四个基本业务环节，构成应付款管理完整的业务循环，包括应付款确认、到期付款、付款核销、期末处理。这四个业务环节，基本涵盖应付款管理日常业务处理流程。

应付款管理主要处理两方面的业务：采购应付和其他应付。

本手册将以应付款四个业务环节为主线，从采购业务应付和其他业务应付两方面，详细说明各个业务节点可以实现的功能和操作方法，为您能够更加高效、灵活的使用本系统提供帮助。

===== 1.3 系统特性 =====

应付款管理主要处理两方面的业务：采购应付和其他应付。主要功能包括：

  * 通过应付单管理采购业务应付。
  * 通过其他应付单管理其他业务应付。
  * 应付单与采购发票彻底分离，应付账款通过应付单确认，应付单是债务成立的标志。
  * 支持“暂估应付”和“业务应付”两种立账模式。
  * 应付单的快速新增功能。
  * 入库单审核时自动生成应付单功能。
  * 支持供应商的多方交易。
  * 按角色区分的应付单、其他应付单新增、付款功能。 
  * 支持一张应付单的多到期日管理。
  * 应付单支持按照含税单价或者不含税单价不同的录入方式。
  * 应付单支持价内税和价外税两种税额计算逻辑。
  * 应付单到付款单，支持按付款计划付款。
  * 费用应付单支持指定入库单或者出库单。 
  * 付款单支持现金折扣和手续费的应用场景。
  * 付款退款单支持手续费的应用场景。
  * 可以针对供应商、订单预付。
  * 有关联关系的应付单/其他应付单与付款单自动核销。
  * 有关联关系的应付单与发票自动核销。  
  * 支持无关联关系的应付单/其他应付单与付款单匹配条件核销。
  * 支持无关联关系的应付单与发票匹配条件核销。
  * 支持应收单/其他应收单与应付单/其他应付单核销。
  * 特殊业务核销支持任意单据的核销，包括：单据尾数的冲销、不同往来单位的应付单/其他应付单与付款单的冲销等。
  * 支持内部应付清理功能。
  * 所有业务单据都可以通过智能会计平台生成业务凭证、总账凭证。
  * 提供各种报表查询功能，具体包括：应付款汇总表、应付款明细表、账龄分析表、到期债务表、往来对账明细表、应付单跟踪表、应付未开票明细表、应付单开票核销明细表、供应商对账单。

====== 2 应付款管理业务专题 ======

应付款管理主要处理两方面的业务：采购应付和其他应付。这两项业务仅是在应付确认环节区别较大，确认后的付款、报表查询等等方面都是相同的。本部分主要包括如下内容：

===== 2.1 采购应付 =====

采购应付主要处理企业有关材料采购产生的应付款项。

**业务场景**

各个企业确定应付款项的环节不一样，有的企业入库后确认应付款项，有的企业发出订单就确认应付款项。为了满足不同企业的不同应用方式，系统通过应付单来确认应付款项。在系统中应付单是企业对采购应付进行管理的唯一单据，采购业务是否收到发票、是否付款以及账龄分析等都是以应付单为依据。

===== 2.2 其他应付 =====

其他应付主要处理的是企业除了材料采购外产生的应付款项。

**业务场景**

除了材料采购，企业还会有很多其他原因产生的应付款项，例如员工报销费用、要支付的一些行政费用等。本系统通过其他应付单来确认除采购业务外产生的应付款项。该部分应付款项确认是通过其他应付单来实现的。在系统中其他应付单是企业除采购业务外应付账款管理的依据。

===== 2.3 费用应付单 =====

企业材料采购过程中，除了购买价款外还会发生一些相关的税费、运输费、装卸费等等。故将应付单分为标准应付单和费用应付单。费用应付单主要来解决企业这部分应付的结算。

===== 2.4 预付款 =====

预付款是向供应商预先支付货款的业务行为，预付款主要有两种场景：
 
  * 针对供应商预付：与供应商商定先预付一定的款项给供应商，之后向供应商发出的订单不允许超过该预付金额的一定比例。
  * 针对订单预付：在与供应商签订订单的条件中规定必须先预付一定比例的款项供应商才会执行该订单。

===== 2.5 应付开票 =====

**业务场景**

企业可以根据自己的实际情况入库后、发出订单后等时点确认应付，确认应付后还会收到供应商开具的采购发票。 

由于企业确认应付的时点与收到发票的时点会有差异，所以应付单与发票的金额可能会存在差异，但是最后的应付款项应该以发票为准，所以还需要将应付单与发票进行核对，根据发票金额对应付金额进行调整，系统因此提供了应付开票核销功能，有关该功能的介绍请参见应付开票核销。

**特别说明：**应付开票业务仅用于采购应付业务，其他应付业务不需要开票。

===== 2.6 到期付款 =====

**业务场景**

及时付款是保证企业良好信用的关键因素，而应付款在确认时，就已经同时确定了付款计划，即明确的到期日，一般采购业务人员在款项快到期时，会向财务部提出付款申请，而具体的付款一般是由出纳负责的。在系统中付款是通过付款单实现的。

  * 应付付款核销
应付款的账龄分析是很重要的业务资料。为了提供准确的账龄分析表，需要准确的知道每一笔应付款项的付款情况，即将应付单与付款单相对应，因此需要进行应付付款核销，有关该功能的介绍请参见[[应付付款核销]]。

===== 2.7 组织间交易 =====

除了企业外部的交易业务，集团型企业内部不同法人之间、利润中心之间、甚至部门之间也经常会存在交易，这即是组织间交易。当组织间交易发生的两个组织是需要各自考核的情况下，就会涉及内部结算。如下图：

[图:fin_组织间交易2.png]

如上图：蓝海公司下各车间存货的流转都属于组织间交易，铸造车间、组装车间属于同一核算组织，不需要单独的考核，所以一般不需内部结算；而铸造车间、组装车间与精密制造属于不同核算组织，那么铸造车间与精密制造之间的交易需要内部结算。

===== 2.8 内部往来清理 =====

对于组织间交易形成的内部往来，有时需要实际的现金收付或者开具发票，有时不需要实际的现金收付或者开具发票。针对不需要实际的现金收付或者开具发票的情况，很多企业都是在年末或者年中进行清理，即内部往来清理。在系统中分为内部应付清理和内部应收清理。



===== 2.9 立账模式 =====

支持“暂估应付”与“业务应付”两种不同的立账模式。“暂估应付”立账模式是根据发票确认应付账款的原则，如果没有到票，则确认为暂估应付，如果已到票了，则确认为财务应付，同时红冲暂估应付；“业务应付”立账模式是货物转移来确认应付账款的原则，如果货已入库，则确认应付账款，后续已到票，如果应付账款与发票存在差异，则进行调差处理生成差异应付单。

===== 3.3 业务初始化=====

当期初单据全部录入完毕后，就可以结束初始化了。结束初始化后不可以再录入期初单据。

账簿中可以设置是通过应付单、其他应付单。生成凭证时如果选择的单据与账簿的设置不相符，系统会提示用户，由用户决定是否继续。此外有以下两点需要注意：

  * 当立账模式为业务应付时，通过业务应付单生成“应付账款”的凭证。
  * 当立账模式为暂估应付时，通过财务应付单生成“应付账款”的凭证。

账务处理的其他功能都是由智能会计平台提供的。有关说明请参考智能会计平台用户手册。
===== 3.13 报表分析=====

==== 3.13.1 应付款汇总表 ====

应付款汇总表主要是用来反映某段时间内与往来单位的期初余额、本期应付数、本期实付数、期末余额等数据的汇总信息。在企业的实际应用中可能需要根据往来单位、采购部门、采购组等不同维度查询。

详细描述请见：[[应付款汇总表]] 

==== 3.13.2 应付款明细表 ====

应付款明细表主要是用来反映某段时间内与往来单位的期初余额、本期应付数、本期实付数、期末余额等数据的明细信息。

详细描述请见：[[应付款明细表]]

==== 3.13.3 应付款账龄分析表 ====

应付款账龄分析表反映的是截止到某一时间点，往来款项余额的时间分布。

此报表的数据来源于应付付款核销未完毕的应付单、付款单、付款退款单。

详细描述请见：[[应付款账龄分析表]]
 
==== 3.13.4 到期债务表 ====

到期债务列表反映截止到指定日期止，已经到期的未核销应付款及过期天数、未到期的应付款及未过期天数。

详细描述请见：[[到期债务表]] 

==== 3.13.5 往来对账明细表 ====

往来对账对账明细表所展示的数据与应付款明细表基本相同，只是当往来单位既是客户有是供应商时，往来对账对账明细表可以将与该往来单位的所有往来都列示出来。

详细描述请见：[[往来对账明细表|往来对账明细表]] 

==== 3.13.6 应付单跟踪表 ====

应付单跟踪表是用来查询与应付业务有关的各种信息的报表，例如应付单的订单情况、入库情况、开票情况、付款情况等等。

详细描述请见：[[应付单跟踪表]] 

==== 3.13.7 应付未开票明细表 ====

应付未开票明细表反映企业当期应付的开票情况，包括本期未开票情况，截止日期未开票情况，支持按物料明细显示。

详细描述请见：[[应付未开票明细表]] 



==== 3.13.8 应付单开票核销明细表 ====

应付单开票核销明细表反映企业当期应付单的开票核销明细情况，包括本期未开票核销情况，截止日期未开票核销情况，按应付单的明细分录显示。

详细描述请见：[[应付单开票核销明细表]] 

==== 3.13.9 供应商对账单 ====
供应商账单提供应付的原始金额、已付款金额、未付款金额和对应的账龄分析，主要用来传递给供应商进行对账。其与往来对账明细表的区别是往来对账明细表会单独列示付款单行数据，供应商对账单不会单独列示付款单单据数据，而是依据核销记录直接取该应付单已核销金额列示在与应付单数据行同一行中。

详细描述请见：[[供应商对账单]]

====== 应付款管理使用流程 ======


**第一步，基础设置**

在系统使用前，我们需要先做基础设置。
  * 首先，设置公用资料。包括：供应商、客户、币别、结算方式、物料、费用项目、采购部门、采购组、采购员、组织信息、账簿信息、汇率体系等。该部分数据如果用户由于已经使用供应链、总账等模块已经设置，则在使用应付款模块时不需要单独设置。

  * 其次，设置系统参数。
进入【财务会计】－>【应付款管理】－>【参数设置】－>【应付款管理参数】
  * 最后，需要维护基础资料
进入【财务会计】－>【应付款管理】－>【基础资料】－>【付款条件】、【应付付款核销方案】、【应付开票核销方案】

**第二步，初始化**

  * 首先，设置系统启用日期。
进入【财务会计】－>【应付款管理】－>【初始化】－>【启用日期设置】
  * 其次，录入期初单据，包括期初应付单、期初其他应付单、期初付款单、期初付款退款单。
进入【财务会计】－>【应付款管理】－>【初始化】－>【期初应付单】（期初其他应付单、期初付款单或者期初付款退款单）
  * 最后，结束初始化。
进入【财务会计】－>【应付款管理】－>【初始化】－>【结束初始化】
结束初始化工作在第一次结账前进行即可，即录入初始单据和录入第一期单据可以同时进行。

**第三步，日常业务操作**

  * 日常业务操作包括录入应付单、其他应付单、付款单、付款退款单等。
  * 应付单：进入【财务会计】－>【应付款管理】－>【采购应付】－>【应付单新增】
  * 其他应付单：进入【财务会计】－>【应付款管理】－>【其他应付】－>【其他应付单新增】
  * 付款单或者付款退款单：进入【财务会计】－>【应付款管理】－>【付款】－>【付款单】【付款退款单】

[[应付款管理#应付款账龄分析表|<<返回应付款管理界面]]

====== 应付款账龄分析表 ======

====== 1 报表功能 ======


应付款账龄分析表反映的是截止到某一时间点，往来款项余额的时间分布。

此报表的数据来源于应付付款核销未完毕的应付单、付款单、付款退款单。
====== 2 操作说明 ======


===== 2.1 核销 =====


因为核销会影响报表数据的准确性，因此系统在报表展示界面提供了调用核销的功能。

===== 2.2 分组汇总 =====


系统提供分组汇总功能。分组汇总依据包括：往来单位名称、原币币别、结算组织、收付款组织。

===== 2.3 账龄分组设置 =====


系统提供用户自定义账龄分组功能。通过该功能用户可以自由定义自己需要报表显示的账龄区间。

===== 2.4 账龄计算标准 =====


账龄计算标准分为按照业务日期计算和按照到期日计算。
===== 2.5 显示选项 =====


报表显示选项包括：

  * 包括未审核单据，默认不勾选
  * 按单据显示，默认不勾选
  * 包含暂估应付
  * 仅显示暂估应付
  * 截止日期的单据余额

以上选项用户可以根据自己的应用选择。

===== 3.1 内部结算、隶属关系查询 =====

请参见[[应付款汇总表|应付款汇总表的内部结算、隶属关系查询]]。

[[应付款管理#期末处理|<<返回应付款管理界面]]


===== 应付款结账 =====


  * 结账的开始日期默认为最新结账日期+1，锁定不可以修改；结束日期默认为开始日期所在月份的最后一天，可以手工修改。
  * 结账界面将显示出用户有应付款管理模块结账权限的所有已经设置启用日期并且已经结束初始化的结算组织。用户可以通过手工勾选来决定对哪些组织结账。

来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%94%E4%BB%98%E8%BD%AC%E9%94%80

[[应付款管理#应付转销|<<返回应付款管理界面]]

====== 应付转销 ======

====== 1 功能说明 ======


由于某种原因（例如公司更名），用户需要将A往来单位的应付转为B往来单位的应付，此时需要使用应付转销的功能。转销后付款、对账都需要与B往来单位进行。

转销功能支持应付单、预付单、其他应付单、费用应付单的转销。 

====== 2 操作说明 ======


该功能为向导界面。

===== 2.1 转销设置 =====


在转销设置界面，用户设置转销的币别、单据（应付单\预付单）、结算组织\收付组织、转出供应商、转入供应商。

结算组织必须为用户有权限的、已经启用应付款管理的结算组织。

===== 2.2 转销数据 =====


根据转销设置，转销数据界面会列示转出供应商所有没有付款的应付单。用户手工修改转销金额、转入业务日期和转入到期日。

转销金额必须小于等于未付款金额。

转入业务日期默认等于系统当前时间，可以手工修改，但是必须大于当前结账日期。

转入到期日默认等于原应付单的到期日，可以手工修改。

===== 2.3 转销记录 =====


通过[[应付转销记录]]可以查看所有的转销结果。

===== 2.4 反转销 =====


转销记录上有反转销功能，通过反转销可以取消转销。
