## 【页面】数据引入工具
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E5%BC%95%E5%85%A5%E5%B7%A5%E5%85%B7

====== 1 功能描述 ====== 
  - 主要用于初始化期间，实施人员尽快将初始数据录入系统，以便快速实施、快速上线。
  - 通过数据引入工具，可以从金蝶云系统把资料数据及模板导出，也可根据用户需要把资料数据批量导入。
  - 通过数据引入工具，还可以将导出的数据引入到另外一个数据中心，实现数据的转移。
  - 数据引入工具与EXCEL紧密结合，不用登陆金蝶云系统可以实现数据的引入。

**功能路径**  【打开Excel】→【金蝶云页签】→【登录】


====== 2 安装/卸载 ======
===== 2.1 安装 =====
==== 2.1.1 环境准备 ====

数据引入工具安装前，必须先安装以下内容：
  - Excel2007及以上版本
  - Visual Studio Tools for Office（VSTO）
  - Microsoft .NET Framework V4.0 

==== 2.1.2 安装 ====
  - 安装好数据引入工具对应版本；
  - 在安装包的路径找到Tools文件夹，打开【DataImport】文件，找到exe文件进行安装；
  - 安装时，务必先安装vstor40_x86.exe，再安装数据引入工具；
  - 安装结束后，打开EXCEL就看到金蝶云页签。

**注意**
如果打开EXCEL没有看到金蝶云页签，则选择EXCEL的“文件→选项→加载项”，在该页面的【管理】下拉菜单选择禁用项目，点击【跳转】，将涉及金蝶云的菜单启用；或者加载项中先禁用项目Kingdee.BOS.Excel.AddIn，然后在COM加载项中重新加载该项目即可。 

==== 2.1.3 启用 ====
  - 安装成功后，直接打开Excel，就可以看到Excel文档中增加了一个“金蝶云”页签；
  - 在“金蝶云”页签中，点击【登录】按钮，弹出登录界面，选择数据中心后，输入正确的用户、密码等信息，即可完成登录；
  - 数据引入工具的使用区分Administrator和普通用户，若是Administrator登录后，显示用户、角色及权限相关操作，若是普通用户登录，显示业务单据和基础资料的相关操作。

===== 2.2 卸载 =====
控制面板的卸载程序中找到“金蝶云 数据引入工具”进行卸载。

 ====== 3 功能操作 ======

数据引入工具提供了用户、角色、功能权限、业务单据、基础资料、辅助资料、科目初始的引入引出，分别介绍如下： 

===== 3.1 用户 =====
  - 登录用户必须是Administrator或者系统管理员的用户才可以操作用户的引入；
  - 点击【引出模板—用户模板】可以引出用户的引入模板，按照模板要求填写相关内容，带*的字段为必填字段；
  - 在用户模板维护好用户数据后，点击【引入数据-引入】，选择引入模板即可实现用户的批量引入；
  - 点击【引出数据-用户数据】可以引出当前数据中心的用户数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心。

===== 3.2 角色 =====
  - 登录用户必须是Administrator或者系统管理员的用户才可以操作角色的引入；
  - 点击【引出模板—角色模板】可以引出角色的引入模板，按照模板要求填写相关内容，带*的字段为必填字段；
  - 在角色模板维护好角色数据后，点击【引入数据-引入】，选择引入模板即可实现角色的批量引入；
  - 点击【引出数据-角色数据】可以引出当前数据中心的角色数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心。

===== 3.3 功能权限 =====
  - 登录用户必须是Administrator或者系统管理员的用户才可以操作功能权限的引入；
  - 点击【引出模板—功能权限模板】可以引出功能权限的引入模板，按照模板要求修改权限状态；
  - 在功能权限模板维护好功能权限数据后，点击【引入数据-引入】，选择引入模板即可实现功能权限的批量引入；
  - 点击【引出数据-功能权限数据】可以引出当前数据中心的功能权限数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心；
  - 功能权限模板文件的一个页签代表一个角色的权限，如果需要多个角色，则可以通过新增页签（页签名称改为角色名称）并将权限内容复制粘贴后再修改即可；
  - 默认情况下，只能选择一个角色进行功能权限数据的引出，可以通过参数设置勾选【支持批量引出】选项后，可以选择多个角色同时引出，Excel中将会依次按角色显示功能权限数据，每个角色的功能权限数据占用一个页签；
  - 默认情况下，只能针对当前页签的角色进行功能权限数据的引入，可以通过参数设置勾选【支持批量引入】选项后，可以同时引入多个角色的权限数据，按照引入文件页签由左到右的顺序逐个引入。

===== 3.4 基础资料 =====
  - 登录用户要求是非Administrator且具有基础资料引入引出、新增权限的用户才可以操作基础资料的引入；
  - 点击【引出模板—基础资料模板】可以引出基础资料的引入模板，按照模板要求填写相关内容，带*的字段为必填字段；
  - 在基础资料模板维护好基础资料数据后，点击【引入数据-引入】，选择引入模板即可实现基础资料的批量引入；
  - 点击【引出数据-基础资料数据】可以引出当前数据中心的基础资料数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心；
  - 在参数设置中启用了【支持批量引出】或者【支持批量引入】选项后，可以选择多个基础资料同时引出引入，每个基础资料一个文件。

===== 3.5 辅助资料 =====
  - 登录用户要求是非Administrator且具有辅助资料引入引出、新增权限的用户才可以操作辅助资料的引入；
  - 点击【引出模板—辅助资料模板】可以引出辅助资料的引入模板，按照模板要求填写相关内容，带*的字段为必填字段；
  - 在辅助资料模板维护好辅助资料数据后，点击【引入数据-引入】，选择引入模板即可实现辅助资料的批量引入；
  - 点击【引出数据-辅助资料数据】可以引出当前数据中心的辅助资料数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心；
  - 辅助资料引出模板包括辅助资料类别和辅助资料，分页签显示；也可以同时引入；
  - 引入时：1）若系统中存在该类别，则将明细辅助资料引入；2）若系统中不存在类别，可以在辅助资料类别模板中先增加类别再增加明细辅助资料，该类别及其明细辅助资料也可以同时引入；3）若辅助资料类别引入失败，该类别下的辅助资料也无法引入。 


===== 3.6 业务单据 =====
  - 登录用户要求是非Administrator且具有业务单据引入引出、新增权限的用户才可以操作业务单据的引入；
  - 点击【引出模板—业务单据模板】可以引出业务单据的引入模板，按照模板要求填写相关内容，带*的字段为必填字段；
  - 在业务单据模板维护好业务单据数据后，点击【引入数据-引入】，选择引入模板即可实现业务单据的批量引入；
  - 点击【引出数据-业务单据数据】可以引出当前数据中心的业务单据数据，再通过【引入数据-引入】引入当前数据中心或者其他数据中心；
  - 在参数设置中启用了【支持批量引出】或者【支持批量引入】选项后，可以选择多个业务单据同时引出引入，每个业务单据一个文件。

===== 3.7 科目初始数据 =====
科目初始数据引入，详见【[[科目初始数据引入|科目初始数据引入]]】中的介绍。 

===== 3.8 引入 =====
  - 要求当前登录用户有引入对象的引入或者新增功能权限；
  - 点击【引入】后，调出通用的引入界面，选择引入文档，执行引入即可。

===== 3.9 参数设置 =====
  - 提供【支持批量引入】和【支持批量引出】，默认都不勾选；
  - 不勾选，引入引出只能单个操作；
  - 勾选后，引入引出都可以选择多个内容同时执行，减少单个操作带来的时间。

===== 3.10 引入设置 =====
  - 提供【追加引入】（默认）和【覆盖引入】两种模式，两种模式只能二选一；
  - 追加引入：将当前引入内容添加到金蝶云系统；
  - 覆盖引入：将当前引入内容全部覆盖金蝶云系统对应内容；
  - 引入后为暂存：默认不勾选；数据引入后是创建状态；如果勾选了，则数据引入后是暂存状态，还需要在金蝶云中进行保存操作。

## 【页面】数据清理工具
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E6%95%B0%E6%8D%AE%E6%B8%85%E7%90%86%E5%B7%A5%E5%85%B7

====== 1 数据清理工具概述 ======
====== 1.1 概述 ======
数据清理工具用于清理指定会计年度期间之前的数据，帮助客户缩减数据中心的数据量，提升系统运行效率。
若想要使用清理工具，需走服务流程。

======1.2 系统特性 ======
  - 提供了预置的检查方案和检查规则；
  - 提供了预置的清理方案和清理规则；
  - 支持用户新增方案和规则的自定义配置，支持二开单据的处理；
  - 数据清理过程提供了向导式的清理模式；
  - 客户端独立的服务工具发布。

======2 数据清理工具操作手册 ======
=====2.1 准备工作 =====
在做数据清理前，要做好以下准备工作。

  （一）务必每个数据中心都要做好备份
  
  （二）备份做好业务数据检查
        检查截止日期前所有组织下面的业务必须都已完成，包括但不限于下面内容：
        1、会计期间，要求清理日期所在的期间处于关闭状态
           启用了总账模块的、未禁用的组织下，对于所有未禁用的账簿，要求包含这个日期的会计期间已关闭；如果没有启用总账，可以不关注
        2、结账余额（也就是结账日生成的时点余额），要求清理日期小于等于最新的模块结账日期
           对于启用了相应模块的、未禁用的组织下（主要是应付、应收、库存等模块），必须存在此清理日期或者之后日期的时点余额。比如2014-01-01当日或者以后的某个日期存在应付余额
        3、业务单据状态，要求所有单据是已完成状态，比如已审、关闭或作废。
             
  （三）环境准备
        数据中心环境要求：6.0+3月17日补丁。
        
=====2.2 客户端登录 =====
清理工具采用绿色的WPF客户端登录的方式，是个独立发布的服务工具，但预设的检查规则和检查方案、清理规则和清理方案需依赖数据中心。

**操作步骤**
  - 双击Kingdee.BOS.XPF.ClearAndInitData.App.exe 文件，并选择WPF客户端；
  - 点击确定；
  - 按登陆金蝶云方式正常登陆（任何金蝶云用户都可以登录）；
  - 登录后出现数据清理界面，即可在这里进行操作。
 
**温馨提示**
  - 需录入授权码才能执行菜单的操作，若有需要请联系客服部；
  - 一定要保证客户端是最新6.0+3月17日补丁环境安装的客户端。

=====2.3 方案和规则设置 =====
====2.3.1 检查规则 ====
**特性**
  - 主要校验是否可以清理截止日期（含该日期）之前的单据等内容，要求在执行清理之前必须检查截止日期前所有组织下面的业务必须都已完成。
  - 根据用户输入的数据清理截止日期，检查不满足条件的数据，主要是为了在执行清理前，把不符合业务要求的数据找出来，比如未完成单据，未关闭期间，该截止日期后存在未结账数据等，避免清理时误删数据。
  - 针对具体业务对象的通用规则，通过过滤条件配置；
  - 针对独特的检查规则，则支持自定义插件处理。

**前提**   梳理好需要清理的组织和模块；

**功能路径**  【检查规则列表】

**操作步骤**
 
  * 新增检查规则
  - 录入检查规则的编码、名称；
  - 确定具体业务对象；
  - 选择检查日期字段，以确定要根据该业务对象的日期字段来执行检查；
  - 确定检查条件，针对每个业务单据的检查条件，按具体业务对象的基本条件进行设置，这里采用的是通用的过滤条件配置方式；
  - 若是业务对象本身的通用过滤条件无法设置，对于这些比较独特的检查规则需要定义插件规则；
  - 点击【保存】，即完成新增规则。

  * 查询检查规则
点击【检查规则】菜单，即可打开“检查规则列表”界面查看已创建的检查规则。

**操作说明**
  - 过滤、刷新、新增、复制、删除、引出等，参见BOS平台附录。 
  - 检查规则定义后，将会为检查方案引用。

====2.3.2 检查方案 ====
检查方案是检查规则的整合，包含所有针对业务对象和公共对象的检查规则。系统预设了检查方案，也支持自定义检查方案。
检查方案用为数据清理向导引用。

**前提**
  - 梳理好需要清理的组织和模块；
  - 根据需要定义好检查方案，若预设的检查方案满足需要则不需要再次定义。

**功能路径**  【检查方案】

**操作步骤**

  *新增检查方案
  - 系统提供预设检查方案，也可以自定义检查方案，定义如下：
  - 录入清理方案的编码、名称；
  - 数据中心版本是默认读取系统的版本，不可修改；
  - 单据规则设置页签是针对具体业务对象的规则定义，先确定业务对象，然后根据需要选择该业务对象的检查规则，可选范围是用户为该业务对象定义的所有检查规则。
  - 元数据版本是默认读取系统中该业务对象的版本内容，不可修改；
  - 公共规则设置页签是针对没有明确的业务对象的规则设置，如根据日期去判断会计期间是否关闭，需要定义插件规则；
  - 点击【保存】，即完成新增方案。

  * 查询检查方案
点击【检查方案】菜单，即可打开“检查方案列表”界面查看已创建的检查方案。

**操作说明**
  - 过滤、刷新、新增、复制、删除等，参见BOS平台附录； 
  - 预设的检查方案不能修改、不能删除；
  - 支持方案引入引出。

====2.3.3 清理规则 ====
**特性**
  - 清理规则是确定要清理的数据范围，例如上游单据存在时，是否允许清理；下游哪些单据要考虑同步删除或者保留；本单处于何种状态可以被清理等。
  - 针对具体业务对象的通用规则，通过过滤条件配置；针对独特的清理规则，则支持自定义插件处理。
  - 系统预设了标准的清理规则，也支持用户自定义清理规则。

**前提**  梳理好需要清理的组织和模块；

**功能路径** 【清理规则列表】

**操作步骤**
 
  * 新增清理规则
  - 录入清理规则的编码、名称；
  - 确定具体业务对象；
  - 选择清理日期字段，以确定要根据该业务对象的日期字段来执行清理；
  - 确定关联清理规则；
  - 确定清理范围，这里设置业务对象本身的通用过滤条件；
  - 若是业务对象本身的通用过滤条件无法设置，相对独特的规则，比如需要定义插件规则，需插件规则页签添加；
  - 清理内容页签定义需要清理的各个关联表，系统自动从元数据中读取出来供参考。如果未能包括的，用户可以自己检查、增加。以便清理完成后生成清理报告，明确告知客户删除了哪些单据号。
  - 点击【保存】，即完成新增规则。

  * 关联清理规则举例介绍
   业务举例：销售订单
   单据转换：1）上拉：网上订单等；2）下推：发货通知单、出库单、应收单、销售订单变更单等；
   关联引用：收款单由应收单下推，但有单独的字段记录销售订单信息。可以认为是特殊的下游单据；
      
   1、上游的检查
      检查：上游的网上订单未删除时，销售订单不删除；如果销售订单上还有关联其他单据的字段，也要检查这个“其他单据”是否还存在；
      不检查：删除当前单据时，不检查上游单据是否存在；
      
   2、本单的处理
      销售订单能否被清理，除了创建日期(或者审核日期，来源于设置的截止日期字段)必须小于清理截止日期，必须满足一定的状态条件；
      同时检查下游需要删除的单据的创建日期与状态条件；
       
   3、下游的处理
      同步删除：销售订单删除时，同步删除销售订单变更单。同步删除的销售订单变更单创建日期必须小于清理截止日期，且满足一定的状态条件。这个可能涉及到多级处理，比如销售订单变更单还有下级要删除；
      保留关联关系：下游的发货通知单、销售出库单等信息不更改；
   
   4、使用说明：
   1）根据给出来的各种可能上游单据，比如销售订单的上游可能有网上订单等，勾选确认要不要检查；
   2）根据各种可能的下游单据，确定要同步删除还是保留关联关系；
   3）关联关系是通过关联类型字段来设置，包括单据转换和单据引用两种，单据转换关系会自动从元素表中读取出来，对于不是单据转换的引用，需要用户自己去追加。



  * 查询清理规则
点击【清理规则】菜单，即可打开“清理规则列表”界面查看已创建的清理规则。

**操作说明**
  - 过滤、刷新、新增、复制、删除、引出等，参见BOS平台附录； 
  - 业务单据预设的规则不能修改、不能删除；
  - 清理规则定义后，将会为清理方案引用。
====2.3.4 清理方案 ====

**特性**
  - 清理方案是清理规则的整合，包含所有针对业务对象和公共对象预设的清理规则。系统预设了清理方案，也支持自定义清理方案。
  - 清理方案应为数据清理向导引用。

**前提**
  - 梳理好需要清理的组织和模块；
  - 根据需要定义好清理规则，若预设的清理规则满足需要则不需要再次定义。

**功能路径**  【清理方案】

**操作步骤**

  * 新增清理方案
系统提供预设清理方案，也可以自定义清理方案，定义如下：

  - 录入清理方案的编码、名称；
  - 数据中心版本是默认读取系统的版本，不可修改；
  - 单据规则设置页签是针对具体业务对象的规则定义，先确定业务对象，然后根据需要选择该业务对象的清理规则，可选范围是用户为该业务对象定义的所有清理规则。
  - 元数据版本是默认读取系统中该业务对象的版本内容，不可修改；
  - 公共规则设置页签是针对没有明确的业务对象的规则设置，需要定义插件规则；
  - 点击【保存】，即完成新增方案。

  * 查询清理方案
点击【清理方案】菜单，即可打开“清理方案列表”界面查看已创建的清理方案。

**操作说明**
  - 过滤、刷新、新增、复制、删除等，参见BOS平台附录； 
  - 预设的清理方案不能修改、不能删除；
  - 支持方案引入引出。

=====2.4 数据清理向导 =====
数据清理采用向导方式来引导数据检查和清理。

**前提**
  - 梳理好需要清理的组织和模块；
  - 根据需要定义好清理方案、清理规则、检查方案及检查规则；
  - 确定好清理截止日期。

**功能路径** 【数据清理向导】

**操作步骤**

  * 数据清理向导
 
第一步：录入编码、名称，确定是否清理上机日志
 
第二步：前置检查

检查在清理截止日期之前的全部业务都已经完成了，若存在未完成的业务，不能进入下一步清理。操作如下：
 
  - 录入清理截止日期；
  - 确定检查方案，下面会自动携带该检查方案包含的检查规则；
  - 点击【执行检查】，按规则开始执行检查，并可以查看到检查结果，双击结果可以查看明细结果；
  - 点击【检查报告】，可以导出未达标数据报告，以便分析。

注意：
一旦根据所选检查方案检查结束后，将不能调整方案，若需要使用其他检查方案检查，必须打开新的向导执行。

第三步：指定清理范围

确定在清理截止日期之前的哪些业务已经结束，可以被清理掉，需要同步删除的业务对象也必须是结束状态、截止日期之前，同时要确定清理的是哪个组织、账簿以及业务对象。操作如下：

  - 确定清理方案，业务对象范围页签会自动携带该清理方案包含的清理规则；
  - 勾选要清理的组织范围和业务对象范围；
  - 点击【下一步】进入执行清理界面。

第四步：执行清理

按照上述范围删除数据，包括业务单据、关联的工作流消息与任务、操作日志、关联的其他特殊信息、余额结转、业务流程实例清理等。操作如下：

  - 检查所清理的业务对象是否齐全，对应的规则是否准确；
  - 点击【执行清理】，按规则开始执行清理，并可以查看清理结果，双击结果可以查看明细结果；
  - 点击【清理报告】，可以导出清理结果，以便分析。

  * 查询数据清理
点击【数据清理列表】菜单，即可打开“数据清理列表”界面查看已执行的数据清理记录。

**操作说明**

  - 过滤、刷新、新增、复制、删除、引出等，参见BOS平台附录。 
  - 结账日期必须大于清理日期，当一个模块启用为2009-01-01，最近的结账日期为2015-10-31，如果清理日期输入为2014-12-28，那么表示用这个日期来清理是可以的。会清理2014-12-28当日及以前的符合条件的数据。如果最近的结账日期为2014-11-30，这个日期就不能使用；
  - 执行完清理后，系统会记录清理日期，下次清理时的清理日期必须输入比本次相等或者更大；
  - 如果模块启用之后，中途停用了，需要人工标记为停用，系统将会略过不再检查。

## 【页面】环境检测工具
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%8E%AF%E5%A2%83%E6%A3%80%E6%B5%8B%E5%B7%A5%E5%85%B7

====== 1 功能描述 ====== 
  - 环境检测工具主要用于诊断机器的异常情况，快速定位及解决问题。
  - 金蝶云环境检测工具提供了客户端、数据库、应用服务器、管理服务器等方面的环境检测服务功能；
  - 通过手动或自动修复、检测报告和常见问题指导等方式解决相关的问题。

**功能路径**
  - 开始菜单中的【程序】→【金蝶云 智造服务平台】→【应用工具】→【环境检测工具】 
  - 环境检测工具的桌面快捷图标 

====== 2 安装/卸载 ======
===== 2.1 安装 =====
==== 2.1.1 环境准备 ====
需要先安装Microsoft .NET Framework V4.0 ，否则无法成功安装环境检测工具。

==== 2.1.2 安装 ====
  - 环境检测工具支持独立安装，在安装包文件的Tools文件夹找到环境检测工具安装文件，双击exe文件即可安装；
  - 安装成功后，电脑桌面产生“金蝶云 环境检测工具”的快捷图标，同时操作系统开始菜单的所有程序中也会显示“环境检测工具”启用菜单，点击即可使用。

===== 2.2 卸载 =====
从控制面板的卸载程序中找到“金蝶云 环境检测工具”进行卸载。 

 ====== 3 功能操作 ======
“环境检测工具”界面，可以看到提供的六种检测类型：整体、客户端、数据库、应用服务器、管理服务器及其它。分别介绍如下： 
===== 3.1 设置 =====
  - 环境检测工具支持设置检测本机和其他机器；
  - 默认情况下，对本机的进行检测；
  - 通过【设置】可对所要检查的机器进行设置；
  - 支持同时设置客户端、数据库、应用服务器或管理服务器所在机器。 

===== 3.2 检测 =====
  - 环境检测工具支持整体检测和选择检测两种方式。
  - 整体检测：针对客户端、数据库、应用服务器、管理服务器及其他的所有检测项目进行检测。
  - 选择检测：客户端、数据库、应用服务器、管理服务器及其他可以对所选检测项检测操作，检测完成后显示检测结果和修复建议。
  - 【详情】可以查看检查项的异常原因以及处理建议。
  - 【导出报告】可以将检查结果保存为报告文件，保存时输入报告文件路径和文件名，在指定的文件路径下生成扩展名为”.xls”的报告文件。 
  - 工具可以向下版本兼容，对低版本的产品也能进行检测。

===== 3.3 修复 =====
环境检测工具支持自动修复和手动修复两种解决方式。 

===== 3.4 常见问题 =====
目前提供的常见问题包括客户端、数据库、应用服务器、管理服务器及其他五大类常见问题，且针对每个问题提供了详细的解决方案。

## 【页面】网络检测工具
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BD%91%E7%BB%9C%E6%A3%80%E6%B5%8B%E5%B7%A5%E5%85%B7

====== 1 网络检查工具概述 ======
===== 1.1 概述 =====
网络检测工具主要是面向重点客户是使用客户端的用户和企业IT运维人员，智能分析诊断网络异常，快速检测、深度检测引导，有效帮助客户定位排查网络问题。

===== 1.2 业务特性 =====
网络检测服务提供了以下特色功能：
  - 异常时智能分析网络异常、提醒、并提供处理建议;
  - 可手工执行网络检测，快速发现网络问题；
  - 检查报告详细介绍了网络检测情况，可全面深入了解当前网络状况。


====== 2 网络检测操作手册 ======
===== 2.1 操作流程 =====

1、当客户环境遇到网络异常时，智能分析网络，定位网络问题，并提醒客户去优化网络；

2、点击【快速检测网络】帮客户快速发现网络问题，主要可以查看TCP端口检测结果；

3、点击【深度检测网络】全面深入检测网络状况，包括网络阻塞情况、TCP端口检测结果，Tracert检测结果及NetStat检查结果；

4、点击【检测报告】可以查看具体明细检测结果，并可以导出报告；

5、点击【会话连接耗时分析】和【http请求速度分析】可以查看具体图表分析。

===== 2.2 注意事项 =====

1、只支持http地址的网络检测，暂不支持https地址；

2、只针对客户端提供【快速检测】和【深度检测】功能，SL不提供。
