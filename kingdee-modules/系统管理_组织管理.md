## 【页面】业务单据组织变更
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%9A%E5%8A%A1%E5%8D%95%E6%8D%AE%E7%BB%84%E7%BB%87%E5%8F%98%E6%9B%B4

====== 1 功能描述 ====== 

组织架构或职能调整后，业务单据上的一个或多个协同业务组织，后续可能需执行相应业务转移处理。例如：A组织采购订单上的收货组织为B组织，现在B组织取消了库存属性或者被禁用，B组织的收货工作将由C组织接管。

通过业务单据组织变更可以将选定业务单据的协同业务组织变更为变更后的组织（从B变为C），业务单据组织变更有业务人员来完成。

**功能路径**

【基础管理】→【基础资料】→【业务变更】 


 ====== 2 字段说明 ======



 ===== 2.1 基本信息 =====

  - 编码：必录项，不能重复录入；
  - 变更前组织：必录项，F8选择，选择有权限的组织范围；
  - 单据上组织：单据上组织 必录项，F8选择，只能选择业务单据上面的非主业务组织字段；
  - 业务单据：必录项，F8选择，选择有权限的业务单据。 

 ===== 2.2 变更数据 =====
  - 变更后组织：必录项，F8选择，选择有权限的组织范围； 
  - 业务单据编码：业务单据编码用来选择变更前组织参与相关业务的单据数据。 


 ===== 2.3 受控字段 =====

  - 字段名：受非业务组织控制的字段，例如：采购订单需要变更库存组织（库存组织是非主业务组织），如果库存组织改变，仓库字段就是受控于库存组织的字段； 
  - 控制方式：分为携带、默认值、留空三种：1）若控制方式为携带，变更后组织下，字段值会携带原字段值；2）若控制方式为留空，变更后组织下，该字段显示为空；3）若控制方式为默认值，变更后组织下，该字段显示为所设置的默认值；
  - 默认值：当控制方式为默认时，可以在此设定一个默认值。 

 



====== 3 功能操作 ======

===== 3.1 新增 =====
增加业务单据组织变更方案，例如，A组织下的采购订单上指明了由B组织收货，现在B组织取消了库存组织属性或者被禁用。B组织的收货工作将由C组织接管。增加该方案来实现这个转变过程，具体操作步骤如下：

  - 录入编码； 
  - 选择需要变更的组织，即变更前组织字段选择B组织； 
  - 选择变更的对象，即业务单据字段选择采购订单； 
  - 选择要变更的组织字段，即单据上组织字段选择收料组织； 
  - 选择变更后组织，即变更后组织字段选择C组织，变更后创建组织支持批量填充； 
  - 选择需要变更的具体业务单据数据，即业务单据编码可以选择由变更前组织B负责收货的采购订单数据； 
  - 点击【执行变更】，即可完成采购订单的组织变更。 

===== 3.2 查询 =====
 
    进入【基础管理】→【基础资料】→【业务变更】，点击【业务单据组织变更列表】菜单，即可打开“业务单据组织变更列表”界面查看已执行的业务单据组织变更方案。



====== 4 其他说明 ======

  业务单据的主业务组织的不能变更，例如：采购订单的采购组织、入库单的库存组织都是主业务组织，不能变更。   
  业务单据上的其他协同业务组织可以变更，例如：采购订单的收货组织/结算组织可以变更。
  业务单据组织变更控制如下：
  1）直接将单据上该业务组织字段进行更新；
  2）将那些按此组织字段过滤的基础资料字段同步更新。

## 【页面】分配执行情况
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%88%86%E9%85%8D%E6%89%A7%E8%A1%8C%E6%83%85%E5%86%B5

====== 1 功能描述 ====== 

分配执行情况列表可以查看分配的执行情况，包括手工分配、自动分配、分配申请。


**功能路径**

【系统管理】→【组织机构】→【基础资料控制】

 ====== 2 字段说明 ======


  - 耗时：分配执行花费的时间； 
  - 执行方式：分为手动、自动及分配申请； 
  - 执行状态：分为成功、部分成功、失败。全部分配成功时，执行状态为成功；有的分配成功，有的分配失败时，执行状态为部分成功；全部分配失败时，执行状态为失败。

====== 3 功能操作 ======

  - 过滤、刷新、删除、退出等，参见BOS平台附录； 
  - 点击“查看历史”，可以打开“分配执行情况历史记录列表”查看历史记录； 
  - 点击“选项”，可以设置分配执行情况记录超过多少条时，将自动归档到历史记录中，默认为200条。

====== 4 分配失败提醒 ======

  - 当分配或取消分配失败后，系统可以通过右上角消息平台提醒用户；分配或取消分配失败后进行消息弹框提醒，详情请参考[[https://vip.kingdee.com/article/393861241091079168|分配失败消息提醒]] 介绍。
  - 分配失败消息级别已设置为紧急，基于消息平台的弹框模式，分配失败后进行弹框提醒，针对失败的级别改成紧急，只要有失败就紧急告知，且同步失败提醒支持消息配置邮箱并支持发送消息给分配人或指定用户，可以参考[[https://vip.kingdee.com/article/495151543159656192?productLineId=1&isKnowledge=2|基础资料同步失败提醒支持消息配置邮箱并支持发送消息给分配人或指定用户]] 。
  - 支持设置是否分配成功或者失败消息不再发送提醒，位置在分配执行情况，选项下面的参数：【关闭自动分配计划结果提醒】、【关闭手动分配结果提醒】、【关闭分配成功结果提醒】、【关闭同步结果提醒】、【关闭同步成功结果提醒】

 
====== 5 其他说明 ======

  - 直接手工分配基础资料时，方案编码、方案名称、所属计划编码、所属计划名称均为空； 
  - 直接手工执行方案时，方案编码、方案名称记录相应的信息，所属计划编码、所属计划名称为空； 
  - 计划自动执行或直接手工执行时，方案编码、方案名称、所属计划编码、所属计划名称均不为空，记录相应的信息；
  - 普通用户可查看自己分配的执行情况，administrator及子系统管理员（启用子系统授权模式，并授予执行情况列表查看权）可以查看所有执行情况；

## 【页面】启用多组织
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%90%AF%E7%94%A8%E5%A4%9A%E7%BB%84%E7%BB%87

====== 1 功能描述 ======


创建的数据中心默认是单体模式，执行多组织应用前需要先启用多组织。

**功能路径**

【系统管理】→【组织机构】→【组织机构】→【启用多组织】

====== 2 业务说明 ======

===== 2.1 单体组织 =====

  - 数据中心创建默认是单体组织，不能进行组织机构维护以及对应的多组织业务；
  - 支持单体组织应用一段时间后再启用多组织；启用后原单体组织成为多组织的顶层组织；
  - 启用后不能反操作，恢复为单体组织状态。

===== 2.2 多组织 =====

启用多组织后
  - 可以进行多组织协同与结算业务；
  - 业务单据上显示组织的内容；

## 【页面】块粘贴并自动申请分配
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%9D%97%E7%B2%98%E8%B4%B4%E5%B9%B6%E8%87%AA%E5%8A%A8%E7%94%B3%E8%AF%B7%E5%88%86%E9%85%8D

====== 1 功能描述 ====== 

目前很多企业使用的是多组织统控模式应用，物料控制策略，一般是创建组织一个，其余的是分配目标组织，物料一旦新增则由创建组织自动全部分配到使用组织。并且每新增组织，所有物料都会同步到该组织下，物料成倍增长，导致物料数据臃肿，容易引发系统性能问题。 对于组织多，每增一个组织，所有物料数据都会全部下发，物料数据成倍增长，而这些数据都不会应用到业务单据中，导致太多冗余数据，业务数据量大，对DBA的挑战很大。 
基于此，星空产品采用物料清理 + 申请分配通道的方案： 
1、物料需清理长期（3个月以上）未被使用的分配数据 ，减少冗余，具体可以参考下面详细描述https://vip.kingdee.com/article/225717672368407040?productLineId=1 
2、为用户提供物料按需自动分配通道，块粘贴按需分配，确保缺数据的时候可以及时补录，本特性重点阐述。 另外一种使用场景是，物料增加后审核完了，新增人不一定能记得去及时分配，也希望可以通过录单时按需自动分配解决。

**功能路径**

【系统管理】→【公共设置】→【参数设置】勾选“启用物料块粘贴自动申请分配”选项；
录单时，当单据体物料数据缺失，右键选择【块粘贴并按需分配】

====== 2 功能操作 ======

  - 管理员登录系统，在参数设置中勾选【启用物料块粘贴自动申请分配】功能； 
  - 给普通用户对应角色进行授权； 
  - 普通用户登录系统，打开单据（以销售订单为例），在物料栏位点击鼠标右键，显示出【块粘贴并自动申请分配】选项；
  - 点击弹窗文本框，将物料按行粘贴到文本框，点击确定按钮；
  - 若当前主业务组织下没有该物料数据，则接着直接弹出分配界面，并对应显示可以分配的源数据记录；
  - 点击【确定分配】后，立即将复制的数据分配到主业务组织，然后直接携带到单据体的明细信息上；
  - 按需分配默认是将数据分配到主业务组织后，会继续将数据分配到所有的业务组织，若业务上希望只分配到当前单据的组织，勾选只分配当前主业务组织，请参考  [[https://vip.kingdee.com/article/455064480448250368?productLineId=1&isKnowledge=2|按需分配支持只分配当前主业务组织]]  介绍。
  - 当发生分配失败，则报提示，方便用户排查原因。

====== 3 其他说明 ======

  - 对于物料数据本身不存在、有数据但是不存在对应基础资料控制策略，或者基础资料源数据是未审核状态，则不能进入按需分配；
  - 将待分配物料数据立即分配到当前主业务组织，再后台自动执行分配到基础资料控制策略定义的可分配组织范围，若当前单据主业务组织已经分配了物料数据，将不再继续分配，具体已分配物料请点击查看详情按钮，打开对应数据的物料列表。 
  - 基础资料分配执行情况查看中执行方式是分配申请；
  - 具体介绍可以参考[[https://vip.kingdee.com/article/314913937391261440?productLineId=1&isKnowledge=2|块粘贴并按需分配]]

## 【页面】基础资料控制策略
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%9F%BA%E7%A1%80%E8%B5%84%E6%96%99%E6%8E%A7%E5%88%B6%E7%AD%96%E7%95%A5

﻿====== 1 功能描述 ====== 

基础资料控制策略主要应用于基础资料的维护控制以及基础资料的组织隔离。策略控制类型分为共享型、分配型以及私有型，这三类控制策略都支持创建组织的定义，分配型控制策略还支持使用组织的定义以及基础资料在字段级别的控制，控制策略将直接影响基础资料的新增、分配及应用方式。


**功能路径**

【系统管理】→【组织机构】→【基础资料策略】

 ====== 2 字段说明 ======


=====2.1 基础资料 =====

来源于基础资料控制类型列表中基础资料，支持F8选择

=====2.2 创建组织 =====
来源于组织列表，支持F8选择；一次只能选择一个创建组织，如果基础资料需要支持多个创建组织则多次操作即可

=====2.3 分配目标组织 =====
来源于组织列表，支持F8选择；支持选择多个组织；不能与创建组织相同；选择后作为基础资料分配的组织范围

=====2.4 属性名称 =====
基础资料所有属性字段，按属性分组来展示

=====2.5 控制方式 =====
	
控制方式分为携带、默认值、留空三种：
  - 携带，分配目标组织下，字段值会携带原字段值；
  - 留空，分配目标组织下，该字段显示为空；
  - 默认值，在分配组织下，该字段显示为所设置的默认值。

=====2.6 默认值 =====

当控制方式为默认时，可以在此设定一个默认值

=====2.7 不可修改 =====

  - 控制基础资料分配后在使用组织该字段值是否可以修改；
  - 只对控制方式=携带有效；
  - 默认勾选，该字段在基础资料分配后。使用组织不可修改，只有创建组织可修改；同时创建组织修改后，会同步刷新使用组织的该字段值；
  - 不选时，该字段在基础资料分配后，使用组织可以修改；不过创建组织修改该字段后，不会刷新使用组织的该字段值。

=====2.8 分配关联检查=====
  - 目前只针对物料清单进行设置；
  - 物料清单分配前，需要设置关联检查的内容，只有关联检查的内容分配了，物料清单才有可能分配成功。

=====2.9 应用更多组织=====
  - 应用更多组织，可以支持将所选择组织的控制策略属性应用到其他分配目标组织；
  - 基础资料控制策略的字段设置支持按照组织批量设置，比如客户是分配型，有30个组织，假如要把客户资料中的一个字段设置成可修改，就需要在30个组织中分别找到这个字段进行设置，重复操作30次，那么通过本补丁的功能，可以实现批量设置应用。请参考  [[https://vip.kingdee.com/article/421701415749445888|基础资料控制策略支持针对字段批量设置应用组织]]  介绍。

 ====== 3 功能操作 ======

=====3.1 新增 =====

    1、打开基础资料控制策略列表后，点击工具栏【新增】按钮，即可打开“基础资料控制策略-新增”界面进行创建；
    2、选择基础资料，录入基础资料编码或者光标定位到文本框，然后点击F8按钮，打开“基础资料控制类型列表”界面来选择回填；
    3、定义基础资料控制策略
         1）选择“创建组织”，录入组织编码或者光标定位到文本框，然后点击F8按钮，打开“组织机构列表”界面来选择回填；
         2）若是基础资料控制类型是分配型，可以继续选择“分配目标组织”，以同样的方式录入组织，
            右边的控制属性列表会展示所选基础资料对应的字段属性，然后根据需要设置控制方式、能否修改以及默认值；
         3）若是基础资料控制类型是共享或私有型，只定义创建组织即可；
    4、点击工具栏的【保存】按钮，则对应基础资料的控制策略创建完成。


 
=====3.2 其他操作 =====

  - 过滤、新增、删除、打印、预览、引出、刷新等，参见BOS平台附录；
  - 分配后自动显示分配明细：勾选该选项后，可以直接打开基础资料列表（显示当次分配的有权限的组织下的基础资料明细），以便于快捷提交并审核。
  - 分配后自动审核： 进行手工分配、自动分配、组织复制的自动分配基础资料环节，勾选“分配后自动审核”选项即可。

 ====== 4 业务说明 ======

=====4.1 基础资料控制策略应用说明 =====

  - 控制类型=共享型与私有型的基础资料，根据基础资料控制策略中的创建组织以及在创建组织下的新增、修改等权限控制新增、修改等操作；
  - 控制类型=分配型的基础资料，根据基础资料控制策略中的创建组织以及在创建组织下新增、修改等权限控制新增、修改等操作，根据控制策略中的分配目标组织控制基础资料的分配范围，根据控制策略中的字段控制策略控制基础资料分配后的字段维护。

====4.1.1 共享型 ====
1、类型=共享型，设置创建组织
2、应用规则
创建组织：维护和使用  非创建组织：使用

====4.1.2 私有型 ====
1、类型=私有型，设置创建组织
2、应用规则
创建组织：维护和使用  非创建组织：不可使用

====4.1.3 分配型 ====

1、类型=分配型
  1）设置创建和使用组织；
  2）设置控制方式和修改控制策略；
  3）物料清单支持分配关联检查；
2、应用规则
  1）不可修改：控制基础资料分配后字段不可维护；
  2）控制方式（留空、携带、默认）：控制分配操作时该字段的处理；
  3）通过【分配】操作实现应用；
  4）分配后
  创建组织：维护和使用；
  使用组织：在策略下维护和使用；
  非使用组织：不可见。
=====4.2 基础资料分配和取消分配 =====

分配型的基础资料，需要在组织间分配，用户可以在基础资料界面或者列表界面进行分配。只有分配给了相关的业务组织后，业务组织才能够使用。目标组织可以依据权限设置对分配过来的基础资料进行修改操作；
用户也可以对已经分配的基础资料取消分配。
====4.2.1 分配 ====
 
1、针对控制类型=分配的基础资料

2、分配操作

1）只有创建组织的记录才可以分配
2）按照基础资料控制策略进行控制
3）分配后对应组织自动增加一条数据，默认为暂存状态 

3、分配界面可以选择地址、描述、邮编、联系人进行过滤（V7.7新增）

4、支持分配基础资料到有权限的组织，请参考https://vip.kingdee.com/article/162237493713611008（V7.7新增）。

5、新版分配，做了基础资料分配服务、产品网络优化控制、数据结构调整调优，实现分配、同步功能优化及性能提升，同时，解决BOM分配行标识重复问题，从而引发一系列业务应用影响。请参考https://vip.kingdee.com/knowledge/642720411930340864?productLineId=1&isKnowledge=2&lang=zh-CN（V9.0新增，建议更新到2025年4月补丁）
====4.2.2 取消分配 ====
 
1、针对控制类型=分配的基础资料

2、分配操作

1）只有创建组织的记录才可以分配
2）分配后目标组织自动删除对应数据     
=====4.3 分配查询和未分配查询 =====
====4.3.1 分配查询 ====
  
分配查询可以查询所选基础资料的分配情况，包括分配到哪个组织、数据状态等，并可针对已有分配结果直接取消分配。

====4.3.2 未分配查询 ====

  - 未分配查询按分配目标组织+基础资料查询出所有未分配的记录报表，并可再次执行分配。
  - 可以查询创建组织中的基础资料有哪些未分配到所选的分配目标组织中。
  - 未分配查询的过滤支持显示隐藏列，能显示单据体字段，方便快速选择数据分配（V7.7新增）。

=====4.4 自动分配方案 =====

对于每一种分配型基础资料，在创建组织中有分配权限的业务操作人员可以且仅可以创建一个自动分配方案，定义方案后，系统按照自动分配方案来执行分配。

1、分配型基础资料列表提供【自动分配方案】的设置，位置在【取消分配】下面，针对具有分配型基础资料“分配”权限的用户有效；

2、自动分配方案定义说明：

  1）针对当前基础资料配置
  2）确定创建组织和分配目标组织，需要与控制策略一致
  3）可以设置过滤条件，支持批量填充，可以将标组织的设置内容，比如：“自动分配过滤条件”、“分配后自动审核”等字段值批量向下填充到其他组织，快速完成方案配置，
  具体可以参考https://vip.kingdee.com/article/352933500472582400?productLineId=1&isKnowledge=2
  4）支持【手工执行】
  5）可以查看【执行情况】

3、自动分配执行：

  1）自动分配方案可以手工执行，也可以通过基础资料自动分配计划来执行，将定义好的自动分配方案加入自动分配计划中，根据后台执行计划，定时执行分配；
  2）只有Administrator才可以设置基础资料自动分配计划；
  3）只有方案包含在自动分配计划中，且计划已启用（由Administrator创建、启用）时，即方案的“计划状态”为“计划已启用”时，方案才能在计划设置的分配周期自动执行；


4、分配执行情况查看：  
  
1）方案执行后可以通过【执行情况】查看分配的执行情况，包括自动或手动分配的执行情况及明细，还可以了解执行方式和分配执行人等信息。
  
2）普通用户可查看自己分配的执行情况，administrator及子系统管理员（启用子系统授权模式，并授予执行情况列表查看权）可以查看所有执行情况。
  
3）当分配或取消分配失败后，系统可以通过右上角消息平台提醒用户；分配或取消分配失败后进行消息弹框提醒，详情请参考[[https://vip.kingdee.com/article/393861241091079168|分配失败消息提醒]] 介绍。

## 【页面】基础资料控制类型
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%9F%BA%E7%A1%80%E8%B5%84%E6%96%99%E6%8E%A7%E5%88%B6%E7%B1%BB%E5%9E%8B

﻿====== 1 功能描述 ====== 

基础资料控制类型统一管理所有受控的基础资料，包括共享型、分配型、私有型。

**功能路径**

【系统管理】→【组织机构】→【基础资料控制】

 ====== 2 字段说明 ======


=====2.1 资料类型 =====
分为主档资料、基础资料两种类型，系统预置且不可修改

=====2.2 策略类型 =====
分为共享型、分配型、私有型，系统会预置，但是只要符合条件可以修改策略
	
=====2.3 不可修改 =====
系统预置，勾选锁定，则不可以修改控制策略的取值

 ====== 3 功能操作 ======


=====3.1 修改规则 =====

  * 共享型→分配、私有：“不可修改”处于未选中状态，且没有录入该基础数据
  * 分配型→共享、私有：“不可修改”处于未选中状态，且该基础资料不存在分配记录
  * 私有型→共享、分配：“不可修改”处于未选中状态
 
=====3.2 其他操作 =====

  - 过滤、打印、预览、引出、刷新、选项等，参见BOS平台附录；
  - 策略的控制类型可以在特定条件才互相转换，一般情况下推荐在没有维护任何数据的情况进行类型的调整。

 ====== 4 业务说明 ======

  -     在单体企业里面，基础资料没有控制策略，可在整个数据中心共享。对有部门级别的基础资料，使用数据权限和字段权限进行控制
  -     在多组织企业中，使用基础资料控制策略，定义不同级别的组织间控制，基础资料分为受控的和不受控的；

 ===== 4.1 不受控基础资料 =====

        不受控的基础资料(公共型）：全局可用，任意组织可定义、任意组织可修改；

 ===== 4.2 受控基础资料 =====

        受控的基础资料根据控制的级别，又细分为3个亚类型：共享型、分配型、私有型，基础资料控制类型列表里边显示的是所有受控的基础资料。
        除非有约定的控制类型锁定，这3个亚类型之间可以相互转化的；           
          1）共享型：由创建组织定义，其他任意组织均可见，只有创建组织才可修改；
          2）分配型：由创建组织定义，分配到目标组织后目标组织才可用，创建组织可以修改，目标组织按照控制策略进行修改；
          3）私有型：由创建组织定义，只有创建组织可使用和修改，不能分配，其他组织不可用。

## 【页面】基础资料组织变更
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%9F%BA%E7%A1%80%E8%B5%84%E6%96%99%E7%BB%84%E7%BB%87%E5%8F%98%E6%9B%B4

====== 1 功能描述 ====== 

组织架构或职能调整后，可能会导致由某个组织（A组织）负责创建/维护的基础资料，需要转移到另外一个组织（B组织）进行创建/维护。例如，组织A变更为组织B，需将A组织原来负责创建物料、供应商、客户等基础资料，现在由B组织负责创建，并维护A组织现有资料。

通过基础资料组织变更可以将选定基础资料的创建组织变更为变更后的组织（从A变为B）。基础资料组织变更由业务人员来完成。


**功能路径**

【基础管理】→【基础资料】→【业务变更】 


 ====== 2 字段说明 ======


  - 编码：必录项，不能重复录入； 
  - 变更前创建组织：必录项，F8选择，选择有权限范围的组织； 
  - 基础资料：必录项，F8选择，支持共享和分配型基础资料； 
  - 变更后创建组织：必录项，F8选择，选择有权限范围的组织；
  - 基础资料编码：基础资料编码用来选择在变更前创建组织下创建的基础资料数据； 
  - 基础资料名称：选择基础资料编码后回填名称。 


====== 3 功能操作 ======

===== 3.1 新增 =====

增加基础资料组织变更方案，例如，该方案用来将A组织下面创建的物料，变更到B组织下，操作步骤如下：

  - 录入编码； 
  - 选择需要变更的组织，即变更前创建组织字段选择A组织； 
  - 选择变更的对象，即基础资料字段选择物料； 
  - 选择变更后的组织，即变更后组织字段选择B组织，变更后创建组织支持批量填充； 
  - 选择需要变更的基础资料数据，基础资料编码字段可以选择变更前创建组织A创建的任何物料数据； 
  - 点击【执行变更】，即可完成物料的组织变更。  

===== 3.2 查询 =====
 
    进入【基础管理】→【基础资料】→【业务变更】，点击【基础资料组织变更列表】菜单，即可打开“基础资料组织变更列表”界面查看已执行的基础资料组织变更方案。


====== 4 业务说明 ======

  共享型、分配型的基础资料支持变更，私有型的不支持；

  对于共享型的基础资料，直接更新该基础资料的创建组织为变更后创建组织；  
  对于分配型的基础资料：
  1）不存在于变更后组织（B组织），需要先将该基础资料分配到变更后组织（B组织）后再变更；
  2）存在于变更后组织（B组织）但未审核，需要先将该基础资料审核后再变更；
  3）存在于变更后组织（B组织）已审核，则可以直接变更，即直接更新该基础资料的创建组织为变更后创建组织。

## 【页面】基础资料自动分配计划
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%9F%BA%E7%A1%80%E8%B5%84%E6%96%99%E8%87%AA%E5%8A%A8%E5%88%86%E9%85%8D%E8%AE%A1%E5%88%92

====== 1 功能描述 ====== 

Administrator可以统筹管理基础资料自动分配方案，设置其执行顺序及分配周期。计划启用后，基础资料可以按照计划设置的内容进行自动分配。

**前提**

业务操作人员已做好基础资料的自动分配方案。

**功能路径**

【系统管理】→【组织机构】→【基础资料控制】

====== 2 功能操作 ======

=====2.1 创建自动分配方案=====

  - 进入【系统管理】→【组织机构】→【基础资料控制】，点击【基础资料自动分配计划】菜单，即可打开“基础资料自动分配计划”界面；
  - 通过“分配周期”字段，设置自动分配的执行周期；
  - 下方左侧表体默认给出了推荐的基础资料分配顺序，默认全部勾选，即全部执行自动分配。可通过取消勾选来取消对应的基础资料自动分配的执行。同时，如果确有需要，可通过“上移”、“下移”菜单来调基础资料的分配顺序；
  - 下方右侧表体展示左侧表体所选中的基础资料已创建的自动分配方案；
  - 保存自动分配计划。
  - administrator在此可以打开查看普通用户建立的“自动分配方案”仅能查看，不支持编辑。


=====2.2 启用自动分配方案=====

  - 点击【启用】按钮即可完成启用自动分配计划；
  - 启用后，计划中所包含的自动分配方案才能按照设置的分配顺序&分配周期进行自动分配；
  - 也可点击“手动执行”，启动的自动分配计划将会立即执行。


=====2.3 其他操作 =====

  - 刷新、删除、退出等，参见BOS平台附录； 
  - 计划启用后创建的自动分配方案不会纳入到计划中。如需纳入，可先停用计划，刷新出新创建的方案后，重新保存、启用即可；
  - 基础资料分配顺序会影响自动分配的正确执行，在调整时请谨慎操作，确保调整的顺序正确。

## 【页面】多组织实施向导
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%A4%9A%E7%BB%84%E7%BB%87%E5%AE%9E%E6%96%BD%E5%90%91%E5%AF%BC

====== 1 功能描述 ====== 

多组织向导，是一个引导Administrator进行组织架构分析与组织定义的设置性向导。通过分析组织属性与企业管理需求，实现组织定义。


**功能路径**

【系统管理】→【组织机构】→【组织快速启用】 


 ====== 2 功能操作 ======

 ===== 2.1 多组织体系搭建流程 =====

 引导Administrator分析客户实际组织架构，快速搭建组织机构体系。

  - 顶层组织确定
  - 法人组织确定
  - 法人明细信息
  - 组织架构图
  - 自动创建组织
 ===== 2.2 操作步骤 =====

点击【多组织实施向导】菜单，逐步引导Administrator完成组织机构的定义任务。当系统检测到企业未购买多组织特性的软件授权，系统会提示用户先去启用多组织。

第一步： 总公司信息

系统自动携带预置组织的详细信息页面，Administrator可维护该组织信息。

点击【下一步】，系统会自动保存修改信息，并进行组织属性变更验证。若验证不通过，则停留在该界面等待进一步修改；验证通过之后，进入“法人公司信息”界面。

第二步：法人公司信息

系统展示系统已有法人组织的基本属性，Administrator可以新增法人组织。点击【下一步】，进入“法人公司明细信息”界面。

第三步：法人公司明细信息

系统展示全部的法人组织，可以设置该法人组织的组织模式，包括3个选项：独立法人模式、多事业部模式、多业务组织模式。

独立法人模式，表示该法人组织为一个整体；多事业部模式，表示该法人组织内部设立多个事业部（利润中心），类似法人核算一样，在组织间以市场转移定价机制来进行内部组织考核；多业务组织模式，表示法人组织内设立多个业务实体，以实现各业务实体之间的数据隔离需求。

当选择独立法人模式时，该法人也可是业务组织，可以设置相应的组织职能。当选择多事业部模式，或者多业务组织模式时，在这个界面还可以为法人组织增添下级业务组织，并设置相应的组织职能。

点击【下一步】，进入“组织架构图”界面。

第四步：组织架构图

系统以图形化展示相应的组织架构图。

点击【创建组织】，系统后台创建新增的组织，并退出向导界面，展示组织机构列表界面。

## 【页面】系统管理实施向导
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%B3%BB%E7%BB%9F%E7%AE%A1%E7%90%86%E5%AE%9E%E6%96%BD%E5%90%91%E5%AF%BC

系统管理实施向导，是一个引导Administrator进行常规的系统设置与管理的工具。主要内容包括组织机构、基础资料控制、系统参数、角色与用户等的定义与维护工作。


**功能路径**

【系统管理】→【组织机构】→【组织快速启用】 



 ====== 2 功能操作 ======

 ===== 2.1 主要功能 =====

引导Administrator按照步骤完成系统管理有关的设置工作，避免遗漏。主要功能包括：

  - 多组织设置
  - 基础资料控制
  - 系统参数
  - 角色与用户授权

 ===== 2.2 操作步骤 =====

点击【系统管理实施向导】菜单，打开向导，逐步引导Administrator处理系统管理的常规任务。

第一步：启用多组织

当系统检测到企业未购买多组织特性的软件授权，该界面不可用，直接进入到“系统参数”界面。

当企业购买了多组织特性，可以在此直接启用多组织。启用多组织后，再次进入向导，将跳过该界面。点击【下一步】，进入“多组织设置”界面。

第二步：多组织设置

系统展示“组织机构”、“组织隶属关系”、“组织业务关系”三个页签，并分别提供相应的实施说明。用户可以在阅读实施说明后，点击对应的链接进行设置。此外，专门提供了“多组织实施向导”的链接。

点击【下一步】，进入“基础资料控制”界面。

第三步：基础资料控制

系统展示“基础资料控制类型”、“基础资料控制策略”两个页签，并分别提供相应的实施说明。用户可以在阅读实施说明后，点击对应的链接进行设置。

点击【下一步】，进入“系统参数”界面。

第四步：系统参数

系统展示“系统参数”一个页签，并提供相应的实施说明。用户可以在阅读实施说明后，点击对应的链接进行设置。

点击【下一步】，进入“角色与用户授权”界面。

系统展示“角色”、“角色批量授权”、“用户”三个页签，并分别提供相应的实施说明。用户可以在阅读实施说明后，点击对应的链接进行设置。

点击【完成】，退出向导界面。

## 【页面】组织业务关系
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E4%B8%9A%E5%8A%A1%E5%85%B3%E7%B3%BB

====== 1 功能描述 ====== 

组织业务关系是根据业务的上下游协同关系建立业务组织之间的相互协作关系。本系统提供丰富的组织业务关系类型，支持跨组织进行业务操作，支持组织间结算。组织业务关系可以按委托方或受托方的角度进行定义和查看，使得组织业务关系在应用时更加灵活、更加便捷。


**功能路径**

【系统管理】→【组织机构】→【组织关系】

 ====== 2 字段说明 ======


=====2.1 业务关系类型 =====
组织业务关系类型主要包括：
====2.1.1 委托销售 ====
委托销售（供应-销售）-受托销售（销售-供应）:
供应组织（即库存组织）委托销售组织，或者，销售组织受托于供应组织（即库存组织），对客户出售产品。其中，供应组织为委托方，销售组织为受托方。单据处理举例：某销售组织录入销售订单，选择从某个库存组织出货。


==== 2.1.2 应收委托 ====

应收委托（销售-结算）-应收受托（结算-销售）：销售组织委托结算组织，或者，结算组织受托于销售组织，与客户进行应收款结算。其中，销售组织为委托方，结算组织为受托方。例如，某销售组织录入销售订单，选择某个结算组织负责与客户处理应收款。

====2.1.3 委托采购 ====

委托采购（需求-采购）-受托采购（采购-需求）：需求组织（即货主组织）委托采购组织，或者，采购组织受托于需求组织（即货主组织），从供应商采购材料。其中，需求组织为委托方，采购组织为受托方。单据处理举例：某需求组织录入采购申请，选择由某个采购组织负责采购。

====2.1.4 应付委托 ====

应付委托（采购-结算）-应付受托（结算-采购）：采购组织委托结算组织，或者，结算组织受托于采购组织，与供应商进行应付款结算。其中，采购组织为委托方，结算组织为受托方。单据处理举例：某采购组织录入采购订单，选择某个结算组织负责与供应商处理应付款。

====2.1.5 委托保管 ====
委托保管（货主-库存）-受托保管（库存-货主）：货主组织委托库存组织，或者，库存组织受托于货主组织，保管货物。其中，货主组织为委托方，库存组织为受托方。单据处理举例：某库存组织新增采购入库单，选择某个货主组织作为货物的货主。

====2.1.6 委托生产 ====
委托生产（需求-生产）-受托生产（需求-货主）：需求组织（即货主组织）委托生产组织，或者，生产组织受托于需求组织（即货主组织），生产产品。其中，需求组织为委托方，生产组织为受托方。单据处理举例：某生产组织录入生产订单，选择某个业务组织为产品货主。

====2.1.7 跨组织领料 ====
  
跨组织领料（生产-供应）-跨组织发料（供应-生产）：生产组织从供应组织（货主组织）领用材料，或者，供应组织（货主组织）为生产组织供应材料。其中，生产组织为委托方，供应组织（货主组织）为受托方。单据处理举例：某生产组织录入生产领料单，选择某个供应组织（货主组织）作为材料供应方。
====2.1.8 库存调拨 ====
库存调拨（调出-调入）-库存接收（调入-调出）：货物从一个库存组织（调出组织）调拨到另外一个库存组织（调入组织）。其中，调出组织为委托方，调入组织为受托方。单据处理举例：某库存组织录入库存调拨单，选择另外一个库存组织作为货物的接收方。

====2.1.9 资产托管 ==== 
资产托管（货主-资产）-资产代管（资产-货主）:货主组织的资产托管到资产组织，或者，资产组织代为管理货主组织的资产。其中，货主组织为委托方，资产组织为受托方。单据处理举例：某资产组织新增采购资产台帐，选择某个货主组织作为资产的货主。
====2.1.10 委托收付 ==== 
委托收付（结算-收付）-受托收付（收付-结算）:结算组织委托收付组织，或者，收付组织受托于结算组织，进行收付款。其中，结算组织为委托方，收付组织为受托方。例如，某结算组织一笔应收账款，选择某个收付组织负责对客户进行收款。
====2.1.11 委托质检 ==== 
委托质检（质检需求-质检）-受托质检（质检-质检需求）：来源组织委托质检组织，或者，质检组织受托于来源组织，对物料进行检验。其中，来源组织为委托方，质检组织为受托方。单据处理举例：某质检组织录入检验单，选择某个业务组织为来源组织。
====2.1.12 委托资金管理 ==== 
资委托资金管理（收付-资金）-受托资金管理（资金-收付）：收付组织委托资金组织，或者，资金组织受托于收付组织，进行资金集中管理。其中，收付组织为委托方，资金组织为受托方。例如，某收付组织的资金头寸，上划到资金组织进行集中管理，资金组织根据资金预算下拨资金到收付组织。
=====2.2 委托方 =====
来源于自定义的组织机构，该组织已审核、未禁用且有对应的组织职能，与受托方具有指定的业务关系的组织，支持F8选择

=====2.3 受托方 =====
来源于自定义的组织机构，该组织已审核、未禁用且有对应的组织职能，与委托方具有指定的业务关系的组织，支持F8选择

=====2.4 默认受托方 =====

按委托方定义时，可以设置默认受托方，业务单据按委托方应用时，选择主业务组织（委托方）后，其他业务组织会默认携带默认受托方
=====2.5 默认委托方 =====
按受托方定义时，可以设置默认委托方，业务单据按受托方应用时，选择主业务组织（受托方）后，其他业务组织会默认携带默认委托方


 ====== 3 功能操作 ======


=====3.1 新增 =====

    创建组织业务关系
    1、打开“组织业务关系列表”界面后，点击工具栏【新增】按钮，即可打开“组织业务关系-新增”界面进行创建；    
    2、选择组织业务关系类型； 
    3、定义组织业务关系
         1）默认情况下是按委托方的角度来定义，可确定默认委托方；
         2）允许按受托方定义，可确定默认受托方；
         3）默认的委托方或受托方只能设置一个；
         4）委托方和受托方的内容是互相同步的；
    4、点击工具栏的【保存】按钮，则组织业务关系创建完成。

 
=====3.2 其他操作 =====

过滤、新增、修改、删除、禁用、反禁用、打印、预览、引出、刷新、选项等，参见BOS平台附录。 

 ====== 4 业务说明 ======

  - 如果没有设置业务组织关系，则业务单据维护时，需按照业务要求应用具有指定组织职能的组织机构；
  - 若设置了业务组织关系设置，则业务单据维护时，需根据设置的关系自动携带对应组织内容（设置了默认）或者在设置关系的组织范围内选择，且要求组织具有业务指定的组织职能。

## 【页面】组织变更
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E5%8F%98%E6%9B%B4

====== 1 功能描述 ====== 

组织变更是企业组织架构或职能的变更，根据企业实际应用提供了四种变更形式：组织拆分、组织合并、组织撤销、组织职能调整。

组织变更由Administrator处理，通过组织变更向导，逐步指导用户处理组织变更业务，在变更过程中，进行业务数据检查，并支持引出检查结果，可以在列表中查看历史变更记录。


**功能路径**

【系统管理】→【组织机构】→【组织变更】

====== 2 功能操作 ======



====== 2.1 变更操作流程 ======


  1、执行向导前，应让业务人员停止业务操作，并备份数据；
  2、选择相应的变更方式：撤销、合并、拆分、职能调整；
  3、选择变更对象；
  4、执行变更检查规则，必要时导出检查结果进行分析；
  5、根据检查报告通知对应业务人员调整业务数据；
  6、完成组织变更。

====== 2.2 变更形式 ======

根据企业实际应用提供了四种变更形式：组织拆分、组织合并、组织撤销、组织职能调整。

  基本执行步骤：
  1、选择变更形式；
  2、选择变更组织；
  3、执行检查；
  4、执行变更：执行变更时会再次检查，以避免业务数据变动影响组织变更。



=====2.2.1 组织撤销=====

组织撤销主要是组织禁用，具体操作如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织撤销，下面会显示组织撤销的操作说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织
        选择要撤销的组织，点击【下一步】，进入变更前检查界面；

第三步：变更前检查
        进入“变更前检查”页面时，将根据系统预置的组织变更检查规则对所选组织进行检查，并在该页面中显示检查结果。
        若所选组织满足变更要求，则可以点击【下一步】执行变更，否则，Administrator需要导出检查结果并通知业务人员调整数据，调整后，Administrator再次执行检查，检查通过后该组织才可以执行变更。
        点击【引出】可以导出检查结果；
        点击【重新检查】可以再次执行检查；
        点击【详情】可以查看检查对象有哪些记录不符合条件；
        点击【保存方案】可以保存该变更方案及其结果；       
业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

第四步：执行组织变更
        变更检查通过后，在“执行组织变更”页面中，点击【执行变更】按钮，组织变更生效。


=====2.2.2 组织拆分=====

通常情况下，组织拆分包括两种应用：原组织存在（A→A、B）和原组织不存在（A→B、C），具体操作步骤介绍如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织拆分，下面会显示组织拆分相关说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织                
        1、拆分后存在（A→A、B），例如，将组织A拆分为A和B，操作如下：
           左边“拆分前组织”分组下，拆分前组织选择A，然后勾选选项【拆分后存在】，点击【调整组织职能】，重新设置A组织的职能；
           右边“拆分后组织”分组下的列表中默认会显示拆分前组织A，接着选择组织B，点击【下一步】，进入变更前检查界面。
        2、拆分后不存在（A→B、C），例如，将组织A拆分为B和C，操作如下：
           左边“拆分前组织”分组下，拆分前组织选择A，不勾选选项【拆分后存在】
           右边“拆分后组织”分组下的列表中，选择组织B和C，点击【下一步】，进入变更前检查界面。

第三步：变更前检查       
        进入“变更前检查”页面时，将根据系统预置的检查规则对拆分前组织A进行检查，并在该页面中显示检查结果。
        若所选组织满足变更要求，则可以点击【下一步】执行变更，否则，Administrator需要导出检查结果并通知业务人员处理数据，业务人员处理后，Administrator再次执行检查，检查通过后该组织才可以执行变更。
        点击【引出】可以导出检查结果；
        点击【重新检查】可以再次执行检查；
        点击【详情】可以查看检查对象有哪些记录不符合条件；
        点击【保存方案】可以保存该变更方案及其结果；
业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

第四步：执行组织变更
        变更检查通过后，在“执行组织变更”页面中，点击【执行变更】按钮，组织变更生效。   



=====2.2.3 组织合并 =====

通常情况下，组织合并包括两种应用场景：原组织存在（A+B→A）和原组织不存在（A+B→C），具体操作步骤介绍如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织合并，下面会显示组织合并相关说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织              
        1、合并后存在（A+B→A），例如，将组织A和B合并为A组织，操作如下：
           左边“合并前组织”分组下的列表中选择组织A和B，勾选A组织对应的【合并后存在】选项；
           右面“合并后组织”分组下面，“原组织存在”行中，点击【调整组织职能】，重新设置A组织的职能，设置后，点击【下一步】，进入变更前检查界面。
        2、合并后不存在（A+B→C），例如，将组织A和B合并为C组织，操作如下:
           左边“合并前组织”分组下的列表中选择组织A和B，
           右边“合并后组织”分组下面，“原组织不存在”行中，可以点击【新增组织】按钮，新增后在前面的文本框回填，然后点击【下一步】，进入变更前检查界面。

第三步：变更前检查       
        进入“变更前检查”页面时，将根据系统预置的检查规则对合并前组织进行检查，并在该页面中显示检查结果。
        若所选组织满足变更要求，则可以点击【下一步】执行变更，否则，Administrator需要导出检查结果并通知业务人处理数据，业务人员处理后，Administrator再次执行检查，检查通过后该组织才可以执行变更。
        点击【引出】可以导出检查结果；
        点击【重新检查】可以再次执行检查；
        点击【详情】可以查看检查对象有哪些记录不符合条件；
        点击【保存方案】可以保存该变更方案及其结果；
业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

=====2.2.4 组织职能调整 =====

组织职能调整主要是组织职能的增加或减少，具体操作如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织职能调整，下面会显示组织职能调整的操作说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织

第三步：变更前检查

        点击【引出】可以导出检查结果；

        点击【详情】可以查看检查对象有哪些记录不符合条件；

业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

## 【页面】组织变更检查规则
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E5%8F%98%E6%9B%B4%E6%A3%80%E6%9F%A5%E8%A7%84%E5%88%99

====== 1 功能描述 ====== 

新增组织/组织添加组织职能，对现有业务的执行无影响，而取消组织的组织职能/禁用组织，都需要考虑对现有业务的后续执行影响。因此，系统提供相应的统一接口，来配置相应的检查条件与提示信息。

系统根据业务实际应用预置了变更检查规则，支持用户自行增加检查规则。

执行组织变更时，将以组织变更检查规则为标准，检查变更组织是否满足变更要求，只有满足变更要求时才能执行变更。


**功能路径**

【系统管理】→【组织机构】→【组织变更】


====== 2 字段说明 ======


===== 2.1 变更类型 =====

按组织变更类型预置检查规则，系统提供的变更类型包括：

  -  禁用组织 
  -  取消核算组织属性 
  -  取消业务组织属性 
  -  取消采购职能 
  -  取消销售职能 
  -  取消库存职能 
  -  取消工厂职能 
  -  取消质检职能 
  -  取消结算职能 
  -  取消收付职能 
  -  取消资金职能 
  -  取消资产职能等


===== 2.2 检查规则 =====

检查规则主要定义变更类型相关的检查对象及检查条件。

==== 2.2.1 控制强度 ====

控制强度包括“强制”和“提示”两种：

  - 强制：要求必须符合检查条件，否则不能执行组织变更
  - 提示：允许不符合条件，不符合条件也可以执行组织变更 

==== 2.2.2 检查条件 ====

针对具体业务对象定义的检查条件，检查条件包括通用过滤和SQL处理两种方式。 


==== 2.2.3 其他字段 ====

  - 业务领域：业务对象对应的业务领域； 
  - 子系统：业务对象对应的子系统的名称； 
  - 业务对象：需检查的业务对象，包括基础资料和单据； 
  - 单据上组织：业务对象上需检查的组织字段； 
  - 预设：标识系统预设的检查条件。

===== 2.2 自定义规则 =====

自定义规则主要是自定义的插件规则。

===== 2.3 前置检查 =====

前置检查是需要在当前规则之前检查的变更类型。

====== 3 功能操作 ======

===== 3.1 配置检查规则 =====


系统支持用户针对每种变更类型自行增加检查规则，操作如下：

  - 变更检查规则列表中，双击列表中记录打开变更检查规则的修改界面； 
  - 选择业务对象，同时回填业务领域和子系统字段； 
  - 选择单据上组织字段，可选该业务对象对应的组织字段内容； 
  - 选择检查条件，从检查条件列表中选择，若列表中没有所需的检查条件，用户也可以新增检查条件，支持基本和高级两种方式，其中，高级是SQL处理方式。 


===== 3.2 其他说明 =====

组织变更检查规则包括检查规则、自定义规则及前置检查，分别说明如下： 
  - 检查规则：变更类型相关的检查对象和检查条件。 
  - 自定义规则：自定义的插件规则，通用情况下，检查对象不只是单个业务对象。 
  - 前置检查：需要在在当前规则之前检查的变更类型，目前涉及前置检查的有禁用组织和取消业务组织属性。

====== 4 业务说明 ======

下面两种情况会应用组织变更检查规则：

  - 执行[[组织变更|组织变更]]时应用； 
  - 直接对组织机构进行属性调整时应用。

## 【页面】组织变更生成向导
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E5%8F%98%E6%9B%B4%E7%94%9F%E6%88%90%E5%90%91%E5%AF%BC

====== 1 功能描述 ====== 

组织变更是企业组织架构或职能的变更，根据企业实际应用提供了四种变更形式：组织拆分、组织合并、组织撤销、组织职能调整。

组织变更由Administrator处理，通过组织变更向导，逐步指导用户处理组织变更业务，在变更过程中，进行业务数据检查，并支持引出检查结果，可以在列表中查看历史变更记录。


**功能路径**

【系统管理】→【组织机构】→【组织变更】

====== 2 功能操作 ======



====== 2.1 变更操作流程 ======


  1、执行向导前，应让业务人员停止业务操作，并备份数据；
  2、选择相应的变更方式：撤销、合并、拆分、职能调整；
  3、选择变更对象；
  4、执行变更检查规则，必要时导出检查结果进行分析；
  5、根据检查报告通知对应业务人员调整业务数据；
  6、完成组织变更。

====== 2.2 变更形式 ======

根据企业实际应用提供了四种变更形式：组织拆分、组织合并、组织撤销、组织职能调整。

  基本执行步骤：
  1、选择变更形式；
  2、选择变更组织；
  3、执行检查；
  4、执行变更：执行变更时会再次检查，以避免业务数据变动影响组织变更。



=====2.2.1 组织撤销=====

组织撤销主要是组织禁用，具体操作如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织撤销，下面会显示组织撤销的操作说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织
        选择要撤销的组织，点击【下一步】，进入变更前检查界面；

第三步：变更前检查
        进入“变更前检查”页面时，将根据系统预置的组织变更检查规则对所选组织进行检查，并在该页面中显示检查结果。
        若所选组织满足变更要求，则可以点击【下一步】执行变更，否则，Administrator需要导出检查结果并通知业务人员调整数据，调整后，Administrator再次执行检查，检查通过后该组织才可以执行变更。
        点击【引出】可以导出检查结果；
        点击【重新检查】可以再次执行检查；
        点击【详情】可以查看检查对象有哪些记录不符合条件；
        点击【保存方案】可以保存该变更方案及其结果；       
业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

第四步：执行组织变更
        变更检查通过后，在“执行组织变更”页面中，点击【执行变更】按钮，组织变更生效。


=====2.2.2 组织拆分=====

通常情况下，组织拆分包括两种应用：原组织存在（A→A、B）和原组织不存在（A→B、C），具体操作步骤介绍如下：

第一步：选择变更方式
        输入组织变更的方案编码和方案名称，并选择变更形式为组织拆分，下面会显示组织拆分相关说明。点击【下一步】，进入变更组织设置界面；

第二步：设置变更组织                
        1、拆分后存在（A→A、B），例如，将组织A拆分为A和B，操作如下：
           左边“拆分前组织”分组下，拆分前组织选择A，然后勾选选项【拆分后存在】，点击【调整组织职能】，重新设置A组织的职能；
           右边“拆分后组织”分组下的列表中默认会显示拆分前组织A，接着选择组织B，点击【下一步】，进入变更前检查界面。
        2、拆分后不存在（A→B、C），例如，将组织A拆分为B和C，操作如下：
           左边“拆分前组织”分组下，拆分前组织选择A，不勾选选项【拆分后存在】
           右边“拆分后组织”分组下的列表中，选择组织B和C，点击【下一步】，进入变更前检查界面。

第三步：变更前检查       
        进入“变更前检查”页面时，将根据系统预置的检查规则对拆分前组织A进行检查，并在该页面中显示检查结果。
        若所选组织满足变更要求，则可以点击【下一步】执行变更，否则，Administrator需要导出检查结果并通知业务人员处理数据，业务人员处理后，Administrator再次执行检查，检查通过后该组织才可以执行变更。
        点击【引出】可以导出检查结果；
        点击【重新检查】可以再次执行检查；
        点击【详情】可以查看检查对象有哪些记录不符合条件；
        点击【保存方案】可以保存该变更方案及其结果；
业务人员处理过程，详见[[基础资料组织变更|基础资料组织变更]]和[[业务单据组织变更|业务单据组织变更]]。

第四步：执行组织变更
        变更检查通过后，在“执行组织变更”页面中，点击【执行变更】按钮，组织变更生效。

通常情况下，组织合并包括两种应用场景：原组织存在（A+B→A）和原组织不存在（A+B→C），具体操作步骤介绍如下：

## 【页面】组织复制新增
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E5%A4%8D%E5%88%B6%E6%96%B0%E5%A2%9E

====== 1 功能描述 ====== 

企业运营过程中，新增的组织与原有组织性质大致相同，通过组织复制新增，可以快速建立组织及其对应内容，降低手工工作量，避免遗漏对应控制。

组织复制新增可以快速复制一个现有组织，不仅可以复制它的组织属性、系统参数、基础资料分配策略、用户及其权限，做到在细微的个性化修改后，即可快速创建好一个组织，并做好各项相关设置；而且，还可以将基础资料自动分配到新建组织中。

**功能路径**

【系统管理】→【组织机构】→【组织快速启用】 


====== 2 功能操作 ======

 
===== 2.1 业务操作流程=====

 组织复制新增，针对参照现有组织进行新增的情况。主要业务操作如下：

  - 选定待复制的源组织；
  - 组织属性复制；
  - 系统参数复制；
  - 基础资料分配策略复制；
  - 基础资料自动分配；
  - 批量同步用户；
===== 2.2 操作步骤 =====

进入【系统管理】→【组织机构】→【组织快速启用】，点击【组织复制新增】菜单，即可打开“组织复制新增”向导界面。
  - 选择要复制的源组织后，点击“下一步”；
  - 组织属性界面复制出源组织的组织属性信息，填入新建组织的个性化信息后，点击“下一步”，可自动将新建组织保存、提交、审核；
  - 系统参数界面会将源组织的系统参数复制给新建组织，差异部分，修改后，请手工保存；无差异内容，点击“下一步”，会自动保存！
  - 基础资料分配策略界面，展示所有分配目标组织为复制源组织的控制策略和创建组织作为源组织的控制策略，创建组织和分配目标组织都由复制源组织变为新建组织（例如，复制组织B产生一个新的组织E，对于物料，系统中原有三条分配策略：A→B、C→B、B→D,则此页显示的物料的分配策略为A→E、C→E、E→D。）可以通过“维护”按钮修改分配策略，或通过“删除”按钮删除分配策略，通“还原”恢复到出修改前的策略。点击“下一步”，将保存基础资料控制策略；
  - 自动分配基础资料，可以选择“是”，立即按照在上一步中保存的基础资料分配策略，将源组织作为分配目标组织对应创建组织中的基础资料，自动分配到新建组织中；即：A→B、C→B的物料，都从A和C分配到E中，也可以选择“否”，自己手动分配；
  - 点击“完成”，退出向导。
 ===== 2.3 其他说明 =====

向导的操作是不可逆的，即：点击“下一步”时，会按照按钮左侧的提示进行相应的操作。

具体流程参考https://vip.kingdee.com/article/226396750217323776

## 【页面】组织机构
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E6%9C%BA%E6%9E%84

﻿

======1 功能说明 ======

多法人、多事业部、多地点等多组织应用模式是本系统的一大亮点，组织机构的搭建是多组织应用模式的基石。组织机构区分核算组织和业务组织，对业务组织可以配置对应的组织职能。组织机构是数据隔离的基本前提。

**功能路径**

【系统管理】→【组织机构】→【组织机构】

======2 字段说明 ======

=====2.1 组织分类 =====

  - 组织分为核算组织和业务组织两种类型，必须至少选一个；
  - 核算组织：是会计做账的主体，建立会计核算体系的基本元素；
  - 业务组织：是业务运作的主体，根据勾选的业务职能决定组织的业务范围。

=====2.2 核算组织 =====

  - 核算组织是财务上独立核算的组织，可以建立会计核算体系，用来管理企业的财务记账与报告。
  - 核算组织需要成本核算，进行账务处理，出具利润报表。
  - 核算组织分为法人和利润中心两种，勾选时必须二选一。

=====2.3 业务组织 =====

  - 业务组织根据职能决定组织的业务范围。
  - 业务上独立运作的组织，用来管理企业的经营业务活动与数据，是核算组织财务记账的业务来源；
  - 勾选业务组织后，才可以选择具体的组织职能。

=====2.4 组织职能 =====

  - 组织因业务角色与职责不同而区分为不同的职能类型；
  - 组织职能应用是通过所选组织是否满足关键业务单据主业务组织的组织属性要求来控制的；例如：销售订单要求销售组织必须具有销售职能，那么BOS设计时，其主业务组织的业务组织职能为销售职能；
  - 金蝶云组织职能具体包括销售职能、采购职能、库存职能、工厂职能、质检职能、结算职能、资产职能、资金职能、收付职能、营销职能、服务职能等。

=====2.5 所属法人 =====

  - 当组织本身为法人时，所属法人就为本身；
  - 当组织为业务组织或者利润中心，必须从系统的法人组织中选择一个组织作为所属法人。

=====2.6 其他字段 =====

  - 编码:组织机构的编码，不能重复；
  - 描述:对组织的描述信息；
  - 组织形态:来源于组织形态基础资料，提供多个形态，例如：公司、工厂、事业部、分公司、办事处等，组织形态不会影响业务；
  - 法人：独立核算的法人组织，当核算组织被选中时，才可选择法人；
  - 利润中心：独立核算的利润中心，当核算组织被选中时，才可选择利润中心。

======3 功能操作 ======

=====3.1 启用多组织 =====

创建的数据中心默认是单体模式，进入【系统管理】→【组织机构】→【组织机构】→【启用多组织】，可以进行启用多组织的处理。

启用后即可进行多组织协同与结算业务，详见[[启用多组织|启用多组织]]。

=====3.2 新增=====

    1、打开“组织机构列表”界面后点击工具栏【新增】按钮，即可打开“组织机构-新增”界面进行创建；
    2、输入组织数据，包括组织编码、组织名称、组织形态等基本信息；
    3、选择组织分类和组织属性
         1）勾选核算组织后才允许选择下面的法人或者利润中心，且需至少选一个；
         2）勾选业务组织后才可以选择下面的组织职能，且需至少选一个职能；
         3）若核算组织=法人，所属法人是法人组织本身；否则若核算组织=利润中心，或者所定义的组织仅是业务组织（非核算组织）时，需要指定法人组织；
    4、点击工具栏的【保存】按钮，则组织机构创建完成；
    5、选择组织点击新增下的【复制】，即可进行组织的复制新增。
    
    
=====3.3 删除=====  

组织一旦提交审核，则不可删除，若不再需要，可以禁用。

=====3.4 禁用=====  

组织一般情况可以禁用；
若需要禁用法人组织，需要先禁用所有下属组织，再做禁用处理。

=====3.5 组织用户维护 =====

可以站在组织的角度添加用户，并同时可以为该用户分配角色。
  
  
=====3.6 其他操作 =====

过滤、新增、删除、提交、撤销、审核、反审核、禁用、反禁用、打印、预览、引入、引出、刷新、选项等，参见BOS平台附录。

======4 业务说明 ======

  - 只有已审核、未禁用的组织机构才可应用在业务中；
  - 组织机构禁用后，可以查询该组织的历史数据，也可以创建用户和角色；
  - 基础资料一般包括创建组织和使用组织，业务单据一般按主业务组织和协同组织区分；
  - 多组织应用涉及：按照组织进行数据隔离，业务领域按照组织属性以及组织业务关系进行处理，支持组织间结算等。

======1 组织机构概述 ======

===== 1.1 组织机构概述 =====
 
组织机构既是系统运行的基础，又是支持业务运作的基石，还是数据隔离的基本设置和前提。主要提供跟组织相关的功能，包括：组织机构、组织关系、基础资料控制、组织变更、组织快速启用等。

===== 1.2 系统特性 =====
 
本系统主要包含以下应用：

  - 组织机构：定义企业的组织机构，支持多组织业务；
  - 组织关系：通过设置组织隶属关系实现汇报关系的数据处理；通过设置组织业务关系实现跨组织结算业务；

## 【页面】组织隶属关系
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E7%BB%84%E7%BB%87%E9%9A%B6%E5%B1%9E%E5%85%B3%E7%B3%BB

====== 1 功能描述 ====== 

组织隶属关系是组织的上下级汇报关系，按组织的上下级关系来汇总统计业务数据，方便上一级组织的管理与分析。组织隶属关系根据组织职能建立组织的上下级关系，例如可以分别为HR、销售管理建立组织层级关系。组织隶属关系还支持自定义多个隶属方案，实现多方案的业务组织汇报关系。


**功能路径**

【系统管理】→【组织机构】→【组织关系】

 ====== 2 字段说明 ======


=====2.1 职能类型 =====
来源于系统中预置的组织职能，只有同一个职能的组织才能设置他们之间的隶属关系
=====2.2 顶层组织 =====
来源于组织机构，用来设置隶属关系的顶点对应的组织
=====2.3 可选组织 =====
可选组织是根据职能类型进行筛选的，一旦职能类型选择后，系统按此过滤出来具有该组织职能的业务组织。

=====2.3 隶属关系 =====

业务组织隶属关系显示在可选组织的右边，选择组织职能类型、顶层组织、可选组织后，就可以将可选组织加入隶属关系中，按树结构显示出来。

需根据组织职能来设置隶属关系，可以为同一个组织职能类型设置多套隶属关系。组织隶属关系设置后，组织在报表统计中的就会按此隶属关系进行上下级汇报，以便于业务报表在组织维度上进行统计汇总。
=====2.5 其他字段 =====

  - 启用日期、截止日期：在启用日期和截止日期这段时间之内，隶属关系才开始能被应用于报表统计中；启用日期必须小于等于截止日期；如果启用日期，截至日期相同（比如都是2012年7月30日），则说明当前的隶属关系在这一天（2012年7月30日）能被使用；
  - 默认方案：可以为同一个职能类型设置多个关于组织隶属关系的方案，但是只能设置其中一个为默认方案，根据隶属关系汇总上下级业务数据时，默认携带这个方案。

 ====== 3 功能操作 ======


=====3.1 新增 =====

    创建组织隶属关系
    1、打开“组织隶属关系列表”界面后，点击工具栏【新增】按钮，即可打开“组织隶属关系-新增”界面进行创建；
    2、输入方案编码、方案名称等基本信息；
    3、定义隶属关系
         1）选择职能类型后，下面的可选组织会显示所有具有所需职能的组织；
         2）选择顶层组织，作为隶属关系的顶点；
         3）选择左边的可选组织，添加到右边的隶属关系中；
         4）右边显示已设置的组织隶属关系，点击【上移】或【下移】，即可调整同一节点下组织的上下位置；
         5）勾选“默认方案”，即可将该隶属关系设置为默认方案；
   4、点击工具栏的【保存】按钮，则组织隶属关系创建完成。


 
=====3.2 其他操作 =====

过滤、新增、查看、修改、删除、提交、审核、反审核、禁用、反禁用、打印、预览、引出、刷新、选项等，参见BOS平台附录。 

 ====== 4 业务说明 ======

组织隶属关系目前在销售毛利润率表以及销售排行表中应用，详见销售排名表和销售利润估算分析表的隶属方案应用介绍。
