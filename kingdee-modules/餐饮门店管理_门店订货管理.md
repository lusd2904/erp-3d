====== 1.充值单 ======

===== 1.1 功能概述 =====
  * 充值单可以下推到付款单和收款单
  * 收款单/付款单：结算方式，由充值单充值方式携带而来。应付金额/应收金额，由充值单上的充值金额携带而来。
  * 如果移动端充值成功，cloud端的充值单的状态不是已审核，则可以通过点击更新支付状态来更新单据的状态
  * 手工新增充值单时，单据类型默认为线下充值，且支付状态默认为“未支付”，不可修改      
  * 充值方式增加枚举值：手工充值。当手工新增单据时，默认为手工充值，且不可修改                      
  * 线下支付，可删除；移动端生成的充值单不允许删除
  * 移动端由于网络等原因上传的充值单为非已审核状态时，点击更新支付状态即可更新
  * 通过移动端充值上传的充值单单据类型为线上充值
===== 1.2 字段说明 =====
^ 字段名称      ^ 字段说明                                          ^
| 门店类型      | 门店充值                                          |
| 支付状态      | 包括未支付和已支付两种                                   |
| 充值方式      | 微信和支付宝                                        |
| 下推        | 可以下推收款单和付款单                                   |
| 更新支付状态    | 如果已经支付成功了，cloud显示未支付，则可以点击更新支付状态按钮变更充值单的支付状态  |
| 已下推付款单金额  | 已支付状态的充值单可以下推到付款单，付款单审核时反写                    |
| 已下推收款单金额  | 已支付状态的充值单可以下推到收款单，收款单审核时反写                    |

===== 1.3 业务说明 =====
一、充值单下推付款单
  * 付款单单据头：往来单位类型，默认为供应商；
  * 往来单位，由充值单上的收款组织携带而来；
  * 业务日期、期望付款日期：由充值单上的日期携带而来；
  * 币别，由充值单上的币别携带而来。
  * 付款组织，结算组织，由充值单上的充值组织携带而来。 
  * 其他字段为空或者依据单据生成逻辑取值。                                                                           
  * 付款单单据体：结算方式，由充值单充值方式携带而来。
  * 应付金额，由充值单上的充值金额携带而来。其他字段为空或者依据单据生成逻辑取值。
二、充值单下推收款单
  * 收款单单据头：往来单位类型，默认为客户；往来单位，由充值单上的充值组织携带而来；
  * 业务日期，由充值单上的日期携带而来；
  * 币别，由充值单上的币别携带而来。
  * 收款组织、结算组织，由充值单上的收款组织携带而来。其他字段为空或者依据单据生成逻辑取值。                                                             
  * 收款单单据体：结算方式，由充值单上充值方式携带而来。
  * 应收金额，由充值单上的充值金额携带而来。其他字段为空或者依据单据生成逻辑取值。

===== 1.1 私有云 =====
===== 1.1.1 配置步骤 =====
1、本机用administrator账户登录星空

2、	进入“文件服务设置” –> 勾选“文件服务器” -> 点击“设置”按钮

3、	新增-文件服务配置 

  * 协议类型：和部署的IIS服务器设置有关，可以是http方式也可以是https方式，默认是http；

  * 端口：当前部署应用服务器端口，可为空；
  * 虚拟目录：当前安装应用服务器虚拟目录站点名称，默认为K3CloudFileServer;
  * 检测文件服务器是否可用：点击按钮进行测试，如果文件服务没有部署，则测试不能通过，保存也不会成功，也可用于检测其他已部署的文件服务是否可用；

===== 1.1.2 常见问题 =====

**  * (503) 服务器不可用**
 
（错误信息）请检查地址、端口等配置，或确认文件服务已经部署。具体报错原因：

System.Net.WebException: 远程服务器返回错误: (503) 服务器不可用。

在 System.Net.WebClient.DownloadDataInternal(Uri address, WebRequest& request)

在 System.Net.WebClient.DownloadData(Uri address)

在 Kingdee.BOS.FileServer.ProxyService.IISFileServerProxy.CheckFileService(FileServiceConArg arg)

解决：打开IIS -> 应用程序池 -> 启动K3CloudFileServer

[图:文件服务器错误1.png]

**  * 服务器500错误**

解决：重启IIS

[图:文件服务器器错误8.png]


**  * 服务器不可用（内存超过95%）**

错误如下图：

[图:文件服务器错误9.png]

2.	检查虚拟目录是否是K3CloudFileServer
3.	检查本机是否内纯超过95%
若都没有问题按一下方法解决
解决：https://vip.kingdee.com/article/12964
找到 中的WCF服务，全部安装好。然后设置一个存储目录。

====== 1.账户余额提现申请单 ======
===== 1.1 功能概述 =====
  * 账户余额提现申请单支持ERP手工新增和移动端的余额提现单
  * 余额提现单可以下推到付款单和收款单
  * 付款单/收款单：应付金额/应收金额由账户余额提现单上的充值金额携带而来
  * 只允许提现储值账户
  * 账户余额提现申请单下推收款单后财务人员才会把金额转到指定的银行卡
  * 账户余额提现申请单审核成功时会扣减对应账户的金额
  * 需要在门店订货账户设置中设置允许提现，提现付款组织，提现次数，提现额度最大值和最小值
===== 1.2 关键字段 =====
^ 字段名称      ^ 字段说明                          ^
| 门店类型      | 账户余额提现                        |
| 提现组织      | 哪个组织用来提现                      |
| 付款组织      | 哪个组织用来付款                      |
| 已下推付款单金额  | 已审核账户余额提现申请单下推到付款单，付款单审核时反写   |
| 已下推收款单金额  | 已审核的账户余额提现申请单下推到收款单，收款单审核时反写  |

===== 1.3 业务说明 =====
一、账户余额提现单下推付款单
  * 付款单单据头：往来单位类型，默认为供应商；往来单位，由充值单上的收款组织携带而来；
  * 业务日期、期望付款日期：由账户余额提现单上的日期携带而来；
  * 币别，由账户余额提现单上的币别携带而来。付款组织，结算组织，取系统参数上设置的提现付款组织。 
  * 其他字段为空或者依据单据生成逻辑取值。                                                                           
  * 付款单单据体：结算方式，为空。应付金额，由账户余额提现单上的充值金额携带而来。其他字段为空或者依据单据生成逻辑取值。
二、账户余额提现单下推收款单
  * 增加账户余额提现单---收款单单据转换规则，单据类型为：其他业务收款单，                                              
  * 收款单单据头：往来单位类型，默认为客户；
  * 往来单位，由账户余额提现上的提现组织携带而来；
  * 业务日期，由账户余额提现单上的日期携带而来；
  * 币别，由账户余额提现单上的币别携带而来。
  * 收款组织、结算组织，由账户余额提现单充值单上的提现组织携带而来。其他字段为空或者依据单据生成逻辑取值。                                                             
  * 收款单单据体：结算方式，为空
  * 应收金额，由账户余额提现单上的提现金额携带而来。其他字段为空或者依据单据生成逻辑取值。

====== 1.门店要货申请单 ======

===== 1.1功能概述 =====

门店要货申请单是门店用来提交要货需求的申请。然后，总部根据要货需求及库存情况进行配送处理。

作为门店货品来源的依据之一，是门店各业务部门或计划部门根据门店食品消耗计划、食品需求等实际情况，向总部提出食品申请的单据；申请单经过各方面的审核后，才能进行配送。
 
===== 1.2 使用前提 =====

定义门店要货申请单的单据类型、业务组织、配送组织、物料、单位等。

===== 1.3 字段说明 =====

==== 1.3.1 表头基本字段说明 ====


  -单据类型：标准要货申请单
  -单据编码：门店要货申请单的单据编码，具有唯一性并遵循门店要货申请单编码规则 
  -申请日期：门店要货申请单的申请日期 
  -单据状态：申请单的状态 
  -申请组织：申请单的发出组织 
  -申请人：申请的发起人，从职员基础资料中进行选择，必须为申请部门下的职员 
  -申请部门：申请的需求部门。从部门基础资料中选择，必须为申请组织下的部门 
  -备注 补充说明

===== 1.4 业务说明 =====

一、门店要货申请单合并业务

合并功能主要应用于客户对门店要货申请单数据的整理，用户可以按业务需要例如按配送组织、需求组织等过滤出门店要货申请单列表，然后对多张门店要货采购申请单据进行合并，满足以下条件的申请单才能合并：

（一）单据状态为“创建”，且作废状态为“未作废”的门店要货申请单才能进行合并 

（二）相同单据类型的门店要货申请单才能进行合并 

（三）必须【配送组织】、【需求组织】相同的门店要货申请单才能进行合并 

（四）门店要货申请单上存在源单单号，则不能进行合并 

（五）门店要货申请单上的币别对合并没有影响 

二、门店要货申请单合并业务

必须遵从以下规则：

（一）门店要货申请单合并后不记录合并前后单据的对应关系 

（二）合并在单据编码最小的申请单上，其余单据在合并后系统自动删除 

（三）合并时，单据头信息默认取第一张单据（即单据编码最小的单据）的单据头信息 

（四）合并时，单据体的记录行依照单据编码顺序以及行号依次并在单据编码最小的申请单上 

（五）合并时，新单据体如果存在相同的物料、且物料属性相同时，将相同物料的数量合并，合并后的物料记录行其他信息默认取第一条物料的对应信息 

（六）合并时，如果进行合并的记录中，相同属性的物料，如果单位不一致，则统一转换为采购单位，申请数量按库存单位进行转换后，再进行合并。合并到新单的单位为库存单位，申请数量为转换合并后的数量 

（七）合并时，单据体上相同的物料，但物料属性不相同时，不对该记录行进行物料的合并 

（八）合并后的新单为创建状态，单据编码符合编码规则自动编码 

三、门店要货申请单单据转换业务 

门店要货申请单可以下推门店要货申请汇总单，也可以在门店要货申请汇总单界面选单门店要货申请单生成门店要货申请汇总单，实现关联业务的转化，门店要货申请单与门店要货申请汇总单转化的规则如下：

（一）单据状态为“已审核”，且业务关闭状态为“正常”，且业务终止状态为 “正常”的门店要货申请单才能转换为门店要货申请汇总单 

（二）在门店要货申请汇总单界面选单时，可选择的申请单列表界面默认只过滤出符合上面条件的申请单 

（三）申请单下推汇总单时，申请单的字段关联携带到汇总单上 

（四）门店要货申请单转换为门店要货申请汇总单时按平台的方式支持一对一转换、多对一转换、按分组策略合并转换 

（五）门店要货申请单的分组策略支持按物料、配送组织、到货日期等的合并转换 

（六）按分组策略转换时存在相同记录行合并转换，则门店要货申请汇总单的交货明细页签需要跟踪到源单的单号、行号 

（七）门店要货申请汇总单保存后，关联反写申请单的关联数量字段；汇总单删除后，也需更新申请单的关联数量字段；门店要货申请汇总单审核后，关联反写申请单的汇总单数量字段，汇总单反审核后，也需要更新申请单的汇总单数量字段

2、门店退货单只有作废与反作废一种整单单据操作

作废操作类似于门店要货申请单，这边就不复述，请参考门店要货申请单

===== 1.5 业务说明 =====

**库存查询** 

门店退货单上支持库存查询功能，直接调用库存数据，具体库存查询的规则同门店要货单，请参考门店要货单

**补货处理** 

退料单支持补货处理，退料方式为： 退货补货。

当系统参数“配送退货时自动创建补货申请”打勾，则门店退货单根据补料数量自动生成门店要货申请。否则需要手工生成要货申请。

**即时库存更新** 

门店退货单会按照库存参数【库存更新方式】影响库存数据，规则如下

  * 门店退货单【库存状态】字段为空时不更新库存，不为空时更新库存 
  * 门店退货单更新库存量以【实退数量】为准 
  * 保存、反作废、审核时扣减库存，删除、作废、反审核时增加库存，具体以【库存更新方式】为准 

**门店退货单批号相关业务**

  * 门店退货单行操作菜单上提供批号相关操作，有以下二种
  * 批号库存，以批号为维度查询物料库存 
  * 批号主档，查询当前物料的批号主档
  * 门店退货单单据转换 
  * 门店退货单可以直接下推门店要货申请单，也可以在门店要货申请单界面选单门店退货单生成，实现关联业务的转化，转化的规则如下：

  * 单据状态为“已审核”，【补料方式】为“创建订单补货”且【补料数量】大于【关联数量】的门店退货单才能转换门店要货申请单   
  * 在门店要货申请单界面选单时，可选择的门店退货单列表界面默认只过滤出符合上面条件的门店退货单 
  * 选择多张门店退货单合并生成门店要货申请单时，退料组织、配送组织、结算币别相同的分录才能合并到一张门店要货申请单上  
  * 门店退货单下推门店要货申请单时，门店退货单的字段关联携带到门店要货申请单上 
  * 门店要货申请单的【数量】不能大于【补料数量】-【关联数量】，否则门店要货申请单无法保存、反作废 
  * 门店要货申请单保存、反作废时，累计反写门店退货单【关联数量】，作废以及删除时需要相应扣减数量
