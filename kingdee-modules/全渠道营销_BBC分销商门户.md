======全渠道营销门户说明======
[图:bbc商城门户登录流程.png]

不同的渠道类型或用户类型设置了不同的商城门户，目的在于使每个用户进入门户后都能进行针对性的操作。
系统检验录入用户账户，并根据用户的账户找到对应的会员ID、渠道ID，如果用户账户的类型是：
  * B2C类型：直接进入B2C网上商城首页（暂不支持，后续开发）
  * B2B类型 & 渠道ID对应的渠道性质=直接渠道：则直接进入B2B直接渠道门户首页（直接渠道）
  * B2B类型 & 渠道ID对应的渠道性质=中间渠道：则直接进入B2B中间渠道门户首页（中间渠道）
  * B2B类型 & 渠道ID对应的渠道性质=终端门店：则直接进入B2B终端门户首页（终端门店）
  * 商家类型：则直接进入商家首页（暂不支持，后续开发）

## 【页面】下游订单发货情况表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8B%E6%B8%B8%E8%AE%A2%E5%8D%95%E5%8F%91%E8%B4%A7%E6%83%85%E5%86%B5%E8%A1%A8

**功能说明：**

对应的下级渠道的所有订单发货情况统计

**功能路径：**

【报表分析】—>【下游订单发货情况表】

**使用前提：**

无

**字段说明：**

报表过滤界面字段说明：

  - 所属渠道：法人渠道，当业务员对应的渠道是门店时，则所属渠道为门店的法人渠道
  - 所属门店：业务员归属门店
  - 时间维度

  *    自定义时间：开始日期、结束日期
  * 开始日期：默认为当月第一天
  * 结束日期：默认当前日期。
  *   今年以来：从当前年度的1月1日；
  *   最近1年：当前日期倒退1年，如当前日期是2016-11-16，则最近一年，的时间范围是2015-11-17~2016-11-16。
  *   本周：从星期天开始到当天；
  *   今天：系统当天日期


**操作说明：**

与其它报表操作类似

## 【页面】下游订单处理
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8B%E6%B8%B8%E8%AE%A2%E5%8D%95%E5%A4%84%E7%90%86

**功能说明：**

上级渠道对下级渠道的订货订单处理

**功能路径：**

【我的订单】->【下游订单处理】

**使用前提：**

当前登记用户渠道为直接渠道

**字段说明：**

下游订单处理显示字段说明
| **名称**  | **字段说明**                                         |
| 表头                                                        ||
| 编号      | B2B渠道订单编号                                        |
| 日期      | 渠道订单下单日期                                         |
| 要货渠道    | 要货渠道，一般为下级渠道或下级渠道对应的门店                           |
| 状态      | 下游订单单据处理状态，与订单状态一致                               |
| 总数量     | 订单所有分录商品数量的汇总                                    |
| 总金额     | 订单所有分录价税合计的汇总                                    |
| 单据类型    | B2B渠道订单或渠道配件订单                                   |
| 表明细                                                       ||
| 商品编码    | 携带渠道入库单明细对应字段                                    |
| :::     | 显示商品编码、名称、商品规格、图片等                               |
| 计量单位    | 订单销售单位                                           |
| 批准数量    | 当前登录渠道批准订货数量                                     |
| 订单数量    | 上级渠道申请订货数量                                       |
| 实际单价    | 渠道订货时实际销售的价格                                     |
| 金额      | 企业发给渠道订货的标准价格                                    |
| 未发货数量   | 未发货数量=批准数量 – 已发货数量。                              |
| 库存数量    | 当前登记渠道对应行商品的即时库存数量                               |
| 行状态     | 与单据状态类似，记录每一行商品的处理状态。包括：保存、提交、审核、打回、关闭、部分发货、已完成  |
| 操作      | 记录显示允许对单据行的具体操作                                  |

**操作说明：**
  - 进入下游订单处理页面
  - 对应不同的订单处理，选择不同的过滤页签
  - 进入选择不同的过滤页签，勾选需要处理的订单，点击操作即完成处理；

过滤页签说明：
  * 待确认：过滤处理需要确认的订单，支持打回、关闭处理；
  * 待审核：过滤处理需要审核的订单，支持打回、关闭处理；
  * 待发货：过滤处理已审核待发货的订单，可支持关闭处理；
  * 所有订单：包含了全部下游渠道或门店申请提交的订单，只查询而不允许做任何操作；

## 【页面】下游退货管理
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E4%B8%8B%E6%B8%B8%E9%80%80%E8%B4%A7%E7%AE%A1%E7%90%86

**功能说明：**

退货管理用于用户已经收货后的退货以及历史退货记录查询，及
上级渠道对下级渠道的退货处理等。

**功能路径：**

【退货】->【下游退货管理】

**使用前提：**

当前登录的渠道具有下级渠道

**字段说明：**
| **名称**  | **字段说明**            |
| 表头                           ||
| 申请单编号   | 退货申请单单据编码，系统自动生成    |
| 申请单日期   | 退货申请单的单据日期          |
| 单据状态    | 显示当前退货申请单的单据状态      |
| 签收状态    | 显示当前退货申请单的签收状态      |
| 表明细                          ||
| 商品编码    | 显示商品编码+商品名称+商品规格型号  |
| 订单数量    | 退货申请单对应的订单的商品订货数量   |
| 已签收数量   | 上级渠道累计退货入库数量        |
| 已退数量    | 下级渠道累计退货出库数量        |
| 申请退货数量  | 退货单申请退货数量           |
| 实际价格    | 退货商品对应的实际销售单价       |
| 价税合计    | 退货商品对应的实际价税合计       |
| 签收状态    | 退货签收状态，与订单的签收状态类似   |

**操作说明：**

1、进入下游退货管理，根据需要选择处理不同的订单
  * 所有退货申请：显示所有供货方类型为渠道且供应方为当前登录渠道的退货申请单。只允许查看；
  * 待审核：显示所有供货方类型为渠道、供应方为当前登录渠道且退货申请单的单据状态为提交状态的退货申请单。允许审核、打回、刷新操作；
  * 待入库：显示所有供货方类型为渠道、供应方为当前登录渠道且下游渠道已发货而未签收的退货申请单。允许退货入库、刷新操作；
2、勾选对应的订单进行处理，当退货申请单的单据状态为已完成时，则表示退货申请已完成。

## 【页面】入库明细表
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%85%A5%E5%BA%93%E6%98%8E%E7%BB%86%E8%A1%A8

**功能说明：**

用于统计分析和查询渠道的所有入库明细

**功能路径：**

【报表】->【入库明细表】

**使用前提：**

无

**字段说明：**

报表过滤界面字段说明：

  *   今年以来：从当前年度的1月1日开始；
  *   最近1年：当前日期倒退1年，如当前日期是2016-11-16，则最近一年，的时间范围是2015-11-17~2016-11-16。
  *   本月：从当前月的1号开始到现在；
  *   上月：当前月的上一个月；
  *   本周：从星期天开始到当天；
  *   今天：系统当天日期
  *   更新过滤条件：可以自定义选择相关条件，如供应货渠道、出库仓库、单据类型等；

**操作说明：**
  - 进入入库明细表；
  - 默认显示当前登录渠道本月的入库明细表；
  - 支持选择不同的筛选条件进行过滤，并将数据查询显示出来。

## 【页面】公告发布
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%85%AC%E5%91%8A%E5%8F%91%E5%B8%83

**功能说明：**

允许直接渠道发布公告给下级渠道

**功能路径：**

【渠道中心】->【公告发布】

**使用前提：**

无

**字段说明：**

略

**操作说明：**
  - 新增公告：进入公告列表，点击【新增】按钮即跳转至公告新增页面。填写相关信息
  - 发布公告：新增的公告默认是未发布，需要手工点击发布。发布后，对应的发布渠道BBC商城前台可查看到公告。公告的发布日期为点击发布后取的系统即时日期；
  - 取消发布：会将发布状态置为否，对应的发布渠道BBC商城前台将不再看见公告；
  - 删除：只有未发布的公告才允许删除，已发布的公告删除时提示【发布中的公告不允许删除】并删除失败；
  - 查看公告：在公告列表里选择对应的公告双击即可查看公告详情

## 【页面】加入购物车
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%8A%A0%E5%85%A5%E8%B4%AD%E7%89%A9%E8%BD%A6

**功能说明：**

与线上商城（如淘宝、京东等）的购物车功能一致

**功能路径：**

【订货】->【快速订货】 ->【加入购物车】或者

【订货】->【配件订货】->【加入购物车】

**使用前提**：

无

**字段说明：**
订货页面展示字段说明：
| **字段**  | **字段说明**                                  |
| 商品图片    | 显示商品的主图                                   |
| 商品名称    | 显示商品名称                                    |
| 商品价格    | 商品的销售价：取商品发布表的价格，具体逻辑，请参考后台的【渠道可销售商品信息表】  |
| :::     | 商品的市场价：取商品档案的市场价                          |
| 库存量     | 取商品发布表的库存量                                |
| 展示品牌    | 根据展示的商品，列出相应的商品品牌                         |
| 展示商品标签  | 根据展示的商品，列出相应的商品便签                         |
| 销售组织    | 界面不显示，但需要记录商品的发布组织，以便加入购物车时携带             |

购物车展示字段说明：
|**名称**|**字段说明**|
|销售组织|关联销售组织表|
|商品ID|关联商品档案表|
|SKUID|关联商品档案表的SKUID|
|规格|显示商品的规格，如果没有规格管理，则为空|
|订购数量|订货数量，可编辑修改|
|订购价格|根据所选择的订购商品自动携带，不可编辑|
|订购单位|根据所选择的订购商品自动携带，不可编辑|
|商品规格|可编辑|

**操作说明：**

1）选择商品

可以按商品或配件分类进行模糊查询搜索，也可以按商品品牌或标签进行过滤选择

配件订单可以根据商品进行查询（商品所包含的配件）

除了大图订货外也支持列表订货，点击订货页面右上方的转换按钮即可以实现不同订货方式的转换
 
2）加入购物车

大图订货：输入订购数量，点击【加入购物车】即可。可重复添加，数量根据加入的次数进行累加 

列表订货：输入订购数量，点击【加入购物车】即可。可重复添加，数量根据加入的次数进行累加
 
3）查看购物车

## 【页面】库存初始化
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E5%BA%93%E5%AD%98%E5%88%9D%E5%A7%8B%E5%8C%96

**功能说明：**

用于系统上线库存初始化操作

**功能路径：**

【我的进销存】->【库存初始化】

**使用前提：**

系统上线前期准备，无任何库存数据

**字段说明：**
| 显示字段说明                       ||
| **字段**  | **字段说明**            |
| 期间      | 初始化期间‘年月’，以月作为期间单位  |
| 开始日期    | 具体初始化开始的日期‘年-月-日’   |
| 结束日期    | 具体初始化结束的日期‘年-月-日’   |
| 启用日期    | 具体启用初始化的日期‘年-月-日’   |
| 初始化状态   | 包含‘未启用、启用、结束初始化’    |

**操作说明：**

初始化流程：

启用初始化-》录入渠道的各个仓库的初始化入库单-》初始化对账-》结束初始化。

**第一步：启用初始化**

需要确定初始化的期间，比如目前南昌是 11 月，启用日期是 11.1 日。则初始 化入库单的单据日期必须是 11.1 日以前，初始化入库单的日期就可以填写 10.31 日。 

操作：
  - 选择一个初始化期间后，启用日期默认为当前选中的期间的开始日期，用户可以修改，修改的日期范围为大于等于开始日期，小于等于结束日期。 
  - 启用初始化的检查：
  * 如果有初始入库单的单据日期大于等于启用日期，则不允许启用，提示用户，让用户调整单据，调整完成后再启用。 
  * 检查渠道入库单（初始化入库除外）、渠道出库单，如果单据日期小于启用日期，则不允许启用，提示用户，让用户调整单据，调整完成后再启用。

**第二步：初始化入库单录入**

如果已经启用了初始化，但未结束初始化，则： 
  - 所有的非初始化库存单据都必须大于等于启用日期。 
  - 所有的初始化库存单据的单据日期必须小于启用日期。 

如果已经结束初始化，则： 
  - 不允许再录入初始化入库单
  - 所有的初始化库存单据的单据日期必须小于启用日期。

**第三步：库存初始化对账**
 
  * 列出已经初始化库存数据报表，用户自己核对。
  * 过滤范围：入库渠道包括当前渠道所属的法人渠道、及其下属门店渠道的初始化入库单， 并且按商品+ SKU+渠道+仓库分组汇总展示。

**第四步：结束初始化**
  - 先从期间表中列出所有的期间；
  - 用户点击“初始化库存查看”，确定初始化数据已经正确无误。
  - 用户用户选择一个期间，点击【结束初始化】。
  - 系统将初始化库存数据结转到渠道期间库存表中。
  - 记录下当前渠道已经完成了初始化。
  - 用户再次进入初始化界面时，系统自动显示初始化期间，初始化状态=已完成。此时不能再结束初始化。

流程说明：
  - 间接渠道向上级渠道提交退货申请单；
  - 上级渠道处理退货申请单，支持打回或审核通过处理；
  - 间接渠道对于已审核的退货申请单，可以进行手工的渠道入库生成红字渠道入库单。当实物退货出库时，审核渠道入库单，并同步更新库存；
  - 上级渠道根据收到的实物退货，选择相应的退货审核单手工生成红字有渠道出库单。实物退货入库时，审核渠道出库单，并同步更新库存。

## 【页面】返利余额
来源：https://help.open.kingdee.com/dokuwiki/doku.php?id=%E8%BF%94%E5%88%A9%E4%BD%99%E9%A2%9D

**功能概述：**企业建立返利账户后，客户在返利结算管理时，返利金额会记录到自己的返利账户上，返利账户使用后也会及时更新客户的返利余额。

**使用前提：**客户使用返还到返利账户余额的返还方式，返利账户已结束初始化。

**功能路径：**【电商与分销】－>【返利管理】－>【返利余额】－>【返利余额】

**返利余额字段说明：**

|**字段**||**说          明**|
|核算组织||处理返利核算的财务组织。|
|返利账户||基础资料中维护的返利账户。|
|客户||返利账户的主体对象，客户可以建立多个不同的返利账户。|
|币别||处理返利业务的结算币别。|
|返利余额||客户当前返利账户上的返利金额。|
|数据状态|||
|更新日期||根据返利计算结果生成，携带返利方式，包括：冲减应收款、其他应付款、赠品出库返还、返还到账户余额。 |
|是否初始化||客户返利账户是否结束初始化的标记，客户的返利账户必须结束初始化后才允许进行账户余额的更新。|

**操作说明：**
  * 新增：只有初始建立客户返利余额时使用，通过新增录入客户的初始化账户余额，提交审核后即结束初始化。对于已经结束初始化的客户账户不允许再次新增。
  * 初始化：用户选中一张返利结算单后进行结算，则进入生成下游单据的选择页面，根据返利的返还方式选择生成不同的下游单，包括：其他应收单、其他应付单或其它出库单以及客户返利账户余额、返利流水明细。
  * 余额调整：根据实际的返利管理情况，对客户的账户余额提供手工调整金额的操作，允许填写客户余额的调整金额，确定后修改客户当前的账户余额；填写正数，增加余额，填写负数则减少余额
  * 业务说明：客户通过结算单返利结算后生成账户余额，若该客户无初始化余额，则该笔结算金额生成客户余额后自动结算初始始化。对账户余额的每一笔更新都会记录到返利余额流水中。

**操作说明：**

  * 待审核：过滤处理需要审核的退货申请单，只支持撤单处理；
  * 待发货：过滤处理已审核待发货的退货申请单，只支持退货出库处理；
  * 待签收：过滤查看已发货待签收的退货申请单，只允许查询不允许任何操作；

  * 删除：退货申请单的单据状态为保存、打回或手工关闭时才可以删除，其他的状态不允许删除。
  * 撤单：退货申请单.的单据状态为已提交或已确认时，才可以撤单处理，其他的状态不允许撤单。
  * 退货：退货申请单的单据状态为审核时，显示退货，点击退货按钮进入渠道入库单退货流程。

  * 关键字查询，在输入框中输入“牛奶”，则表示查询商品包括牛奶 或者 商品编号包括牛奶 或者 订单编号包括牛奶的订单，查询范围是所有退货申请单。
  * 时间段查询，提供当天、一周以内、一月以内、三个月以内、指定时间范围的查询，查询范围是对当前选定的页签。比如当前是在待签收页签，如果选择当天，则表示当天待签收的退货申请单。
