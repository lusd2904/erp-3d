# WP03 审批流设计

## 边界

审批流是 L2，引擎只负责提交后的流程实例、待办和流转；单据状态与审核、副作用仍由 L1 `BillOpService` 管理。BPMN 解析出的模型固定保存在流程定义版本上，实例引用该版本，后续发布不会改变运行中流程。

## 流程生命周期

单据提交时，L1 在事务内将单据改为 `AUDITING`，`WfBridge` 匹配组织、单据类型、生效期和启动条件。匹配到流程时，创建实例并按开始节点展开任务；没有匹配流程时，由 L1 保持原有人工审核行为。

审批动作先锁定单据头，再锁定 `wf_instance` 和任务，之后验证处理人、节点能力和任务状态，以统一 L1 单据操作的锁顺序。会签按 `any`、`all`、`ratio`、`votes` 判定；顺序会签只开放当前顺位任务。节点通过后取消同节点剩余任务，节点抄送在此时创建。加签人全部同意后原待办恢复；转交保留任务历史并改派当前处理人。

流程到达结束事件时，实例完成和 `BillOpService.auditByWorkflow` 在同一 `DbService.tx` 中提交。L1 审核失败时，审批票、实例状态和单据副作用一并回滚。驳回到发起人、撤回和管理员终止会结束流程并调用 L1 驳回回调；驳回到已处理节点会取消当前待办、递增轮次并重新创建目标节点任务，单据仍为 `AUDITING`。

代理仅在任务创建时解析生效期内的直接代理人，任务同时记录本人和当前处理人。用户可在 `/wf/delegations` 设置、查看和撤回自己的授权；撤回或后台任务发现代理过期时，待办都在事务内归还本人并记录操作日志。节点超时任务通过 `JobScheduler` 注册，由 `MysqlLockService` 避免多实例重复提醒。

## 数据与接口

审批实例、定义版本、模板、任务、动作日志、代理、超时计划和流程变量存放在 `wf_*` 表。模型和会签规则存 JSON；并行网关汇合状态存实例变量，不保存在进程内存。流程动作通过 `todo.changed` 在事务提交后通知用户。

API 挂载在 `/api/v1/wf/`，提供定义校验、草稿与发布、模板、代理授权、待办、已办、发起流程、抄送、审批、驳回、撤回、转交、加签和终止。`GET /api/v1/bills/{form}/{id}/flow` 返回实例、任务和动作历史。

## 验收

`test/engine/07-approval.e2e-spec.ts` 覆盖 60% 比例会签自动终审、第三节点退回第二节点后重办、代理期内派给代理人及过期归还，并补测转交、顺序加签、撤回和超时站内提醒。WP02 原 01–06 用例保持不变。
