## 1. 金蝶把“流程”拆成四层

| 层 | 金蝶的叫法 | 负责什么 | 关键原文 |
|---|---|---|---|
| L1 单据状态机 | BOS 单据状态字段 + 操作列表 | 单据和行的状态，以及“哪个操作把状态从 A 改成 B” | 【单据状态】【操作列表】【bos通用操作列表】 |
| L2 审批 / 工作流 | 审批流、工作流 | 单据提交后的多级审批、条件路由、会签、驳回、消息、自动动作 | 【审批流设计】【工作流设计器】 |
| L3 业务流程 | 业务流程 / 自由流程 | 多张单据之间的上下游路线，以及允许走哪条路线 | 【业务流程】【业务流程与自由流程】 |
| L4 单据转换与反写 | 单据转换规则、反写规则 | 下推 / 选单时字段怎么带过去；下游怎样回写上游的累计数量和关闭状态 | 【单据转换规则】【反写规则】 |

这一点决定了选型：**通用 BPMN 引擎（Flowable / Camunda）只覆盖 L2**。L1、L3、L4 在任何方案下都要自己写。

## 2. 单据状态（L1）

### 2.1 通用状态【单据状态通用说明】【bos通用操作列表】

| 状态 | 进入方式 | 原文要点 |
|---|---|---|
| 暂存 | 暂存 | 不做合法性校验；报表统计不考虑暂存单据 |
| 创建 | 保存 | 校验编码唯一、必录和合法性 |
| 审核中 | 提交 | 适用于暂存、创建、重新审核三种状态；先保存再提交 |
| 已审核 | 审核 | 审核中或重新审核 → 已审核；启用审批流后，由终审节点执行审核 |
| 重新审核 | 反审核 / 撤销 / 驳回 | 反审核：已审核 → 重新审核；撤销：审核中 → 重新审核 |

### 2.2 其他独立的状态维度
- **关闭**：只对已审核单据有效，已审核 → 关闭。另有行级业务关闭，由反写的关闭控制自动置位。【bos通用操作列表】【反写规则】
- **作废**：只对已审核单据有效。【bos通用操作列表】（合稿复核改判：按具体单据页，只能作废创建 / 重新审核的单据，见需求说明书 C-01）
- **禁用**：用于基础资料，只对已审核的基础资料有效。【bos通用操作列表】
- **冻结 / 终止**：用“状态转换”操作自定义，可以加在表头或表体。【bos通用操作列表】
- **业务状态**（行级，各单据自己定义）：例如工序计划行为 创建 / 计划 / 计划确认 / 下达 / 开工 / 完工 / 关闭，可以通过行执行 / 反执行跳转。【工序计划状态控制】

### 2.3 操作约束【bos通用操作列表】
- 删除：只能删暂存或创建状态的单据。
- 修改：只能改暂存、创建、重新审核状态的单据。

### 2.4 配置能力【单据状态】【操作列表】
- 每个状态可以配置字段控制（可否编辑）和菜单控制（可否点击），还可以设“清空操作字段”，例如重新审核时清空审核人。
- 每个操作可以绑定状态字段及目标值，并配置校验规则、权限项、是否写操作日志。

### 2.5 职责分离参数（按单据配置）【单据参数配置】
- 审核人与创建人不能是同一人。
- 反审核人必须是审核人。
- 删除人、修改人必须是创建人。
- 操作二次验权。

## 3. 审批流 / 工作流（L2）

| 能力 | 金蝶原文 | 来源 |

| 可视化建模 | 两个设计器。审批流有开始、审批、终审、消息、人工服务、结束节点；工作流按流程 → 节点 → 动作三层，一个节点可以有多个自动动作，但只能有一个人工动作 | 【流程设计器】【审批流设计】【工作流设计器】 |
| 审批节点 | 普通审批节点不改单据状态，终审节点完成审核；审批项分正向、驳回、终止三类，可以自定义并绑定表单操作 | 【审批流设计】【工作流设计器-审批-字段说明】 |

| 会签 | 按票数（确定票数 / 比例票数）或按投票人数（比例人数）判定；可以要求按顺序处理；与“指定下一步处理人”“选择驳回节点”互斥；会签节点不支持超时 | 【会签审批流程】【高级选项_页签】【工作流设计器-审批-字段说明】 |
| 条件分支 | 两种：流程模板的启动条件，或连线上的条件 | 【条件分支流程】 |
| 并行分支 | 出入模式分并行（等全部前序到达）和串行（任一到达即走，其余丢弃） | 【并行分支流程】 |
| 参与人 | 用户、角色、任岗员工、岗位、部门（负责人 / 直属员工 / 全部员工，可含上下级部门）、汇报关系（上级、下级、同级）、流程变量（发起人）；可用并且、或者、排除组合；可设参与人方案优先级；解析不到人时跳过节点 | 【工作流设计器-审批-字段说明】【岗位信息】 |

| 传阅、批量处理、指定下一步处理人、追加参与人 | 节点选项；追加参与人的前提是允许指定下一步处理人 | 【高级选项_页签】 |
| 驳回 | 工作流必须画驳回线，不能驳回到开始节点；审批流在运行时选择驳回节点，可以默认驳回到开始节点；驳回后单据进入重新审核 | 【工作流设计器】【审批流设计器-字段说明】 |
| 撤回 / 撤销 | 发起人撤销提交：审核中 → 重新审核。处理人撤销已办：节点勾选“允许撤销”后，在后续任务还没处理前可以撤回到原节点，并执行“撤销操作”关联的补偿操作。参数“流程任务撤销回本人” | 【bos通用操作列表】【工作流设计器-审批-字段说明】【流程中心系统参数】 |

## 4. 业务流程、单据转换、下推与选单（L3 / L4）

- **业务流程**【流程设计器】【业务流程配置中心】【业务流程管理中心】【子流程嵌套】
  - 由单据节点、子流程节点（只能作末端）和连线组成；连线上可以挂专属反写规则和流程消息。
  - 保存后为“创建”，发布后为“启用”并生成版本。
  - 按入口单据加单据类型配置版本，带生效和失效日期，可设默认流程；一个入口单据对应一个模板。
  - 下推时生成业务流程实例号并一路携带；运行中的实例可以强制切换版本。
- **自由流程**：只靠单据转换规则下推。【业务流程与自由流程】
- **单据转换规则**【单据转换规则】
  - 基本设置：源单 → 目标单；主实体关联和控制字段；单据类型映射。
  - 字段映射方式：自动、公式、求和、平均、计数、最大、最小、逗号连接；另有过滤和仅过滤。
  - 分组：一对一、多对一、按规则分组合并。
  - 其他：排序、选单条件、插件、表单服务、尾差处理。
- **运行时操作**：下推、选单、特定下推、特定选单、上查、下查、全流程跟踪。【下推与特定下推】【bos通用操作列表】
- **列表选项**（按用户保存）：下推或选单时整单转换；上查、下查按整单；下推和选单的默认目标单据。【选项设置】
- **单据参数**：批量下推“生成全部”失败的单据自动暂存；下游分录超过 X 行时自动拆单（系统隐含上限为 1 万行）。【单据参数配置】
- **自动下推三种方式**【自动下推】
  - 工作流的“自动单据转换”动作，要求规则是一对一。
  - 在审核操作上配自动下推服务。
  - 插件。
- **反写规则**【反写规则】
  - 触发：保存或审核时反写；删除或反审核时回滚。
  - 方式：累加、扣减、覆盖（带回滚值）。
  - 多源分配：自上而下，或按权重；可设分配上限。
  - 关闭控制：设行关闭条件；整单关闭可按“任一行关闭”或“全部行关闭”。
  - 超额控制：禁止超额、允许超额一次、允许超额；可配校验公式。
  - 原文场景：跨级反写、同组反写、按 98% 关闭、按 1.2 倍超额。
  - 规则状态：草稿、正常、禁用。
- **单位换算**：数量统一按基本单位数量传递和反写。【单位换算处理】
- **单据类型**：可以绑定编码规则、布局（视图）、必录和锁定（与 BOS 设置叠加，从严）、业务流程及版本、打印控制。【单据类型】

## 5. 我们的流程引擎功能清单

一期按电子元器件 ERP 的实际需要裁剪；二期是增强项。

| 编号 | 功能 | 一期 / 二期 | 对应金蝶 |
|---|---|---|---|
| F1 | **单据状态机**：每类单据用 JSON 定义状态、操作、前置条件、字段锁定和菜单控制；通用操作包括暂存、保存、提交、撤销、审核、反审核、关闭 / 反关闭、作废、删除；支持行级业务状态和执行 / 反执行 | 一期 | L1 |
| F2 | **职责分离参数**：审核人≠创建人、反审核人=审核人、关键操作二次验权 | 一期 | 单据参数配置 |
| F3 | **流程设计器**：用 bpmn-js 可视化建模，只用 BPMN 子集（开始、用户任务=审批节点、终审标记、排他网关 / 并行网关、服务任务=自动动作、结束），中文属性面板 | 一期 | 审批流 / 工作流设计器 |
| F4 | **流程定义版本、模板、启停**：按单据（及单据类型）配置启动条件、生效期和节点视图，一张单据只挂一个模板，用启动条件区分；运行中的实例继续走旧版本 | 一期 | 流程配置中心 |
| F5 | **审批节点**：参与人可以是用户、角色、部门负责人、发起人上级（按部门树或汇报关系）、发起人本人；解析不到人时跳过或转给管理员（可配） | 一期 | 参与人 |
| F6 | **顺签 / 或签**（任一人通过）和**会签**（全部通过 / 按比例 / 按票数，可选按顺序处理） | 一期 | 顺签、会签 |
| F7 | **条件分支**（连线表达式，取单据字段，如金额、客户等级）和**并行分支**（并行网关，全部汇合） | 一期 | 条件 / 并行分支 |
| F8 | **驳回**：驳回到发起人，或驳回到任一已走过的节点（运行时选择）；驳回后单据进入重新审核 | 一期 | 驳回 |
| F9 | **撤回**：发起人在第一个节点处理前撤回；处理人在下一节点处理前撤回自己的审批 | 一期 | 撤销 |
| F10 | **转交**（转办）和**加签**（前加签 / 后加签） | 一期：转交、后加签；二期：前加签、传阅 | 转发、加签 |
| F11 | **代理（委托）**：按时间段和流程模板，把任务委托给他人，待办标记委托；委托可以撤回 | 一期 | 流程委托 |
| F12 | **待办中心**：待办、已办、我发起的、抄送；在单据页上直接审批；审批意见和审批历史时间线；流程图上高亮当前节点 | 一期 | 信息中心 |
| F13 | **消息**：节点到达、驳回、完成时发站内消息（WebSocket 铃铛）；邮件和企业微信放二期 | 一期站内；二期外部渠道 | 消息节点 / 消息平台 |
| F14 | **超时**：节点设时限，到期提醒；自动通过或自动转交放二期；工作日历放二期 | 一期提醒；二期自动处理 | 超时处理 |
| F15 | **自动动作节点**：审批通过后自动下推下游单据，或调用内部服务（例如 MO 审核后自动下达） | 二期（一期用“审核后自动下推”参数实现） | 自动单据转换动作 |
| F16 | **非审核操作走流程**：例如反审核、作废、物料禁用也要审批 | 二期 | 工作流对其他操作的支持 |
| F17 | **实例管理**：管理员可查看、暂停、恢复、终止实例，转派任务，迁移版本（二期） | 一期：查看 / 终止 / 转派；二期：其余 | 流程管理中心 |
| F18 | **单据转换规则引擎**：源 → 目标单配置表，包括字段映射（直取 / 公式 / 汇总）、分组合并（一对一 / 按字段合并）、选单条件、可转数量 = 源数量 − 已转数量；运行时支持下推、选单、上查、下查、全流程跟踪（基于 bill_link 表） | 一期 | 单据转换规则 |
| F19 | **反写规则引擎**：保存或审核时累加、扣减、覆盖源单字段；删除或反审核时回滚；超额控制（禁止 / 按比例允许）；行关闭和整单关闭（任一行或全部行，支持按比例关闭）；多源按“自上而下”分配；跨级反写 | 一期（多源按权重分配放二期） | 反写规则 |
| F20 | **业务流程路线**：限定某单据类型允许的下游路线（例如“直接入库”和“汇报入库”两条路线），生成路线实例号 | 二期（一期在转换规则里配“允许的源单据类型”即可） | 业务流程 |
| F21 | **流程报表**：节点平均耗时、超时率、个人待办排行 | 二期 | 流程分析报表 |

| 方案 | 现状 | 优点 | 缺点（对本项目） |

| **Flowable 7.x / 8.x** | Apache 2.0；7.2.0 于 2025-08 发布，基于 Spring Boot 3；8.0.0 于 2026-02 发布，基于 Spring Boot 4 | 完整 BPMN 2.0，含会签（多实例）、边界定时器、历史、REST；中文社区资料多 | 只能用 Java；只覆盖 L2，L1、L3、L4 仍要自写；自带约 80 张 ACT_* 表；中国式审批（加签、驳回到任意节点、撤回、委托）都要二次开发命令；如果后端选 NestJS，就要多部署一个 Java 服务 |
| **Camunda 7** | 社区版已于 2025-10-14 发布最后版本 7.24 后停止维护（EOL）；企业版有 LTS 到 2030 | 成熟，与 bpmn-js 同源 | 新项目不应依赖已停更的社区版；企业版要付费 |
| **Camunda 8** | 从 8.6 起，Self-Managed 部署用于生产需要企业版许可 | 云原生、可扩展 | 需要许可证；需要 Zeebe 和 Elasticsearch，对单台 lustone 服务器过重；也不覆盖 L1、L3、L4 |
| **自研轻量引擎 + bpmn-js** | bpmn-js 采用 bpmn.io License（可免费商用，但渲染图上的 bpmn.io 水印必须保留且可见） | 与 NestJS 同语言、同库（MySQL 表约 8 张）；只实现第 5 节的 BPMN 子集；中国式审批语义可以直接按金蝶做；L1–L4 统一设计，状态、审批、下推、反写在同一个数据库事务里 | 需要自己保证正确性（并发、回滚）；不支持完整 BPMN（我们也不需要） |

### 6.2 结论：推荐“自研轻量引擎 + bpmn-js 设计器”（后端采用 NestJS 时）

理由：
1. 金蝶的流程能力里，对 ERP 最关键的是状态机、下推和反写（L1、L3、L4），没有现成引擎可以替代，必须自写。剩下的审批（L2），我们只需要一个 BPMN 子集：顺签、或签、会签、条件、并行、驳回、撤回、转交、加签、委托、超时提醒。
2. 审批通过要触发“单据状态变为已审核”，并可能接着下推、反写、改库存，这些要在**同一个 MySQL 事务**里完成。自研引擎和业务共用一个 Prisma 事务；用外部 Java 引擎就得处理分布式一致性。
3. Camunda 7 社区版已停止维护，Camunda 8 生产要许可证，都不适合本项目。
4. bpmn-js 只用于建模和展示。我们存 BPMN XML，后端解析成内部 JSON（节点、连线、条件、参与人配置）后执行。以后如果要迁到 Flowable，BPMN 定义还能复用。
5. 规模合适：单工厂、几十个用户，单进程引擎就够用；不需要分布式调度。

**备选**：如果老板选择 Spring Boot 作为后端，就改用 **Flowable 7.2（Spring Boot 3）** 承担 L2，前端仍用 bpmn-js 或 Flowable 设计器。会签用多实例，驳回、加签、撤回用 Flowable 的 ChangeActivityState 和自定义命令实现。L1、L3、L4 仍然自写。

### 6.3 自研引擎的最小数据模型（供合稿用）
- `wf_definition`（流程定义：key、名称、单据类型、版本、BPMN XML、解析后的 JSON、状态）
- `wf_template`（模板：单据、单据类型、启动条件、生效 / 失效日期、启用）
- `wf_instance`（实例：定义版本、单据 ID / 编号、发起人、状态（运行 / 暂停 / 终止 / 完成）、当前节点集合）
- `wf_task`（任务：实例、节点、处理人、委托来源、状态（待办 / 已办 / 已撤回 / 已转交）、到期时间、会签票）
- `wf_action_log`（审批记录：动作（同意 / 驳回 / 转交 / 加签 / 撤回 / 终止）、意见、时间）
- `wf_delegate`（委托规则）
- `bill_convert_rule`（转换规则：字段映射 JSON、分组、选单条件）
- `bill_writeback_rule`（反写规则：触发操作、方式、目标字段、超额策略、关闭策略）
- `bill_link`（源单行 → 目标单行，记录转换数量，用于上查 / 下查 / 回滚）
