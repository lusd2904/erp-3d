## 1. 三类“流程”的分工（原文：流程设计器、业务流程与自由流程）
| 类别 | 管什么 | 设计器 | 是否改单据状态 |
|---|---|---|---|
| 审批流 | 单据的多级审批 | 审批流设计器（开始、审批、终审、消息、人工服务、结束节点） | 普通审批节点不改；**终审节点**执行后完成审核并改单据状态 |
| 工作流 | 更复杂的审批和自动化：流程→节点→动作三层；动作有审批、消息、脚本、自动单据转换、自动单据提交、服务 | 工作流设计器 | 由审批动作绑定的表单操作（保存/提交/审核/反审核，也可以是禁用、作废、整单关闭等）决定 |
| 业务流程 | 多张单据之间的上下游路线（单据节点、子流程节点、连线；连线上挂反写规则和业务流程消息） | 业务流程设计器 | 不改，只约束下推路线并生成业务流程实例号 |

- 业务流程 vs 自由流程：业务流程约束多单据路线，只有一个入口单据；自由流程只靠单据转换规则下推。子流程节点只能当末端节点。
- 业务流程的生命周期：保存（状态=创建，保存时不校验）→ 发布（先校验完整性，生成版本，状态=启用）→ 在**业务流程配置中心**给入口单据按“单据类型”配版本、生效日期、失效日期，可设默认流程（一个入口单据对应一个模板）→ 运行时下推或选单后生成流程实例 → 在**业务流程管理中心**查看实例流程图，并可把运行中的实例**切换版本**。

## 2. 单据状态（原文：单据状态通用说明，及各单据页面）
- 通用单据状态：暂存（不校验）→ 创建（保存时校验）→ 审核中（提交工作流）→ 已审核 → 重新审核（审核被驳回）。
- 作废、关闭/业务关闭、冻结、终止是另外的状态维度（各单据字段表里有）。
- 行状态示例：
  - 工序计划单据体：创建 / 计划 / 计划确认 / 下达 / 开工 / 完工 / 关闭，可以通过“行执行 / 反执行”灵活跳转。
  - 生产订单行：计划 → 计划确认 → 下达 → 开工 → 完工 → 结案（详见 摘录汇总.md §1）。
- 流程实例状态：运行中、暂停、挂起（带错误信息）、终止（不可逆，也不反审核单据）、完成。
- 业务流程状态：创建、启用。
- 反写规则状态：草稿、正常、禁用。

## 3. 审批流与工作流的节点能力
- **顺签**（顺签审批流程）：
  - 线性逐级审批，例如主管 → 经理 → 总监（总监为终审），终审后给发起人发消息。
  - 每一级可以配多个参与人，但**任一参与人处理即视为本节点完成**。全站没有出现“或签”这个词，按原文语义，这就是或签。
  - 审批流不画驳回线，运行时由“允许选择驳回节点”选项决定能不能驳回、驳回到哪个节点。
- **会签**（会签审批流程、工作流设计器-审批-字段说明）：
  - 按票数通过：确定票数，或比例票数。
  - 按投票人数：比例人数。
  - 可以要求参与人按顺序处理。
  - 会签与“指定下一步处理人”、“选择驳回节点”互斥。
- **并行 / 条件分支**（并行分支流程、条件分支流程）：
  - 节点的出入模式有两种。并行：等全部前序到达。串行：任一分支到达即可，其余分支丢弃。
  - 条件分支有两种做法：模板的“启动条件”，或连线上的条件。
- **驳回**：
  - 工作流必须显式画驳回线，不能驳回到开始节点。
  - 审批流在运行时选择驳回节点，可以设“默认驳回到开始节点”。
  - 审批项有三类：正向、驳回、终止（例如审批同意、驳回重审、终止流程），审批项可以自定义，并绑定表单操作。
- **其他节点选项**：
  - 转发；加签（前加签、后加签，受“工作流加签规则”约束）；传阅；批量处理；指定下一步处理人；追加参与人。
  - 解析不到处理人时跳过节点。
  - 超时处理：自动执行某个审批项，或转交他人，按“工作流日历”计算工作时间。
  - 消息、邮件通知（邮件审批）、电子签章、撤销。
- **参与人**：用户、角色、任岗员工、岗位、部门（负责人 / 直属员工 / 全部员工，可含上级或下级部门）、汇报关系（直接或间接上级、下级、同级）、流程变量（如发起人），可以用“并且 / 或者 / 排除”组合，可以设参与人方案的优先级。
- **委托与移交**：
  - 流程委托规则：按时间段把任务委托给他人，待办会标“委托状态=是”。
  - 流程移交：按用户维度移交在办任务。
  - 另有工作流角色、角色组。
- **对“审核”以外操作的审批**（工作流对其他操作的支持）：
  - 把禁用、反审核等操作包装成“提交 XX”操作，把审批动作绑定到目标操作。
  - 操作上可以勾选“是否检验流程”：勾选后不能绕过流程直接改状态。
  - 一张单据只能有一个流程模板，按“启动条件”区分不同流程，例如：禁用状态=否且单据状态=创建；反审核流程的启动条件是单据状态=已审核。
- **生命周期**：设计 → 测试 → 发布版本 → 模板配置（适用的单据、组织、启动条件、节点视图）→ 启用 → 发起 → 处理 → 流程实例和待办管理（暂停 / 终止 / 恢复）→ 归档。
- **运行参数**（流程中心系统参数）：处理模式有消息队列（推荐）和同步两种；邮件发送可选上一步处理人的邮箱、单个虚拟账户或多个虚拟账户。
- **报表**：流程总体状况分析、流程时间耗费分析、流程节点时间耗费分析、流程运行状况分析；另有流程日志。

## 4. 待办与信息中心（信息中心_*）
- 菜单：待处理任务、已办任务、我的流程、在办流程、草稿箱、发件箱、废件箱、收藏夹、我的加签、我的转发、我的可发起流程、流程反馈、监控方案。
- 待办的字段：发送人（上一步处理人；多人投票时取最后一个生效的投票人）、主题、接收时间、阅读状态、内容、流程名称、流程实例、流程模板、上一步处理项、上一步处理意见、单据摘要、委托状态。
- 处理入口有两个：信息中心的待办，或者直接在单据 / 列表上点“审核”。

## 5. 单据转换（下推 / 选单）规则（单据转换规则、下推与特定下推、自动下推）
- **规则要素**：
  - 源单与目标单，以及主实体关联和控制字段。
  - 单据类型映射。
  - 字段映射方式：自动、自定义公式、求和、平均值、计数、最大值、最小值、用逗号连接；还有“过滤 / 仅过滤”。
  - 分组合并：一对一、多对一、按规则分组合并。
  - 排序、选单条件、插件、表单服务、尾差处理。
- **运行时操作**：下推、选单、特定下推、特定选单、上查、下查、全流程跟踪。
- **自动下推的三种方式**：
  - 工作流里的“自动单据转换”动作（要求规则是一对一）。
  - 在“审核”操作上配自动下推服务。
  - 插件。
- **单位换算**：数量统一按基本单位数量传递和反写，前台再按换算关系显示。

## 6. 反写规则（反写规则）
- **触发**：保存或审核时反写；删除或反审核时回滚。
- **反写方式**：累加、扣减、覆盖（带回滚值）。
- **多源单分配**：自上而下，或按权重；可设分配上限。
- **关闭控制**：设行关闭条件（字段、值）；整单关闭可以按“任一行关闭”或“全部行关闭”。
- **超额控制**：禁止超额、允许超额一次、允许超额；可以配校验公式。
- **原文场景**：跨级反写、同组反写、按比例关闭（例如 98%）、按比例超额（例如 1.2 倍）。
- **在业务流程上的位置**：连线上可以关联一条“专属反写规则”，只在这条路线上生效。
